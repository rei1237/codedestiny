# Frontend Design

## Core Philosophy

Approach design work as "the design lead at a small studio known for giving every client a visual identity that could not be mistaken for anyone else's."

The goal is creating **distinctive, intentional visual work**—not following templates or common defaults.

## Key Principles

### 1. Ground in Subject Matter

Before designing anything:
- Identify the **concrete subject** the page represents
- Understand the **audience**
- Clarify the **primary function**
- Use the subject's own vernacular and materials to inform design choices

Example: A music player's design should feel different from a meditation timer. Let the subject shape the visual identity.

### 2. Typography as Personality

**Type is not decoration—it's voice.**

- Pair display and body typefaces deliberately
- Use intentional scale, weights, and spacing
- Typography should be memorable, not neutral
- Each pairing should feel intentional for that specific subject

### 3. Structure Encodes Information

**Design elements reflect content, not decorate arbitrarily.**

- Numbering, hierarchy, and spacing should map to actual relationships
- Visual structure should reinforce the user's mental model
- Avoid arbitrary decorative flourishes

### 4. Motion With Purpose

Animation should serve the subject deliberately—either:
- **Clustered into orchestrated moments** (e.g., a loading sequence, a page transition)
- **Minimized to avoid appearing AI-generated** (subtle interactions, not everything moving)

Avoid animation for its own sake.

## Common Defaults to Avoid

Three clustering patterns dominate current AI design (these are not wrong if briefed specifically, but shouldn't fill open directions):

1. **Cream backgrounds with serif display faces** — warm, editorial, often overused
2. **Near-black with acid accents** — high contrast, tech-forward, common starting point
3. **Broadsheet-style layouts** — newspaper-like grids, editorial voice

Know these patterns; use them when intentional, not by default.

## Design Process (Two Passes)

### Pass 1: Compact Design Plan

Before writing any code, develop a plan covering:
- **Color palette** — 3–5 intentional colors for this subject
- **Typography** — display + body pair with scale/weight hierarchy
- **Layout structure** — how content relates spatially
- **Signature element** — one distinctive visual feature (icon, animation, pattern)

### Pass 2: Critique Against Brief

Before coding:
- Does this plan address the brief?
- Is every choice intentional for *this* subject?
- Would another subject need a completely different treatment?
- Are we defaulting to a template, or creating something distinctive?

## Writing Standards

**Copy serves clarity, not decoration.**

- Use active voice
- Choose plain verbs over fancy ones
- Write conversationally, tuned to audience and brand
- Avoid corporate jargon and redundant marketing speak

## Application to Code Destiny

For Code Destiny's UI/UX:

1. **Subject**: AI-powered fortune-telling and destiny insights (mystical, personalized, visual)
2. **Audience**: People seeking astrological/tarot guidance (mix of spiritual + tech-savvy users)
3. **Personality**: Balance mystique with accessibility; avoid stereotypical "mystical" clichés

**Distinctive choices for Code Destiny:**
- Typography reflecting both elegance and modernity (not serif + minimal, nor sans + sterile)
- Color palette avoiding purple-and-gold mysticism clichés
- Layouts that guide users through journeys (fortune-telling is a narrative experience)
- Motion emphasizing revelation (results appearing, insights unfolding)

## Guidelines for Implementation

1. **Start with subject, not templates**
2. **Critique before coding** — is every element intentional?
3. **Typography has work to do** — it's not neutral
4. **Color serves meaning** — avoid decoration
5. **Motion reveals, not distracts**
6. **Copy is clear** — avoid flowery language
