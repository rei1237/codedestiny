# GREEN 수정 실행

사용자 요청: $ARGUMENTS

🔴 **이 커맨드는 [CLAUDE.md](../../CLAUDE.md) §🟢 실행 계약의 GREEN 경로를 발동시킨다.** 아래 순서를 그대로 따른다.

## 1. 등급을 먼저 판정한다 (RED 면 여기서 경로가 갈린다)

요청이 아래 중 **하나라도** 걸리면 RED 다:

결제·이용권·월정석·가격 / 인증·세션 / 프로덕션 DB·마이그레이션 / 배포·릴리스·CI 워크플로 / Worker 라우팅·R2 / **삭제·리네임** / 공유 모듈·공통 훅·다중 참조 함수·기본값 / 정적 셸 `index.html`·`public/**` 미러 / `config/payment-freeze.json` 등재 파일 / 절대 규칙 1~6 접촉 / **2개 이상 파일**.

- **RED 면** — 그 사실과 걸린 항목 한 줄만 알리고, 이 커맨드를 중단한 뒤 평소 절차(라우팅 문서 → 워크트리 → 선보고 → 수정)로 간다. 🔴 사용자가 `[등급] GREEN` 을 적었어도 판정이 이긴다.
- **판정이 애매하면 RED 다.** 확신이 없는 것을 GREEN 으로 밀지 않는다.
- **GREEN 이면** 2번으로 간다.

## 2. 대상을 잡는다 — 여기서 오래 끌지 않는다

- 요청에 `@경로`·`ide_selection`·파일 경로가 있으면 **그것만 Read 한다.** 추가 탐색 금지.
- `탐색 필요` 로 왔으면 `code-locator` 에이전트로 위치만 받는다. 본세션에서 Grep 을 훑지 않는다.
- 🟢 **`docs/context/*.md` 라우팅 표는 면제다.** 근거는 고치는 파일과 그 직접 이웃에서 얻는다.
- 🟢 **워크트리 면제** — 단일 파일이면 현재 디렉터리에서 바로 고친다. 2개 파일 이상이면 애초에 RED 이므로 1번으로 돌아간다.

## 3. 즉시 고친다

- 🟢 **이 응답 안에서 Edit 를 낸다.** 계획·설명·요약만 내고 턴을 끝내면 실패다.
- 🟢 **확인 질문 금지.** 해석이 여럿이면 요청 문장이 가장 직접 지지하는 것을 골라 실행한다.
- 🟢 **덮어쓰기가 기본이다.** 기존 코드를 살리려고 래핑·조건 분기·옵션 플래그·새 변형을 만들지 않는다. `[변경]` 이 대체를 뜻하면 갈아 끼운다.
- 범위 **밖**에서 발견한 결함은 고치지 말고 4번 보고에 후속 과제로만 적는다(원칙 14).

## 4. 검증하고 보고한다 — 여기는 면제가 아니다

```bash
npm run lint && npm run typecheck && npm run check:quick -- --skip-build
```

🔴 `--skip-build` 를 빼지 말 것(빼면 로컬 `build:cf` 가 실패하며 27~174초를 태운다).
UI 를 고쳤으면 `verify:hero-contrast` · `verify:mobile-detail-nonintrusive` 를 함께 돌린다.
