# 월정석 소환과 개발 정산

공개 서비스의 이용권·월정석·단건 결제 정책은 기존 코드가 정본이다. 아래 숫자는 `scripts/fixtures/mock-card-rpg.mjs`의 격리 개발 설정이다. 운영 배너 가격, 기간, 풀, 보장, 프로덕션 활성화는 미승인이다.

| 배너 | 슬롯 1개 / 10개 | 일반 슬롯별 개별 확률 | 픽업 |
|---|---|---|---|
| 언덕 너머의 동료들 | 40 / 400 | 윤달 15%, 모카 45%, 루나 40% | 윤달 |
| 빗소리가 그친 자리 | 40 / 400 | 서한비 15%, 연이 45%, 영냥이 40% | 서한비 |
| 방에 남은 작은 기억 | 20 / 200 | 연꽃의 문장 15%, 세 번째 알람 45%, 창가의 아침 40% | 연꽃의 문장 |

1회와 10회 모두 순서대로 같은 보장 규칙을 적용한다. 해당 배너에서 픽업 없이 9회가 누적되면 다음 슬롯은 픽업 확정이다. 픽업 당첨 시 0으로 돌아간다. 희귀도 보장, 별도의 마지막 칸 덮어쓰기, 배너 간 보장 이월, 무료 소환은 없다. 같은 배너의 개발 설정 버전 교체는 누적을 유지하고 새 배너 ID는 0부터 시작한다. 설정 ID는 banner `dev-1`, pool `pool-1`, price `price-1`이다. 픽업과 개별 확률·확정 비용은 조회 시 서버가 보낸 버전을 표시한다. 기간이 없으면 카운트다운을 두지 않는다.

개발 서버에 연결한 mock-user의 월정석은 기존 `User.profileSubscription.membershipCreditLots`에서 조회한다. 운영 지갑 복사나 별도 RPG 잔액 필드는 없다. 결제 검증용 `makeFakePaymentDb`와 기존 `consumeMonthlyCreditLotsWithDb`가 만료를 제외하고 지급일 기준 FIFO로 정수 차감한다. 기존 lot 스키마에는 유료·무료 양자 구분이 없다. 테스트 지급 출처와 구매 출처, 만료된 지급분을 별도 lot으로 만들어 검증한다. 생애 첫 fixture에는 유효 월정석 600개가 들어 있다. 메모리 검증과 달리 개발 서버 실행본은 포트별 `.tmp/mock-wallet-<포트>.json`을 원자 교체하여 재시작해도 기존 테스트 잔액을 유지한다.

`account + key` 하나에 배너·횟수·가격·풀 버전을 묶는다. 이미 확정한 결과는 배너가 중단·만료돼도 같은 키로 가져올 수 있다. 새 요청은 기간·금액·확률 합계·풀·계정·누적을 검사한 뒤 서버 난수로 추첨한다. 동일 DB 트랜잭션 안에서 lot CAS 차감, MonthlyCreditLedger 지출 증빙, 소유 ID, 중복 조각, 보장, 영수증을 쓴다. 저장 실패는 전부 롤백한다. 클라이언트는 이력을 다시 읽어 필요한 카드만 개발 컬렉션에 반영한다. 공개 연출과 새로고침은 실험용 원장을 변경하지 않는다. 캐릭터 중복은 장당 개발 조각 3개, 예장 중복은 개별 장착 가능한 새 소유 개체다. 일반 미리보기에서는 2~3단계의 고정 결과 실험을 계속 이용할 수 있다.

개발 원장 API는 루프백 연결에서 `CD_MOCK_DEV=1`, `NODE_ENV=development`, 개발 로그인 때 발급한 기기 세션 쿠키를 확인한다. 쿠키는 HttpOnly·SameSite=Strict이며 로그아웃 또는 12시간 경과 시 만료된다. 소환 요청은 JSON으로 보내고 확인 화면에 표시한 차감액과 차감 전 잔액이 서버 계산과 일치해야 한다. 재시도는 기존 확정 영수증을 먼저 찾는다. 결과의 정산 직후 잔액은 그 영수증에 저장한 금액이다.

## 격리 검증

- `node scripts/verify-card-rpg-wallet.mjs`로 실제 월정석 lot 차감 함수와 기존 영냥이 상품의 월정석 할인 예약 함수가 같은 테스트 잔액을 다투는 사례를 실행한다. 만료 제외·FIFO, 부족, 연타, 키 인자 충돌, 10회 천장, 복수 예장, 배너 변경, 복구·재시작을 확인한다.
- `node scripts/verify-card-rpg-wallet-ui.cjs`는 전용 loopback mock API와 빈 Chromium 컨텍스트에서 세션 없는 요청 거부, 캐릭터 10회 소환(600→200), 예장 10회 소환(200→0)을 확인한다. 예장 거래 승인 직후 응답을 끊고 브라우저를 새로고침해 영수증에서 10장을 복구한 뒤 선택한 중복 예장의 소유 ID와 도감 장착 대상 ID를 대조한다. 실제 운영 MongoDB 트랜잭션 및 다중 서버 운영 정산은 미검증이다.
