# 마스터 인연의 서 실제 응답·모바일 리더 검증

사용자의 명시적 LLM 호출 승인 이후 진행했다. 가상 인물 2명의 입력을 사용하고 Gemini 엔드포인트만 허용했다. 운영 DB 연결·실결제·운영 배포는 하지 않았다. 실제 응답 원고는 로컬 build-cache/p0-live/full/solo-book.md 및 compat-book.md에 보관한다.

## 발견과 수정

## 실제 LLM 결과

모델: gemini-2.5-flash. 초기 대표 장 6개와 편집 수정 대표 장 6개를 확인한 뒤, 최종 생성 함수로 전체 두 권을 생성했다. 전체 생성은 40개 장에 대해 공급자 호출 50회(재작성 포함), 로그상 입력 214,561 토큰·출력 145,337 토큰이다. 이는 청구 금액 또는 모든 내부 과금 항목의 합산이 아니다.

| 원고 | 완료 | 본문 글자 수 | 장별 분량/구조/DNA | 장 사이 동일한 100자 이상 문단 |
| --- | ---: | ---: | --- | ---: |
| 개인판 | 20/20 | 58,094 | 모두 통과 | 0 |
| 궁합판 | 20/20 | 64,347 | 모두 통과 | 0 |

첫 장·교차 해석·DNA·마지막 조언을 읽어 초기 모순의 수정과 근거/조언 연결을 점검했다. 최종 궁합의 끌림 시각화는 low로 유지되고, 요약도 서로 다른 기질을 조율해야 하는 관계로 설명한다. 조언에는 질문할 문장과 주 1회 대화 시간처럼 실행 가능한 예가 추가됐다. 동일 문단 검사는 의미상 반복이 전혀 없음을 뜻하지 않는다.

새 입력·다른 언어·모든 생성의 해석 타당성이나 상담 효과를 보증하는 검사는 아니다. 일부 전문용어와 제공된 성요의 등급 표기는 여전히 남는다. 원래 계산 엔진, 가격, 이용권 등급/한도는 변경하지 않았다.

기존 `verify-llm-generation-resilience`의 짧은 장 허용 예외도 장별 전용 품질 계약으로 갱신했다. 실제 응답·캐시의 검증 경로와 분량/구조/DNA 거부 계약을 확인하며, 갱신 후 884개 검사가 통과했다. 기존 검사에 있던 예외 문구를 복원해 품질 검증을 우회하지 않았다.

## 모바일·결제 복구 확인

Chromium의 360/390/430/1280px에서 개인판과 궁합판을 확인했다. 가로 넘침 0, 조사한 노출 컨트롤의 44px 미달 0, 페이지 오류 0. 신규 목차·상담 요약·본문을 실제 생성 데이터로 확인했다. 물리 Android/iOS 기기나 WebView 검증을 대신하지 않는다.

`node scripts/verify-master-love-codex-reader.mjs`는 로컬 개발 서버에서 모든 API를 mock한다. 목차 20개, 10장 이동과 초점, 상세 본문 열기, Esc 닫기, 저장소 차단, 취소 응답에서 결과 미표시를 네 화면 폭에서 통과했다. PDF 문서/페이지 선택자와 forceVisible 계약은 유지하고 정적 가드로 확인했다. 실제 PDF 파일 생성은 별도 미검증이다.

빌드 후 제목 계층 검사에서 공통 리더의 H1과 진입 페이지의 서버 H1이 중복될 수 있음을 발견했다. 리더 표지를 H2로 정리하고 별도 결과 라우트는 자체 H1을 소유하도록 수정했다. 표지 스타일은 유지하며 브라우저 검사에 결과 화면 H1 1개 조건을 추가했다.

UI detector는 anti-pattern 0, 기존 프로젝트 타이포 체계와의 차이 advisory 25개였다. 해당 결과 화면의 기존 서체와 색상 체계를 유지했다. Impeccable의 기존 PRODUCT/DESIGN 보조 기록에 버전 불일치 안내가 있었지만 이번 작업에서 전역 디자인 기록을 개편하지 않았다.

## 스테이징 모드 호환

main a724956a6의 외부 공급자 없는 스테이징 모드를 통합했다. `APP_ENV=staging`, `STAGING_LLM_MOCK_ENABLED=true`, `WORKERS_AI_ENABLED=false` 세 조건이 함께 충족된 경우에만 명시적으로 표시된 검증 원고를 생성한다. 개인판·궁합판의 장별 분량과 DNA 필드 계약은 동일하게 검사한다. 실제 운영 생성 경로는 이 조건 없이 fixture로 폴백하지 않는다.

격리 Mongo replica에서 실제 `/generate` 핸들러를 호출해 20개 장 저장·완료 후 소비를 확인했다. 이 검사는 외부 네트워크를 차단했으며, 실제 배포된 스테이징·PG 검증이나 실제 상담 품질 평가를 대신하지 않는다.

결제·회차 회귀는 [P0 보고서](payment-p0-incident-20260909.md)에 별도로 기록한다. 실제 LLM 호출 승인은 PG 결제·운영 DB 쓰기·배포 승인으로 확장하지 않았다.
