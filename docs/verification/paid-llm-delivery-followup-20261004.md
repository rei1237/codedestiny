## 수정 내용

### 공통 서술형 결과 변경 철회

공통 중복 문장 정리는 표적 mock 검사에서는 통과했으나 전체 Jest에서 손금 소제목 보존 회귀 1건을 발견했다(332 suites 통과, 1 suite 실패). 저장소 회귀 원칙에 따라 b7d229323을 b909cb0c4에서 전부 revert했다. 손금 및 공통 서술형 결과 동작은 기존대로 유지한다. 운영 반영 전 철회했으며 실제 고객 결과 변경은 없다.

### 찻집 자동 복구 연결

- `worker/routes/fortune-tea-house.js`: 실패 처리 시 현재 잠금에 속한 저장 체크포인트와 실제 예약된 시도 횟수를 재조회한다.
- 원래 입력·남은 시도 예산이 있으면 `partial`로 저장하고 202를 반환한다. 기존 cron이 동일 구매·동일 결과 ID로 재개하며 deferred cancel을 호출하지 않는다.
- 입력/계산 근거 오류, 시도 예산 소진, 체크포인트 없는 구버전은 기존 종단 실패 처리로 남긴다.
- 다른 워커가 잠금을 가져간 경우 이전 워커가 실패 상태를 덮어쓰거나 결제를 취소하지 못한다.
- 이미 실패한 과거 문서를 배포만으로 일괄 재개하지 않는다. 시도 한도를 늘리거나 새 과금 경로를 만들지 않는다.
- 커밋: `2d9088233`.
