# 운명의 찻집: 십성 손님·꽃돼지 구현 검증

## 범위와 승인

2026-09-30 Phase 0 보고 후 사용자가 구현을 승인했다. 꽃돼지 WebP는 6종씩 두 번 미리보기를 제시했고, 각 6종의 화면 연결을 별도로 승인받았다. 추가 요청에 따라 말풍선은 크림·연분홍 바탕, 꽃잎 장식, 둥근 꼬리로 조정했다.

## 구현

- `lib/fortune-tea-house/saju-guests.js`: 기존 명식 확정표와 엔진 용신 오행만 소비하는 순수 함수. 원국 천간·지장간, 대운·세운 천간을 자리별로 보존한다. 용신과 희신이 겹치면 용신을 우선한다. 없는 등급은 `unavailable`이며 한신으로 추정하지 않는다.
- `src/features/fortune-tea-house/lib/sajuAdapter.ts`: 기존 엔진의 `usefulGods`를 `usefulGodEvidence`로 보존한다. 계산 함수나 엔진은 변경하지 않았다.
- `lib/fortune-tea-house/saju-category.js`, `saju-guest-prompt.js`: UI 선택 우선, 규칙 기반 추론, 주·보조 주제, 분류 불가 시 UI에서 주제 선택 요청. 10개 주제 모듈과 최대 12개 관련 손님을 기존 LLM 호출에 주입한다. 추가 공급자 호출은 없다.
- `worker/routes/fortune-tea-house.js`: 기존 실제 프롬프트 조립부에 손님·주제 모듈 연결. KST 요청 날짜 사용. 월운이 없으므로 월·일·상하반기 적기 창작 금지. 서버가 만든 손님 명단과 판정은 LLM 병합으로 덮어쓸 수 없다. 사주 계열 캐시만 v5로 구분한다.
- `QuestionInputScene.tsx`, `SajuGuestList.tsx`: 주제 선택과 원국·대운·세운별 접이식 손님 카드. 전문 명칭, 등급, 전통 성정, 실제 자리와 근거를 함께 표시한다.
- `LandingPig.tsx`: 대사·포즈·타이머를 국소 상태로 분리. 일반 대사 7초, 새 긴 대사 15초. 최근 노출을 가능한 범위에서 제외하고 연속 반복을 막는다. 긴 대사는 처음 5회 이후, 최소 5회 간격, 랜딩 마운트당 최대 2회. 숨김·화면 밖에서는 타이머를 멈춘다. 모션 감소에서는 기본 포즈 및 무전환 대사를 사용한다.
- 기존 랜딩의 960px 포함 메인 그리드·진입 버튼·safe-area 규칙은 유지했다. 모바일 말풍선은 캐릭터와 다른 행을 사용한다. 전체 대사 높이를 미리 확보하고 투명도만 바꾼다. 작은 높이에서 말풍선을 숨기던 규칙은 제거했다.
- `public/images/fortune-tea-house/flower-pig-*.webp`: 승인된 신규 12종. 512×512, 실제 alpha 채널, 개별 약 26~33KiB. 표시하는 한 장만 lazy 로딩한다. 문구를 그림에 넣지 않았다.
- `i18n/authored/fortuneTeaHouse-46.json`: 새 UI 문구와 요구 대사의 12개 런타임 언어 번역. 기존 코어 사전 병합기를 사용했다. 원어민 문체 검수는 별도다.

## 측정 결과와 한계

아래는 **실제 랜딩 React 컴포넌트와 해당 CSS를 분리 실행한 합성 측정**이다. Next 이미지 컴포넌트·버튼·사전 훅은 대역했고, 외부 통신은 차단했다. 이미지 실패 폴백 재렌더는 제외했다. 전역 Tailwind·앱 셸·로그인·API·실기기는 포함하지 않는다. 따라서 전체 앱 INP, LCP, 하이드레이션 또는 실제 Android WebView 수치로 해석하면 안 된다.

조건: Chromium headless, CPU 4배 감속, 390×844, 초기 마운트 이후 15초 idle. 원본 랜딩과 변경 랜딩을 같은 조건으로 비교했다. 원본 코드는 이번 작업 전의 랜딩이다.

전체 CPU 개선을 주장하지 않는다. 확인된 개선은 대사 전환의 레이아웃·부모 재렌더 제거다. 단일 짧은 실행이라 시간 수치는 변동할 수 있다.

- 변경 전: 360×640에서 말풍선 숨김. 390×844, 412×915, 768×1024, 960×900에서 긴 대사와 캐릭터 경계가 겹쳤다. 1280×900에서는 겹치지 않았다.
- 변경 후: 위 6개 뷰포트 모두 말풍선 표시, 캐릭터 겹침 0, 가로 넘침 없음.
- 12개 로케일 × 6개 뷰포트 = 72조건에서 4개 대사 전환: 겹침 0, 높이 고정, 가로 넘침 없음. reduced-motion에서 캐릭터 animationName은 모두 `none`.
- 전체 Next dev 실행은 C: 워크트리와 D: node_modules 연결 때문에 실패했다. 기본 번들러의 드라이브 경로 해석, 경로 보존 옵션의 CSS 플러그인 중복, Turbopack의 외부 루트 심볼릭 링크 제한이 관측됐다. 프로젝트 설정을 우회 수정하지 않았다.
- 서버 DB/네트워크·Workers CPU, 공급자 TTFT·실토큰·완료 시간, 실제 Android WebView INP, 실기기 safe-area는 미측정이다. 실 LLM·실결제·운영 DB를 실행하지 않았다.
- 기존 엔진 계산 지연을 근거 없이 고치거나 새 캐시를 도입하지 않았다. 손님 명단은 초안 정규화에서 준비하고 프롬프트에는 필요한 명단만 선택한다.

## 검증

- `tsc --noEmit --incremental false`: 통과.
- 변경 파일 ESLint: 오류 0. 기존 Page/QuestionInput effect 의존성 및 Worker 미사용 변수 경고는 범위 밖으로 유지.
- 찻집 Worker 7개 스위트: 152개 통과. 겁재/상관의 유리한 등급, 판정 누락, KST 경계, 20개 카테고리 질문, 명단 변조 방어 포함.
- 관련 UI·i18n·유료 복구: 30개 통과.
- `npm run check:fast`: 유료 게이트 87개 통과. 전체 Jest 325개 스위트/4,813개 통과. Node 테스트 2,113개 통과/1개 실패로 최초 실행 중단.
- 최초 실패는 공용 사전 변경 후 사이트맵 서명 원장이 갱신되지 않은 상태의 주간 lastmod 검사였다. 기존 생성기 `npm run sitemap:generate`로 원장을 재생성했고, 해당 6개 검사와 드리프트 검사를 재실행했다. 사이트맵 로직 수정은 없다. 전체 실행과 최종 main CI의 결과는 최종 전달 보고에 구분한다.
- 최신 main 병합 및 원장 재생성 후 `npm run test:node`: 2,129개 통과, 실패 0.
- `git diff --check`: 통과. 엔진·`calculateLocalResult()`·KASI/normalizeSaju·PortOne/Inicis·결제 정책은 작업 diff에 없다. 기존 main의 동시 작업은 원격 main 병합으로 보존했다.

## 남은 확인과 롤백

- 엔진에 없는 구신·한신·월운·십성 강약 점수를 새로 만들지 않았다. 신살 손님도 추가하지 않았다.
- 실제 LLM 답변 품질·본문에서 등급을 뒤집지 않는지는 유료 샘플 평가가 남는다. 목 테스트는 명단/판정의 구조적 보존과 프롬프트 배선을 검증한다.
- 전체 앱 및 실기기의 반응형 화면·safe-area·INP 확인이 남는다. 분리 컴포넌트 증거를 전체 앱 검증으로 대체하지 않는다.
- 상담 이어가기 기능·가격·차감·환불·이용권 소진은 변경하지 않았다.
- 문제가 생기면 이 작업의 UI/에셋 커밋 또는 해석 커밋만 선택적으로 revert한다. 저장된 선택적 `guests`/`usefulGodEvidence` 필드는 삭제 마이그레이션하지 않는다. 오래된 결과에는 손님 카드를 표시하지 않고 기존 렌더링을 유지한다. 결제·KV/R2·사용자 자산 스키마를 되돌리지 않는다.
