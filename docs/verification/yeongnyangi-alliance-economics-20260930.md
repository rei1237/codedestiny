# 영냥이 제휴 결제와 비용 검토

사용자는 영냥이에 기존 이용권·월정석을 적용하고, 충분한 혜택과 마진을 함께 확보하길 요청했다. 이후 월 서버비 약 **70달러**, 월 **50묶음 판매**를 기준으로 고등어·연어·광어·참치 전용 횟수권 생성을 요청했다. 공용 이용권 가중 차감안은 새 방향으로 대체되어 아래에 검토 이력만 남긴다. 이 문서는 **승인 전 검토**다. 가격·횟수·만료기간·판매 정책을 새로 실행하지 않는다. 이전 공용 이용권 5%·20%·25% 가중 차감안은 폐기된 검토 이력이다. 새 보고 도구는 그 정책 파일이나 차감 함수에 의존하지 않는다.

## 현재 판단

신규 상담 목표 분량을 약 12% 줄이고 출력 예산을 정리한 뒤, 1,000원 상담의 보수적 주문당 시나리오는 **574.20원**이다. 최대 입력·출력과 허용된 시도를 모두 쓴 가정이며 평균 원가나 공급자 청구 실측이 아니다.

월 50묶음이면 서버비 98,000원은 묶음당 **1,960원**이다. 다음 세 등급은 가입 혜택 사용 0회에서 고객 혜택 최소 20%와 검토 목표인 매출 마진 30%를 함께 만족한다. **고등어는 만족하지 못한다.** 고등어 4.92%를 충분한 마진으로 표현하거나 상위 등급의 이익으로 숨기지 않는다.

모두 검토 가격·횟수이며 상품을 실행하지 않았다. 같은 생선 등급의 사주·자미두수·숙요점·베다점·점성술·타로 6체계를 대상으로 계산했고 융합은 제외했다. 고등어는 낮은 마진의 체험용으로 별도 판단하거나 유료 횟수권 판매를 보류하는 선택이 필요하다. 후자는 기존 단건·가입 혜택을 없앤다는 뜻이 아니다. 더 싼 후보 9,900원/11회는 할인 10%, 고정비 배분 후 327.80원·3.31%라 최소 20% 고객 혜택도 충족하지 않는다.

사용자 예시 **5,000원/7회**는 월 50장·가입 사용 0회에서 운영 이익 **-81,697.27원**이다. 30% 마진을 내려면 회당 비용이 **126.49원 이하**여야 한다. 재시도 없는 첫 응답 성공이라도 같은 입력·출력 상한을 다 쓰는 가정은 312.10원이므로 부족하다. 실제 평균이 126.49원 이하인지 확인한 자료가 없어서 수익성 있는 입문권으로 확정할 수 없다.

## 계산 기준

- 사용자 제공 서버비: 월 약 70달러. 환율 1,400원/달러 가정으로 **월 98,000원**. 실제 청구서·귀속 비용은 확인하지 않았다. 보고 도구는 이를 기본값으로 사용하며, 고정비를 조용히 0원으로 두지 않는다.
- VAT 계산률 10%, PG 계산률 4%는 미확인 계약 가정이다. 순수입은 `판매가 / 1.1 - 판매가 × 0.04`로 계산한다.
- 회당 574.20원은 LLM 상한 시나리오 **524.20원 + 별도 변동비 예비분 50원**이다. 이 50원은 실청구 원가가 아니다. 월 70달러가 DB·저장 등 같은 비용을 이미 포함한다면 중복 충당일 수 있어 0원 예비분 민감도를 별도 제공한다.
- 운영 이익 = 유료 판매량 × 장당 기여액 − 월 서버비 − 실제 사용된 가입 상담 수 × 회당 비용. 모든 유료 횟수권은 포함 횟수를 전부 사용한다고 가정한다.
- 목표 마진은 **운영 이익 / 부가세 포함 총매출** 30%다. 대표 급여·법인소득세 등은 포함하지 않는다.
- 월 판매량 기본값은 사용자 지정 50묶음이다. 100/300/1,000장과 월 가입 혜택 사용 0/50/100/300회는 추가 민감도 시나리오다. 전망이나 실적이 아니다. 서로 다른 월 판매·사용 시점의 현금흐름은 아직 모델링하지 않았다.
- 횟수권의 유효기간, 월정액 여부, 연장·복원·중복 구매·미사용 처리 방식은 **미정**이다. 기존 이용권의 권리를 이 검토로 줄이지 않는다.

목표 비용 산식:

```text
N = 월 유료 판매량, R = 가입 상담 사용 횟수, P = 판매가, Q = 포함 상담 횟수

```

## 공용 이용권 25% 검토 이력

이 절은 전용 횟수권과 비교하기 위한 이전 검토안이며 **확정 정책이 아니다**. 모든 28개 상품과 9개 비Family 구매 정책 중 기존 건당 가격 범위를 통과하는 207개 조합을 계산했다. 구매 당시 가격과 전체 기본 한도를 사용한다.

```text
필요횟수 = ceil(이용권가격 × 4 / (상품단건가격 × 3))
상담당 한도차감 = floor(기본월한도 / 필요횟수)
동종 최대 횟수 = floor(기본월한도 / 상담당 한도차감)
```

조건은 **이용기간 안에 전체 기본 한도를 같은 상담에 모두 사용했을 때, 그 상담들을 단건 결제한 합계보다 최소 25% 저렴**하다는 뜻이다. 남은 한도로 25%를 보장하는 것이 아니며, 일부 사용·다른 서비스 혼합·쿠폰·할인 가격은 제외한다. Family는 기존 1배 차감을 그대로 둔다. 이 산식은 문서에 보존한 과거 검토이며 현재 보고 도구에서 실행하지 않는다.

영냥이 상품 혼합의 최대 비용을 동적 계획법으로 계산해도 모든 조합의 최악은 1,000원 상담 반복이었다. 30%로 높이면 이전 v2·legacy Standard는 각각 고정비 **차감 전부터 -9원**이다. 25% 역시 위 기여액에서 월 서버비와 가입 상담 비용을 충당해야 하므로 사업 전체 무손실이나 충분한 마진을 보장하지 않는다. 꿀꿀운세의 다른 상품을 함께 쓰는 비용은 이 영냥이 내부 혼합 계산에 포함하지 않았다.

25% 시나리오에서 변동비가 2배이면 현행 Standard/Premium/VVIP의 고정비 전 기여액은 -10,018.55/-28,485.27/-58,032.04원이다. 환율 1,600원/달러·PG 5%·회당 예비분 100원이라는 별도 스트레스에서는 -1,181.35/-4,172.22/-8,957.63원이다. 기존 Family의 500회 고등어 권리를 유지하면 기준 시나리오부터 고정비 전 -157,605.45원이다. 과거 권리를 소급 축소해 계산을 맞추지 않는다.

월정석 검토값은 기존의 5배이며 단건 1,000/3,000/5,000/10,000/20,000/50,000원에 각각 500/1,500/2,500/5,000/10,000/25,000개다. 실제 승인·반영 상태와 구분해 사용자에게 안내한다.

## 새 상담 최적화와 기존 저장 계약

새로 준비하는 상담에만 `concise-reading-20260930`을 저장한다. 챕터·소절의 목표와 최소 분량은 **약 12%만** 줄인다. 핵심 판단, 개인별 계산 근거, 관찰 신호와 행동 조언, 질문 답변, 모든 챕터·소절의 식별자와 역할은 유지한다. 최소 분량을 추가로 80% 완화하지 않는다.

새 프로필의 기본 출력 바닥은 4,096토큰이며, 실제 상한은 `max(4,096, 전체 목표 + 메타데이터 600자 + 질문당 480자의 토큰 환산)`에 thinking 1,024토큰을 더한다. 소절 목표 합계가 챕터 목표보다 크면 더 큰 값을 사용한다. 입력 하드 상한 50,000토큰은 줄이지 않는다. 큰 챕터와 질문 8개의 답변 예산을 보존한다.

새 요청에서만 프롬프트의 중복 `OUTPUT_SCHEMA`를 제거하고 실제 `responseSchema`는 유지한다. `DOMAIN_CONTEXT`의 JSON 문자열 중첩을 객체로 풀어 이스케이프 중복을 없앤다. mock 비교로 동일한 계산 사실·질문·규칙을 확인하며, 실제 입력 토큰 절약률을 측정했다고 표현하지 않는다.

**이미 저장된 요청**은 원래 목표·최소 분량·출력 예산·본문을 그대로 쓴다. 일반·신점·질문시각 상담의 과거 구매 재준비가 저장 계약을 덮어쓰지 않는 mock 회귀를 둔다. **과거 가격으로 산 이용권으로 지금 새 요청을 만드는 경우**에는 새 concise 프로필을 적용한다. 이용권 구매 버전과 상담 요청 저장 버전을 혼동하지 않는다.

기존 저장 요청에서 계산한 고등어 비용 시나리오 **653.60원**은 역사 비교값이다. 새 요청의 574.20원으로 기존 요청까지 제한된다고 말할 수 없다. 새 요청의 상품별 같은 상한 시나리오는 연어 872.00원, 광어 1,329.84원, 참치 2,337.01원, 2체계 융합 2,083.46원, 전체 융합 3,253.49원이다. 이것들은 판매 가격이 아니다.

현재 런타임은 장당 최초 생성 1회와 추가 시도 최대 1회를 허용한다. 사용자 재시도·크론·fix epoch가 이 예산을 늘리지 않으며 provider 내부 fallback은 없다. 저장된 사용 가능한 초안을 먼저 복구하고 다시 읽으므로 복구와 완료 결과 열람에 LLM을 쓰지 않는다. 새로운 retry 계층을 추가하지 않았다. 실제 타임아웃 비율·문장 품질 개선은 실 LLM으로 측정하지 않았다.

## 실측과 가정

`PASS_COST_EVIDENCE`는 비어 있다. 웹 판매 허용 정책은 실원가 증거가 아니며 mock 결과를 그 증거로 채우지 않는다.

[Google 공식 가격](https://ai.google.dev/gemini-api/docs/pricing#gemini-2.5-flash)을 2026-09-30 확인했다. Gemini 2.5 Flash Standard 텍스트 입력은 100만 토큰당 0.30달러, 출력·thinking은 2.50달러다. 캐시 할인 없이 계산하며 다른 모델 override는 별도 원가 확인이 필요하다. 매 생성 입력 50,000토큰, 장별 시도 2회, 질문 분석 2회, 첫 장에 질문 8개의 답변 여유를 넣은 상한 가정이다.

[Cloudflare Workers 가격](https://developers.cloudflare.com/workers/platform/pricing/)의 요청·CPU 비용만으로 DB·저장·지원·환불 비용 전체를 설명할 수 없다. 사용자 제공 70달러가 어떤 서비스들을 포함하는지 확인한 후 회당 예비분과 중복을 제거해야 한다.

기존 사주 v7의 일부 저장 토큰 표본은 존재하지만 고등어·다른 체계·질문 상담의 평균이나 상한으로 일반화하지 않았다. 기존 로그의 `serviceId`, `requestId`, 접근 수단, 재시도·실패·환급을 묶고 공급자 사용량·PG 정산·서버/DB 비용을 같은 기간에 귀속해야 한다. 새 유료 호출 없이 기존 저장 로그부터 분석한다.
