# 모바일 홈과 정책 안내 구현 기록

## Overview

사용자가 승인한 크림·핑크 바탕과 꽃돼지의 달빛 정원을 홈과 정책 안내에 적용했다. 홈은 무료 시작과 이용권 비교를 먼저 보여주고, 정책 화면은 필요한 조항을 쉽게 찾도록 구성한다. 이 문서는 해당 화면의 기록이며 전역 `DESIGN.md`나 `PRODUCT.md`를 대체하지 않는다.

구현 기준은 `templates/home-funnel.html`, `styles/home-funnel.css`, `js/core/home-funnel.js`, `app/components/PolicyGuide.jsx`, `app/components/PolicyGuide.module.css`다. 홈 템플릿은 `scripts/design/build-home-funnel.mjs`로 실제 진입점 `index.html`에 반영하며 public 미러는 기존 동기화 절차를 따른다.

## Colors

크림은 화면 바탕, 연한 장밋빛은 히어로, 짙은 자주색은 본문에 사용한다. 홈의 진한 핑크는 주요 행동을, 정책 화면의 강조색은 현재 위치와 본문 링크를 표시한다. 이용권 비교는 어두운 자주색 바탕과 금빛 숫자로 구분한다.

홈 어두운 모드는 기존 `neo-mode`에 맞춰 화면 내부 토큰을 전환한다. 정책 안내는 후속 정적 통합에서 같은 `fortuneThemeModeStateV1` 선택을 읽도록 맞췄다. 정적 페이지의 배경·본문·보조문자·강조색과 헤더·푸터를 함께 전환한다. React 페이지 소스의 시스템 다크 규칙은 보존하되, 제공되는 정적 문서에서는 독립 토큰이 우선한다.

## Typography

기존 글꼴을 상속하고 외부 폰트를 추가하지 않는다. 홈 제목은 짧은 줄과 한글 단어 단위 줄바꿈을 사용하며, 설명문은 최대 65ch로 제한한다. 정책 본문은 홈보다 넉넉한 행간(1.9)을 사용해 긴 조항을 읽기 쉽게 한다. 검색 입력 글자는 모바일에서도 16px을 유지한다.

## Layout

홈 순서는 두 CTA 히어로 → 여섯 고민 진입점 → 이용권 가치 비교 → 해석·검수 기준 → 추천 리딩 네 가지 → 검색 → 정책·도움말 링크다. 첫 CTA는 기존 무료 운세 입력을 열고, 두 번째는 같은 페이지의 이용권 설명으로 이동한다.

사용자의 추가 요청에 따라 홈 최대 폭은 430px이며 데스크톱에서도 가운데 놓인 같은 모바일 레이아웃을 사용한다. 히어로와 고민·리딩 카드는 항상 한 열이다. 히어로 좌우 바깥 여백은 12px, 일반 섹션은 20px이며 섹션 사이에는 42px 여백을 둔다. 꽃돼지는 모든 화면에서 116px 원형 초상으로 배치해 CTA와 분리한다. 별도의 데스크톱 확장 분기를 두지 않는다.

정책 안내는 정적 브랜드 헤더 → 히어로 → 정책 간 이동 → 핵심 조항 바로가기 → 기존 본문 → 정적 안내 푸터 순서다. 최대 폭은 430px이며 모든 화면에서 요약 카드를 세로로 쌓고 목차는 가로 스크롤을 사용한다. 고정된 React 공통 하단 탭은 불러오지 않는다. 정책 본문, 시행일, 정본 경로를 요약 카드가 대신하지 않는다. 생성·라우트·성능 근거는 [정적 통합 후속 보고서](moonlight-static-policy-followup.md)에 기록했다.

## Elevation & Depth

대부분의 카드와 버튼은 그림자 없이 얇은 경계선과 면 색상으로 구분한다. 꽃돼지 초상과 계정 메뉴에만 제한적인 그림자를 둔다. 기존 하단 내비게이션과 프로필 시트의 표현은 해당 컴포넌트가 계속 소유한다.

## Shapes

둥근 히어로와 카드 안에 짧은 제목·설명·행동을 묶는다. 주요 CTA와 검색 입력의 최소 높이는 48px이며 내비게이션·접기 항목·링크의 터치 영역은 44px 이상을 기준으로 한다. 키보드 포커스는 청록색 3px 외곽선과 4px 간격으로 표시한다.

## Components

- **공유 꽃돼지 이미지:** 사용자가 제공한 WebP는 `public/icons/app-logo-512.webp`와 바이트가 같아 기존 파일을 재사용했다. 홈·결제의 공용 자산을 중복 생성하지 않고 홈의 단일 히어로 preload를 사용한다. 이미지 원본 크기는 512×512이며 홈 모바일 표시는 116×116, 정책 모바일 표시는 72×72다. 원형 프레임은 CSS 표현이며 투명 배경 가공물이 아니다.
- **무료 시작·프로필:** 원래 `destinyCardForm`, `dpDestinyPanel` ID와 기존 액션을 유지한다. 새 컨트롤러는 표시 상태와 이동을 연결하며 프로필 저장을 소유하지 않는다. 계정·쿠키 영역도 기존 DOM과 핸들러를 재배치해 사용한다.
- **서비스 탐색:** 여섯 고민 진입점과 홈 검색은 기존 finder로 이어진다. 홈의 추천 네 가지는 전체 서비스 목록을 대체하지 않는다. 유료 추천은 먼저 상담 미리보기를 열며 카드 배지 자체가 접근 권한을 부여하지 않는다.
- **이용권 비교:** 가격·한도·표시 횟수는 기존 `lib/payment/pass-pricing.js`, `worker/lib/profile-limits.js`, `js/core/service-registry.js`에서 생성한다. 비교 조건과 기간·한도 설명을 가격 근처에 둔다. 이 문서는 변동 가능한 가격 숫자를 별도로 저장하지 않는다.
- **정책 안내:** 공통 히어로·요약 링크·아코디언으로 읽기 순서를 정리하고 기존 법적 본문을 유지한다. 선택된 안내 탭은 `aria-current`와 밑줄로 구분한다.

## Do's and Don'ts

- 승인된 꽃돼지 정체성과 기존 꽃·달 장식을 재사용한다. 사용하지 않는 잠든 연이 `zzz`, 이전 히어로 문구·장식 DOM과 전용 구형 CSS는 정리 대상으로 삼았으며 새 화면에 다시 추가하지 않는다.
- 이용권·월정석·단건 결제 용어와 기존 결제·인증·프로필 소유권을 유지한다. 홈 문구나 가격 배지로 새로운 혜택·환불·권한을 만들지 않는다.
- 화면별 스타일 범위를 유지하고 관계없는 운세 결과 화면까지 색상이나 구조를 확장하지 않는다. 모션 감소 설정에서는 해당 화면의 애니메이션·전환·부드러운 스크롤을 끈다.
- 구현 캡처 `build-cache/home-ui/home-390.png`, `build-cache/home-ui/privacy-policy.png`를 확인해 이 기록을 작성했다. 캡처 확인은 전체 브라우저 회귀나 접근성 통과를 의미하지 않는다. 빌드·변경 기반 검사·다른 화면 폭·동작 검증의 최종 결과는 작업 완료 보고를 따른다.
