# 프로필과 달빛 다이어리

2026-11-17 구현 기준. 이 문서는 해당 표면의 시각·상태·동작 계약이다. 전역 정체성은 [디자인 정본](../context/design-canon.md), 전역 토큰은 [DESIGN.md](../../DESIGN.md)를 따른다. 코드와 문서가 다르면 실제 구현을 먼저 확인한다.

## 목적과 정보 순서

프로필은 운세를 시작하는 자리이며, 일상 기록은 별도의 전체 화면 다이어리로 이어진다. 기본 순서는 **이름·일주 캐릭터·오행·성별 → 이 프로필로 운세 보기 → 출석·꿀방울과 운세 사용처 → 달빛 다이어리 → 보조 성장·출생 정보**다. 내 정원 진입에서 보이는 기존 동반자와 정령 도감은 보조 기능으로 유지한다.

출생 정보는 접어서 제공한다. `생시 모름`, `생시 미입력`, `생년월일 미입력`, `성별 미입력`, `출생지 미입력`을 구분하며, 모르는 정보를 확정값처럼 표시하지 않는다. 프로필 바꾸기·수정·운세 시작은 기존 컨트롤러를 사용한다.

## 시각 계약

- 프로필과 다이어리는 크림 종이, 로즈 강조, 딥 플럼 본문, 청동·골드 장식의 달빛 예화를 사용한다. 얇은 테두리, 달력 종이의 이중 선, 기존 꽃가지 마스크로 깊이를 만든다. 장식은 터치를 받지 않는다.
- 네오에서는 배경·표면·본문·보조 글자·강조색을 한 벌로 전환한다. 프로필은 `--pc-*`, 계정·목록은 `--mg-*`, 다이어리는 `--dy-*`가 소유한다. 다이어리 내부에 별도 테마 스위치를 만들지 않는다.
- 제목은 기존 주아체 `--font-display`, 입력·설명·가격·조작은 Pretendard `--font-body`를 사용한다. 기존 전용 한자·명조 사용부는 유지한다.
- 주 행동은 최소 48px, 아이콘 조작은 44px이다. 날짜 선택과 보기 전환은 선택 상태를 선·배경·`aria-pressed`로 알린다. 포커스 외곽선과 빠른 눌림 반응을 유지하며 reduced motion에서는 이동 효과를 제거한다.
- 오늘 화면은 흐름 안내 다음에 계획과 일기를 배치한다. 1000px 이상에서는 두 열, 그보다 좁으면 한 열이다. 달력도 같은 분기에서 달력·선택 날짜 계획을 나란히 놓고, 일 보기에서는 한 열을 사용한다. 430px 이하에서는 여백과 반복 요일 배치를 줄인다.

## 상태와 동작 계약

| 표면 | 구현된 계약 |
|---|---|
| 일주 캐릭터 | 출생 입력과 한국 날짜로 미리보기를 재사용한다. 실패한 요청은 캐시에서 제거한다. 로딩 중 `aria-busy`, 성공 시 캐릭터·오행, 실패 시 재확인, 정보 부족 시 프로필 완성 행동을 제공한다. 동적 모듈 실패도 로딩을 끝내고 재시도 버튼을 보인다. |
| 꿀방울 | 기존 지갑 노드를 이동해 컨트롤러를 재사용하고 종료 시 원위치로 돌린다. 추천은 기존 카탈로그의 `GGULGGUL` 지정 상품에서 최대 3개를 고른다. 서버 확인 소유 상품 우선, 이후 비용·카탈로그 순이다. 비용·잔액·부족 수량은 데이터를 사용한다. |
| 소유·해제 | `CdHoney.getUnlockedFeatureKeys()`가 현재 프로필의 서버 unlock을 확인한 경우만 `열어 둔 운세 · 다시 보기`로 표시한다. 무료 캠페인 접근 가능 상태를 소유로 해석하지 않는다. 추천 링크는 기존 운세·확인 흐름으로 연결하며 표시 자체가 차감·해제를 수행하지 않는다. |
| 다이어리 진입 | 기본 링크는 `/diary/?from=profile`이다. 셸이 최초 마운트에서 이 값을 읽어 뒤로 가기를 프로필 목록에 연결하고, 같은 셸 수명의 내부 탭 이동에서도 복귀 상태를 유지한다. 오늘·달력·기록·더보기와 중앙 새로 추가 행동을 사용하는 자체 내비게이션을 유지한다. |
| 월·주·일 | 선택 날짜와 보기 모드를 `d`·`view`로 전달할 수 있다. 이전·다음 기간과 오늘 이동을 제공한다. 월은 일정 수·기록·완료 표시, 주는 날짜별 일정 요약, 선택 날짜 패널은 일정·할 일·루틴·흐름/기록/회고를 보여 준다. |
| 일정 | 제목·날짜·시작/종료 시각·종일·메모를 편집한다. 매일·선택 요일의 매주·매월 같은 날짜 반복과 선택적 종료일을 지원한다. 반복 편집·이동·삭제는 `이번 일정만`과 `반복 전체`를 구분한다. 삭제는 확인 후 실행한다. |
| 할 일 | 추가·완료/완료 취소·내용 수정·날짜 이동·확인 후 삭제를 제공한다. 일정과 달리 반복 규칙은 없다. |
| 일기 | 기분·오늘 한 줄·여러 줄 일기를 기존 필드로 저장한다. `memoNote`는 오늘 일기·날짜 기록·오늘의 나가 공유하며 줄바꿈을 유지한다. 오늘의 나도 여러 줄 textarea를 사용한다. |
| 저장 | 입력이 멈춘 뒤 600ms에 저장하고 blur·페이지 이탈·다이어리 flush 시에도 시도한다. pending·saved·error를 구분하며 일기 입력부는 상태와 다시 저장하기를 제공한다. 일정·할 일은 명시적인 저장 버튼을 사용하고 실패 시 편집 내용을 남긴다. |

기존 검색은 오버레이로 유지해 검색어를 URL에 남기지 않는다. 백업·복원과 기록·통계·회고는 기존 저장 계약을 사용한다. 반복 일정은 저장 원본과 수정 예외를 검색하며, 미래의 모든 반복을 무한히 기록으로 만들지 않는다.

## 데이터와 한계

- 다이어리는 현재 브라우저의 기존 localStorage와 날짜별 확장 저장소를 사용한다. 로그인만으로 다른 기기·브라우저에 동기화된다고 안내하지 않는다. 기기를 바꾸기 전에는 더보기의 백업을 사용한다.
- 저장 실패 초안 복구는 앱 메모리에만 있다. 같은 앱 내 화면 이동에서 재시도할 수 있으나 새로고침·탭 종료 뒤 복구를 보장하지 않는다. 저장 성공 문구는 실제 쓰기 성공 이후에만 표시한다.
- 반복 일정은 조회 범위에서 계산하며 원본 날짜와 ID를 유지한다. 매월 같은 날짜가 없는 달은 건너뛴다. `이번 이후 전체`, 시간대별 알림, 외부 캘린더 동기화는 이 구현의 기능으로 안내하지 않는다.
- `mountProfileDiary(..., { embedded: true })`에는 기존 책 모달 경로가 남아 있다. iframe 준비/실패/재시도, 닫기·포커스 복귀·초안 flush를 제공하지만 기본 프로필 진입은 이 모달을 사용하지 않는다.
- 하단 탭 링크는 `from=profile`을 덧붙이지 않는다. 탭 이동 후 새로고침까지 프로필 복귀 상태가 유지되는 계약은 아니다.
- `/diary`는 개인 기록 화면이다. 기존 `ROBOTS_META.NOINDEX`, canonical 미지정, 색인·광고 제외 계약을 유지한다. 공개 검색용 본문이나 홍보 페이지로 바꾸지 않는다.
- 이용권·월정석·단건 결제 정책, 인증, API 응답 구조, DB·LLM 정책은 이 표면 문서가 재정의하지 않는다. 꿀방울 표시도 기존 카탈로그·지갑·해제 판정에 종속된다.

## 검증 범위

이 문서는 위 코드와 승인된 표면 방향을 대조해 작성했다. 시각 검수 대상은 360·390·430·1440px의 기본·네오, 로딩/실패/빈 값/저장 실패, 키보드·포커스·넘침이다. 실제 검수와 명령 결과는 해당 변경의 최종 작업 보고를 따른다. 이 문서 작성 단계에서 브라우저·실 API·실결제·운영 DB 검증을 새로 실행하지 않았다.
