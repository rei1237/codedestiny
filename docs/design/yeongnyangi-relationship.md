# 영냥이 궁합 진입 — 밤의 상담실

대상: 홈 궁합 안내, 질문 선택, 두 사람 소개, 상담 방식 선택. 입력은 Operate, 홈 안내는 Persuade다. 기존 남색·샴페인 골드 토큰과 서체를 유지한다.

## Direction contract

- THESIS: 영냥이가 기다리는 상담실에서 질문과 두 사람의 이름을 차례로 준비한다. 입력과 다음 행동을 장식보다 먼저 읽게 한다.
- OWN-WORLD: night-tokens의 남색 표면, 밝은 본문, 금색 주 버튼. 기존 상담 삽화와 작은 표정만 사용한다.
- STORY: 질문 선택 → 이름 입력과 선택 출생정보 → 추천 상담과 다른 방식. 기존 추천·선택 로직은 유지한다.
- FIRST VIEWPORT: 데스크톱은 왼쪽 삽화·오른쪽 입력, 위에는 세 단계 표시. 모바일은 입력과 행동을 먼저, 작은 삽화를 뒤에 둔다. 홈은 설명·CTA 뒤에 작은 삽화를 둔다.
- FORM: 사용자가 승인한 코드 기반 구현. 새 시각 세계나 생성 목업은 만들지 않는다.
- FINISH: 실제 모바일·데스크톱 캡처와 mock 입력 검증, 디자인 검사, 변경 검토 및 main CI로 완료를 판단한다.

## 자산 출처

- `/assets/yeongnyangi/reading-art/insight.webp`: 기존 생성 삽화 재사용. 제작 기록은 `public/assets/yeongnyangi/reading-art/README.md` 참조. 720×480, 원본 바이트 유지.
- `/assets/yeongnyangi/expressions/welcome.webp`: 사용자 영냥이 표정 원화에서 준비한 기존 128×128 WebP. 출처는 같은 폴더 README. 화면에서는 장식 안내 이미지로 48×48 표시.

결제·가격·인증·API·DB·추천 조건·실제 상담 및 결과 리포트는 범위 밖이다. 검증은 mock이며 운영 증거와 구분한다.

## 구현 기록

- 색상은 기존 `--yn-*` 토큰을 참조한다. 남색 입력·선택 표면, 밝은 본문, 보조 설명색을 유지하고 금색은 현재 단계·추천·주 행동에 사용한다. 별도 전역 토큰은 만들지 않는다.
- 서체는 기존 상속을 유지한다. 상담 제목은 `clamp(1.6rem,3vw,2.1rem)`·600, 홈 제목은 `clamp(1.5rem,2.8vw,2rem)`·600이며 입력 글자는 16px이다.
- **입력 우선 규칙.** 상담은 최대 1120px 안에서 삽화와 입력을 두 열로 배치한다. 759px 이하에서는 질문과 인물 입력을 한 열로 전환하고 삽화 안내를 입력 뒤에 둔다. 홈 삽화도 설명과 CTA 뒤에서 160px로 축소한다.
- **선택 정보 분리 규칙.** 이름 입력과 다음 행동을 먼저 보여주고 출생정보는 기본 접힌 상세 영역에서 선택한다. 추천 상담은 금색 테두리와 주 버튼, 다른 상담은 구분선과 보조 버튼으로 구분한다.
- 버튼은 최소 높이 48px, 이름 입력은 52px이며 키보드 포커스는 금색 3px 외곽선과 4px 간격으로 표시한다. 단계 전환 시 제목으로 포커스를 이동한다. 이 값과 배치는 궁합 진입 범위의 구현 기록이며 서비스 전체 규칙으로 확대하지 않는다.

## 확인 범위

- 캡처: `build-cache/yeongnyangi-relationship-entry/{entry,questions,people,profiles,engines}-{360,390,430,1280}.png` 총 20장. 독립 시각 리뷰 결과는 `ship`이며 중대한 수정 요청은 없었다.
- 디자인 검사 결과는 `[]`였다. 이는 시각 검토 및 디자인 검사 증거이며 `check:fast`·main CI 통과나 실제 기기·운영 검증을 뜻하지 않는다.
- 새 이미지 생성 없이 위 기존 자산 2개를 재사용했다. 기존 밤의 상담실을 지역 확장했으며 전역 `DESIGN.md`와 디자인 sidecar는 변경하지 않는다.
