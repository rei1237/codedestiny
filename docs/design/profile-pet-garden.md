# 프로필 카드 달빛 정원

2026-11-09 승인된 프로필 다마고치 통합. 기존 프로필 노드를 홈 입구로 이동하고, 프로필 시트에서는 동일 노드를 빌려 쓴다. 기존 이용권·월정석·단건 결제와 기록 열람 정책은 그대로다.

## 캐릭터와 원화

- 저장 프로필마다 알 3종 중 하나를 선택해 즉시 부화한다. 일반 99%, 사자·기린·코뿔소 합계 1%이며 각 희귀종의 조건부 확률은 동일하다.
- 일반 캐릭터의 몸색은 실제 일간 오행을 따른다. 목=연두, 화=장밋빛, 토=따뜻한 금빛, 금=은백, 수=물빛. 희귀 동물과 개발자 전용 영냥이는 원화 색을 유지한다. 알은 장식 계열만 바꾼다.
- 최신 사용자 요청으로 랜덤 몸색 6종을 오행색으로 대체했다. 무늬 4 × 원화 표정 동작의 대기 리듬 6 × 장식 8 = 종별 192개 외형 조합이며, 오행 5색을 포함하면 일반종별 960개 조합이다.
- 15종 동물과 영냥이의 원화를 모두 새로 제작했다. 각 캐릭터에 대기·먹기·놀기·잠자기 각 4프레임이 있다. 원본 영냥이 마스터 파일은 변경하지 않았다.
- 원화 출처·생성 프롬프트·격자 규격은 `public/assets/profile-pets/moon-garden-v1/art-manifest.json`에 있다. 내장 image_gen으로 생성했고, 준비 스크립트는 셀 분리·규격 조정·WebP 최적화만 수행한다.
- 개발자 전용 영냥이는 사용자 지정 계정을 서버 User 레코드로 판별한다. 클라이언트 이메일·캐릭터 ID로 특수 배정을 요청할 수 없다. 첫 로그인 후 카드 조회에서 전용 부화를 연결하므로 운영 DB 직접 수선은 필요 없다.

## 저장·보상 경계

- `profile_pets`: 계정+프로필의 고정 배정, 친밀도, 한국 날짜별 먹이·놀이 상태. 생년 정정 시 특성·희귀 여부·친밀도를 보존하고 일반종과 오행색만 현재 명식에 맞춘다.
- `profile_pet_actions`: 최초 돌봄 요청 영수증. 자정을 넘긴 재시도도 이전 행동을 새 날짜에 적용하지 않는다. 동일 요청 키를 다른 프로필·행동에 재사용하면 거절한다.
- 같은 친구에게 먹이·놀이를 모두 완료하면 기존 지갑에 계정당 KST 하루 1개를 추가한다. 두 돌봄은 각각 최초 1회만 친밀도 +5, 최대 100이다. 미접속 패널티는 없다.
- 돌봄·친밀도·보상 원장·지갑은 기존 Mongo 트랜잭션 예산 안에서 함께 반영한다. 보상 원장은 계정+날짜의 고유 _id로 중복을 막는다. 트랜잭션 실패 시 비원자 지급으로 폴백하지 않는다.
- 새 돌봄은 기존 EXP·레벨·월정석에 연결하지 않는다. 기존 정령 EXP 보너스도 보존한다. 탈퇴 시 신규 두 컬렉션을 함께 삭제한다.

## 정적 운세와 UI

- 현재 `profileCharacterPreview`와 사주 일진 엔진을 그대로 사용한다. LLM 호출과 생성형 폴백은 없다. 카드 내 무료 풀이와 기존 상세 화면의 이용 조건을 분리한다.
- 기존 달빛 예화·플럼/크림/골드 카드 세계관을 이어 가며 둥근 기존 서체 토큰을 이름·반응에 사용한다. 행동 버튼은 본문 서체, 최소 48px 높이, 모바일 2열이다.
- 프로필 수정·전환·운세 선택·성장 미션·정령·출생 정보는 유지한다. 옛 다마고치 주소는 기존 프로필 리다이렉트를 유지한다.
- 기존 공개 URL의 title/description/H1/canonical/robots/sitemap은 변경하지 않는다. 개인 캐릭터와 상태는 서버 HTML에 넣지 않고 인증된 비공개 응답으로 읽는다.

## 달빛 예화·꿀단지 확장 — 2026-11-09

사용자가 기존 보상 수량 유지와 친밀도별 반응·진행 상태 개선을 선택했다. 친밀도는 기존 반응의 30·70 구간과 100 완성을 꽃으로 보여주며, 출석 전후 인사말을 달리한다. 출석 보상이나 돌봄 보상의 배율을 바꾸지 않는다.

크림·로즈 카드와 네오의 플럼 표면에 기존 꽃가지 선화·달·연꽃 그림을 사용한다. 행동 버튼은 먹이/놀이/잠자기/운세의 네 색상과 직접 그린 SVG를 쓰고, 실제 타고난 오행은 다섯 색의 꽃 배지로 표시한다. 본문은 기존 본문 서체, 이름은 둥근 서체를 유지한다.

프로필 안에서 원래 출석·꿀방울 위젯의 실제 DOM 노드를 이식한다. 부모 캐릭터 컨트롤러가 미리보기 조회 전에 지갑을 표시하므로 캐릭터 로딩·오류에서도 출석과 사용처를 이용할 수 있다. 프로필 전환·root 교체·재시도 때 원래 노드를 복귀하고 다시 연결한다. 별도 출석 핸들러나 지갑 상태 저장소는 만들지 않는다.

기존 5일 도장판과 한국 날짜 기준 월별 기록, 꿀방울 사용처·필요 개수·해금 상태를 같은 카드에서 연다. 월력은 접어서 확인한다. 기존 controller의 읽기 전용 잔액 상태와 갱신 알림을 통해 게임 헤더를 동기화하고, 잔액만 바뀔 때는 버튼을 재생성하지 않아 키보드 초점을 유지한다. 서버 지급·원장·가격·구매 결과·인증 로직은 변경하지 않는다.

## 검증

운영 DB·실결제·실 LLM을 사용하지 않는다. 서버 mock 트랜잭션 테스트, DOM 행동 테스트, 원화 검증 및 기존 출석·정령·레벨 검증을 수행한다. 실제 계정 부여와 지급은 이 개발 검증의 증거에 포함하지 않는다.

공통 얼굴 파츠는 원화 얼굴과 겹치는 시각 결함이 있어 제거했다. 각 동물의 원래 표정 프레임을 보존하고, 여섯 가지 대기 리듬으로 성격을 표현한다. 별도 얼굴을 이마에 겹쳐 붙이지 않는다.

최종 독립 시각 검수는 SHIP 판정이며 일반 동물의 이중 얼굴과 영냥이 프레임 잔여 조각이 해소됐다. 360·390·430·1280px에서 가로 넘침이 없고 주요 행동 버튼은 48px 이상이다. 검수는 가상 프로필과 localhost mock API만 사용했다.

프로필 공용 스크립트가 바뀌어 독립 정적 페이지·React 로더의 콘텐츠 해시 핀을 기존 도구로 갱신했다. React billing-client의 변경은 PAID_SERVICE_RUNTIME_SRC 캐시 핀 한 줄뿐이다. 결제 정책·렌더러·요청·차감 로직은 바뀌지 않았으며 신규 worker/payments 모듈에도 옮길 정책 변경이 없다. 동결 매니페스트는 이 의도된 참조 갱신의 해시만 다시 기록했다.
