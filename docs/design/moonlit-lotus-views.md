# 달빛 연화당 — 시점 둘러보기와 조작 영역

2026-11-17 승인된 계획. 기준 커밋: 사주 입묘 완료 `53216a36ea6558f2e594a28236145224ce42fd9e`.

## 목적과 범위
마당·법당·연못을 각 다섯 시점에서 둘러본다. 기존 그림의 따뜻한 화풍과 캐릭터 정체성을 유지하며 모바일에서 풍경과 조작부가 겹치지 않게 한다. 기존 108배 집계, 비공개 기도·확언 기록과 구매 기록은 그대로 보존한다.

## 동작 계약
- 시점: left-wide, left, front, right, right-wide. 장소·활동 URL에 선택적 view만 추가한다. 시점 변경은 replaceState, 장소·활동 이동은 기존 pushState다.
- 수평 48px 드래그 또는 방향키·시점 버튼으로 인접 시점 이동. 세로 스크롤·확대·화면 가장자리 뒤로가기를 보존한다.
- 다음 그림이 준비될 때까지 현재 그림과 캐릭터 Canvas를 유지한다. 시점 전환은 집계 시간을 소유하지 않는다.
- 기본 화면: 상단 / 풍경 / 시점 조작 / 활동 메뉴의 그리드. 활동 패널은 별도 행 또는 열을 차지한다. 시작·일시정지·닫기는 내부 스크롤 밖에서 접근한다.
- 추가 기능은 더보기에 유지. 목탁·염불 조작은 하나로 통합. 사진 편집은 명시적으로 연 전용 작업 화면이다.
- 개인 공간의 noindex와 기록 저장 경계, 가격·이용권·인증·API·DB 계약은 유지한다.

## 자산·성능
배경은 내장 imagegen으로 기존 장면을 참조해 제작한다. 모바일 768×1152, 가로 1536×1024. 새 그림의 목표는 모바일 300KiB / 가로 500KiB 이하, 총 약 12MiB 이하. 완성 자산과 생성 프롬프트·해시 기록은 views-v1 manifest에서 관리한다. 캐릭터 원본과 기존 정면 가로 그림은 보존한다.

## 검수
360/390/430px·데스크톱·가로·글자 확대에서 풍경/패널 비겹침, 주요 행동 접근, 다섯 시점, 실패 복구, 키보드·뒤로가기, 계정별 기록, 9/27/108배와 사진 구도를 확인한다. 모의 API만 사용한다. 실제 측정 결과와 앱 출시 계획은 검수 후 기록한다.

## 2026-11-17 구현·검수 결과
- 새 WebP 27개: 6,652,174bytes. 세로 최대 215,042bytes, 가로 최대 347,014bytes. 기존 가로 정면 3개는 재사용한다. manifest에는 원본 생성 파일명·정규화한 제작 지시·규격·해시를 기록했다.
- 실제 로컬 mock 화면 360×800, 390×844, 430×932, 1440×900, 844×390을 시각 검수했다. 풍경·패널 겹침이나 캐릭터 잘림은 없었다. contain 여백은 그림 전체를 보존하기 위한 의도다.
- 390×844: 상단 56px, 참배 패널 270px. 횟수와 시작/일시정지 버튼은 패널 내부 스크롤 밖에 있다. 기도 저장 버튼도 고정했다. 360×440의 작은 뷰포트에서 입력·저장 성공을 확인했다. 이는 실제 Android IME 검증을 대체하지 않는다.
- 실제 1회 참배 후 일시정지 → 시점 10회 전환에서 count=1, 동일 Canvas, history.length=11이 유지됐다. Home/방향키, pagehide 참배 일시정지와 음악 중지, 사진 편집 종료 후 view 유지가 동작했다.
- 터치 스와이프가 전역 tabindex 규칙에 의해 manipulation으로 바뀌어 취소되던 문제는 연화당 viewport의 선택자에서 해결했다. 실제 touch 이벤트로 좌우 전환을 확인했다. 전역 body의 pan-y 제한도 이 페이지에서만 pinch-zoom을 허용하도록 조정했다. 브라우저 에뮬레이션의 합성 pinch는 scale=1에 머물렀으므로 실제 기기의 확대 동작은 출시 전 확인 항목이다.
- 글자 크기 200%에서 가로 overflow가 없었다. 사진 편집 Canvas는 536×804로 정상 생성됐고 닫기는 48px이다. 스토어용 캡처는 개발 표시가 없는 release APK에서 별도 제작한다.
- 시점 URL·edge/vertical swipe 제외·실패/늦은 decode·캐릭터 mount 보존·전체 이미지 규격/용량을 `__tests__/ui/moonlit-scene-views.test.mjs`에서 검증한다. 9/27/108배와 계정별 revision/lease 계약은 기존 테스트로 확인한다.
- `impeccable detect --json`의 대상 파일 검사는 발견 0건이었다. 실기기 시작 시간·GPU 메모리·장시간 프레임률은 측정하지 않았다.

이후 순서와 스토어 초안은 [Android 출시 계획](moonlit-lotus-android-release-plan.md)에 정리했다.

## 가만히 머물 때의 풍경 움직임
- 정면 마당·법당은 실제 등불 좌표의 밝기가 12초 주기로 은은하게 변하고, 정면 연못은 오른쪽 수면에만 14초 주기의 잔물결이 생긴다. 세로·가로 좌표를 따로 두며 다른 시점에 정면 광원을 잘못 투영하지 않는다. 모든 시점에는 작은 빛 입자 3개가 22~27초 주기로 천천히 흐른다.
- 새 이미지·라이브러리·Canvas·프레임별 React 상태 갱신 없이 CSS transform/opacity만 사용한다. 정면에서 최대 5개 애니메이션, 다른 시점은 3개다. 효과는 그림 내부에서 잘리고 캐릭터·소품 조작보다 뒤에 있으며 터치를 받지 않는다. 사진 저장에서는 장식 레이어를 제외한다.
- 공간 메뉴의 `풍경 움직임`으로 끌 수 있다. 기존 가볍게 보기 및 기기 모션 감소 설정에서도 제거한다. IntersectionObserver, visibilitychange, pagehide/pageshow에 따라 보이지 않는 동안 애니메이션을 멈춘다. 참배 집계·오디오·개인 기록을 변경하지 않는다.
- mock 브라우저에서 390/1440px × 3장소를 캡처해 시각 검수를 통과했다. 추가 360/430px·844×390에서 가로 넘침이 없었다. 사용자 끄기, 가볍게 보기, 모션 감소, 화면 밖 정지, pagehide의 5개 CSS animation paused 및 복귀 재생을 확인했다. 실제 Android 프레임·전력 검증은 출시 APK 단계에 남아 있다.
- 회귀 검사는 `node --test __tests__/ui/moonlit-scene-views.test.mjs` 5/5. 변경 UI의 `impeccable detect --json` 발견 0개. 개인 공간의 noindex와 기존 URL/메타데이터는 유지하며 사이트맵 추적본 일치도 확인했다.
