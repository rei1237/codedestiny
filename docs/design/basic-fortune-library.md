# 숙요점·자미두수 기본 분석 화면

## Overview

프로필 메뉴에서 여는 기존 숙요점·자미두수 전체 화면 모달을 **핵심 → 해석 → 상세** 순서로 읽도록 정리한다. 숙요점은 달과 은빛의 차분한 밤, 자미두수는 먹색 표지와 종이 본문의 기록물 분위기다. 이 문서는 두 결과 화면에만 적용하며 전역 디자인 기준을 대체하지 않는다.

서양 점성술은 기존 화면을 유지한다. 이번 작업에서 새로 작성했던 로컬 ‘세 개의 별’ 목업은 사용자 요청으로 제거했으며, 해당 구성을 재도입하지 않는다.

## Colors

숙요점은 어두운 배경에 밝은 본문과 절제된 따뜻한 강조색을 사용한다. 자미두수는 종이색 본문과 먹색 핵심 요약·명반을 구분한다. 배경·본문·보조색을 한 세트로 유지한다. 실제 색상 정본은 `styles/basic-fortune-library.css`다.

## Typography

기존 `Noto Sans KR`, `Pretendard` 본문과 `Gowun Batang`, `Gowun Dodum` 제목 스택을 재사용한다. 새 폰트를 추가하지 않는다. 주요 제목은 `clamp(30px, 5vw, 42px)`, 본문은 16px와 1.8 행간, 보조 설명은 14px다. 장식용 브랜드 표시는 12px이며 필수 설명을 이 크기로 내리지 않는다. 긴 프로필명과 문장은 줄바꿈을 허용한다.

## Layout

모달 바깥 영역은 화면 전체를 사용하고 본문은 기존 `--cd-w-prose` 토큰(기본값 760px)으로 제한한다. 모바일 본문 좌우 여백은 20px, 768px 이상에서는 36px다. 핵심 해석을 먼저 노출하고 명반·달력·참고 기록은 접기 영역에 보관한다.

자미두수는 명궁·재백궁·관록궁·부부궁·복덕궁 바로가기로 기존 해석 패널을 연다. 600px 이하에서 전체 12궁은 세로 목록이 기본이며, ‘차트’ 버튼으로 원래 명반 배열을 볼 수 있다. 배열 모드의 600px 최소 너비는 명반 내부에서만 스크롤한다.

## Elevation & Depth

큰 그림자와 반복 장식을 줄이고 구분선·배경 명도로 단계를 나눈다. 모달 내 기존 애니메이션은 끄며, 접기 화살표 전환은 동작 줄이기 설정에서 제거한다.

## Shapes

핵심 해석과 접기 목록은 직선 구분선을 쓴다. 태그와 궁 선택은 기존 알약형 토큰을 사용한다. 보조 카드에는 기존 카드 반경을 재사용한다. 새 래스터 이미지·라이브러리 없이 직접 작성한 작은 장식용 인라인 SVG만 추가한다. SVG는 `aria-hidden`으로 읽기 순서에서 제외한다.

## Components

- `js/core/saju/basicFortunePresentation.js`: 기존 렌더 결과의 DOM을 이동해 읽기 순서를 구성한다. `sukuyo`, `ziwei`, `init`만 공개하며 원래 ID·결과 데이터·행동 핸들러를 유지한다.
- 숙요점: 본명숙과 기존 기질 해석을 먼저 보여주고 사랑·일·조언, 27숙 명반·달력, 상세 자료를 접기로 나눈다.
- 자미두수: 명궁·신궁·오행국에 쉬운 설명을 붙이고 기존 `_renderZwPanel`을 호출한다. 선택 버튼의 `aria-pressed`는 명반 셀 선택·닫기와 함께 갱신한다. 해석 패널은 `aria-live="polite"`를 사용한다.
- 접기: 네이티브 `details`/`summary`와 `aria-expanded`를 사용한다. 내부 링크의 목적지가 접혀 있으면 상위 접기를 먼저 연다.
- 접근성: 입력·버튼·접기 조작부의 최소 높이는 44px, 키보드 포커스는 3px 외곽선으로 표시한다. 누락 프로필·로딩·오류·재시도 상태도 같은 색상 체계를 사용한다.

## Do's and Don'ts

- 계산 엔진, API 응답, DB 스키마, 인증, 가격, 이용권·월정석·단건 결제 및 유료 접근 판정은 변경하지 않는다. 표현용 배지가 접근 권한을 부여하지 않는다.
- 공통 모바일 래퍼나 기존 점성술 화면으로 이 스타일을 확장하지 않는다. 실제 적용 범위는 숙요점·자미두수 모달의 `.fr-overlay`다.
- 새 UI 레이블은 한국어·영어·일본어·중국어 간체·번체를 제공한다. 기존 상세 해석 전체를 재번역한 것은 아니며, 기존 번역 품질과 혼용 문구는 별도 확인 대상이다.

검증은 저장소 루트에서 아래 순서로 재현한다. 설치된 프로젝트 의존성과 Playwright Chromium이 필요하다. 스크립트는 브라우저 요청을 로컬 파일로 충족하므로 별도 HTTP 서버가 필요 없다.

```powershell
node scripts/verify-basic-fortune-library.mjs --baseline
node scripts/verify-basic-fortune-library.mjs
npm run check:fast -- --plan
npm run check:fast
```

`--baseline`은 현재 `origin/main`과의 차이에서 이전 파일을 읽는다. 비교 기준을 바꾸면 새 기준으로 측정되므로 당시 자료를 먼저 보존한다. 후속 실행은 `generatedAt`을 제외한 세 체계의 계산 결과 동일성, 360·390·430·768·1280px 가로 넘침, 궁 선택, 긴 이름·언어·프로필 없음·새로고침·로딩·오류 복구·모의 공유 페이로드를 확인한다. 일부 출생정보 누락은 입력 시나리오이며 안내 문구의 모든 조합을 단언하는 검사는 아니다.

모든 API 요청은 모의 응답으로 처리하고 외부 호스트는 차단한다. 실 LLM·실결제·운영 DB·실제 공유 전송 검증이 아니다. 로컬 산출물은 `.impeccable/basic-fortune/before/`와 `after/`에 저장된다. 문서 작성 시 읽은 `after/report.json`은 오류 배열이 비어 있으며 LCP 328ms, CLS 0을 기록했다. 이는 로컬 모의 환경의 단일 관측값이며 운영 성능·개선율·사용자 체감 지표로 일반화하지 않는다. 해당 보고서의 모달 폭은 이후 전체 화면 CSS 검증과 구분해 확인해야 한다.

별도 마무리 리뷰는 실제 캡처를 검토하고 대비·글자 크기·선택 상태 수정 후 전달 가능으로 판정했다. 이 문서 작성 단계에서는 브라우저 검사나 `check:fast`를 재실행하지 않았으며, 최종 실행 결과와 PR 검사는 작업 인수인계 기록을 따른다.
