# 영냥이의 모자 계산 계약

- `POST /api/yeongnyangi/free/hat`: 인증된 사용자의 `profileId`만 받는다. 기존 프로필 소유권 조회·요청 보안과 사용자별 10분 6회 제한을 거친다. 같은 Worker 인스턴스의 중복 계산은 진행 중 잠금으로 막고 `finally`에서 해제한다. 응답은 `no-store`, 결과 DB 저장은 없다.
- 기존 출생 계산기 다섯 종과 휴먼 디자인 계산기를 순차 실행한다. 유료 해설·출석·멸치/월정석/이용권 차감은 호출하지 않는다.
- `worker/yeongnyangi/hat/rules.ts`의 `yeongnyangi-hat-v1` 규칙은 계산된 십성, 명궁·신궁의 별(공궁은 삼방사정), 트로피컬 태양·달, 라히리 라그나·태양·달, 천문식 27숙, 휴먼 디자인 유형·프로필을 기숙사 상징으로 번역한다. 서로 다른 체계를 하나의 학술 체계로 설명하지 않는다.
- 체계 안의 근거 가중치를 합계 1로 정규화하고 체계별 동등하게 합산한다. 동점은 달빛서가 → 별불공방 → 새벽첨탑 → 금실금고 → 바람회랑 → 별숲온실 순이다. 날짜 운세·이름·난수는 배정에 쓰지 않는다.
- 결과는 기숙사·버전·실제 대표 근거 최대 3개·체계별 반영/제외와 사유를 반환한다. 근거가 적으면 지어내서 3개로 채우지 않는다. 점수는 정확도나 미래 확률로 노출하지 않는다.
- 시간 미상은 시주를 제외한 사주만 사용하며 절기 경계의 한계를 표시한다. 출생지 누락에 서울을 넣지 않는다. 해외 출생 자미두수와 지원하지 않는 하우스는 제외 사유를 표시한다. 전부 제외면 정보 보완, 일시 엔진 실패면 503 재시도다.
- 원래 계산기의 지원 범위와 정규화를 따른다. 런타임/출생 계산법이나 규칙을 바꿀 때 재현성 검사를 실행하고 결과에 포함되는 규칙 버전을 함께 올린다.

검증: `node --require ./scripts/lib/mock-network-guard.cjs --test __tests__/ui/yeongnyangi-hat.test.mjs`. 소유권·중복·부분 계산·엔진 실패·음력·동점·정규화·여섯 기숙사 도달·27숙/12별자리 매핑을 mock에서 확인한다. 실제 운영 DB나 유료 AI를 호출하지 않는다.
