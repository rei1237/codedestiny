# 사주·대운 해석 계약

## 목적과 적용 범위

실제 명식에서 계산한 관계를 근거로 대운과 세운을 설명한다. 명식 계산의 재현성과 전통 명리 해석의 타당성은 별도다. 점수는 서비스 내부의 비교값이며 적중률·성공 확률·재산 규모가 아니다.

`제련 발복`, `보석 용해`, `화련진금`을 전문 판정명으로 사용하지 않는다. 금 일간과 수화의 충을 일괄 발복 처리하거나 辛 일간에 丁 운이 왔다는 이유만으로 치명적 흉운으로 처리하지 않는다. 천간합·육합·천간충·지지충·삼합·반합 등 실제 관계를 표시하고, 일간·월령·십성·조후·억부 및 다른 생극 관계를 함께 설명한다.

## 계산과 해석의 정본

- 역법·명식·입운: `lib/korean-calendar/`. 역법과 명식의 시간 보정 기준, 대운 기산 시계와 나이 기준을 결과 메타에 남긴다. 현행 natal 정책은 평균태양시 분 단위 보정이며 진태양시의 균시차 보정으로 소개하지 않는다.
- 대운 시계는 환산된 출생 순간과 절기의 차이를 사용한다. 출생지의 민용 날짜, 한국 표준시, 표시하는 세는 나이를 구분한다.
- 공통 강약·종격: 화면 원본 `js/saju-engine.js`와 생성된 `lib/saju/natal-power.js`. 영냥이와 snapshot은 추출 런타임을 재사용한다. 최소 오행을 별도 용신으로 지명하지 않는다.
- 합화·삼합 조건: `sajuHapAssessment`, `sajuSamhapState`를 `scripts/sync-saju-luck-rules.mjs`로 `lib/saju/luck-rules.js`에 생성한다. 화면·Worker·퀀텀 관계의 회귀를 함께 실행한다.
- 미확인 시주는 관계·장간·통근 근거로 쓰지 않는다. 생시 미상에서는 대운 시작 시점과 현재 대운을 확정하지 않는다. 이미 표시된 이전 명식의 대운과 그래프도 지운다.

## saju-luck-v2 해석 관례

합의 짝이 있다는 사실과 합화 성립은 분리한다. 결과의 `hapEl`은 후보 오행이고, `transformed`가 참일 때에만 평가 오행을 변경한다. 이 엔진은 후보 오행에 대한 월령의 지지, 투간, 통근, 쟁합 부재와 직접 충 부재를 모두 확인하는 보수적인 계산 관례를 쓴다. 각 조건을 결과에 남기며 이를 모든 학파에 통용되는 유일한 정답으로 소개하지 않는다. 통근은 기존 지장간 표를 사용하고, 지장간 배열의 마지막을 정기, 첫 항목을 여기, 사이를 중기로 표시한다.

삼합은 세 구성 지지의 서로 다른 글자가 모두 있을 때 구성된다. 동일 지지를 반복해서 세 번 센다고 삼합이 되지 않는다. 두 글자의 반합은 왕지를 포함하는 경우로 구분하며 생지와 고지만 있는 경우를 완성된 삼합으로 승격하지 않는다. 삼합의 구성 여부 역시 무조건적 합화나 사건 발생의 증명이 아니다.

새 충이 들어오면 기존 합의 조건도 다시 살핀다. 원국에 합이 있다는 이유만으로 새 충을 지우지 않는다. 종격 등 내부 분류는 해석 후보이며, 비율이나 단일 배치만으로 개인의 삶을 확정하지 않는다.

## 리포트 계약

대운의 기존 9장과 AI 상담의 기존 12장을 유지한다. 각 장은 계산된 근거, 전통 해석, 성립·완화 조건, 생활 장면, 실행할 수 있는 선택으로 이어진다. 대운 천간의 십성, 지지 본기와 장간의 십성, 통근 위치, 원국과의 합·충 및 세운과 대운의 연결을 구분한다. 알 수 없는 근거를 문장 분량을 위해 채우지 않는다.

비겁과 재성의 균형에 따른 경쟁·동업 부담, 식상생재의 생산·수입 연결 등 조건부 전통 해석은 허용한다. 단일 십성만으로 손실·성공을 보장하지 않는다. 질환 진단, 오행에 따른 금융상품 추천, 색·방향·물건이 재물운을 보장한다는 설명은 사용하지 않는다. 연이와 네오는 같은 계산 사실을 다른 어조로 설명하며 네오도 사용자를 모욕하지 않는다.

문구 필터는 조건부 해석 전체를 막지 않는다. 강한 보장 표현과 계산 충돌·근거 없는 장기 질환·특정 투자상품 권유를 구별한다. 챕터 수, 최소 본문 기준, 저장 결과 재열람, 호출·재시도 예산 계약은 유지한다.

## 서비스 연결

| 서비스 | 공통 계산을 받는 경로 |
| --- | --- |
| 사주·대운·정적 총운·퀀텀 | `js/saju-engine.js`의 공통 명식, 대운 bridge, 관계 함수 |
| 사주 AI·재물 질문 | `worker/routes/fortune.js` → `saju-ai-prompt`의 명식 근거와 카테고리별 챕터 |
| 인생의 책·인생 총운 | `calculateLifeBookAiSaju` → 공통 명식·대운·`buildSajuNatalAnalysis` |
| 연애·관계 리포트 | `love-secret-ai-calculation`·`master-love-codex` → 본인/상대의 공통 life-book 계산 |
| 신년운세 | `worker/routes/new-year-ai.js` → 공통 명식·해석 + 해당 연도 세운·월운 |
| 영냥이 사주 | `calculateScreenSaju` → 공통 명식·life-book 대운 + 화면 런타임·사용자 확인 계약 |
| 다이어리 앱·모달 | `fortune-adapter.ts`·`luck-sync-diary.js` → 공통 원국, 해당 날짜의 정오 KST 일진 |
| 일일 발송 | `saju-snapshot-from-birth` → 공통 명식·강약·조후·용신 후보 |

원국의 사실과 시간 기준을 통일하되, 다이어리 일별 점수와 대운의 비교 점수처럼 목적이 다른 평가를 같은 숫자로 강제하지 않는다. 다이어리는 기존 `fortune-core` 평가를 유지한다. 서비스별 챕터 계약, 기존 저장 본문과 결제 identity도 유지한다.

## 가격과 기존 구매

사용자 승인 범위는 `unlock.section_daewun` 3,000원에서 5,000원으로 변경하는 것이다. 내부 단위 50, 표시 월정석 500, 이용권 사용금액 5,000원은 기존 서버 가격 resolver에서 파생한다. 다른 서비스와 이용권 판매 가격은 바꾸지 않는다. 화면 초기 가격도 `syncSajuReadingPrices`를 통해 서버 registry에서 생성한다.

이미 완료된 결제의 금액과 구매 권한을 재가격화하지 않는다. 동일 프로필의 기존 구매 결과 재열람을 보존한다. 새 주문과 기존 결제 완료 주문을 회귀에서 별도로 확인한다. 실제 결제·운영 DB 수정·유료 LLM 생성·운영 승격은 이 코드 검증에 포함하지 않는다.

## 검증과 근거

- 역법 및 시간: 공통 시간 계약, 절입 경계, 음력·윤달, 과거 한국 표준시·서머타임, 해외 시간대, 민용 연도 경계, 성별·생시 미상.
- 해석: 화면/Worker 실행 비교, 합과 합화 분리, 쟁합·충 반례, 중복 지지, 반합, 辛丁 고정 감점 제거.
- 소비자: 동물점·인생의 책·destiny bias·snapshot·영냥이의 실제 계산 결과 비교.
- 결과: 기존 챕터와 가격 정본, 조건부 해석의 허용/거절 사례, 모드 변경, 모바일·데스크톱 로컬 브라우저, 기존 구매 복구.
- 생성: `node scripts/sync-saju-luck-rules.mjs --write`, `node scripts/extract-saju-runtime.mjs --write`, `npm run build:korean-calendar-table`, `npm run sync:public`.
- 전달: `npm run check:fast -- --plan` → `npm run check:fast` → 변경 단위 커밋 → main 통합·push → 해당 SHA GitHub CI 확인.

[한국천문연구원 역서](https://astro.kasi.re.kr/kor/life/post/calendarData)는 역법 확인 자료이며 길흉 해석의 실증 근거가 아니다. [적천수 원문](https://zh.wikisource.org/wiki/滴天髓)은 계절과 배합에 따른 전통 해석을 검토하는 참고 자료다. 위 보수적 합화 구현을 원문에 명시된 단일 공식으로 주장하지 않는다. 실제 유료 생성 결과의 문장 품질과 실기기 동작은 mock·브라우저 검사와 구별해 보고한다.
