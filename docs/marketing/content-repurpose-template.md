# 콘텐츠 재활용 틀 — 워드프레스 글 → 무료 기능 1개 → 인스타·숏폼

작성 2026-11-16. 문서 전용이다. 워드프레스·인스타그램·틱톡·유튜브 채널은 이 문서로 건드리지 않는다. 원문 글은 사용자가 직접 쓴다.

## 쓰는 순서

1. 사용자가 워드프레스 글 원문을 쓴다.
2. 글의 주제를 아래 표에서 하나 고른다. 글 하나에 무료 기능 링크는 **정확히 1개**만 넣는다(여러 개를 넣으면 클릭이 나뉘고 어느 글이 어느 기능으로 보냈는지 읽을 수 없다).
3. 같은 글을 인스타 카드(§4)와 숏폼 대본(§5)으로 다시 쓴다. 각 채널 링크에는 §3의 UTM을 붙인다.
4. 게시 전 §2 문구 규칙을 확인한다.

## 1. 주제 → 무료 기능 1개

목적지는 2026-11-16 로컬 mock 개발 서버(`npm run dev`)에서 모두 200 응답과 제목을 실측했다. 운영 URL은 `https://code-destiny.com` + 경로다.

| 글 주제 | 무료 기능 (1개) | 경로 | 실측 title |
|---|---|---|---|
| 사주 기초·내 명식·오행 | 무료 만세력 | `/manse/` | 무료 만세력 보는 법 \| 사주팔자 원국·오행 균형 확인 |
| 무료 사주 전반·입문 | 무료 사주 모음 | `/saju/free/` | 무료 사주 모음 \| 오늘의 운세, 운명의 꽃, 최애운명, 타로 |
| 오늘·내일·한 주 흐름 | 오늘의 운세 | `/today/` | 오늘·내일 운세, 사주부터 숙요점까지 \| 꿀꿀 운세 |
| 속마음·재회·연락·선택 고민 | 타로 질문 고르기(출생정보 없이 카드·기본 풀이) | `/tarot/` | 타로 카드·속마음·재회 질문 고르기 \| 꿀꿀 운세 |
| 꿈·상징 | 무료 꿈해몽 | `/dream/` | 무료 꿈해몽 \| 꿈 상징과 감정으로 읽는 해몽 보는 곳 |
| 관계·궁합 | 궁합 무료 안내 | `/compatibility/` | 궁합 보기 \| 무료 안내·사주·숙요점·타로 비교 |
| 연애운 | 연애운 기본 풀이(로그인 후 무료) | `/love/` | 연애운 사주로 읽는 법 \| 로그인 후 무료 기본 풀이 |

- 표에 없는 주제는 가장 가까운 줄 하나를 고른다. 새 줄을 추가할 때는 경로가 실제로 200인지 먼저 확인한다.
- `/love/`는 기본 풀이에 로그인이 필요하다. 글에서 "로그인 없이"라고 쓰지 않는다.
- 유료 상담(찻집·흑월·라이트 사주)을 글의 대표 링크로 쓰지 않는다. 글 → 무료 결과 → 화면 안의 결정 정보 패널 순서로 이어지게 둔다.

## 2. 문구 규칙

- 정확도·적중률·보장 표현을 쓰지 않는다: 적중, 유일, 방식까지, 결과 보장, 100%, 반드시, 사용자 수·적중률 수치.
- 마감·한정 압박을 새로 만들지 않는다(무료 배너의 실제 운영 기간 표기만 예외).
- 신뢰 근거는 **이 문구 그대로만** 쓴다: "2024년 공개 글에서 두 대통령의 2025년을 미리 짚은" — 반드시 원문 날짜 링크 `https://code-destiny.com/insights/presidential-saju-public-records/` 와 함께 쓴다. 이 페이지는 "방식" 예측이 실제와 맞지 않았다는 점도 스스로 밝힌다. 줄이거나 바꿔 "적중"으로 읽히게 만들지 않는다.
- 운세는 참고용이라는 점을 해친다면 문장을 고친다. 건강·투자·법률 결정을 대신하라고 쓰지 않는다.
- 다른 사람의 이름·생년월일·사주 결과를 예시로 쓰지 않는다(공인 공개 기록 페이지는 예외이며 링크로만 연결).

## 3. UTM 규칙

정본은 [docs/analytics-kpi.md 소셜 링크 UTM 규칙](../analytics-kpi.md#소셜-링크-utm-규칙)이다. 여기서는 그 규칙이 허용한 값만 쓴다.

- 값은 소문자 snake_case(`[a-z0-9_]`)만. 개인정보·토큰·사용자 ID 금지.
- `utm_source`: 허용 값은 `instagram` · `threads` · `kakao` · `youtube` · `naver_blog` · `x` 뿐이다.
- `utm_medium`: 오가닉 게시물·프로필 링크는 `social`, 광고는 `paid_social`. `channel`·`share`·`post`는 쓰지 않는다.
- `utm_campaign`: 시리즈·장치. 이 틀은 `blog_repurpose`(게시물 본문 링크)와 기존 예시 값 `profile_link`(프로필 링크)를 쓴다.
- `utm_content`: 게시물 단위. 형식 `<주제 키>_<YYYYMMDD>`, 예: `manse_20261120`.

채널별 처리:

| 채널 | UTM | 이유 |
|---|---|---|
| 워드프레스 글 본문 링크 | **붙이지 않는다** | `wordpress`는 허용 source 목록에 없다. 블로그 도메인에서 오는 클릭은 GA4가 referral로 자동 귀속한다. |
| 인스타그램 카드·프로필 | `utm_source=instagram&utm_medium=social` | 허용 값 |
| 유튜브 쇼츠 설명·고정 댓글 | `utm_source=youtube&utm_medium=social` | 허용 값 |
| 틱톡 | **보류** | `tiktok`은 허용 source 목록에 없다. 쓰려면 analytics-kpi.md 규칙에 먼저 추가해야 한다(사용자 결정 필요). 그 전까지는 UTM 없이 쓰거나 게시하지 않는다. |

예: `https://code-destiny.com/manse/?utm_source=instagram&utm_medium=social&utm_campaign=blog_repurpose&utm_content=manse_20261120`

**측정 상태: 미검증.** 이 UTM이 GA4에 귀속되는지는 GA4 DebugView에서 실제 수신을 확인하기 전까지 "추적됨"으로 보고하지 않는다. 사이트 내부 링크에는 UTM을 붙이지 않는다(세션 출처를 덮는다).

## 4. 인스타그램 카드 (캐러셀 5~7장)

| 장 | 역할 | 채우는 법 |
|---|---|---|
| 1 | 질문 한 줄 | 글 제목을 독자의 고민 문장으로 바꾼다. 예: "요즘 같은 고민이 반복된다면" |
| 2 | 왜 그런가 | 글의 핵심 개념 1개를 한 문장 + 짧은 설명 |
| 3 | 직접 확인하는 법 | 표 §1의 무료 기능 1개 이름과 무엇이 나오는지 |
| 4 | 예시 읽기 | 샘플 프로필(실제 사람 아님)로 읽는 법 1개. "예시" 표기 |
| 5 | 주의점 | 출생시간·절기 경계 등 결과가 달라지는 조건, 참고용 안내 |
| 6 (선택) | 신뢰 근거 | §2의 승인 문구 그대로 + "원문 날짜는 프로필 링크에서" |
| 마지막 | 행동 | "프로필 링크 → <무료 기능 이름>" (캡션에 UTM 링크는 클릭되지 않으므로 프로필 링크 또는 링크 스티커 사용) |

캡션: 글 요약 2~3줄 + 무료 기능 이름 + 원문 글 안내. 해시태그는 주제 관련 3~5개.

## 5. 틱톡·유튜브 쇼츠 대본 뼈대 (15~45초)

| 시간 | 장면 | 대사 뼈대 |
|---|---|---|
| 0~3초 | 질문 자막 | "<고민 문장>, 이유가 있을 수 있어요." |
| 3~15초 | 핵심 개념 1개 | 글의 핵심 1개만. 용어는 한 번 풀어 말한다. |
| 15~30초 | 확인하는 법 | "<무료 기능 이름>에서 생년월일만 넣으면 <나오는 것>이 보여요." 화면 녹화는 샘플 프로필로. |
| 30~40초 | 주의점 | "출생시간을 모르면 <달라지는 점>은 참고만 하세요." |
| 40~45초 | 행동 | "설명란 링크에서 무료로 확인해 보세요." |

- 15초 판은 0~3 / 3~10 / 40~45 장면만 남긴다.
- 신뢰 근거 문구를 넣을 때는 §2 승인 문구 그대로, 설명란에 원문 링크를 함께 둔다. 영상 안에서 "맞혔다"로 바꿔 말하지 않는다.
- 설명란 링크는 §3 표를 따른다(유튜브만 UTM, 틱톡은 보류).

## 6. 게시 전 점검

- [ ] 무료 기능 링크가 정확히 1개인가
- [ ] 금지 표현(§2)이 없는가
- [ ] 신뢰 문구를 썼다면 승인 문구 그대로 + 원문 링크가 있는가
- [ ] UTM 값이 §3 허용 값뿐인가, 워드프레스 본문 링크에 UTM이 없는가
- [ ] 측정 보고에서 DebugView 확인 전 "추적됨"이라고 쓰지 않았는가
