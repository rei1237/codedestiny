# 꿀꿀 운세 카카오 CRM 운영 기록

확인일: 2026-09-28. 코드 준비와 실제 운영 설정, mock 검증과 실수신을 구분한다.

## 실제 계정에서 확인

- 비즈 앱 1417356, 꿀꿀운세. 연결 채널 꿀꿀 운세 `_GgxaGX`, 채널 숫자 ID 442646424.
- 대표 채널을 지정하고 카카오 로그인 동의 미리보기에서 **선택 가능한 채널 추가** 항목을 확인했다. 채널 친구 추가는 자체 사이트 광고 수신 동의와 별개다.
- `plusfriends`는 사용 안 함. 관계 조회 API 권한이 있다고 가정하지 않는다. 기존 `talk_message` 선택 동의는 채널 광고 발송 권한이 아니다.
- 채널 관리자센터의 웰컴 메시지·메시지 작성·친구 그룹·고객 파일 메뉴를 확인했다. 발송 설정 Step 2에서 일반 15원/타겟 20원 + VAT 10%, 현재 캐시 0원, 보유 메시지 이용권 0개를 확인했다. 예약 시각과 새 친구 추가 후 발송 옵션도 제공된다. 친구 그룹 지정/제외 옵션을 실제 열었고 선택된 그룹은 없어 대상 0명이다.
- 사이트 사업자 정보 정본 `lib/site-policy-config.js`의 공개 고객센터 번호를 채널 연락처에 등록했다. 내부 테스트 수신자 번호를 공개 연락처로 사용하지 않았다.
- 웰컴 이미지 업로드 및 정식 등록 완료, 메시지 ID 17583152. 02:58 KST부터 발송중 상태를 재조회했다. 첫 테스트는 친구가 아니어서 거절되었다. 친구 추가 후 다시 테스트했고 사용자가 이미지와 버튼 연결이 모두 정상이라고 확인했다.

## 구현 범위

- `KakaoChannelInvite`: 가입 완료 표시가 있는 세션, 무료 별자리/띠 결과, 영냥이 상세 페이지에 선택 안내. 로그인·구매를 막지 않는다. 확인된 친구·차단·거부·닫은 상태는 안내를 숨긴다. 확인 불가 상태는 unknown으로 안내한다. 채널 클릭만으로 친구나 동의 상태를 만들지 않는다.
- `/channel/`: 주간 무료 콘텐츠와 가격표를 참조한 영냥이 상담 설명, 수신 설정. 운영 배포 전 이 신규 URL로 캠페인을 발송하지 않는다.
- `/api/kakao-crm/preferences`: 로그인 사용자 자신의 동의만 기록. 동의·철회의 서버 시각, 출처, 문구 버전, 문구 원문을 저장한다. 채널 관계와 별도 모델이다.
- 관계 조회는 `KAKAO_CHANNEL_RELATION_ENABLED=true`와 서버 비밀키가 있어야 호출된다. 기본 비활성. 웹훅은 인증과 채널 ID, 날짜를 검증하며 늦게 온 added 이벤트로 나중 blocked 상태를 덮지 않는다. open_id를 계정으로 추측 매핑하지 않는다.
- `/admin/kakao-crm/`: 소재와 링크, 고유 캠페인 ID, 대상 수, 실제 확인 단가, 부가세, 예산, 발송 시각, 대상 근거를 검토한다. 동일 ID 중복 생성·예산 초과·09~20시(KST) 밖 검토를 차단한다. 유료 소재는 실결과 제공 증거가 없으므로 검토 승인 불가.
- 정산은 관리자 입력 근거 방식이다. 발송·실패 건수, 환불/세금 제외 매출, 발송비, 쿠폰, PG, LLM 원가를 입력한다. 미확인 비용은 null이며 이익을 계산하지 않는다. 할인 후 순매출에서 쿠폰을 중복 차감하지 않는다.

## 자동화의 현재 한계 — 완료로 표시하지 않음

서버 발송 어댑터와 예약 실행기는 연결하지 않았다. 개인 메시지 API를 광고 발송에 사용하지 않는다. 운영 중지 버튼은 사이트 검토 기록만 중지한다. **이미 카카오에서 예약한 메시지는 카카오에서 직접 취소해야 한다.**

수신 자격 함수는 별도 광고 동의, 확인된 친구 관계, 24시간 이내 관계 확인, 친구 추가 후 24시간 대기, 최근 7일 발송 제외를 판정한다. 함수와 mock 검증은 준비됐지만 **개인별 실제 발송 이력/수신거부를 카카오 그룹과 자동 동기화하는 기능은 미연결**이다. 따라서 웹사이트 동의 철회만으로 카카오의 기존 수동 예약이 자동 취소된다고 안내하지 않는다. 현재는 대상 그룹을 운영자가 대조·제외한 후 검토 근거를 남겨야 한다. 대조할 수 없는 대상은 캠페인에서 제외하고 전체 친구 발송으로 우회하지 않는다.

가입 완료 마커가 없는 기존 정적 가입 흐름과 카카오 로그인에서의 자동 가입은 각각 실기기 추가 검증이 필요하다. 비카카오 계정의 친구 여부를 임의로 연결하지 않는다. 계정 연결 범위를 확대하지 않았다.

## 운영자가 완료할 설정과 권한

1. 카카오 Developers → 앱 1417356 → 카카오 로그인 → 동의항목에서 채널 관계 조회 `plusfriends`의 신청/설정 가능 여부를 확인한다. 필요한 서비스 목적과 개인정보 안내, 선택 동의 화면을 준비한다. 권한 승인 없이 OAuth scope를 늘리지 않는다.
2. 카카오톡 채널 → 고객관리 API 정책 동의는 사업자가 내용을 확인하고 수락한다. 그룹 API 이용 가능 여부는 이 단계 뒤 다시 확인한다.
3. 관계 웹훅 등록 URL은 운영 배포 뒤 `https://code-destiny.com/api/kakao-crm/webhook`이다. 공식 정책에 맞는 Primary Admin Key를 Worker secret `KAKAO_CHANNEL_ADMIN_KEY`에 저장한다. 브라우저·문서·Git에 키를 넣지 않는다. 관계 조회 플래그는 권한 승인 뒤에만 켠다. 콜백 3초 응답 조건과 DB 지연/재전송 시나리오는 실제 등록 전에 추가 검증해야 한다.
4. 비즈월렛 연결·충전과 카카오 최종 견적을 사업자가 확인한다. 사용 가능한 메시지 유형/모먼트 API 계약·권한은 별도로 확인한다. 발송 API 승인 전 행동 기반 추천은 보류한다.
5. 채널 자체 친구 추가/차단 처리와 사이트 동의 기록을 혼동하지 않는다. 별도 광고 캠페인의 동의 철회 반영 작업과 예약 취소 담당자를 지정한다.

## 소재와 첫 운영안

별도 `kakao-crm-copy-20260928.md`에 네 가지 소재의 원문·버튼·URL을 둔다. 원본은 자체 캐릭터 자산을 참고해 신규 생성했다. 경쟁 이미지의 인물·표현·구도는 복제하지 않았다. 가격, 할인, 무료 상담권, 마감, 결과 보장 문구는 이미지에 넣지 않았다.

- 와이드: 800×600 PNG/JPG, 10MB 이하. 실제 작성 화면 기준 본문 76자, 버튼 1개·8자.
- 웰컴: 800×400 PNG/JPG, 10MB 이하. 이미지 첨부 시 본문 300자, 미첨부 400자. 본 작업은 버튼 1개 사용. 광고 표시·수신거부 문구는 카카오 템플릿에서 제공된다.
- 첫 운영은 신규 친구 웰컴 → 기존 무료 `/saju/` 안내다. 별도 광고 캠페인을 같은 시점에 보내지 않는다.
- 첫 정기 캠페인은 무료 연이 주간 운세다. `/channel/` 운영 반영과 대상 검토 후 월요일 12시 같은 낮 시간으로 예약한다. 신규 친구 24시간/최근 발송 7일/철회·차단·미확인 관계 제외. 명단을 대조할 수 없으면 보류한다.
- 가을 소재는 할인 없는 무료 콘텐츠 안내다. 추석이 지난 시점에 맞춰 '연휴 끝' 문구를 썼다. 네오와 영냥이는 소재 준비만 완료하고 유료 구매→결과 저장→재열람 실검증 전 발송 보류.

계정에 표시된 타겟 단가 20원 + VAT 10%로 계산하면 100명 2,200원, 1,000명 22,000원이다. 일반 단가는 15원 + VAT 10%다. 인원은 예시이며 실제 대상별 최종 견적이나 발송 승인이 아니다. 현재 캐시 0원이다. 실제 대상 수·단가·예산·소재·발송 시각을 확인한 후 예약한다. 할인/상담권 정책은 변경하지 않았다.

## 계측과 검증

`channel_invite_view` → `channel_add_click`은 사이트 관찰값이다. 친구 추가 완료를 뜻하지 않는다. `crm_landing_visit`과 기존 상세·결제 시작·서버 확인 구매·결과 완료 이벤트에 동의된 세션 캠페인을 붙인다. 발송별 UTM은 `crm-<관리자 캠페인 ID>`이다. 로그인 복귀 때 같은 탭의 세션 식별자를 유지하며 분석 동의 철회 시 지운다. 질문·생년월일·결과·수신자 ID를 UTM에 넣지 않는다.

카카오 열람/클릭은 카카오 보고서에서만 가져온다. 자체 방문을 열람률이나 카카오 클릭으로 표시하지 않는다. 발송·실패는 카카오 보고서 기반 관리자 입력이며 자동 영수증이 아니다. 주문/원가와 캠페인을 연결하는 서버 정산 파이프라인은 미구현이므로 GA4만으로 실매출·순이익을 단정하지 않는다.

- Node CRM 단위 검사 6개 통과: 규격/URL, 예산/VAT, 시간대, 자격/빈도, 비용 미확인, 동의된 로그인 복귀 계측.
- Worker mock 8개 통과: 동의 기록, 클릭과 동의 분리, Origin/문구 버전, 웹훅, 권한 미설정, 공식 관계 조회 요청 계약, 유료 발송 제외, 중복 ID.
- `npm run typecheck` 통과, 변경 파일 ESLint 통과.
- `npm run check:fast` 실행 중 ESM 테스트 설정과 사이트맵 원장·이미지 링크 정적 검사 문제를 발견해 수정했다. 두 번째 실행의 Jest 309 suites 통과, 후속 Node 1,778개 전부 통과, `npm run verify:sitemap-drift` 통과. check:fast 전체 재실행은 중복하지 않았으며 최종 공식 게이트는 main CI다.
- 로컬 Next 화면 검증은 다른 드라이브의 node_modules 연결로 생긴 번들 오류 때문에 미완료다. 카카오 실제 모바일 미리보기 검증과 구분한다.
- 실제 카카오 웰컴 이미지 미리보기 및 내부 수신/버튼 연결: 사용자 확인 완료. 결제/LLM/운영 DB 테스트는 하지 않았다.
- 무료 랜딩 디자인과 이전 AI 상담 결과 노출 문제는 사용자 요청으로 별도 세션에서 진행한다.
