# 검증된 엔진의 신규 계산 단계 연결 계획

status: proposed-not-activated

후속 CR-005 승인으로 최초 생성/재개 경계를 기본 OFF로 구현했다. [09 구현 보고서](09-execution-selection-report.md)를 따른다. 준비 단계의 영속 선택은 [CR-006](change-requests/CR-006.md)으로 분리했으며 단계별 활성화는 아직 시작하지 않았다.

작성 기준: `5e2e5499e76581507ff7e876c7c0c8522495a590`, 구현 커밋 `9c7d6181727ae732d3c7c2865475ba8abdaf357a`. 기존 감사 전용 워크트리에서 작성했다. **이번 산출물은 계획과 CR 문서뿐이다. 코드·플래그·저장본·설정 변경, 엔진 실행, push·배포는 하지 않는다.** 운영 연결과 단계별 활성화는 별도 승인 대상이다.

## 1. 출발점과 적용 원칙

[07 구현 보고서](07-expansion-implementation-report.md)와 [검증 집계](results/expansion-20261101/summary.json)를 읽어 재확인했다. 이전 실행에서 OFF 40,000회 비교 차이 0, 확정 101건/1,109필드와 추가 4건 통과, 대운 무작위 20,000건·통제 오라클 2,340건 일치, 저장·유료 mock 28개 통과다. 이번에 재실행하지 않았으며 전체 서비스·실제 사용자 분포·운영 저장소의 무결점 증거로 확대하지 않는다.

현재 `DEFAULT_AUTHORITY_FLAGS`는 두 값 모두 false이고 `daeunAuthorityV2`는 호출별 opt-in이다. 전역 활성화 환경변수·백분율 배포 제어기가 이미 있다고 가정하지 않는다. 기존 두 인자 호출과 자료 버전 생략 동작을 유지한다. 단계 연결은 **기본값을 바꾸는 방식이 아니라 승인된 소비자의 신규 실행 래퍼에서만 명시적으로 선택**한다.

선택 단위는 `소비 기능 + 신규 실행 식별자 + 고정된 입력/기준일 + 자료 버전 + 계산 옵션`이다. 생년월일이 같다는 이유로 기존 기록을 새 요청으로 만들지 않는다. 사용자가 기존 정책에 따라 명시적으로 시작한 별도 요청만 신규 후보이며, 재시도·재열람·공유·PDF·결제 복귀·부분 생성 재개는 신규가 아니다.

지원 판정은 연도 숫자만으로 하지 않는다. 음력→양력 변환일, 윤달 존재·길이, 보정 후 자미 날짜(23시 익일 포함), 이전/다음 절입, 공개 입력 계약을 모두 검사한다. 보호 월의 존재가 지원 연도 확장을 뜻하지 않는다. 미래 출생 등 각 제품의 기존 입력 제한도 그대로 둔다.

**초기 서비스 파일럿은 위 구현 범위보다 좁다.** 알려진 시간·서울·현대 구간부터 시작하며, 시간 미상·역사 음력도 기존 서비스가 받던 입력이라는 이유로 실험군에 자동 넣지 않는다.

## 4. 신규 계산·저장 결과·재개의 분기 계약

순서는 인증/소유자 확인 → 기존 요청·결과 상태 판별 → 신규일 때만 적용 자격 판정 → 자료/옵션 선택 고정 → 해당 기존 실행 흐름으로 진행이다. 현재 제품의 과금·임대 잠금·동시성 순서를 임의 재배열하라는 뜻이 아니다. 부작용 전에 범위 판정을 완료할 수 없는 소비자는 전환을 보류한다.

| 요청 상태 | 동작 | 금지 |
|---|---|---|
| 완료된 저장·유료 결과 | 기존 원문·명반·근거·언어·상품·소유자 그대로 반환. 새 v2로 생성되어 저장된 결과도 동일하게 보존 | 새 계산, LLM, 추가 차감, 최신화 덮어쓰기, 플래그 OFF에 따른 숨김 |
| 생성 중/부분 저장/전달 대기/실패 후 재개 | 원 요청 ID·잠금·결제 증거·저장 입력/명반/버전 유지. 이미 저장된 장은 변경하지 않음 | 재추첨, 새 idempotency key, v1/v2 챕터 혼합, 전체 재생성 |
| 과거 요청에 버전 또는 snapshot 없음 | 신규 실험군에서 제외. 기존 재개 계약을 유지할 수 있는지 별도 mock 확인. 기존 계산이 필요한 재개는 **동일 구버전 복원**과 신규 v2를 분리 | 누락을 신규로 간주하거나 v2로 보충. 현재 코드의 fallback 존재를 안전성 증거로 간주 |
| 저장 조회 오류·소유자 불명·경합 | 기존 오류/재시도 계약으로 중단하고 상태 재확인 | 조회 실패를 “기존 결과 없음”으로 취급하고 생성/결제 |
| 진짜 신규 요청 | 기존 ID 체계·원자적 claim을 유지하며 1회 선택. 명시적인 새 요청 외에는 기존 결과를 우선 | 배포 시각만 보고 신규 판정, 프로필 변경을 이유로 과거 결과 수정 |
| 환불·회수·탈퇴 관련 기록 | 기존 접근 회수·인증 정책 유지 | 보존을 이유로 접근권한 복구/타 계정 노출 |

기존 `calculationMeta.policyVersion/tableFingerprint`, 대운 `policyVersion`, 자미 `evidence`/`lunar.source`는 계산 근거다. 이것만으로 모든 소비자의 재시도 버전 고정이 구현돼 있다고 주장하지 않는다. 사주 `resumeBody`, 자미 `llmMeta.chartSnapshot/resumeBody`의 실제 저장·직렬화·잠금 조건을 검증한다. 새 요청의 선택을 기존 허용 필드로 손실 없이 유지할 수 없으면 [CR-005](change-requests/CR-005.md) 승인 전 그 소비자를 ON하지 않는다. 기존 문서에 필드를 backfill하지 않는다.

브라우저 query/localStorage/요청 body에 있는 플래그는 권한 있는 선택으로 신뢰하지 않는다. 운영 연결 승인 후 새 제어가 필요하면 서비스 소유 경계의 허용 목록으로 제한한다. 화면 새로고침·두 탭·기기 변경·재시도에도 같은 요청은 같은 선택이어야 한다. 클라이언트 구버전 캐시를 강제로 믿지 말고 서버의 신규 요청 판정과 맞지 않으면 중단한다. 버전별 신규 캐시 충돌을 기존 형식으로 피할 수 없으면 스키마/키 변경 CR을 먼저 검토한다.

## 5. 지원 범위 밖·실패 처리

**사전 선택과 오류 후 폴백을 분리한다.** v2를 선택하기 전의 확정된 비대상은 원래 허용된 legacy 경로를 유지할 수 있다. v2 선택 후 예외를 catch하여 v1로 자동 재계산하거나 일부 필드만 v1로 채우지 않는다.

| 판정 | 신규 요청 처리 |
|---|---|
| 플래그 OFF / 승인 소비자·집단 밖 | 기존 경로와 결과 유지. 확대 자료 버전을 함께 넘기지 않음 |
| 범위 밖 날짜·해외·음력 대운·초기 대상 밖 시간/성별 미상 | 사전 판정에서 제외. legacy가 원래 지원했고 알려진 오류 대상이 아닌 경우에만 기존 계산 유지. 이를 v2 검증 성공으로 집계하지 않음 |
| 공식 오류가 확인된 입력인데 선택 가능한 검증 경로가 없음 | 알려진 잘못된 값을 정확하다고 제공하는 우회 금지. 해당 신규 계산만 보류·입력 확인 안내. 기존 저장본 열람은 유지 |
| 잘못된 날짜/윤달/시간/옵션/버전 | 기존 입력 검증 또는 명시 오류. 정상 범위 밖과 구별, 입력을 자동 보정하지 않음 |
| `TERM_INSTANT_UNCERTAIN`, `DAEUN_TERM_FRAME_UNCERTAIN` | 판정 유보. 분 반올림·대표 시각·legacy로 확정하지 않음 |
| 사전 적격이었는데 `TERM_AUTHORITY_OUT_OF_RANGE` / `CALENDAR_AUTHORITY_OUT_OF_RANGE` 발생 | 적격 판정/자료 계약 결함으로 보고 신규 v2 중단. 예외율에 포함; “정상 제외”로 숨기지 않음 |
| 예기치 않은 계산 오류·버전/해시 불일치·Swiss 연결 | 해당 경로 중단, 새 선택 OFF. 다른 엔진으로 대체하지 않음 |
| 시간/성별 미상의 대운 | 구현의 unknown/null 유지. 초기 대운 실험에서는 제외; 대운이 필수인 상품이면 없는 결과를 완성으로 처리하지 않음 |

안내 문구는 새 UI 작업 승인 시 i18n 키로만 추가한다(범위 미지원·입력 확인·일시 실패·저장 결과 열람). 검사 후에 결제/이용권 사용을 시작하도록 기존 흐름과 맞추되, 이미 결제된 재개 오류는 기존 보상/재개 정책을 따른다. 이 계획으로 신규 환불·무료 제공·자동 지급 정책을 만들지 않는다.

## 6. 단계별 실행안 — 전 단계 현재 OFF, 아직 미실행

비율은 **해당 기능의 적격 신규 요청**에 대한 제안값이며 전체 사용자 비율이 아니다. 날짜만 지나거나 표본이 부족하다는 이유로 자동 승급하지 않는다. 기능별로 따로 승인·관측하고 원국과 대운을 동시에 첫 활성화하지 않는다.

| 단계 | 수행·결과물 | 진행 조건 |
|---|---|---|
| R0 연결 준비 | 승인 대상 소비자/허용 입력 표, 저장 상태 분기, 버전 고정 설계, import 그래프, 현재 main과 로컬 구현 차이 검토 | CR-005 필요 범위 승인. 엔진/결제 보호 파일 추가 수정은 새 CR. 기존 구현이 main/운영에 반영됐다고 가정하지 않음 |
| R1 로컬 연결 구현, OFF | 전용 래퍼와 소비 계약 mock. 신규/기존/재개/범위 밖/경합/되돌림 테스트. 운영 API 호출 없이 합성 입력만 사용 | §7 검증 모두 통과. 기존 핀/원문 보존, 새 승인 그래프 별도 고정 |
| R2 배포 준비, OFF | 승인된 통합 변경의 CI·빌드·브라우저 점검, 신규 요청 차단 스위치 리허설 | Swiss 비연결 실행 그래프와 필요한 CI의 안전 실행 방안 확보. 현재 전체 CI/빌드 차단 상태로 승급 불가. 게이트 삭제/약화로 대체 금지. push/배포 별도 승인 |
| R3 제한 시범 | 승인된 내부 대상의 **새 계산만**, 사주 원국/자미를 분리. 기존 기능에 안전한 비유료 계산 표면이 없으면 임의로 새 상품을 만들지 않고 mock 단계 유지 | 기능별 합성 경계 전수 + 적격 새 요청 최소 100건, 최소 24시간. 원문·과금 회귀 0, 예상 밖 차이 0. 실 LLM·유료 실행은 별도 승인 전 미실행 |
| R4 적격 신규 1% → 5% → 25% | 기능별 고정 집단. 서버가 기존 요청 ID/선택을 유지하고 비율 변경은 이후 신규에만 적용 | 매 단계 최소 48시간·적격 v2 완료 200건, 표본 층별 확인. 기준 미달이면 유지; 한 단계씩 네오 승인 |
| R5 적격 신규 100% | 검증된 소비자·입력 교집합 안에서만 확대 | 최소 7일·1,000건 관측 및 §8 기준 통과. 전체 생년/전체 서비스 100%를 의미하지 않음 |
| R6 대운 별도 시범 | R3~R5를 대운 원래 14년·서울 양력에 다시 적용 | 원국/대운 동일 자료·입력 확인. 전체 대운표/LLM 연결은 추가 계약·CR 없이는 포함하지 않음 |

위 건수/시간은 제안한 승인 기준이며 실제 트래픽으로 검증된 수치가 아니다. 미래 연도·역사 구간·경계 표본을 실사용자가 채울 수 없으므로 합성 골든과 운영 관측을 따로 평가한다. 신규 요청의 실제 birth data를 외부 oracle에 보내는 운영 shadow는 계획에 포함하지 않는다. LLM을 두 번 생성하여 비교하지 않는다.

## 7. 연결 전에 새로 필요한 회귀 검사

이전 계산 정확도 검사에 아래 소비 흐름을 추가한다. 이번 문서 작업에서는 모두 미실행이다.

1. **OFF 동일성:** 기존 40,000 비교 및 소비자 실제 출력/표시 계약. 공식 101건/1,109필드·추가 4건을 보존. 승인 수정으로 기대한 차이와 예상 밖 회귀를 분리한다. 이전 82건 변화는 기존 표본에서의 기록이며 향후 모든 요청의 차이를 면제하는 규칙이 아니다.
2. **지원 결정표:** 두 달력 옵션 조합, 버전 생략/잘못된 버전, 평/윤달·양력 교집합·가장자리·보정 날짜·미해결 구간·시간/성별 미상·비서울·부정확한 offset. 사전 적격과 실제 어댑터 허용/거절이 일치해야 한다.
3. **저장/유료 보호:** v1/v2 완료 원본의 직렬화 해시 불변. 재열람/공유/PDF에서 계산·LLM·추가 차감 0. 소유자/서비스/언어/상품/환불 접근 규칙 유지. 저장 실패·빈 결과·다른 계정·만료 세션을 신규로 처리하지 않음.
4. **재개/경합:** 두 탭, 재시도 중 비율 변경, prepare 후 OFF, 명반 저장 전 중단, 일부 챕터 완료 후 OFF, lease 만료, 중복 요청, 결제 복귀, 버전 메타데이터 없는 과거 기록. 신규 선택 1회·기존 키 보존·장 혼합 0·추가 차감 0.
5. **소비 일관성:** 준비/근거/최종 명반/LLM 사실 입력/화면/PDF가 같은 snapshot 사용. 대운을 넣는 경우 원국과 같은 절입 창. 자미 원 입력 연도·소한/유년을 자동 변경하지 않음. 요약 필드 누락을 LLM 추정으로 채우지 않음.
6. **차단 리허설:** Swiss/WASM/비허용 import·실네트워크·결제 호출을 의도적으로 탐지하는 mock 실패 검사. 기존 제한 핀과 새 소비자 핀을 구분. 전체 Worker 엔트리를 계산기 테스트 목적으로 실행하지 않음.
7. **품질/용량:** 타입·대상 lint·허용 그래프 빌드·생성 미러·i18n·960px/모바일 표시. 이전 클래식 증가 99,735바이트가 실제 대상 번들/로딩에 미치는 영향은 추가 측정. 정적 검사 통과를 물리 기기/운영 증거로 표현하지 않음.

기존 회귀 명령은 [확대 도구 README](../../tools/oracle/expansion/README.md)에 있다. 기존 결과를 덮어쓰는 러너는 재실행하지 않고 새 출력 경로·매니페스트로 보존한다. 실제 통합 후 검사 명령 목록을 확정하며 `check:fast -- --plan`이 Swiss 연결 전체 검사를 선택하면 자동 실행하지 않는다.

## 8. 관측·중단·되돌림 기준

집계는 기능/선택 버전/계산 옵션/판정 사유별 신규 적격·완료·실패·정상 제외·저장 재열람·재개를 분리한다. 기존 운영 관측 장치로 가능한지 R0에서 확인한다. 새 영구 로그/스키마가 필요하면 별도 승인한다. 원문 생일·좌표·질문·계정 식별자는 새 로그에 남기지 않는다. 사건 추적은 기존 접근 통제된 실행 ID를 사용한다.

| 조건 | 제안 조치 |
|---|---|
| 저장본 변경/소실·잘못된 계정 노출·중복 차감·idempotency 충돌·v1/v2 혼합·Swiss 실행 시도 | **1건만으로 즉시 확대 중단 및 영향 경로 신규 v2 OFF**. 개인정보/결제 기존 사고 절차 적용; 자동 환불/덮어쓰기 금지 |
| 공식 골든 실패·OFF 예상 밖 차이·공식 근거와 다른 결정적 사실·적격인데 범위 오류·버전/해시 누락 | **재현 1건 또는 근거 확인 1건으로 해당 기능 신규 v2 OFF**. 전체 평균 성공률로 상쇄하지 않음 |
| 새 미분류 결과 차이·지원 여부 오판 의심 | 다음 단계 중단, 해당 입력군 제외·증거 판정. 기존 서비스 값과 다르다는 이유만으로 검증된 공식 수정을 회귀라고 단정하지 않음 |
| 신규 계산의 예상 밖 실패율 | 비교 가능한 같은 범위의 OFF 대조군 대비 +0.5%p 이상이 30분 창 2회 연속이고 각 집단 200건 이상이면 해당 경로 OFF. 표본 미달/대조군 없음은 승급 보류. 연속 3회 실패 또는 사용자 영향 확인은 건수 대기 없이 중단 |
| 계산 p95 지연 | 같은 창/표본에서 OFF 대비 20% 이상이면서 100ms 이상 증가가 2회면 확대 중단·원인 확인. 계산 시간과 LLM/네트워크 시간을 분리 |

수치 임계값은 운영 기준선 측정 전의 **제안**이다. 안전/저장/정확도 0허용 기준은 완화하지 않고, 성능 기준은 R0에서 측정 환경과 함께 승인한다. 최소 관측 기간·건수를 충족해도 자동 ON/승급하지 않는다.

되돌림 순서:

1. 영향받는 기능의 **새 요청에 대한 v2 선택을 OFF**하고 전환 시점·원인·구현 SHA·자료 버전·관측 수를 기록한다. 전역 기본값이나 과거 선택 기록을 편집하지 않는다.
2. 이미 완료된 v1/v2 결과는 그대로 조회한다. 코드 되돌림 이후에도 v2 저장 결과를 읽는 호환성은 유지한다. 원본 전체 재계산·삭제·캐시 일괄 삭제 금지.
3. 진행 중 요청은 원 snapshot/버전을 유지한다. 단순 성능·연결 문제라면 안전성이 확인된 snapshot으로 기존 재개를 계속할 수 있다. 계산 정확도/보안/저장 결함 의심이면 영향 요청만 보류하고 기존 상태·결제 증거를 보존한다. 중간에 v1로 바꿔 나머지 장을 완성하지 않는다.
4. 이후의 진짜 신규 요청만 §5의 사전 legacy 선택 기준을 적용한다. 알려진 잘못된 값을 legacy로 되돌려 제공하는 경우는 계산 보류한다. 기존 유료 재개의 권리를 새 결제로 대체하지 않는다.
5. OFF 제어만으로 막히지 않는 클라이언트 캐시/서버 연결 결함은 해당 연결 커밋만 되돌리는 변경안을 만든다. 안전한 저장 결과 reader를 제거하거나 자료 테이블을 과거 값으로 덮어쓰지 않는다. push·배포가 필요한 되돌림도 별도 운영 승인 범위에서 실행한다.
6. 원인 수정·추가 골든·원본 해시·재개/경합·OFF 검증 후 R3부터 재진입한다. 되돌림 종료는 신규 v2 실행 0, 저장 결과 조회 성공, 추가 과금/원문 변경 0 확인으로 판정한다.

## 9. 승인 경계와 이번 종료

- [CR-005 신규 실행 선택·재개 고정](change-requests/CR-005.md): 유료/저장 경계의 신규 선택 보존, 공개 래퍼 연결 계약. 미승인·미구현. 기존 CR-001~004를 결제/저장/전체 소비자 전환 승인으로 확대하지 않는다.
- 6개 엔진 내부 추가 수정, 불변 함수, KASI timezone, `normalizeSaju` timezone, PortOne/Inicis 실행 파일, KV/R2/사용자 자산 형식 변경이 필요하면 각각 구체적인 새 CR/승인을 먼저 받는다. CR-005도 이 경계를 포괄 면제하지 않는다.
- 활성화 전에는 현재 main에 대한 통합 영향과 공식 CI 경로를 다시 검증해야 한다. 로컬 과거 통과를 현재 main CI·운영 SHA 일치로 간주하지 않는다. Swiss 차단이 해결되지 않은 실행 경로는 보류한다.
- 가격·이용권·월정석·단건 결제·인증·소유권·보관함 분리·960px·i18n 정책 유지. 공개 URL/SEO 본문 변경은 이 문서 작업에 없다.

이번 검증은 문서 링크/상태·지원 수치·호출부의 정적 확인과 문서 검사에 한정한다. 서비스 코드·플래그·기존 증거 수정 0, 새 계산/외부 API/운영 DB/LLM/결제 호출 0이다. 기존 격리 작업 공간에 문서만 로컬 커밋하고 main 병합·push·배포 없이 종료한다.

문서 2개의 상대 링크 16개·코드 블록 짝 검사 통과, 기본 OFF 코드와 이전 집계 정적 대조 통과. `npm run verify:doc-freshness`는 종료 0(활성 정본 문서 4개 대상; 새 문서 링크는 별도 검사). `npm run check:fast -- --plan`은 이번 두 Markdown만 선택했고 공백/문서 freshness 검사만 요구했다. `npm run check:fast` 실제 실행도 종료 0이다. Git fsmonitor IPC 경고가 있어 `git -c core.fsmonitor=false diff --cached --check`로 별도 공백 검사를 확인했다. 엔진 회귀·브라우저·CI를 이번에 재실행한 것으로 보고하지 않는다.
