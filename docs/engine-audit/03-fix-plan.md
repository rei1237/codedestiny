# Phase 3 — 공식 근거로 확인된 오류만의 수정 계획

status: done

후속 상태: 2026-11-01 네오가 CR-001/002를 승인하여 기본 OFF로 구현·검증했다. [05-final-report.md](05-final-report.md)가 최신 상태다. 아래는 승인 전 계획 기록이며, 운영 활성화와 push/배포 승인을 뜻하지 않는다.

**계획 작성만 완료. 구현·운영 적용·저장 결과 재계산은 미실행이다.** 입력 101개/1,109필드의 공식 추가 판정은 [02a](02a-authoritative-adjudication.md)를 따른다. 아래 두 결함군 이외의 후보·학파 선택·Swiss 영역은 계획 대상에서 제외한다.

## 수정 원칙과 기각한 지름길

1. 실행 시작점은 어댑터 래퍼로 유지한다. 기능 플래그는 기본 OFF이며 신규 계산에만 적용한다. 제안 키는 `sajuTermAuthorityV2`, `koreanCalendarAuthorityV2` 두 개다. 구현 시 기존 설정 소유자를 먼저 확인하고, 여러 화면별로 다시 계산하는 기능 플래그나 달력 공식을 복제하지 않는다.
2. `sajuAdapter.ts::calculateLocalResult()` 수정 금지, KASI prefetch timezone 주입 금지, `normalizeSaju.ts` timezone 필드 추가 금지를 그대로 유지한다. 이 규칙은 변경 요청서에서도 해제 요청하지 않는다.
3. 표시 기둥만 교체하거나 일주를 하루 빼는 수정은 금지한다. 격국·용신·십신·자미 배치에 들어가는 원국 자체가 같은 날짜·절입 근거로 계산되어야 한다.
4. `kasiSolarDate` 전달만으로 A2가 해소되지 않았다. 공개 어댑터 실험에서 근거 날짜만 바뀌고 실제 기둥은 원래 날짜로 남았다. 이를 수정 완료로 간주하지 않는다.
5. 모든 절기에 1분을 더하거나 반올림을 ceil로 바꾸지 않는다. 생성기는 이미 분 반올림이며 정밀 천문 근거와의 차이를 먼저 해소해야 한다.
6. 역사 음력 오류를 이유로 출생 IANA 시간대·DST·지방 평균시·자시 관법을 변경하지 않는다. 특히 1912년 이전 모든 출생을 UTC+8로 치환하지 않는다.
7. 양·음력 보정, 절입 자료, 화면·워커·LLM용 근거는 같은 권위 버전을 쓰게 한다. 승인된 범위부터 래퍼를 통해 단계 전환하며 전체 엔진을 한꺼번에 교체하지 않는다.

## F1 실행 전 준비와 승인 후 순서

- 먼저 JPL/공식 초 자료로 23개 절입의 경계 구간을 더 좁히고, 입력 분의 00초와 근접 ±1초/±1분을 별도 새 골든 자료로 검증한다. 이번 선형 보간 수치를 그대로 운영 정본으로 쓰지 않는다. 미래 2027/2028 자료는 예측 버전·갱신 시각을 붙이고 2028 잠정 월력요항을 영구 정본처럼 고정하지 않는다.
- v1 분 테이블은 보존한다. 새 자료는 `utcMs`, 절기 index, year, 출처·검증 버전으로 정렬하고, 활성 플래그의 계산만 실제 출생 순간과 비교하도록 제안한다. `termClock`에서 초를 버린 뒤 비교하는 구조는 수정 대상이다. 출생 시간이 미상인 기존 정책은 바꾸지 않는다.
- `canonicalNatal.pillars`, 절기 window, LLM에 전달하는 근거가 같은 버전을 표시하도록 한다. 대운까지 영향을 받는 공유 계산 경로는 별도 승인 범위와 회귀 증거를 확보하기 전 확대하지 않는다.
- 내부 변경이 필요하므로 CR-001 승인 전에는 코드·테이블 생성·스냅샷 갱신을 하지 않는다. 기존 생성 파일을 손으로 수정하거나 freshness 검사를 약화하지 않는다.

## F2 실행 전 준비와 승인 후 순서

- 공식 확인된 8개 역사 음력월의 시작일·월 길이·윤달 여부와 인접 월의 연결을 KASI로 확인한다. 이번 67개 샘플에 한정한 날짜 예외 목록으로 끝내지 않고, **월 경계 자료**로 양방향 변환의 역함수·단조성·30일 유효성을 보장한다. 추가 구간은 확인 전 활성화하지 않는다.
- 새 역사 달력 버전은 기존 표와 나란히 보존한다. 공통 권위 선택은 출생 정보의 timezone과 별개인 내부 옵션이다. 신규 결과 계산을 시작하는 래퍼에서 한 번 선택하고, 음력→양력과 자미의 양력→음력 및 23시 날짜 이동까지 같은 버전으로 전달한다.
- 사주 `resolveSolarDate()`가 확정한 날짜와 `calculateNatalSaju()`가 실제 계산하는 날짜를 일치시킨다. 원래 사용자가 입력한 음력/윤달 정보는 기존 근거 구조에서 보존하고, 정규화된 양력을 또 음력으로 재해석하지 않게 한다.
- 자미는 출생 시계 보정과 날짜 이동을 한 번만 적용한다. 공식 음력을 미리 넣으면서 내부 시계 보정을 다시 적용하는 래퍼는 채택하지 않는다. 수정 후 76개 자미 입력을 기존 학파 설정 그대로 비교한다.
- `kasiSolarDate`가 있다고 무조건 신뢰하는 것이 아니라 기존 검증된 출처 조건을 유지한다. 운영에서 Horizons/KASI를 계산마다 실시간 조회하는 구조는 이 계획에 넣지 않는다. 검증 도구와 운영 번들은 계속 분리한다.
- 내부 경계·원국 재계산이 포함되므로 CR-002 승인 전에는 코드 변경하지 않는다.

## 영향 평가

| 범위 | 이번 표본의 관측 | 해석/남은 확인 |
|---|---|---|
| 사주 절입 | 설계 경계 23/1,392 = 약 1.65%; 무작위 표본에서 해당 확정 사례 0 | 경계에 집중한 시험이므로 실제 이용자 오류율이 아님. 0건도 무오류 증거 아님 |
| 사주 역사 음력 | 무작위 20,000개 중 2개 = 0.01% | 현재 공개 어댑터의 표본 관측. 다른 원국 경로 및 실제 연령 분포 미확인 |
| 자미 역사 음력 | 무작위 비교 가능 19,438개 중 76개 = 약 0.391% | 1900~2050 균일 표본. 실제 사용자·유료 이용자 비율로 추정하지 않음 |
| 두 역사 결함의 입력 합집합 | 무작위 20,000개 중 78개 = 0.39% | 별개 입력이며 공통 달력 오류. 두 엔진의 실서비스 장애 건수 합계가 아님 |
| 결제·저장 | 조회·실행·변경 0 | 구매/차감/로그인 성공을 검증한 것 아님. 기존 결과는 그대로 유지 |

추후 승인된 구현의 동일 20,000개 표본을 재실행하여 실제 변경 비율·예상 밖 변경을 별도로 산정한다. 이번 결과를 수정 후 영향률로 대신하지 않는다. 실제 고객 데이터 조회·유료 결과 재계산은 계획에도 포함하지 않는다.

## 저장 결과·유료 흐름·배포 전환

- 읽기/재열람/다운로드는 저장된 원본을 사용한다. 저장 원국·유료 결과를 새 버전으로 덮어쓰거나 재생성하지 않는다. 결제 형식, KV/R2 스키마, 사용자 자산 형식은 변경하지 않는다.
- 신규 계산에서만 기능 플래그와 권위 버전을 선택한다. 기존 `engineVersion`/`policyVersion`/`tableFingerprint` 등 이미 존재하는 근거 필드로 새 버전을 구별할 수 있는지 확인하고, 새 저장 필드가 필요하면 별도 forward-fix 설계 승인을 받는다.
- 이용권/월정석/단건 결제·가격·결제 실행 파일·인증 로직은 수정 범위 밖이다. 결과 보상·재계산 혜택·자동 지급을 새로 약속하지 않는다.
- 사용자에게 차이를 설명하는 문구가 필요해도 별도 i18n 키로만 제안한다. 960px 레이아웃은 유지한다. 기존 계산 버전은 폐기하지 않으며, 실제 폐기 코드가 생기는 승인 단계에서만 `_graveyard/` 규칙을 적용한다.
- OFF→내부 합성 입력→신규 계산의 제한된 경로 순으로 전환한다. 되돌림은 플래그 OFF로 이후 신규 계산을 이전 경로로 돌리는 방식이며, 이미 저장한 어느 버전의 결과도 삭제·수정하지 않는다.

## 승인 후 통과해야 할 검증

1. 공식 출처로 확정한 101개 원본 입력, 67개 달력 대조, 두 KASI 날짜 인자 대조를 고정한다. 이 골든 검사는 외부 오라클 설치나 네트워크를 필수로 요구하지 않는다. 기존 골든 스냅샷은 덮어쓰지 않는다.
2. 절입 전후·정규화 날짜·윤달/월말·1903년 9월 30일·23시 이동·역사 표준시/DST를 검증한다. 경계 자료 범위 밖에서는 검증되지 않은 v2 결과를 성공으로 표시하지 않는다.
3. 같은 계산에 원국·근거·격국/용신 입력·자미 배치가 서로 다른 버전을 쓰지 않는지 확인한다. B 학파 항목의 예상 밖 변경은 실패로 본다.
4. 결제·로그인·저장 결과 재열람의 기존 mock 회귀를 유지한다. 타입/린트/빌드 및 기존 엔진 검증은 **허용 경로만** 실행한다. Swiss 연결 테스트를 포함하는 현재 전체 CI는 별도 실행 경계 해결 전 차단한다. 이 계획을 CI 우회 승인으로 사용하지 않는다.
5. 운영 배포와 유료 흐름 실검증은 별도 승인 대상이다. 공식 판정 완료와 운영 수정 완료를 구분해 보고한다.

## 종료

확정된 F1/F2만 계획에 포함했다. B 학파·베다 주 검증기·Swiss 연결 경로·기타 C/D 항목은 수정하지 않는다. CR-001/CR-002는 승인 대기이며, 이번 턴은 보고서·계획·증거 작성 후 종료한다.
