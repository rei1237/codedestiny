# CR-003 — 공식 절입·음력 권위 자료의 검증 범위 편입

status: proposed-awaiting-approval

작성일: 2026-11-01. 기준 `d1238c68404f639f1222a8f077854952b7353665`. **미승인·미구현**. 범위 확대 계획 작성 요청은 엔진 변경 승인이 아니다. [전체 계획](../06-expansion-and-daeun-plan.md)의 E0~E3를 참조한다.

## 제한 사항과 재현 입력

현재 절입 v2는 14개 연도, 음력 v2는 24개 역사 월뿐이며 둘의 시기가 겹치지 않는다. 이는 명시된 지원 제한으로, 새로 확정한 계산 오류가 아니다.

- 절입 공백 예: 양력 `2001-06-15 12:00`, 서울 기본 시계, `sajuTermAuthorityV2:true` → 현재 `TERM_AUTHORITY_OUT_OF_RANGE`. `verifiedNodeTermWindow`의 연도 검사를 읽어 확인한 정적 예상이며 이번 실행 재현은 하지 않았다.
- 달력 공백 예: 양력 `2000-06-15 12:00`, `koreanCalendarAuthorityV2:true` → 현재 `CALENDAR_AUTHORITY_OUT_OF_RANGE`. 월 범위 조회를 읽어 확인한 정적 예상이다.
- 두 플래그 동시 ON의 지원 교집합은 현재 비어 있다. 범위 거절을 우회하거나 v1로 조용히 폴백하는 것이 이 요청의 목적이 아니다.

기대값: 승인된 확대 구간에서 공식 원문을 확보하고 그 원문으로 확정한 값만 반환한다. 위 공백 입력의 **수치 정답은 이번에 수집하지 않았으므로 미확인**이다. 기존 101건/추가 4건의 확정값과 섞지 않는다.

## 승인 요청 단위와 최소 변경

| 단위 | 최초 목표 | 변경 허용을 요청하는 대상 |
|---|---|---|
| CR-003-T | 현대 절입 2000~2028 연속화, 인접 節 포함 | 별도 공식 자료 버전·생성 도구·`authority-data.generated.js`·승인된 자료 선택/조회와 정본 미러 |
| CR-003-L | 역사 음력 1900~1912 연속화 후 현대 2000~2028. 실제 월과 양력 교집합을 기록 | 검증된 평/윤 월 경계·명시적 자료 범위·왕복 변환 검증·해당 생성물 |

두 단위를 따로 승인할 수 있다. 더 넓은 1900~2050은 검증 목표이며 이 초기 편입 범위에 자동 포함하지 않는다. 역사 UT1을 현재 UTC 필드로 넣거나 미래 예측을 영구 정본으로 취급하는 변경은 승인 대상에서 제외한다. 시각계 계약 변경이 필요하면 별도 설계/CR로 다시 제출한다.

불변 규칙 3의 엔진 읽기 전용에 대한 **자료와 조회 범위에 한정한 예외**를 요청한다. 기존 표 `table.generated.js`, 기본 OFF, `calculateLocalResult`, prefetch, `normalizeSaju`, 결제·저장 스키마는 그대로다. 새 버전은 기존 자료/증거를 삭제하지 않고 추가한다. 이전 버전 조회·골든 재현이 유지되도록 자료 선택 계약을 검증한다.

## 제안 diff — 계약 예시, 적용 패치 아님

```diff
--- tools/oracle/implementation/build-authorities.mjs (후속 격리 도구 제안)
- // 기존 증거 디렉터리와 버전을 대상으로 생성
+ // 새 출력 디렉터리의 공식 원문/매니페스트를 검증
+ // 기존 버전 보존 + 승인된 연도/월만 새 권위 버전으로 생성
--- lib/korean-calendar/authority-data.generated.js (생성 계약 제안)
- // kasi-jpl-authority-20261101: 현재 한정 자료
+ // 현재 자료는 보존; 검증을 완료한 추가 버전은 별도 산출물
--- lib/korean-calendar/authority.js (필요할 때만)
- // 현재 권위 버전의 지원 집합 조회
+ // 명시적으로 선택한 승인 자료 버전의 지원 집합 조회
+ // 지원 밖/미확정 시각은 계속 거절, v1 자동 폴백 금지
```

최종 파일명·자료 선택 API는 수집 결과와 번들 영향 확인 후 고정한다. 자료 선택 때문에 새 플래그가 필요하면 기본 OFF이고 알 수 없는 버전은 거절한다. 기존 플래그를 전 사용자에게 켜거나 기존 함수의 기본 결과를 변경하지 않는다. 생성물은 정본 생성기로 만들며 손으로 미러를 편집하지 않는다.

## 근거·완료 기준·영향

- 현재 근거: `lib/korean-calendar/authority.js::verifiedNodeTermWindow/verifiedLunarMonthForSolar`, `authority-data.generated.js`, [구현 보고](../05-final-report.md). 월 경계는 [KASI](https://astro.kasi.re.kr/kor/life/pageView/8), 천문·시각계는 [JPL 공식 매뉴얼](https://ssd.jpl.nasa.gov/horizons/manual.html)을 기준으로 한다. 공식 자료 확보와 런타임 편입을 분리한다.
- 모든 추가 節의 직접 부호/경계 검사, 모든 추가 월의 공식 경계 및 일별 왕복, 윤달·연말·23시 이동·지원 끝 거절, 양력 교집합 검사를 완료한다. 단순 왕복 일치만으로 공식 정답이라고 판정하지 않는다.
- 기존 101+4 골든, 기본 OFF 20,000입력 × 두 엔진의 차이 0, 과거 원문/핀 보존을 확인한다. ON 변경 건수·분모·영향 필드를 자료 버전별로 보고한다. 새 결함은 A/B/C/D로 분류하고 이 CR의 범위를 넘어 고치지 않는다.
- 새 자료의 크기·생성 클래식 번들 증가량도 기록한다. 허용 경로만 타입/린트/어댑터 빌드·회귀를 실행하고 Swiss 연결 전체 검사는 계속 차단한다.
- 기존 저장·유료 결과를 갱신하지 않는다. 신규 계산만 명시 옵션으로 선택하며 이전 버전의 저장본은 원본 재열람한다. 되돌림은 옵션 OFF다.

**별도 승인 없이는 수집 확대·런타임 편입·운영 활성화를 시작하지 않는다.** 이 CR 승인도 push·배포·학파 변경·Swiss 실행 승인이 아니다.
