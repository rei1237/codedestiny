# CR-002 — 공식 역사 음력과 원국 날짜 단일화

status: implemented-default-off

**2026-11-01 네오 승인 후 기본 OFF로 로컬 구현·검증 완료.** 아래 diff는 승인 당시 제안 기록이며 실제 변경/범위 제한/검증은 [05-final-report.md](../05-final-report.md)를 따른다. 사주 불변 함수·timezone 금지·결제 동결·저장 결과 보존 규칙은 유지한다. 운영 활성화·push·배포는 하지 않았다.

- 결함: 사주 2개/자미 76개 입력, 1,085필드의 출력 오류. 공식 음력 67개 추가 대조에서 66개가 양력 하루 지연, 1개가 유효한 30일을 거절.
- 재현: 평달 음력 1909-08-11 16:44 남성 서울. 서비스 일주 戊子/시주 庚申. [KASI 공식 변환](https://astro.kasi.re.kr/life/lunc?yyyy=1909&mm=08&dd=11)은 양력 1909-09-24/일진 丁亥, 기대 시주 戊申.
- 자미 예: 양력 1909-09-25 16:52 여성 서울. 공식 음력 8/12, 시계 보정16:50을 iztro에 넣으면 천동 寅(2), 서비스는 丑(1). 전체 공식 입력·기대값은 [판정 자료](../results/adjudication-20261101/decisions-official.json).
- 근거: 현재 KASI 65일·2음력일·8월 초하루, JPL DE441 8개 합삭 구간, 공개 어댑터 67개 역변환. 역사적 시간대 채택에 대한 추측을 정답으로 사용하지 않음.
- 추가 전달 결함: 기존 두 번째 인자로 공식 `kasiSolarDate`를 주어도 근거 날짜만 바뀌고 실제 원국은 원래 음력을 다시 변환함. [prefetch-controls.json](../results/adjudication-20261101/prefetch-controls.json).

## 제안 diff — 핵심 계약, 전체 적용 패치 아님

역사 달력의 v2 자료/옵션은 공통 코어 한 곳에서 처리하고, 기본 v1은 유지한다. 검증한 월 경계와 인접 월의 역변환을 확보한 뒤 어댑터 플래그가 선택한 신규 계산에만 전달한다. 다음 전달 변경도 그 플래그 안에서만 적용하는 제안이다.

```diff
--- app/saju/animal-destiny/engine/localSajuCalculator.ts
+++ app/saju/animal-destiny/engine/localSajuCalculator.ts (v2 선택 분기 제안)
  const solarDate = resolveSolarDate(input);
  const canonicalNatal = calculateNatalSaju({
-   birthDate: /* 원래 input.year/month/day */,
-   calendarType: /* 원래 lunar 또는 solar */,
-   isLeapMonth: Boolean(input.lunarLeap),
+   birthDate: /* 검증된 solarDate.year/month/day */,
+   calendarType: 'solar',
+   isLeapMonth: false,
+   originalCalendar: /* 원래 입력 날짜·calendarType·윤달 보존 */,
    birthTime: /* 기존 값 유지 */,
    birthPlace,
  }, { allowMissingLongitude /* 및 승인된 권위 버전 */ });
```

주석 부분은 기존 형식/타입과 검증 결과를 유지해 구현할 계약이며 실행 가능한 패치가 아니다. 승인 범위에는 이 내부 전달 및 원래 입력 근거 보존, 공통 `solarToLunar/lunarToSolar`의 명시적 v2 권위 옵션, 자미 날짜 이동·시계에서 같은 옵션을 사용하는 연결이 포함된다. `normalizeSaju`에 timezone을 추가하거나 `calculateLocalResult`를 변경하지 않는다.

고정 KST 역산 대신 공식 역사 월 경계를 쓰는 v2 자료는 기존 생성물과 분리한다. 개별 생일에 하루를 더하거나 빼는 예외표, 전 시대 UTC+8 치환, 자미 결과의 별 위치 사후 덮어쓰기는 제안하지 않는다. 공식 자료가 없는 구간까지 v2 정확도를 주장하지 않는다.
