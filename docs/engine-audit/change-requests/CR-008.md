# CR-008 — 사주 격국 단일 판정과 외격 범위

status: proposed-awaiting-neo-decision

## 승인 대상과 멈춘 이유

사용자는 모든 운세의 정확도·결과 품질 개선, 특히 사주 분석의 정확한 격국과 외격 포함을 요청했다. 기존 불변 규칙 1·3·7은 계속 유효하다. 이번에는 공개 어댑터를 읽기 전용으로 검증했다. 아래 **학파 프로필 선택과 엔진 내부 판정 변경은 아직 구현하지 않았다.** 결과 화면의 기존 승인된 순서·접힘 개선은 별도 커밋이다.

## 재현한 문제와 확인 수준

`tools/oracle/gyeokguk/verify.mjs`는 서비스 `computeNatalFromInput()`이 반환한 같은 기둥을 워커 공개 래퍼 `natalCoreFromPillarRows()` 및 `buildGyeokgukAnalysis()`에 전달한다. 역법을 두 번 계산하지 않는다.

- 48개 합성 입력 중 격국 이름/종류 차이 29건: 생시 있음 11/24, 생시 미상 18/24. 목적 표본이므로 전체 고객 영향률로 사용할 수 없다.
- 분류는 B(서비스 프로필 차이)다. 확정된 천문 사실 오류 A가 아니다. 판정 규칙을 승인하기 전 자동 교체하지 않는다.
- 공통 프로필의 외격 양성·반례·보류 및 공개 표시 래퍼 보존 계약 19건 통과. 규칙에 맞게 동작한다는 증거이며 독립 정답 19건이라는 뜻은 아니다.
- 원시 요약/소스 해시: [gyeokguk-profile-comparison.json](../results/gyeokguk-profile-comparison.json).

구체적 재현: 양력 `1988-05-15 08:30`, 남성, 기존 어댑터 기본 입력. 반환 기둥은 `戊辰 丁巳 庚午 己卯`다.

| 경로 | 실제 결과 | 원인 |
| --- | --- | --- |
| 앱 `localSajuCalculator.ts::buildGyeokgukAnalysis` | 전왕격 / 특수격 | 화의 effectivePower 비율 0.52 이상이면 전왕 후보, 점수 5.17이 월령 후보 편인격 3.57보다 높음 |
| 공통 `natal-core`를 호출한 워커 래퍼 | 편인격 / 일반격 | 금 일간의 종혁은 巳酉丑 완전국·비중·관살 제한 미충족. 종살도 뿌리·인성 등 조건 미충족 |

**조건부 기대값:** `rok-yangin-strictjong-v1`을 서비스 정본으로 승인한다면 이 명반은 편인격이며 전왕격을 확정하지 않는다. 이 기대를 모든 학파의 정답으로 주장하지 않는다.

독립 오라클 `korean-saju@0.3.0`(기존 격리 venv, MIT 원문·메타데이터 재확인)을 같은 출생 입력으로 실행했다. 연월일은 같지만 시주는 `庚辰`이며 편인격/외격 없음이다. 서비스의 역사적 시각 보정과 오라클의 KST/진태양시 기준을 아직 통일하지 않았으므로 **D**, 같은 명반의 교차검증 통과로 세지 않는다. KASI는 이 학파 판단 자체를 확정할 수 없다. 실 KASI 호출은 하지 않았다.

## 외격 범위와 결정 필요 항목

| 항목 | 공통 모듈 현재 지원 | 추가 결정·검증 |
| --- | --- | --- |
| 종재·종살·종아 | 필수조건별 pass/fail/unknown | 종아를 신약으로만 제한하지 않는 기준, 관살 혼합과 생조 잔존 해석 |
| 가종재·가종살 | 별도 조건. 진종 탈락만으로 가종 판정 안 함 | 여기·중기 뿌리, 합거·충의 영향 및 반례 확대 |
| 곡직·염상·가색·종혁·윤하 | 각각 별도 전왕 조목 | 戌·丑월 가색은 보류 유지. 완전 삼합·관살 제한의 문헌 층위 결정 |
| 종강·종왕 | 비겁/인성 중심의 엄격 프로필 | 수치 0.7과 재관 배제 조건은 개발 정책. 보편 규칙으로 표시 금지 |
| 화기 5종 | 일간 합 짝과 화신으로 분기 | 일간 참여·월령·쟁합·충·뿌리 조건 및 5종 양성/반례 모두 확장 |
| 양신성상 | 공통 모듈 미지원 | korean-saju 소스의 16종 목록에는 있음. 원문·성립/파격·경계 사례 승인 전 추가 금지 |
| 가화·종세 및 다른 외격 | 미평가 | 미평가를 불성립이나 일반격 확정으로 오인하지 않도록 구분. 이름을 늘려 자동 채택하지 않음 |

오라클의 “16종”은 화기 5 + 종격 5 + 일행득기 5 + 양신성상 1이라는 해당 버전의 분류다. 가종을 별도 격으로 셀지 등 분류 차이가 있으므로 외격 전체의 보편적 개수로 사용하지 않는다. 설치 소스 `korean_saju/saju/oegyeok.py::OegyeokType`에서 확인했다.

## 제안 diff와 범위

다음은 **미적용 제안**이다. 승인 전 실제 코드에 넣지 않는다.

```diff
--- app/saju/animal-destiny/engine/localSajuCalculator.ts
+++ app/saju/animal-destiny/engine/localSajuCalculator.ts
@@ calculateNatalAnalysis: 격국 결과 선택 지점
- const gyeokgukAnalysis = buildGyeokgukAnalysis(/* 기존 인자 */);
+ const legacyGyeokguk = buildGyeokgukAnalysis(/* 기존 인자 그대로 */);
+ const gyeokgukAnalysis = options?.gyeokgukAuthorityV2 === true
+   ? projectApprovedGyeokguk(pillars, approvedRuleProfile)
+   : legacyGyeokguk;
```

- 실제 적용 전 함수 인자 타입·호출부·용신/직업/재물 해석 의존성을 확정한다. 위 diff는 편집 위치와 선택 구조 제안이며 바로 적용하는 패치가 아니다.
- `projectApprovedGyeokguk`는 별도 어댑터에서 기존 공개 래퍼를 호출하고 최종격·월령격·특수격 후보 상태·보류 사유·판정 버전을 함께 투영한다. top-3 점수순 목록을 성립한 외격 목록으로 쓰지 않는다.
- 격 이름만 바꾸고 구 용신·직업 해석을 붙이지 않는다. 이에 필요한 `calculateNatalAnalysis` 및 관련 해석 연결은 내부 수정 범위로 별도 승인 명시한다. 공통 엔진의 규칙 추가는 이 CR의 프로필 결정 이후 항목별 diff로 검토한다.
- `sajuAdapter.ts::calculateLocalResult()`는 변경하지 않는다. timezone 주입·normalizeSaju 필드 추가도 금지한다. 신규 계산용 별도 공개 어댑터에서 선택하고 기존 호출은 OFF일 때 완전히 보존한다.
- 준비 시점의 입력·명반·격국 프로필·계산 버전을 고정한다. 생성·결제 복귀·재시도·재열람 중 최신 엔진으로 재판정하지 않는다. 기존 저장/유료 결과는 업데이트 대상에서 제외한다.
- 미지원/자료 부족이면 후보/보류/미평가를 보존한다. 생시를 임의로 채우지 않는다. 고객 화면은 해당 결과에 기반한 해석을 우선하고 세부 근거는 기본 접힘이다.

## 승인 후 완료 기준과 되돌림

1. 동일 명반 기준으로 오라클 옵션을 통일하고, 정격·건록·양인·각 외격의 양성/음성/1조건 차이/생시 미상 사례를 고정한다. 외격 판정은 네오가 학파 기준을 승인한다.
2. 신규 계산만 opt-in, 기본 OFF. OFF 출력은 기존 결과와 깊은 비교로 동일해야 한다. ON은 격국·용신·프롬프트·표시가 같은 판정 ID를 사용해야 한다.
3. 기존 확정 역법 101건, 준비/재개/동시요청/결제 복귀/OFF 전환/기존 저장 결과 보존 회귀를 실행한다. 별도 감사 브랜치의 CR-001~006을 이 UI 브랜치에 암묵적으로 합치지 않는다.
4. 버전 불일치, 저장 원문 변경, 추가 차감/생성, 확정 외격의 반례 오판, 지원 밖 입력의 강제 확정이 하나라도 나오면 신규 선택을 OFF. 이미 준비된 요청은 고정 버전/명반으로 마무리한다. 과거 결과 롤백 재계산은 금지한다.
5. Swiss 연결 서비스, 베다 주 오라클 미확보, 실제 PG/DB/LLM, push·배포는 이 승인 범위에 포함하지 않는다.
