# CR-009 — stateless 자미 결과의 영속 명반 연결

status: proposed-not-implemented

## 확인한 경계

현재 worker/routes/ziwei-island.js::handleBlueprint는 무인증·무DB 계산이다. worker/routes/ziwei-island-report.js::buildReportFromBirth는 해금된 저장 프로필에서 명반을 다시 계산한다. worker/routes/ziwei-daehan.js는 daehan_purchases/출생 해금 reader이며 공통 계산 준비 ID를 소유하지 않는다. 기존 CR-006의 FEATURE는 ziwei-ai-consultation으로 고정돼 있으므로 해당 컬렉션과 요청 ID를 다른 상품의 사실 저장소처럼 사용하지 않는다.

이것은 실제 고객 결과 오류를 재현했다는 뜻이 아니다. 신규 계산 버전을 여러 표면에 켰을 때 준비→기준연도 변경→재열람 중 명반/유년 혼합을 방지하기 위한 저장 계약 제안이다. 현재 새 선택은 OFF이고 기존 원문과 해금 정책은 보존했다.

## 재현·기대값

합성 프로필 2000-06-15 12:00/남성/서울, 기준연도 2026으로 blueprint를 만든 뒤 2027 기준으로 프로필 심층 보고서를 호출하면 서로 다른 yearlyLuck 기준일을 선택할 수 있다. 이번에는 권한 API를 실제 실행하지 않고 두 함수의 인자 흐름을 읽어 확인했다. 기대는 동일한 신규 준비 ID를 사용하는 표면에 한해 같은 chartSnapshot/targetYear/digest를 읽는 것이다. 요청이 의도적으로 다른 기준일이면 새 준비 ID를 사용한다.

## 제안 diff 범위 — 아직 적용하지 않음

1. 신규 전용 모델 EngineCalculationPreparation을 worker/lib/models.js에 추가한다. 기존 ZiweiCalculationPreparation과 결과 모델은 수정하지 않는다.
2. 필드: _id(서버 SHA-256), userId, featureKey, requestId, profileId, inputDigest, system, engineVersion, interpretationVersion, targetDate, support, chartSnapshot(Mixed), snapshotDigest, createdAt. 문자열/필수/immutable, minimize:false, TTL 없음. _id는 userId+featureKey+requestId+system으로 고정하고 계정/기능/입력 일치까지 검증한다. 실제 운영 생성·이관·backfill은 제외한다.
3. 신규 worker/lib/engine-calculation-preparation.js에서 get/insertIfAbsent/read-back만 제공한다. 읽기 실패는 신규가 아니고, duplicate는 승자만 재조회한다. basis/generate에서 유실이면 503; 입력 충돌은 409. 과거 결과는 준비 기록 생성 없이 원문 reader로 반환한다.
4. island의 익명 무료 blueprint는 현행 무DB 계약을 유지한다. 인증된 신규 보고서 요청의 준비 경계에서만 위 저장소를 사용하고, 무료 preview와 유료 결과가 동일 pin이라고 표시하려면 별도 인증된 준비 endpoint/UI 전달 계약을 먼저 확정한다. 클라이언트 chart/version을 신뢰하지 않는다.
5. 기존 profile unlock/계정 검사/PG/가격·차감/환불 함수는 변경하지 않는다. 권한 의미를 변경해야 한다면 이 CR도 승인으로 확대하지 않는다.

이 범위는 저장 스키마·새 준비 endpoint를 추가하므로 인수인계의 forward-fix-only와 CR-005/006 저장 승인 경계를 적용해 제안 상태로 남긴다. 서양/베다/숙요 실계산 승인, 사주 학파 변경, 운영 활성화·push·배포는 포함하지 않는다.
