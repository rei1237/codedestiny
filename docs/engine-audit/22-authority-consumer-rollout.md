## 연결 순서

1. 현재 통합 체크아웃과 별도 감사 브랜치의 CR-001~006 차이를 검토하여 필요한 승인 변경만 통합한다. 다른 세션의 미커밋 파일은 덮어쓰지 않는다. 공식 역법 101건을 **최종 통합 트리에서** 다시 검증한다.
2. 신규 사주 준비 경계에서 프로필을 한 번 선택하고 입력·명반·판정 ID·보고서·버전을 고정한다. 저장소의 인증 범위와 원자적 최초 삽입 계약을 실제 서비스의 기존 준비/재개 장치에 연결한다. 기존 완료본은 읽기 전용이며 준비 API로 마이그레이션하지 않는다.
3. LLM에는 `preparedSajuPromptFacts`로 동일 snapshot을 전달한다. 격국·외격·용신을 프롬프트에서 다시 계산하거나 후보를 확정으로 승격하지 않는다. 숫자 점수, 미평가 상신/병약/사건 시기 등은 새로 지어내지 않는다. 상담의 결론과 실제 행동 조언을 먼저 제공한다.
4. 사주를 포함하는 다른 운세는 사주 부분에만 같은 사실 snapshot을 사용한다. 자미두수·서양·베다·숙요·타로를 사주 규칙으로 치환하지 않는다. 궁합은 당사자별 pin/판정 ID를 유지한다.
5. 각 서비스마다 새 계산 → mock 결제 복귀 → mock LLM 생성 → 저장 → 새로고침/재열람까지 같은 명반·버전·원문을 검증한다. 동시 요청·중복 이벤트·응답 유실·부분 생성·OFF 전환에서 추가 차감·추가 생성·명반 변경이 없어야 한다.
6. 지원한 분석 항목과 유료 상품의 약속 범위를 맞춘 뒤 제한된 테스트 환경부터 켠다. 현재 CR-008의 좁은 보고서를 기존 종합 상품 전체로 대체하지 않는다. 운영은 최종 검증 및 별도 배포 요청 전까지 OFF다.

## 지원 밖 처리와 되돌림

- 부족한 출생 정보·미평가 외격·용신 관점 충돌은 pending/not-evaluated를 보존한다. 임의 시각·격·점수·시기를 채우지 않는다.
- 이미 생성한 본문은 신판정과 다르다는 이유로 덮어쓰지 않는다. 기존 원문 읽기와 신규 분석을 구분한다.
- 신규 요청만 OFF로 되돌린다. 준비가 끝난 요청은 선택 당시 pin으로 완성하며 과거 pin 버전 reader를 제거하지 않는다.
- 판정 ID/명반 불일치, 기존 본문 변경, 중복 차감/생성, 지원 밖 입력의 강제 확정, 저장 실패 후 완료 표시가 한 건이라도 나오면 해당 서비스의 신규 선택을 OFF로 유지한다.
- 화면·PDF·공유·LLM의 판정 ID와 내용이 일치해야 연결 완료다. mock 검증, 실제 외부 연동 검증, 운영 적용을 별개 상태로 보고한다.
