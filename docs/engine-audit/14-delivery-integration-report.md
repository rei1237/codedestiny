## 확정 결함과 수정 범위

명반/버전은 준비 이후 고정됐지만 `worker/routes/ziwei-ai.js::resolveCurrentMajorLuckByChartAge`가 현재 연도로 나이를 다시 셌다. 합성 입력 서울 양력 `2023-02-04 11:42`, male을 2026년에 준비하고 2027년에 결제 복귀하면, 세운은 2026년인데 근거의 세는나이는 **4→5세**였다. 수정 전 통합 테스트는 이 실제 출력 차이로 실패했다. 2034→2035년의 대한 경계에서는 12→13세로 다음 궁을 고르는 위험도 후속 회귀로 검증했다. 실제 고객 피해/발생 건수는 미확인이다.

수정은 라우트의 실행·표시 문맥에 한정했다. `preparedZiweiChart`가 준비 ID가 있는 명반을 그 명반의 `yearlyLuck.year`에 연결하고, 현재 대한 해석에서 그 연도를 사용한다. prepare/basis 선택과 생성 및 공개 결과 변환에서 문맥을 복원한다. 같은 helper를 쓰는 화면 근거·생성용 확정 사실·`meta.dayun`이 일치한다.

WeakMap은 명반 객체에 필드를 넣지 않고 일시적인 표시 문맥만 연결한다. DB 기록/버전 선택의 권위는 기존 준비 기록과 snapshot이다. 저장된 명반 바이트·스키마·입력 해시·주문 ID·사용자 소유자·계산 플래그는 변경하지 않았다. 준비 기록이 없는 기존 결과는 기존 날짜 해석 경로를 유지한다. 과거 저장/유료 결과의 재계산·backfill·덮어쓰기는 없다.

엔진 내부, `calculateLocalResult`, KASI prefetch, normalizeSaju, PortOne/Inicis 실행 파일은 변경하지 않았다. 가격·결제 정책·인증·권리 판정·차감/환불 함수도 변경하지 않았다. 신규 UI 문구/레이아웃 변경은 없다. 승인된 라우트 연결/표시 범위에서 해결했으므로 새 엔진 내부 변경 CR은 필요하지 않았다.

## 통합 검사 경계

[하네스 설명](../../tools/oracle/delivery-integration/README.md)의 실제 코드/모의 경계를 따른다. 전체 Worker import는 Swiss 때문에 계속 차단했다. 실제 클라이언트 콜백과 라우트 함수만 AST 추출하고, 기존 소스 핀으로 허용한 공개 명반 어댑터를 연결했다. 모듈별 private 함수 스코프를 보존하고 외부 호출로 폴백하지 않는다.

PG/LLM뿐 아니라 DB·인증·결제창도 mock이다. 13번 보고서의 전용 로컬 Mongo 서버는 재시작하지 않았고 추가 실제 기록을 쓰지 않았다. 영수증 조회 mock과 사용 처리 표식의 횟수 검증을 실제 청구/환불 검증으로 해석하지 않는다. 완성 본문의 의미·분량·LLM 실제 프롬프트 전체와 React 렌더링/모바일 브라우저 복귀는 이번 증거 밖이다.
