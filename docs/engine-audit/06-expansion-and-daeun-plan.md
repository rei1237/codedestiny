## 2. 추가 작업 순서와 승인 단위

우선순위는 기존 자료를 보존한 범위 목록 → 공식 증거 확대 → 대운의 동일 관례 대조 → 승인한 범위만 구현 순이다. 각 단계에서 실패/미확인 구간을 분리하며 전체 성공 비율로 숨기지 않는다.

|---|---|---|

## 3. 사실값과 관례를 구분하는 검증 방법

### 절입·음력·출생 시계

- 절입은 JPL 지구중심 태양 겉보기 황경의 목표각 전후 부호로 판정한다. 양 끝을 직접 조회하여 검증하고 보간값만을 정답으로 사용하지 않는다. KASI 공표 분 시각은 표시 단위로 비교하며 임의 초값을 붙이지 않는다. 원문 충돌은 다수결로 해결하지 않는다.
- 음력은 KASI 공식 변환을 기준으로 하고 manseryeok/iztro 등은 보조 대조에 사용한다. 서비스 음력을 다시 입력한 오라클 결과는 음력 독립 검증으로 세지 않는다. 월 경계 확인과 모든 날짜의 왕복 검사는 각각 외부 정답 대조와 내부 일관성 검사로 구분한다.
- 현재 KASI 공개 변환 화면의 양력 입력 상한은 2050-12-31이다. 이는 확인한 웹 화면의 범위이며 모든 KASI API/자료의 공통 상한을 단정하지 않는다. 2051년 이후의 공식 근거 확보 여부는 미확인이다. [KASI 음양력변환계산](https://astro.kasi.re.kr/kor/life/pageView/8), 2026-11-01 문서 열람.
- Horizons의 과거 UT는 1962년 이전 UT1, 이후는 UTC로 설명되며 미래 윤초는 미확정이다. 역사 `UT1` 숫자를 그대로 `utcMs`로 넣지 않는다. 시각계 변환 근거·민용시 대응·불확실성 범위를 따로 검증한다. 1962 전환 경계의 상세 시점도 원문 기준으로 확인한다. [JPL 시간계 설명](https://ssd.jpl.nasa.gov/horizons/manual.html#time), [Universal Time 설명](https://ssd.jpl.nasa.gov/horizons/manual.html#universal-time-tdb---ut-conversion), 2026-11-01 열람.
- 1954~61 UTC+8:30 및 1948~51·1955~60·1987~88 DST는 **조사 대상 구간**이다. 정확한 전환 날짜·시각을 공식 기록/고정한 시간대 자료와 대조하기 전 정답으로 고정하지 않는다. IANA/Intl 버전, 존재하지 않는 시각과 중복 시각의 해석을 기록한다. 역사 달력의 초하루와 역사적 법정시를 같은 문제로 취급하지 않는다.
- 시간 미상은 현재 정오 가정과 `termTimeAssumed`를 보존한다. 당일 절입이 있으면 미상 시간 전체가 같은 원국인지 별도 표시 대상으로 조사한다. 이 조사만으로 정오 정책을 바꾸거나 대운 시작 나이를 꾸며내지 않는다.

### 사주 대운

현행 소스 계약은 `lib/korean-calendar/daeun.js::daeunFromFrame`이다. 양년 남/음년 여 순행, 나머지 역행; 순행은 다음 節, 역행은 직전 節; 시진·민용일 차를 년/월/일로 환산하며 23시의 시지 인덱스를 11로 취급한다. 세는 나이와 0번 미입운을 유지한다. 이는 **현재 코드의 관례**이며 모든 학파의 유일한 정답이라는 뜻이 아니다.

| 항목 | 판정 방식 | 바꾸려면 필요한 결정 |
|---|---|---|
| 출생 순간·절입·음양력 | 공식 자료와 시각계 검증 후 A/C 판정 | 자료 범위 편입 CR-003 |
| 순역·기준 연간 | 선택한 입춘 연간과 성별 매핑에 따른 결정적 계산 검사 | 다른 연 기준·성별 정책은 B. 성별 미상은 여성으로 치환 금지 |
| 기운수·시진·23시·나이 | 현재 sect 1 관례를 고정하고 동일 입력/동일 節로 기대값 산출 | sect 2, 분·초 비례 환산, 만 나이/소수 나이로 교체는 B이며 CR-004에 포함하지 않음 |
| 경계와 기간 | 원국에 쓴 v2 연간·월주, 같은 이전/다음 節를 사용 | v1 대운과 v2 원국 혼용 금지. 미해결 구간/정확히 경계인 경우의 포함 규칙 명시 |
| 시작일·주기 | 생일에 년→월→일 순서로 더하기, 윤년/말일 보정, 주기 연속성 | 표시 나이만 바꿔 내부 날짜 오류를 숨기지 않음 |

KASI/JPL은 천문·달력 사실의 근거다. **대운 관례 자체를 공식 기관이 인증한 것으로 표현하지 않는다.** lunar-javascript 1.7.7은 기존 sect 1의 포팅 원천이므로 독립된 학파 판정자로 세지 않는다. 동일 節를 넣은 명세 기반 독립 산술 검사와 오라클의 원래 천문값으로 계산한 결과를 구분한다. 다른 허용 오라클의 관법이 다르면 B/D로 남긴다. 기존 라이선스 원장은 [01-license-ledger.md](01-license-ledger.md)를 사용하며 실행 전 실제 설치 버전·라이선스·전이 그래프를 재확인한다. 신규 의존성은 이번 계획에 추가하지 않는다.

## 4. 제안 검사 집합·통과 기준 — 이번에는 미실행

1. **기존 기준 보존:** 최초 101건/1,109필드와 추가 4건/7필드, 공식 24개월/712일, 기존 소스 핀·원문 해시. 기존 골든을 새 결과로 덮어써 통과시키지 않는다.
2. **범위별 전수 경계:** 추가한 모든 節의 ±1초/±1분/±1시간, 경계 하한·상한·내부, 양 끝 연도, 입춘 전후. 새 음력 월의 모든 날짜 왕복 및 평달/윤달·29/30일·음력 연말. 시각 불확실성 구간이 시진/자정 경계를 걸치면 대표 시각으로 강제 선택하지 않는다.
3. **대운 최소 집합:** 기존 168節 × 전후 6시점 × 남녀 = 2,016입력. 모든 12시진 및 23:00/00:00/00:59 경계, 시간·성별 미상, 잘못된 성별/시간, 2월29일·월말·연말, 양/음년 네 순역 조합을 보강한다. API가 분 입력만 받는 경우 ±초 검사는 승인된 공통 공개 코어 래퍼에서, 분 입력 회귀는 원래 어댑터에서 수행하고 표면별 수를 분리한다. 내부 함수를 테스트에서 바로 호출해 어댑터 전달 검증을 대체하지 않는다.
4. **기준 통일:** 원국 연간/월주, 순역, 기준 節의 ID/순간/권위 버전, 기운 년월일, `startSolar`, 첫 주기 간지, 세는 나이, 0번 미입운과 10년 주기를 대조한다. `baseTerm`을 기존 분 테이블에서 다시 검색하지 않는다. 출생 시계와 節를 같은 KST 프레임에 놓되, 역사/해외는 별도 근거 없으면 거절한다.
5. **영향 측정:** 기존 고정 시드 20,000입력의 OFF 비교를 반복하고, 대운 지원 범위의 성별/시간 확인 표본 20,000개를 별도 고정 시드로 추가한다. 허용/거절/미상/불일치와 비교한 필드 수를 분리한다. ON 변화는 신규 대운 값과 공식 자료 확대에서 예상한 변화만 허용하고 배우자·관계 해석 등 비대운 변경은 실패 처리한다. 합성 비율을 실제 고객 오류율로 부르지 않는다.
6. **A/B/C/D:** 같은 관례·시계인데 공식 사실과 다르면 A; 관례 차이는 B; 공식 범위/시간계/오라클 한계는 C; 맞출 수 있는 시간대/옵션 차이는 D. 미확정은 예상값을 채우지 않는다. 새 A는 재현·기대값·근거·영향을 붙여 별도 계획/CR에 넣는다.
7. **허용 실행:** 서비스는 공개 어댑터와 승인 핀 그래프만 실행. VM fetch/네트워크/WASM/Swiss 차단 유지. KASI/JPL 수집은 별도 프로세스, 신규 결과 디렉터리·원문 해시·모델/응답 메타데이터 고정. 기존 증거는 불변. CI용 골든은 오라클 설치/실네트워크 없이 실행 가능해야 한다.
8. **저장 보존:** 가상 v1/v2 저장·유료 결과를 재열람할 때 계산기/오라클/과금 호출 0회, 원문 불변, 추가 차감 0회를 mock으로 확인한다. 실패/범위 밖/플래그 OFF에도 저장 결과를 가리거나 덮어쓰지 않는다. 이는 실결제·실서비스 검증과 구분한다.

새 계산 지원 범위는 `공식 자료 ∩ 어댑터 입력 계약 ∩ 선택된 관례 ∩ 완료한 테스트`로만 선언한다. 모든 승인 대상에서 A 미해결 0, 예상 밖 OFF 차이 0, 비대운 필드의 예상 밖 변화 0, 원문/저장본 변경 0을 만족해야 한다. 실패 구간은 제외하고 표에 남긴다.

## 5. 변경 요청과 제외 사항

| 요청 | 불변 규칙과 관계 | 상태 |
|---|---|---|
| [CR-003 공식 권위 자료 범위 편입](change-requests/CR-003.md) | 엔진 데이터·공통 조회·정본 생성물은 규칙 3의 읽기 전용 대상. 기존 CR의 한정 범위 밖 편입은 새 예외 승인 필요 | 제안, 미승인. 절입/음력/시각계 변경을 묶어 자동 승인하지 않음 |
| [CR-004 대운 전용 연결](change-requests/CR-004.md) | 공개 래퍼와 내부 계산기 전달/대운 연결은 규칙 3의 추가 예외. 현행 차단 제거만으로 해결 불가 | 제안, 미승인. 기본 OFF·현행 관례 유지·서울 양력 파일럿 한정 |

`calculateLocalResult()` 수정, KASI prefetch timezone 주입, `normalizeSaju` timezone 추가는 **두 CR 모두 승인 요청하지 않는다**. 필요하다고 판명되면 이 계획으로 우회하지 않고 새 CR을 작성한다. 결제 실행 파일·인증·스키마·UI·가격 변경, 학파 교체, 해외 장소 전달, 전체 셸/워커 확대, Swiss 실행/대체, 베다 검증기 설치, 운영 활성화는 제외한다.

자료 확대 후 버전·해시는 새 계산 근거에 기록하고 이미 저장된 결과는 그대로 읽는다. 저장 시 권위 버전별 동시 신규 요청의 충돌 여부는 mock 검사하되 KV/R2 키나 사용자 자산 스키마 변경이 필요하면 별도 CR로 멈춘다. 롤백은 신규 계산의 옵션 OFF이며 기존 결과 재계산·삭제가 아니다.

## 6. 이번 문서 작업의 검증과 종료

현재 소스와 기존 보고서/집계를 읽고 지원 범위·대운 전달·차단·일반 성별 입력의 영향 지점을 확인했다. KASI/JPL 공식 **설명 페이지**만 열람했으며 새 생일/천문 계산 데이터 수집은 하지 않았다. 운영 코드·기존 데이터·소스 핀·플래그·의존성은 변경하지 않는다.

검증 결과: 새 문서 3개의 로컬 링크 9개와 코드 블록 짝 검사 통과, 기존 집계 101/1,109·OFF 40,000비교 차이 0의 기록 일치, 두 플래그 기본 OFF·대운 차단 코드 존재를 정적 확인했다. `npm run verify:doc-freshness`는 종료 0(루트 활성 문서 4개 대상)이며 새 문서 링크 검사는 별도 수행했다. `git diff --check`도 통과했다. 엔진 실행·회귀 재실행·full CI·빌드·push·배포는 이번 작업에서 미실행이다. 계획 작성 완료와 CR 승인/구현 완료를 구분한다. 다음 행동은 CR별 범위 결정이며, 별도 승인 전 실행을 시작하지 않는다.
