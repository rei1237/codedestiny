# CR-001/002 구현·회귀 보고

status: done

2026-11-01 네오의 명시 승인을 받아 **두 CR만 구현했고 기능 플래그는 모두 기본 OFF**다. 기존 호출부에서 활성화하지 않았다. 로컬 검증·커밋까지만 수행하며 push·원격 통합·CI·배포는 하지 않는다. 전체 운세 엔진의 정확도 인증이나 베다/숙요/서양점성술 검증 완료 보고가 아니다.

이번에 다룬 결함 유형은 **2개**다. 절입 경계의 원국 전환과 역사 음력의 날짜/별 배치를 바꾸므로 결과 정확도 영향은 높지만, 실제 고객 발생률·유료 피해 수는 조사하지 않았다. 101개 또는 추가 4개를 독립 결함 수로 부풀리지 않는다. B 학파 선택, C/D 한계, 다른 엔진 경로는 변경하지 않았다.

## 자료 범위와 남은 제한

- 절입: 2000, 2002, 2005, 2006, 2012, 2014, 2017, 2018, 2019, 2023, 2024, 2025, 2027, 2028년의 12節 168개와 연말/연초 인접 경계까지 **184개**. NASA/JPL Horizons DE441 지구중심 겉보기 태양 황경을 직접 조회해 각 전환을 **40 ms 구간**에 가뒀다. 이것은 모델 계산의 구간 폭이며 실제 천문 현상의 절대 정확도 40 ms 보장이 아니다. 구간 안의 출생 순간은 판정하지 않는다. 선형 보간만으로 전환값을 확정하지 않았고, 보간 후 양쪽 황경을 다시 공식 API로 확인했다.
- 미래 2027/2028은 수집 시점의 예측 버전이다. 2028 KASI 월력 자료의 잠정 성격도 유지한다. 기존 분 단위 표는 **수치와 지문이 그대로**다. 새 공식 자료는 `authority-data.generated.js`에 분리했다.
- 역사 음력: 1903-08~12, 1904-01/09~11, 1905-03~05, 1907-05~07, 1908-03~05, 1909-07~09, 1911-10~12의 **24개월/712일**. 각 월 초하루·길이·마지막 날·다음 초하루를 KASI에서 확인했다. 1903년 9월 30일도 유효하다. 전 시대 시간대나 윤달 학파를 바꾸지 않았다. 수집된 24개월에는 윤달이 없으며, 미확인 윤달의 v2 지원을 주장하지 않는다.
- 두 플래그는 **입력별로 검증된 권위를 선택하는 내부 계약**이다. 지원 범위가 다르므로 전 사용자 일괄 ON 또는 두 플래그 동시 일괄 ON은 하지 않는다. 범위 밖은 이전 답을 v2인 것처럼 반환하지 않고 명시 오류를 낸다. 범위 확대·대운 연결·운영 활성화는 별도 검증과 승인 대상이다.
- 공개 사주 어댑터의 기존 성별·출생지·timezone 미전달 계약은 변경하지 않았다. 따라서 해당 공개 표면을 넘어 대운이나 모든 해외 출생 경로까지 검증 완료로 확대하지 않는다.

## 수정 파일과 불변 규칙

- `lib/korean-calendar/{policy,authority,authority-data.generated,core,ganji,natal,index}.js`: 플래그 정본, 분리 자료, 공통 달력과 절입 조회.
- `app/saju/animal-destiny/lib/sajuAdapter.ts`, `engine/localSajuCalculator.ts`: 공개 선택 인자 전달, 달력 한 번 정규화, 원국/절기 근거 일치. **`calculateLocalResult()`와 KASI prefetch 본문은 바이트 비교상 불변**이다. `normalizeSaju.ts`는 변경하지 않았다.
- `lib/ziwei-birth-clock.js`, `worker/lib/ziwei-ai-chart.js`, `worker/lib/guardian-fortune/adapters/ziwei.js`: 같은 역사 달력을 시계와 명반에 전달. 학파/소한 seedYear 규칙 변경 없음.
- `scripts/build-korean-calendar-table.mjs`, `js/core/korean-calendar.js`, `public/js/core/korean-calendar.js`: 승인 모듈의 정본 생성 연결/미러. 기존 표 `table.generated.js`는 불변.
- 정적 생성기 후속 10개 파일(`index.html`, `js/core/index-inline-runtime.js`, `public/js/core/index-inline-runtime.js`, `public/{index,en/index,ja/index,zh/index,zh-tw/index,ggulggul/index,static/index}.html`)은 캐시 URL의 `?v=` 값만 갱신했다. 변경 전후에서 그 값만 정규화하면 내용이 동일함을 검사하여 문구·마크업·레이아웃·계산 로직 변화가 없음을 확인했다.
- 정적 전달 검사의 생성물 불일치는 기존 `scripts/generate-sitemap.mjs`로 동기화했다. 루트/public의 사이트맵 XML 12개는 `lastmod` 외 내용이 동일하고, `config/sitemap-lastmod.json`은 내용 지문·날짜 외 구조와 경로 집합이 동일함을 검사했다. 새 주소·SEO 문구·색인 정책은 추가하지 않았다.
- `__tests__/fixtures/korean-calendar/authority-v2-*.json`, `__tests__/ui/calendar-authority-regression.test.mjs`, `tools/oracle/implementation/`: 독립 공식 골든·검증/수집 도구. 운영 의존성과 lockfile은 변경하지 않았다.

결제/가격/이용권/월정석/단건 결제, PortOne/Inicis, 인증, API 라우트, DB/KV/R2/사용자 자산 형식, 기존 저장·유료 결과, 960px 레이아웃 및 UI/i18n/SEO 문구는 변경하지 않았다. 저장 결과 재계산/덮어쓰기 0건이다. 추가된 문자열은 내부 오류 코드와 근거 버전이며 사용자 UI 문구를 추가하지 않았다. 폐기한 운영 코드가 없어 `_graveyard/` 이동도 없다.

신규 의존성 설치는 없다. 격리 Node 12개 허용 MIT 메타데이터를 다시 확인했고, 기존 달력 생성기에 사용되는 `astronomy-engine@2.1.19`의 MIT 메타데이터도 확인했다. 운영에 이미 있는 Swiss/LGPL/미확인 라이선스의 존재는 이전 원장대로 남아 있으며 제거·교체·실행하지 않았다.

## 종료 기록과 후속 확인

push·배포 금지 지시를 유지한다. 전체 CI/전체 Jest/전체 앱 빌드는 Swiss 연결 경로 때문에 미실행이다. 허용 공개 어댑터는 핀 검증 후 빌드·실행했고 생성된 클래식 스크립트도 검사했다. 실제 결제·로그인·운영 DB 성공을 검증했다고 주장하지 않는다.

다음 작업은 별도 승인 때만 한다: 권위 자료 범위 확대, 성별 기반 대운 연결, B 학파 결정, 베다 주 검증기 확보, Swiss 실행 경계 해결, 운영 활성화/전달. 연 1회 KASI 월력·음력 변경과 JPL 예측 버전을 확인하되 기존 저장본은 보존하고 새 자료 버전과 새 골든으로만 추가한다. 되돌림은 새 계산에서 플래그 OFF이며 저장본을 롤백하거나 재계산하지 않는다.
