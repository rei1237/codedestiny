# A 후보 101개 입력의 공식 근거 추가 판정

status: done

**2026-11-01 추가 판정: 101개 입력 모두에서 출력 오류를 확인했다. 이 집합의 미확정 후보는 0개이며, 독립 결함 101개라는 뜻은 아니다. 수정 계획은 절입 경계 정밀도와 역사적 한국 음력이라는 두 결함군으로 제한한다.** 운영 코드 수정·저장 결과 재계산·Swiss 실행은 0건이다. [Phase 3 수정 계획](03-fix-plan.md)은 작성만 했으며 구현 승인이 아니다.

최초 [Phase 2 보고서](02-diff-report.md)의 ‘미확정 101개’는 당시의 판단으로 보존한다. 이번 판정은 서비스 기준 `20904183a1b0276584ed6f74313bf1e6cdeaf442`, Phase 2 산출물 커밋 `1b91faf5380e3ab07da71e3dc29f6a892d8bc448`에 고정한 결과를 대상으로 한다. 현재 운영 배포가 같은 코드인지 검증한 것은 아니다.

## 공식 출처와 실행 경계

- KASI [음양력변환계산](https://astro.kasi.re.kr/kor/life/pageView/8)이 실제 사용하는 공개 `/life/solc`, `/life/lunc` 요청을 조회했다. 비밀키나 서비스 프록시 없이 **한국천문연구원 호스트에 직접** 요청했다. 65개 양력 날짜, 2개 음력 날짜, 8개 음력월 초하루를 수집했다. 요청/응답 날짜·윤달·일진을 검사하고 HTTP 상태·수집 시각·응답 SHA256을 저장했다.
- KASI [2023 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2023) 등 14개 연도를 조회했다. 2023/2024/2025/2027/2028은 표를 제공하여 8개 후보 경계를 다시 확인했다. 2000~2019 해당 9개 연도 페이지에는 요청 연도 절기표가 없었다. **그 15개 후보를 ‘이번 KASI 실조회 확인’으로 표시하지 않았다.** 이들은 저장 KASI 표와 이번 JPL 직접 계산으로 판정했다.
- JPL [Horizons 매뉴얼](https://ssd.jpl.nasa.gov/horizons/manual.html#observer-table)과 [공식 API 문서](https://ssd-api.jpl.nasa.gov/doc/horizons.html)에 따라 태양 `10`, 지구중심 `500@399`, 관측량 `31`(겉보기 황경), `UT`, 그레고리력을 지정했다. 응답은 Sun/Earth **DE441**, GEOCENTRIC, AIRLESS, `ObsEcLon`을 명시했다. Swiss 또는 Swiss 래퍼가 아니다. 라이브러리 설치 없이 공식 천문 자료만 읽었다.
- API 문서는 버전 1.3을 표시하지만 실제 응답 signature는 1.2였다. 이를 숨기지 않고 대상·중심·모델·열 이름·열 수·JD/입력 시각 매칭·46행을 명시적으로 검사했다. 문서 버전 일치만으로 파싱을 신뢰하지 않았다.
- 역사적 8개 월에는 JPL 태양/달 각 32시점을 추가 조회했다. 1962년 이전의 JPL `UT`는 **UT1**이다. 저장된 ISO `Z` 문자열은 요청 숫자 시점을 표현하는 편의 표기이며 당시 UTC가 존재했다는 주장이 아니다.
- 서비스 계산은 기존 허용 공개 사주 어댑터만 추가 호출했다. 자미 서비스는 Phase 2의 고정 결과를 사용하고, iztro만 공식 KASI 날짜로 다시 계산했다. 네트워크 수집과 서비스/오라클 실행 프로세스는 분리했다. 서비스 실행 중 fetch와 Swiss 경로는 차단했다.

## 결함군 1 — 절입 경계가 먼저 바뀜

23개 입력 모두에서 입력 순간의 JPL 태양 황경은 목표 각도보다 작고, 60초 뒤에는 목표 각도보다 컸다. 따라서 해당 입력 순간에는 이전 연·월주를 유지해야 한다. 선형 보간으로 추정한 실제 절입은 입력보다 **약 31.05~56.52초 뒤**다. 이 소수점 시각은 설명용 추정이며 공식 초 단위 정본이나 운영 스냅샷으로 사용하지 않는다. 오류 판정 자체는 입력 순간의 황경 부호로 했다.

| 입력 | 서비스 | 공식 천문 근거 / 기대 |
|---|---|---|
| `edge-001687`, 2023-02-04 11:42 서울 | 연·월 `癸卯 / 甲寅` | JPL 02:42 UT = 314.9995980°, 02:43 = 315.0003021°. 입춘 이전이므로 `壬寅 / 癸丑`. KASI 현재 페이지도 11:43 |
| `edge-000587`, 2000-03-05 15:42 서울 | 월 `己卯` | JPL 06:42 UT = 344.9995382°, 06:43 = 345.0002340°. 경칩 이전이므로 `戊寅`. 저장 KASI 15:43; 해당 연도 현재 페이지 표는 없음 |

소스 추적: `scripts/build-korean-calendar-table.mjs`는 이미 `kstParts(term.ms + 30000)`으로 **분 반올림**한다. `lib/korean-calendar/core.js::expandTerms/isAtOrAfter`는 분 정밀도 표를 그대로 비교하고, `natal.js`의 연·월주도 이 표를 따른다. 따라서 원인을 ‘초 절사 버그’로 단정하는 수정안은 기각한다. **천문 모델 오차와 분 단위 표/비교를 함께 검증해야 하며, 단순 +1분·ceil·표시 문자열 교체로 고치지 않는다.**

2027/2028의 4개 후보는 미래 천문 예측에 대한 현재 기준 판정이다. 특히 [2028 KASI 자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2028)는 공식 월력요항 발표 전 자료임을 표시한다. 미래 윤초/자료 갱신 가능성을 기록하고, 그 소수점 시각을 영구 고정하지 않는다. 31초 이상의 경계 차이와 현재 공표 분 값이 함께 지지하는 출력 오류는 확인했지만, 최종 배포용 초 정본은 후속 검증 대상이다.

## 결함군 2 — 역사적 한국 음력과 고정 KST 역산 표의 차이

KASI [1909년 음력 8월 11일](https://astro.kasi.re.kr/life/lunc?yyyy=1909&mm=08&dd=11)은 양력 **1909-09-24, 丁亥**다. 서비스는 09-25에 해당하는 **戊子**를 반환했다. 음력 8월 14일도 공식 09-27/庚寅 대신 09-28/辛卯였다. 같은 시진의 시주도 일간 이동에 따라 달라졌다.

자미 76개 입력은 독립 IANA 지방 평균시·기존 23시 날짜 이동을 다시 확인한 뒤, 그 날짜의 KASI 음력을 iztro에 넣었다. 모든 입력에서 iztro의 음력 echo가 공식 값과 같고, 기존 A의 **1,081필드 모두** 공식 날짜 대조값과 서비스가 달랐다. 辛년 천괴/천월 등의 이미 분리된 학파 차이는 이번 A에 포함하지 않았다.

공통 달력의 원인을 더 좁히기 위해 공식 음력 67개를 `computeNatalFromInput`에 정오 입력으로 넣었다. **66개는 공식 양력보다 하루 늦었고 1개는 거절됐다.** 거절된 날짜는 [1903년 음력 9월](https://astro.kasi.re.kr/life/lunc?yyyy=1903&mm=09&dd=01)의 30일로, KASI는 그 달을 30일로 제공하며 9/30 = 1903-11-18을 반환한다. 이 실행은 내부 `lunarToSolar` 직접 호출이 아니다. 증거는 [calendar-probes.json](results/adjudication-20261101/calendar-probes.json)이다.

| 해당 음력월(모두 평달) | KASI 초하루의 양력 | JPL 합삭을 끼우는 UT1 범위 |
|---|---|---|
| 1903-09 | 1903-10-20 | 15:30~16:00 |
| 1903-12 | 1904-01-17 | 15:30~16:00 |
| 1904-10 | 1904-11-07 | 15:30~16:00 |
| 1905-04 | 1905-05-04 | 15:30~16:00 |
| 1907-06 | 1907-07-10 | 15:00~15:30 |
| 1908-04 | 1908-04-30 | 15:30~16:00 |
| 1909-08 | 1909-09-14 | 15:00~15:30 |
| 1911-11 | 1911-12-20 | 15:30~16:00 |

8개 초하루는 `/life/lunc`로도 각각 직접 확인했다. JPL 달-태양 황경차가 위 구간에서 음→양으로 바뀌므로 합삭에 UTC+9를 기계적으로 적용하면 다음 날짜가 된다. 이는 `ephemeris.js::KST_OFFSET_MS/kstDayIndex`의 전 시대 고정 KST 생성 정책이 현재 공식 역사 음력과 다르다는 설명을 지지한다. **이 증거로 당시 법정시·역법 채택을 확정하거나, 1912년 이전 출생 시간대를 일괄 UTC+8로 바꾸지 않는다.** 출생 시각 보정과 공식 음력 달력의 역사 자료는 별개다.

추가로 A2 두 입력에 공식 날짜를 기존 `computeNatalFromInput(input, {kasiSolarDate})` 인자로 넣었다. `calculationEvidence.solarDate`는 09-24/09-27로 바뀌지만, `canonicalNatal.civil`과 실제 기둥은 09-25/09-28로 남았다. `localSajuCalculator.ts::calculateLocalSaju`가 `resolveSolarDate()` 결과를 구한 뒤 원래 음력 입력을 `calculateNatalSaju`에 다시 전달하기 때문이다. [prefetch-controls.json](results/adjudication-20261101/prefetch-controls.json)에 결과가 있다. prefetch 함수 호출·timezone 주입은 없었다. **KASI 값만 전달하면 충분하다는 얕은 수정안은 이 두 입력에서 검증상 실패**했으므로 계획에서 제외한다.

## 아직 확정하지 않은 사항

- 101개 입력 밖의 결함 수·운영 이용자 비율·현재 배포 상태. 이 집합이 서비스 전체의 오류 전부라는 주장은 하지 않는다.
- 절입 오차에서 기존 천문 모델과 분 반올림이 각각 기여한 양, 미래의 영구적인 초 단위 절입값.
- 8개 월 밖의 모든 1900~1911년 공식 역사 음력, 인접 월 길이와 전체 지원 범위의 회귀. 8개 구간만을 근거로 전체 과거 시간대 정책을 변경하지 않는다.
- 다른 셸/앱/LLM 입력 경로의 실제 오류 비율, 대운(현재 공개 사주 어댑터는 성별 미전달), 소한·유년, 격국/용신 등의 학파 판정.
- Swiss 연결 서비스와 베다 주 검증기 미확보. 해당 영역은 이번에도 차단이고 정확도 판단에 포함하지 않는다.

이들은 **미확정 범위·원인 세부사항**이며, 이미 관측·확인된 101개 출력 오류를 101개 미확정 버그로 다시 세는 것은 아니다. Phase 3에는 위 두 결함군만 포함하고 나머지는 제외한다.

## 재현 자료와 검증

`tools/oracle/adjudication/collect.mjs` → `calendar-probe.mjs` → `prefetch-control.mjs` → `moon-support.mjs` → `judge.mjs` 순으로 공식 수집과 오프라인 대조를 분리했다. 과거 탐색용 원문은 `sources/`에 함께 보존했다. 재수집에는 별도 출력 폴더를 사용하며 최초 Phase 2 원시 파일은 변경하지 않는다.

최종 자료는 [results/adjudication-20261101](results/adjudication-20261101/)에 있고, 파일별 출처·해시는 `manifest.json`, 판정은 `decisions-official.json`이다. 공개 출처 증거 검증, 기존 입력 집합/원시 해시 보존, 설치 라이선스·서비스 소스 핀, 문법 검사를 실시한다. 실제 실행 결과와 전달 상태는 아래 종료 기록에 남긴다.

### 종료 기록

검증: `node --test tools/oracle/test/adjudication.test.mjs` 7개 통과(원본 101입력/1,109필드, JPL 시점·공식 달력·공개 어댑터 대조, 원시 해시, 소스 핀). `node tools/oracle/verify-licenses.mjs` 설치된 12개 패키지 MIT 확인. 새 `.mjs` 문법 검사와 `git diff --check` 통과. 추가 증거 104개 파일 2,705,202바이트(매니페스트 제외), 기존 Phase 2 증거 16개 파일 불변, 서비스 소스 핀 39개 불변을 확인했다.

`npm run check:fast -- --plan`은 critical로 전체 Jest 등 Swiss 연결 검사를 선택한다. **계획만 조회했고 전체 실행·CI·push는 하지 않았다.** 최초 증거 검사 작성 중 구문 오타 1개를 수정한 뒤 7개 전체 검사를 통과했다. 운영 코드 검증 실패를 숨기거나 게이트를 축소한 것이 아니다.

계획과 변경 요청서만 작성했다. 운영·결제·인증·저장 결과·의존성·UI/SEO 변경은 없다. 구현은 별도 승인 전까지 시작하지 않으며, Swiss 연결 전체 CI를 촉발하는 push도 하지 않는다.
