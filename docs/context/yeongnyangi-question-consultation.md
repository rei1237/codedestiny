모든 생선은 직접적인 답, 질문과 관련된 성향 또는 상황 패턴, 실제 근거의 쉬운 뜻,

새 영냥이 질문형은 기존 결과 스키마와 렌더러에 성향(타로는 현재 태도)·강점과 그림자·반복 패턴을 먼저 담고, 질문과 기간별 답변·근거·실행 챕터를 이어 붙인다. 타로는 모든 카드의 이름·정역·상징·자리·질문 적용·행동을 설명한다.
길이만으로 재생성하지 않으며, 필수 구성·근거·시기·완료 저장·복구 검사는 유지한다.

## 추가 질문의 사용·제외·저장

추가 질문은 같은 상담 안에서 기본 답변을 이해하고 적용하는 대화다.
기본 답변 완료 후 결과 상단의 남은 횟수 안내와 하단 입력창으로 포함된 추가 질문을 모두 이어서 사용할 수 있다. 신규 UI에서는 조기 종료 버튼을 제공하지 않는다. 질문 예시는 입력만 돕고 자동 전송·자동 차감하지 않는다. 기존 종료 기록과 close API의 호환은 유지하며 완료 결과 열람을 막지 않는다.
임의의 만료 기간·이월·추가 질문 유료 상품을 만들지 않는다.

- 하나의 핵심 의도와 답변을 1회로 본다. 문장·메시지·물음표 개수로 세지 않는다.
- 필수 확인, 의미 확인, 근거 보충, 분류/범위 안내, 정정, 결제/이용권/열람 지원은 제외한다.
- 대상·주제·기간·계산 조건이 바뀌면 새 상담 사유와 선택지를 안내한다. 결제·상품 변경은 자동 실행하지 않는다.
- 저장된 근거·기본 답변·대화를 사용한다. 새 차트 계산·재추첨·전체 리포트 재생성은 호출하지 않는다.
- `generationCheckpoint.conversation.revision`의 원자적 CAS로 한 요청만 예약한다.
- 유효 답변과 used 증가를 한 문서 write로 저장한 뒤 다시 읽어 전달 가능 상태를 확인한다.
- 실패·중복·네트워크 재시도는 같은 요청 ID를 유지한다. 저장 응답 유실 시 저장된 결과가 우선한다.
- 근거 부족만 알린 답은 사용으로 확정하지 않는다.
- 내부 호출 예산은 별도다. 같은 예약의 제공자 시도는 최대 2회, 회차 전체의 호출 상한도 둔다.
  상한을 넘으면 횟수를 차감하지 않고 지원 확인으로 안내한다. 자동 재생성 루프는 없다.
- 한도를 다 쓰거나 일찍 마쳐도 기본 결과와 저장된 대화를 삭제하지 않는다.
  한도 0 또는 종료 상태의 정정·지원은 지원 경로로 계속 안내한다.

## 기존 구매와 모든 유료 결과

새 계약은 prepare 시에만 저장한다. 기존 저장된 상품·금액·장 구성·구매 권한을 덮어쓰지 않는다.
기존 동일 생선 이용권은 원래 적용 가능 상품 판정을 거쳐 새 상담을 구매할 수 있다.
단건·월정석·Family·생선 전용 횟수권은 기존 funding claim과 결제 증빙 검사를 유지한다.
재열람은 현재 잔액이나 이용권의 현재 유효기간으로 다시 과금하지 않고,
소유자와 원래 구매/차감 증거·회수 여부를 기준으로 기존 저장 결과를 연다.

타 서비스의 공용 저장 결과 검사는 기존 `paid-result-revocation.js`,
`paid-completed-result-access` fixture와 서비스 고유 렌더러를 유지한다.
서비스별 생선 가격 이식이나 범용 JSON 상세 화면으로의 변경은 없다.

- 고등어, 부탁 거절: “이번에는 가능한 범위를 먼저 말해 봐. 가상의 십성 근거에서 책임을 먼저 맡으려는 패턴이 있다고 가정하면, 바로 수락한 뒤 혼자 부담을 키울 수 있어. 예를 들어 ‘오늘은 어렵고 금요일에 20분은 가능해’처럼 말하는 거야. 상대가 급하더라도 네 일정이 달라지는 것은 아니니, 대안을 줄 수 있는지와 수락 여부를 나눠 정해.”
- 연어, 이직 준비: “퇴사 날짜보다 비교 기준부터 정리하자. 가상의 직업 관련 하우스와 주인 행성은 전문성을 쌓는 조건을, 현재 다샤는 책임 증가를 가리킨다고 가정할게. 새 직장의 이름보다 실제 업무·학습 기회·생활 제약을 비교해야 해. 이번 주에는 채용공고 두 개와 현재 역할을 같은 항목으로 적어 봐. 이것은 취업 보장이 아니라 준비 방향이야.”
- 광어, 생활과 돈: “갈등을 줄이는 첫 약속은 지출을 모두 같게 만드는 것보다 함께 정할 지출의 경계를 합의하는 거야. 가상의 두 명식 사이 합은 가까워지는 계기, 충은 반응 속도의 차이라는 조건부 해석으로 읽을 수 있어. 한 사람은 바로 정하고 다른 사람은 시간을 두고 싶을 수 있지. 실제로 그런 장면이 있는지 확인한 뒤, 큰 지출은 하루 뒤 다시 의논하는 약속을 시험해 봐.”
- 참치, 시기 전환: “지금은 기존 역할을 정리하고 다음 시기에 가져갈 강점을 선별하는 준비부터 하자. 가상의 현재·다음 대한에서 관록궁과 재백궁의 사화 연결이 다르다고 가정하면, 같은 노력도 일과 자원을 배분하는 방식이 달라질 수 있어. 이 구간은 대한의 나이 범위이며 정확한 취업일을 뜻하지 않아. 앞으로 유지할 일, 줄일 일, 미리 배울 일을 하나씩 적어 두자.”

## 깊이와 검증 범위

모든 생선은 질문에 관련된 가장 깊은 분석을 제공한다. 상충 근거·반대 가능성·조건·생활 장면·실천을 함께 검토하며 가격별 근거 개수와 문단 수 제한을 생성 프롬프트에서 제거했다. 기존 구매의 장 구성과 저장 본문은 소급 변경하지 않는다.

새 질문 계약은 한국어 단일 체계 흐름에 적용한다. 타 언어·퓨전·기존 일반 메뉴·신점·질문하늘은 기존 구매 및 생성 계약을 유지한다. 공통 생성기의 답변 품질 원칙은 재사용하되 다른 서비스 가격과 말투는 바꾸지 않는다.

새 타로 상담은 선택한 스프레드의 모든 자리 질문을 기본 답변 안에서 다룬다. 카드 수로 상품을 올리지 않으며 실제 정역·순서·연결 묶음을 저장해 재사용한다.

후속 답변은 직접 답·이유·행동과 유효한 근거 ID를 검증하고 기존 확정 주장 차단을 재사용한다. 내부 입력은 120,000자를 넘으면 자동으로 잘라 생성하지 않고 지원 확인으로 보낸다. 이는 고객의 추가 질문 차감이 아니다.

검증은 외부 통신을 차단한 mock이다. 타입 검사와 변경 UI lint, Worker dry-run 번들 및 실제 계산→근거 선택→mock 생성 요청 검사, 저장 CAS/중복/실패/정정·확인 제외 검사를 수행한다. 393px·1280px component mock 화면은 가로 넘침·브라우저 오류 없이 검사했고 독립 시각 검토를 받았다. 실 LLM 문장 품질·실결제·운영 DB·실기기·운영 배포 검증은 수행하지 않았다.

## 미정 범위와 전달

확정된 가격·횟수·개인 연애 배정은 다시 묻지 않는다.
운영자가 이후 결정할 범위는 복합 궁합+장기 흐름 패키지, 다른 체계의 장기 계산 개발,
미사용 횟수 이월이나 별도 후속 구매 상품을 새로 만들 경우의 정책이다.
현재 구현은 이를 자동 생성하거나 판매하지 않는다.

검증 기록과 실행 결과는 이 문서의 후속 갱신 및 최종 보고에 기재한다.
로컬·main·운영 전체 동기화는 영냥이 우선 작업 이후 별도 인수인계로 분리한다.

## 2026-10-08 분량과 화면

`consultation-budget.ts`는 이전 v6 생선별 목표 분량을 최초 상담과 전체 추가 질문의 합계로 사용한다. 추가 질문이 있으면 최초 상담에 약 80%, 나머지 약 20%를 횟수로 나누어 배정한다. 추가 질문 없는 고등어는 최초 상담에 전부 배정한다. 이는 생성 목표이며 실제 글자 수 보장이 아니다. 길이만 짧다는 이유로 유료 재시도하지 않는다.

모듬·초융합은 기존 v5의 18·28개 본문 챕터와 예방·실천 1개를 유지하고, 전체 최초 분량 안에서 다시 배분한다. 신규 주문에 분량·횟수를 저장하며 과거 주문의 저장 계약은 바꾸지 않는다. 추가 질문은 저장된 모든 챕터의 근거 선택자를 사용하고 이전 답변의 결론을 이어서 구체화한다.

타로는 질문 키워드·기간·등급으로 배열을 고른다. 연어 이상 추천은 최소 6장이고 재물은 연어·광어 7장, 참치 10장을 추천한다. 직접 선택과 기존 등급별 최대 카드 수는 유지한다. 카드 섞기는 확정 덱의 화면 순서만 바꾸며 선택 이후에는 잠긴다. 월정석 잔액은 기존 잔액 API를 읽어 할인 가능한 수량과 함께 표시한다.
