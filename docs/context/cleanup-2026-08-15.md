## 안전하게 지울 수 있는 것 (근거 확보)

### 1. 레포 전용 정리 스크립트가 이미 담당하는 것 — 새 명령을 만들지 말 것

`scripts/safe-clean-repo.mjs` 가 `.next`·`out`·`dist`·`build`·`coverage`·`playwright-report`·`test-results`·`.wrangler`·`.cloudflare`
디렉터리와 `*.tsbuildinfo`·`*.log`·`_tmp_*`·OS 잔재를 지운다. 보호 목록(`index.html`·`package.json`·`worker/`·`app/`·`public/` 등)도 내장돼 있다.

```bash
npm run clean:repo:dry      # 계획만 (reports/cleanup-plan.json 에 기록)
npm run clean:repo:apply    # 실제 삭제
```

이걸로 `tsconfig.tsbuildinfo`(464KB) · `llm.log` 가 함께 정리된다. 🔴 **같은 일을 하는 rm 명령을 따로 짜지 말 것**(원칙 6 중첩 금지).

### 2. 감사·측정 산출물 `reports/` — 약 22MB

`duplicate-files-report.json`(0.6MB) 등 전부 스크립트 산출물이다.

- `scripts/verify-doc-freshness.mjs:20` 이 `reports/` 를 **활성 문서에서 참조 금지 경로**로 규정한다 = 영속 자산이 아니라는 선언.
- `scripts/generate-adsense-route-audit.mjs:14` 와 `safe-clean-repo.mjs` 가 실행 시 다시 만든다.

```bash

git rm -r --cached reports           # 추적 중이면 (.gitignore 에 추가돼 있음)

```

### 6. 정리되지 않은 워크트리 22개

`.claude/worktrees/` 아래 22개가 남아 있다. 각각이 레포 전체 사본이라 디스크와 grep 양쪽을 오염시킨다.

```bash
git worktree list                    # 어떤 브랜치가 물려 있는지 확인
git -C .claude/worktrees/<이름> status --short   # 미커밋 작업이 있는지 개별 확인
git worktree remove .claude/worktrees/<이름>
git worktree prune
```

🔴 **일괄 삭제하지 말 것** — 미커밋 작업이 남아 있을 수 있다. `status --short` 가 빈 것부터 지운다.
