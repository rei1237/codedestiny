# 영냥이 자유질문 개선

## 현재 단계 (2026-09-26)

Phase 1의 근거 계약·순수 빌더·계산 래퍼·신규 요청 저장 연결과 Phase 2 질문 분석기·분석 체크포인트를 구현했다. Phase 3은 첫 장의 프롬프트 조립에 분석·근거를 연결했다. Phase 4는 신규 질문형 첫 장의 근거·기간·안전 검증과 검증 실패 시 최대 1회 재생성, 이후 유료 접근을 보존하는 미완료 지원 확인을 연결했다. Phase 5는 신규 질문형 입력의 12개 결과 언어와 첫 장 답변의 normal/limited/care 표시를 연결했다.  Phase 7(2026-10-02)은 신규 질문형 상담에 주·월·연 기간 해석과 기간 상담 계약을 더했다. 전체 Phase 1~6 완료로 해석하지 않는다.

대상은 Code Destiny `/yeongnyangi/`의 명시적인 질문형 상담 메뉴(6개 단일 엔진 및 퓨전)다. 기존 요청과 일반 리포트·신점·호라리에는 신규 버전을 소급하지 않는다. SoulCat은 범위 밖이다.

## 파일과 데이터 경계

- `worker/yeongnyangi/fortune/ask/contracts.ts`: `ask-evidence-v1`, 근거 출처·기간·시간 의존성·접근 등급 계약.
- `categories.ts`: legacy 주제와 표준 주제 매핑. `healing`은 `self`, 외부 `western`은 내부 `astrology`.
- `packet.ts`: 계산 결과를 선택·정규화하고 F/T ID를 정렬 후 부여한다. 카테고리로 자른 뒤에도 ID를 유지한다. 퓨전의 중복 교차 근거는 합친다.
- `window.ts`: 이전 12개월~이후 24개월의 달력 조회 범위. 모든 달에 예측이 존재한다는 뜻이 아니다.
- `wrappers.ts`: 기존 사주·자미 연도 계산과 베다 3단계 다샤를 재사용한다. 궁합 및 검증된 서양 트랜짓 표본을 투영하는 함수도 준비했다.
- `tarot.ts`: Web Crypto 난수로 기존 정본 카드·스프레드·해석기를 재사용한다.
- `service.ts`: 새 질문 요청 준비 때 패킷을 만들고 `generationCheckpoint = { version: 'ask-generation-v1', evidence }`로 저장한다. 구매 `snapshot`과 생성 진행은 분리한다.
- `worker/lib/yeongnyangi-models.js`: 기존 상담 문서에 선택적 Mixed 필드만 추가한다. 마이그레이션·기존 요청 재작성은 없다.

신규 필드는 소유자 검증을 받는 기존 상담 문서에만 저장한다. 공개 API의 `presentFortune`에는 노출하지 않는다. 패킷은 개인정보 제거 계층을 통과하며, 일반 로그에 질문·프로필·전체 근거를 추가하지 않는다. 새 보존 기간이나 무기한 보관 약속은 추가하지 않는다.

## 근거 해석 한계

- 원래 체계와 근거를 보유한 컨텍스트를 구분한다. 타로에 첨부된 사주 일진은 사주 근거다.
- 기존 질문 패킷은 사주 대운과 자미 대한을 제외한다. 2026-10-06 신규 `purpose-counsel-v1` 상담은 참치·기존 전문가 등급의 사주 대운과 원국 심화 근거를 허용한다. 자미 대한 제외와 베다의 별도 다샤 체계는 유지한다.
- 일운은 기준일 하루, 세운은 연도, 절기 시작 시각은 시점으로 보존한다. 시점 근거를 임의의 월 구간으로 넓히지 않는다.
- 시간 미상은 보수적으로 시간 의존 필드와 파생값을 제외한다. 다른 출생 체계의 미상 입력 허용 UI는 아직 확장하지 않았다.
- 자미 유년 결과에 복사된 생년 사화는 독립적인 유년사화로 사용하지 않는다. 유월·서양 진행/솔라리턴·숙요 능범기간은 미지원이다.
- 베다 출생 차트의 Swiss 정밀도가 고차라까지 보증하지 않으므로 별도 검증되지 않은 트랜짓은 제외한다.
- 사주·자미가 실제 선택된 경우 기간 보강을 연결했다. 다른 단일 엔진의 교차 사주 기간은 기존 제공 범위만 보존한다.
- 궁합/서양 트랜짓 투영 함수는 mock에서 검증했지만 새 상대 입력과 라이브 호출에 아직 연결하지 않았다. Phase 2~5의 소유자·체크포인트·입력 연결 때 완성해야 한다. 베다 궁합의 성별 입력 연결도 그때 확인한다.
- 타로 재요청은 동일 의도의 저장 결과를 먼저 읽는다. 읽기 불확실성에서 재추첨하지 않는다. 동시 최초 요청은 기존 원자적 upsert의 승자 결과를 공유한다.

가격 정본·이용권/월정석/단건 결제·차감/환불은 변경하지 않는다. 기존 ask v1~v3는 첫 장 근거 계약을 유지하며, 신규 목적별 상담은 아래의 장 배분 규칙을 적용한다.

## 목적별 상담과 전체 대운 (2026-10-06)

- `counsel-purpose.ts`의 `purpose-counsel-v1`은 신규 요청 지문·저장 consultation·장별 계획에 기록한다. 기존 구매와 재시도는 저장 계약을 사용한다. 공개 응답에서 내부 `counselVersion`·`counsel`은 제거한다.
- `saju/cycle-evidence.ts`는 기존 심화 계산기를 명시적인 운 행으로 재사용한다. 원국 단독, 원국+한 대운, 원국+그 대운+해당 세운을 각각 계산한다. 공용 계산기의 세 번째 선택 인자 `luckRows`를 생략한 기존 호출은 그대로다. 빈 배열은 현재 연도 자동 보충을 하지 않는 원국 계산이다.
- 개고·도충·투간/투출·격국 조건을 시기별로 투영하고, 반복되는 원국 근거는 중복하지 않는다. 원국의 강약·종격·용신 정책과 한난·조습 값은 그대로 유지한다. 새로운 점수나 학파 판정을 추가하지 않는다.
- 대운 질문의 허용 범위는 질문별로 정한다. 전체/기간 미지정은 모든 계산 주기, 현재/다음·간지·연도·나이 지정은 해당 주기다. 다른 질문의 연도가 전체 대운을 자르지 않는다. 과거·미래 대운은 최근 조회창 밖에도 보존하되, 일반 기간 질문과 하위 등급으로 확장하지 않는다.
- 대운 메뉴와 대운 자유질문은 기존 장 수·분량 예산 안에서 주기를 배정한다. v6 선택기는 배정 주기를 유지하고, v7 원장은 각 주기의 소유 장을 고정한다. 각 주기에 원국 비교·연애·건강·재물·직업·행동을 연결한다. 생시 미상은 정밀 대운을 만들지 않는다.
- 일반 상담에는 목적별 설명 지침과 생활 언어 우선 원칙을 적용한다. 질문 답변은 해당 질문의 분류를 따르며, 전문 용어는 필요한 경우에만 쉬운 뜻을 붙인다. 신점·호라리 전용 계약, 지원 언어, 유료 호출/재시도 횟수는 유지한다.
- 검증: `node --test __tests__/ui/yeongnyangi-purpose-counsel.test.mjs` 및 기존 ask·상담종류·v7 wiring, 사주 advanced-factors·gyeokguk mock 테스트. 실제 LLM 문장 품질은 mock 통과로 입증하지 않는다.

## Phase 2 분석 체크포인트

- `fortune/ask/analysis.ts`: 원문 질문 ID별 표준 주제와 기간 질문 여부를 분석한다. ID 누락·중복·알 수 없는 주제·비정상 JSON·공급자 오류는 규칙 분석으로 전환한다. 폴백의 다국어 어휘는 제한적이며 알 수 없는 질문은 기존 선택 주제를 유지한다.
- 공통 `CodeDestinyProvider.analyzeQuestion`: 공통 모델 선택을 유지하고 temperature 0, 출력 1,024토큰, thinking 0, 15초, 공급자 시도 1회로 호출한다. 공급자 간 폴백도 끄며 실패하면 로컬 규칙만 사용한다.
- `claimChapter`의 결제/환불 확인과 잠금을 재사용한다. `saveAskAnalysis`는 소유자·잠금·유료 증명을 확인하는 트랜잭션으로 `generationCheckpoint.analysis`만 저장하고 재읽는다. 동일 분석은 덮어쓰지 않는다. 저장 불확실성에서는 장 생성으로 넘어가지 않는다.
- 재시도는 저장된 버전·질문 ID 계약을 확인하고 분석 호출을 생략한다. 저장 실패로 실제 기록이 남지 않았다면 기존 장별 재시도 예산 안에서 다시 분석할 수 있다.
- 입력의 태그 구분 문자는 이스케이프한다. 모델 출력에서는 허용된 ID·주제·boolean만 취하며 자유 텍스트 지시문은 저장하지 않는다. 분석은 Phase 3에서 첫 장 프롬프트에 연결했다. 구매 snapshot, 가격, 차감·환불 정책, 공개 응답은 그대로다.

## Phase 3 첫 장 프롬프트

- `fortune/ask/prompt.ts`는 저장된 분석의 원문 질문 ID와 패킷 버전을 확인하고, 질문별 표준 주제의 F/T 근거 ID와 기간 필요 여부를 조립한다. 같은 근거 값은 한 번만 싣는다.
- `service.ts`는 분석 저장 후 현재 요청을 다시 읽고 신규 버전의 첫 장에만 저장된 분석과 패킷을 전달한다. 후속 장과 이전 구매는 기존 프롬프트를 유지한다.
- 첫 장 프롬프트는 질문·태그 종료 문자열을 데이터로 이스케이프하고 분류 결과를 명령으로 취급하지 않는다. 새로운 계산이나 스냅샷 재작성은 없다. 기존 장 출처·길이 검증은 그대로 유지했다. 패킷 ID·시기 검증은 Phase 4에서 연결했고 실제 문장 품질 평가는 남아 있다.

## Phase 4 첫 장 검증과 미완료 복구

- 신규 질문형 첫 장의 모델 응답은 질문별 `factIds`·`timingIds`·`evidenceStatus`를 내부 검증 자료로 생성한다. 검증기는 저장된 분석의 질문 ID와 주제별 F/T ID, 원 출처 ID, 기간 해상도, 요청된 기본 기간, 내부 ID 노출과 확정적 표현을 대조한다. 검증 자료는 저장 전 제거하므로 공개 장 응답의 필드 구조는 유지한다.
- 제공된 근거가 부족한 질문은 `limited` 답변으로 표시하도록 지시하고 숫자 날짜를 검사한다. 이 표시는 검증용이며 Phase 5의 사용자 화면 모드와 동일하다고 주장하지 않는다. 문장과 계산 사실의 의미적 일치, 요청 문구만 있는 기간의 완전한 해석, 다국어 표현의 품질은 자동 검증만으로 확정하지 않는다.
- 첫 장 품질 실패는 기존 장 시도 예산 안에서 한 번만 재생성한다. 다음 품질 실패는 내부 `ASK_LIMITED_REVIEW_REQUIRED`로 남겨 자동 큐·정기 복구·사용자 재시도가 추가 LLM 호출을 만들지 않게 한다. 저장된 장과 유료 접근은 보존하고 `COMPLETED`로 표시하지 않으며, 기존 공개 지원 확인 코드로 보여준다. 공급자·저장 실패의 기존 복구 예산과 완료 전 저장 결과 재읽기 계약은 유지한다.
- 실제 LLM 문장 품질과 사주 전문가 검수는 별도 승인·검수자가 필요하다. mock 검사는 근거 계약과 경계의 동작만 확인한다.

## Phase 5 질문 입력과 결과 표시

- 신규 명시적 질문형 메뉴의 결과 언어 선택을 12개 런타임 언어로 열었다. 일반 상담은 기존 한국어·영어·일본어, 신점·질문 시점 상징 상담은 기존 한국어 제한을 유지한다. 저장된 구매 언어는 복구·재열람에서도 우선한다. 질문 원문은 구매 언어와 다른 언어여도 그대로 저장한다.
- 질문 입력의 언어·주제·질문 안내와 선택 주제, 첫 장 질문 답변의 제목·근거·시기·조언·모드 설명은 12개 언어로 제공한다. 기존 프로필·차트·공유 등 주변 UI는 한국어/영어/일본어 정본이 있는 범위만 사용하며 나머지 9개 언어는 영어 안내로 표시한다. 전체 화면 현지화 완료로 해석하지 않는다.
- Phase 4 검증에 통과한 첫 장의 `evidenceStatus=limited`는 `limited`, 그 밖의 건강 주제는 `care`, 나머지는 `normal`을 선택적 공개 `questionAnswers[].mode`로 저장한다. F/T ID와 내부 검증 상태는 계속 제거한다. `limited`가 건강 주제와 겹치면 근거 부족 표시가 우선한다. 모드 필드가 없는 기존 결과는 이전 렌더 경로를 유지한다.
- 언어 검사는 한국어 대체와 문자권 불일치를 거칠게 걸러낸다. 같은 라틴 문자권 언어 간 오역, 중국어 간체·번체 혼동, 해석의 의미적 사실 일치나 전문가 수준 문장 품질은 인증하지 않는다. 질문 분석 규칙 폴백의 다국어 어휘도 여전히 제한적이다.

## Phase 7 기간 상담 (2026-10-02)

- 기간 해석: `fortune/ask/period.ts`의 `resolveAskPeriods`가 질문 문구를 기준일(브라우저 IANA 시간대, 기본 Asia/Seoul의 `consultationClock`)로 절대 구간으로 바꾼다. 주는 월요일~일요일(`이번 주`·`다음 주`·`차주`·`금주`)이다. 달은 `이번 달`·`다음 달`·`YYYY년 N월`·`올해/내년 N월`·연도 없는 `N월`(기준월부터 처음 오는 N월)을 받는다. 연도는 기존 `resolveQuestionYears`를 재사용한다. `createConsultation`은 구간의 합집합을 `period.start/end`에, 개별 구간을 `period.ranges`에 넣고 `resolver: 'ask-period-v1'`을 표시한다. `앞으로 3개월` 같은 상대 길이와 `상반기`·계절은 기존처럼 라벨만 남는다.
- 저장과 재열람: 기간은 기존 `snapshot.analysis.consultation`에 저장되므로 다시 열어도 날짜가 바뀌지 않는다. 질문 문구가 요청 지문에 들어가므로 기간이 바뀐 질문은 새 요청이고, 같은 시도의 재시도는 저장 요청(타로 카드 포함)을 다시 읽는다. API 필드·DB 스키마는 그대로다.
- 신규 상담만: `resolver`가 있는 상담의 질문형 첫 장만 `ask-first-chapter-v3`를 쓴다. 저장된 기존 상담은 v2 계약·스키마·토큰 예산을 유지하고 소급 재생성하지 않는다.
- 근거 선택: 요청 시작 시점에 진행 중인 사주 월운(시작일 이전의 마지막 절입)을 `relation: 'in-effect'`로 함께 싣는다. 양력 조회 구간과 절기 월은 다르다는 설명을 붙인다. 검증기는 이 근거를 기간 밖 인용으로 거부하지 않는다. `limited` 답변은 상담 구간의 시작·끝 날짜를 다시 적는 것만 허용하고 그 밖의 날짜는 계속 거부한다. 연 해상도 근거로 월·일을 단정하는 답변 거부도 유지한다.
- 프롬프트(질문형 첫 장 계약에만): `ASK_PERIOD_GUIDE`는 주·월·연 규모별 해석, 해상도 규칙(연→주 길흉 금지, 시점→월 확대 금지, 월 근거 없는 12개월 분할 금지, 조회 창≠예측 범위, 점수·확률·행운의 날 금지, 근거 부족 시 '기간의 흐름'과 '그 기간에 실천할 조언' 구분)과 체계별 금지(자미 생년 사화≠유년사화·유월 없음, 숙요 능범기간·길흉일 없음·상대 미입력 시 관계 단정 금지, 서양 출생 차트≠트랜짓·진행/솔라리턴 없음, 베다 다샤 경계 유지·고차라 정밀도 가정 금지, 타로 속마음·미래 확정 금지, 퓨전 출처 유지·이중 계산 금지·억지 통합 금지)를 담는다. `ASK_COUNSEL_PRINCIPLES`는 질문 먼저 답하기, 근거→생활 장면→선택, 용어 설명, 불안·의존 유도 금지, 의료·투자·법률·상대 마음 단정 금지, 고양이 말투 반복 금지다. 공용 페르소나 파일은 바꾸지 않았다.
- 답변 칸: 기존 4칸에 역할을 정했다(answer 한 줄 답, reason 흐름·근거·장면·강점/주의, timing 절대 기간과 해상도 한계, action 행동 2~3개). v3 스키마에만 `review`(기간이 지난 뒤 돌아볼 질문 1개)를 required로 둔다. 저장 전 5~200자로 정규화하고, 내부 ID·HTML·매일 확인/추가 상담 유도·존재하지 않는 알림/기록 표현·단정 표현이면 거부하지 않고 제거한다. 금지 어휘 검사는 한국어 기준이다. 상대연도·내부 근거·호칭 교정은 `review`에도 적용한다.
- 분량: v3는 질문당 답변 여유를 480자에서 700자로 올렸다(v5/v6·v7·간결 경로 모두). 질문형 첫 장 최대 목표 4,209자 + 8×700자에서도 장 출력 상한 24,576토큰 아래임을 가드 테스트로 고정했다. LLM 호출 수·재시도 예산은 그대로다.
- 화면: 한국어 사이트의 질문형 입력에만 기간 칩(이번 주·다음 주·이번 달·다음 달·올해·내년)을 둔다. 칩은 질문 맨 앞의 기간 문구를 넣거나 바꿀 뿐 별도 요청 필드를 보내지 않는다. 입력 아래에 서버와 같은 해석기로 계산한 절대 기간과 '주는 월요일~일요일' 안내를 보여 주고, 기간이 둘 이상이면 함께 본다는 안내를 낸다. 결과 화면은 기간 라벨 옆에 절대 날짜를, 답변 아래에 '이 기간이 지나면 돌아볼 질문'(12개 언어 라벨)을 표시한다. 새 생성·과금·차감·환불·인증·소유권 동작은 없다.
- 미지원 그대로: 주간 일별 근거 신규 계산, 자미 유월·독립 유년사화, 숙요 능범기간·단일 상담 일숙, 서양 트랜짓·진행법·솔라리턴, 베다 고차라. 이 해상도는 `limited`와 실천 조언으로 답한다. 실제 LLM 문장 품질은 mock으로 확인하지 않았으며 별도 승인된 표본이 필요하다.
