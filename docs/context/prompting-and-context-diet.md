# 요청 방법 · 컨텍스트 다이어트

> [CLAUDE.md](../../CLAUDE.md) §🟢 실행 계약의 **사용자 쪽 절반**이다.
> 계약은 에이전트가 지킬 것을, 이 문서는 사용자가 줄 것을 정한다. 둘 중 하나만 있으면 효과가 안 난다.
> 최초 작성 2026-09-06.

## 왜 이 문서가 있나 — 진단 (2026-09-06 실측)

증상은 "토큰은 많이 쓰는데 코드가 안 고쳐진다"였고, 원인은 셋으로 갈렸다.

| 증상 | 원인 (설정 축) |
|---|---|
| 읽기·탐색만 하다 diff 0 으로 끝남 | 라우팅 표가 **모든 축**에 사전 문서 읽기를 강제(11개 문서 161 KB) + 요청이 기능명만 담아 탐색이 길어짐 |
| 확인 질문으로 멈춤 | 멈춤 유발 장치 5겹: 원칙 1·7·16 · 절대 규칙 1·2·3 승인 지점 · `guard-costly-commands` fail-closed `ask` |
| 극소량만 고침 | 최소 변경 편향 3중: `oh-my-fable` "인접 결함 보고만" + 원칙 2 + 원칙 14 |

**근인은 우선순위 붕괴다.** 🔴 마커가 수십 개면 전부 최우선이고, 전부 최우선이면 실행이 진다.
해법은 규칙을 지우는 것이 아니라 **위험 등급(GREEN/RED)을 도입해 저위험 축에서만 방어를 끄는 것**이다. 그 등급 정의가 CLAUDE.md 실행 계약이다.

기준선 수치: **편집 1건당 툴 왕복 13.3회**(2026-09-06 실측, 12세션). GREEN 축 목표는 **3회 이하**.

## 1. 참조 방식 — 여기서 가장 크게 절약된다

같은 요청이라도 대상을 어떻게 지목하느냐로 첫 Edit 까지의 왕복 수가 갈린다.

| 지목 방식 | 첫 Edit 까지 드는 것 | 언제 쓰나 |
|---|---|---|
| 🥇 `@경로` + 함수/셀렉터 이름 | 탐색 0 — 바로 Read 1회 후 Edit | **기본값으로 삼는다** |
| 🥈 `@경로` 만 | Read 1~2회 | 파일은 아는데 지점을 모를 때 |
| 🥉 기능·화면 이름 | Grep·Glob 3~8회 (변동 큼) | 파일을 모를 때 — 이때만 |
| ❌ 증상만 ("버튼이 안 눌려") | 탐색이 예산의 대부분 | 원인 조사가 **목적**일 때만 |

**경로를 모를 때의 정석**: 요청에 "탐색 필요"라고 적는다 → 에이전트가 `code-locator` 서브에이전트로 위치만 받아오고(본세션 컨텍스트를 안 태운다), 판정과 수정은 본세션에서 한다. 🔴 돌아온 목록은 재료지 결론이 아니다(원칙 13).

VS Code 확장에서는 파일을 열어 둔 채 코드를 선택하면 `ide_selection` 으로 함께 전달된다 — **경로를 타이핑하는 것과 같은 효과이므로 가장 싸다.**

## 2. 작업 단위 절단

**한 요청 = 한 파일 = 한 동작 변경.** 이 셋 중 하나라도 깨지면 RED 로 승격되어 워크트리·선보고·문서 읽기가 전부 살아난다.

절단 기준:

- **파일이 2개 이상이면 쪼갠다.** 쪼갤 수 없는 것(공유 모듈 수정 등)은 애초에 RED 이므로 쪼개려 하지 말고 그대로 RED 로 보낸다.
- **"그리고"가 들어가면 쪼갠다.** "버튼 색 바꾸고 문구도 고쳐줘"는 두 요청이다.
- **한 세션 = 한 작업.** 끝나면 이어서 다른 축을 시작하지 말고 `/clear`. 세션을 늘리는 것이 이 레포에서 가장 비싼 선택이다(원칙 12).
- 조사와 수정을 한 요청에 섞지 않는다. 조사는 결론이 산출물이고, 수정은 diff 가 산출물이다. 섞으면 조사에서 예산이 끝난다.

## 3. 하지 말 것

- 🔴 **스크린샷 직접 첨부** — 전체 페이지 1장이 약 29,000 토큰이고, 한 번 들어오면 **그 세션의 모든 후속 요청에서 다시 지불된다.** 파일로 저장해 경로만 주면 `visual-checker` 가 텍스트 결론만 돌려준다. 훅 `guard-image-read.mjs` 가 비싼 Read 를 잡아 준다.
- **긴 로그·전체 파일 붙여넣기** — 경로와 줄 범위만 준다. 에이전트가 `Read` 의 `offset`/`limit` 으로 필요한 만큼만 가져온다.
- **여러 축 묶어 던지기** — 결제 + UI + SEO 를 한 요청에 담으면 전부 RED 로 판정된다.
- **세션 연장** — "조금만 더"가 컨텍스트 초과의 정석 경로다. 인수인계는 `docs/handoff/<주제 이름>.md` 에 쓰고 `/clear` 한다.

## 4. 코드 수정 요청 템플릿 (복붙용)

슬래시 커맨드 [`/fix`](../../.claude/commands/fix.md) 가 같은 내용을 자동으로 발동시킨다. 손으로 붙여넣을 때는 아래를 쓴다.

```
[대상] <@파일경로 + 함수/셀렉터 이름 — 모르면 "탐색 필요">
[현재] <지금 이렇게 동작한다 / 이렇게 보인다>
[변경] <이렇게 바꾼다. 대체인지 추가인지 명시>
[범위] <이 파일만 / 여기 포함 N개 파일까지>
[등급] GREEN — 질문하지 말고 첫 응답에서 바로 수정할 것
```

작성 규칙 셋:

1. **`[변경]` 에 "대체"라고 쓰면 갈아 끼운다.** 안 쓰면 보수적으로 덧붙일 수 있다.
2. **`[범위]` 를 비우지 않는다.** 범위가 없으면 등급 판정이 RED 로 떨어진다(fail-closed).
3. **`[등급] GREEN` 은 선언이지 보증이 아니다.** RED 목록에 걸리면 에이전트가 그 사실 한 줄을 알리고 RED 로 처리한다 — 그게 정상 동작이다.

RED 축(결제·인증·배포·삭제·공유 모듈)은 템플릿을 쓰지 말고 **평소대로 맥락을 충분히 적어 보낸다.** 거기서는 방어 절차가 값을 한다.

다른 프로젝트(`.cursorrules`·`.clinerules` 등)에 그대로 복사할 프로젝트 비의존 버전: [execution-contract-portable.md](execution-contract-portable.md)
