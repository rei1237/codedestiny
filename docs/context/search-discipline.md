# 검색·수정 원칙과 반복 작업 금지 (근거)

> 이 파일은 필요할 때만 읽는 참조 문서입니다. 항상 로드되는 규약 요약은 루트 [CLAUDE.md](../../CLAUDE.md)에 있습니다.

## 검색 & 수정 원칙 (토큰 절약)

> 🔴 **읽기 제한과 수정 제한은 다르다.** 아래는 *목적 없는 훑기*를 막는 규칙이지 *확인*을 막는 규칙이 아니다. 회귀 경로 추적(원칙 7)·삭제 전 3면 grep(원칙 9)·부정 단언의 근거 확보(원칙 8)에 필요한 읽기는 **사용자 확인 없이 한다.** 코딩 원칙이 이 섹션보다 우선한다.

- 사용자가 "전체 검색"을 명시하지 않는 한 목적 없이 프로젝트 전체를 훑지 않는다. 요청 키워드(기능명/함수명/에러 문구/라우트명)를 먼저 추출해 Grep/Glob으로 좁혀서 필요한 위치부터 읽는다.
- 검색 순서: 정확 키워드 → 동의어/별칭 → 호출 경로. **파일 수로 읽기를 끊지 않는다** — 회귀 경로가 20개 파일에 걸치면 20개를 본다. 다만 그 범위가 요청보다 훨씬 넓어져 작업 자체를 다시 정의해야 할 것 같으면 그때 사용자에게 알린다.
- 동일 목적의 검색/읽기 결과는 재사용하고, 코드가 바뀌지 않았다면 다시 조회하지 않는다.
- **읽는 범위와 고치는 범위는 별개다.** 요청 범위 밖 파일은 근거 확인을 위해 읽되 **수정하지 않는다.** 관련 없는 리팩토링/정리를 끼워 넣지 않는다.
- 전체 빌드/전체 테스트/레포 전체 스캔은 사용자가 요청했거나, 변경 영향이 명백히 넓거나, **심볼·파일 삭제가 포함된 변경**일 때 수행한다(원칙 9).
- 최종 보고 시 어떤 키워드로 어떤 파일을 좁혀 찾았는지 한 줄로 남긴다.

### public/ 미러 검색 제외 (2026-08-16 추가)

리포 루트 `.ignore` 가 **`sync:public` 이 만든 `public/` 사본 169개를 Grep/Glob 에서 뺀다.** ripgrep 은 `.gitignore`·`.ignore`·`.rgignore` 를 모두 읽고 git 은 `.ignore` 를 읽지 않으므로, 추적·빌드·배포·CI 는 한 줄도 바뀌지 않고 **검색 결과만** 정본으로 좁혀진다. 목록은 손으로 쓰지 않는다 — `sync:public` 이 매 실행마다 다시 계산한다(`scripts/sync-legacy-static-to-public.mjs` 의 `syncSearchIgnoreList()`).

**왜** (2026-08-16 실측): `public/` 은 추적 코드파일의 10%(266/2,536)인데 **실제 심볼 검색 히트의 19~58%**(중앙값 ≈26%)를 차지했다. 미러된 것이 정확히 자주 찾는 파일(`js/core/*`·루트 엔진·정적 셸)이기 때문이다. 실측 예: `openPhysiognomyApp` 28파일 중 13(46%), `saju-core` 12 중 7(58%), `destiny-profile` 131 중 29(22%). 셸 사본 한 장은 2.68 MB라 한 번 열면 컨텍스트가 통째로 날아간다.

**탈출구 — 셋 다 살아 있다. 미러가 사라진 게 아니라 기본 결과에서 빠진 것뿐이다.**

| 하려는 것 | 쓰는 것 |
|---|---|
| 미러까지 포함한 전수 검색 | `git grep <패턴>` (git 은 `.ignore` 를 안 본다) 또는 `rg -u <패턴>` |
| 특정 미러 파일 읽기 | 경로를 직접 준 Read — `.ignore` 는 Read 를 막지 않는다 |
| 루트↔미러 드리프트 조사 | 내용이 **어긋난** 사본은 애초에 제외되지 않는다(아래) |

🔴 **위 13번 줄("심볼·파일 삭제가 포함된 변경은 전체 스캔")과의 관계** — 삭제 전 3면 grep(원칙 9)에는 이 제외를 **적용하지 않는다. 반드시 `git grep` 으로 한다.** `verify:payment-choice-parity` 가 `public/js/destiny-profile.js` 를 파일로 열어 단언하듯 미러가 참조를 갖고 있는데 그것을 못 보면, "임포터 0" 을 죽었다는 증거로 오독해 삭제 사고가 난다. `.claude/agents/deletion-auditor.md`·`regression-scout.md`·`paid-gate-auditor.md` 에 같은 지시가 박혀 있다.

**미러를 경로로 직접 읽는 것은 규약 위반이 아니라 설계다.** `verify:*` 50개 이상과 `__tests__/` 4개가 셸 6벌·`public/js/destiny-profile.js` 등을 의도적으로 연다(루트↔public 동일성 단언). `.github/workflows/paid-flow-gates.yml` 도 `public/js/destiny-profile.js` 를 트리거 경로에 갖고 있다. 이들은 경로 지정 읽기라 `.ignore` 의 영향을 받지 않는다.

**제외 판정은 선언이 아니라 실제 내용으로 한다** — `public/` 은 사본과 원본이 **섞여** 있고(1,224개 중 실제 사본은 169개, 나머지 86%가 원본), `staticTargets` 배열을 믿으면 원본을 삼킨다:
- `staticTargets` 는 `icons`·`sudda` 를 복사 대상이라 선언하지만 **루트에 원본 디렉터리가 없어** 복사 루프에서 skip 된다 → `public/icons/`(20) · `public/sudda/`(53) 은 원본이다.
- `cpSync` 는 **삭제를 하지 않는다** → 루트에서 지워진 파일이 `public/` 에 고아로 남는다. `public/js/` 121개 중 **18개**가 루트에 없는 고아이고, 다른 사본이 없으므로 빼면 검색에서 영영 사라진다.
- 그래서 제외 대상은 ①루트에 **바이트 동일**한 원본이 있는 파일 ②루트 `index.html` 에서 파생한 셸 6벌 ③`public/manifest.json` 에서 파생한 로케일 매니페스트 뿐이다. **내용이 어긋난 사본은 일부러 남긴다** — 드리프트야말로 사람이 찾아야 할 것이다.

### 반복 작업 금지 (2026-08-11 추가)

아래는 "이미 얻은 정보를 다시 사는" 행위를 막는 규칙이다. 사용자가 명시적으로 요청한 경우에만 예외.

- **`git diff` 전체를 수정할 때마다 다시 읽지 않는다.** 방금 내가 만든 변경은 이미 알고 있다. 확인이 필요하면 해당 파일·해당 hunk만 좁혀서 본다(`git diff -- <path>`).
- **불필요한 전체 저장소 분석 금지.** 위 검색 원칙과 동일 — 요청 범위 밖으로 스캔을 넓히지 않는다.
- **테스트/verify 실패 시 전체를 다시 돌리지 않는다.** 실패한 그 스크립트(가능하면 그 케이스)만 재실행하고, 전체 재실행은 수정이 여러 스크립트에 걸칠 때 마지막에 한 번만.
  - 🔴 **예외 — 심볼·파일 삭제가 포함된 변경은 CI 가 부르는 것과 같은 전체 명령을 한 번 돌린다.** 부분 실행(27 스위트)으로 통과를 확인하고 넘어갔다가 전체(140 스위트)에서 깨져 PR #543 이 CI 에서 두 번 실패했다. 절약보다 손해가 크다.
- **이미 통과한 check 는 재실행하지 않는다.** 그 check 가 보는 파일이 그 뒤로 바뀌지 않았다면 통과 상태를 그대로 신뢰한다.
- **PR 생성 후 요청받지 않은 설명·자체 리뷰를 덧붙이지 않는다.** 링크와 한 줄 요약으로 끝낸다.
- **preview 를 습관적으로 돌리지 않는다.** 배포 전 프리뷰 단계는 없다(2026-08-11) — `deploy:preview` 는 흐름 밖의 로컬 도구이고 실행하면 Cloudflare 에 아티팩트가 남는다. 점검은 업로드 없는 `deploy:check`.
- **프로덕션 배포 로그 전체를 읽어 분석하지 않는다.** 성공/실패와 실패 시 해당 에러 구간만 확인한다.
