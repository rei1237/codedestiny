## 2026-10-16 운영 연결 승인 (아래 mock 단계 기록보다 우선)

사용자가 실제 결제·메일 연결, 운영 승격, 정상 작동 확인 후 Threads 홍보 게시·고정을 요청했다. 답변 작성은 외부 AI를 보조로 쓰는 수동 입력·검수로 유지한다. 자동 AI 호출은 구현하지 않는다.

- 보통 결제 후 24시간, 접수가 몰리면 3일 이내 답변. 하루 질문 30개, 질문당 10,000원. 결제 준비일(KST)에 수량을 원자적으로 예약하며 지연 승인 가능성이 남은 자리는 자동 재판매하지 않는다.
- 답변 발송 전 작성·검수 여부에 관계없이 취소·전액 환불 요청을 허용한다. 요청은 상담 발송을 먼저 잠그고 운영자에게 알린다. 실제 환불은 기존 관리자 결제 주문 화면에서 PG 상태 확인 후 처리한다. 발송 후 및 계약 불일치는 법정 권리를 제한하지 않고 공식 고객센터에서 접수한다.
- 최초 답변 발송 후 7일간 본문을 재열람·재발송하고 이후 본문·회신 이메일·출생정보·결제창 고객정보 복제본을 제거한다. 취소·환불 확정 후에도 7일 내 상담 본문을 제거한다. 작성만 한 미결제 초안은 7일 후 제거한다. 거래 기록은 별도로 남긴다.
- 회사 공식 메일은 BUSINESS_IDENTITY.email을 사용한다. 운영자 접수·취소 메일에는 질문·출생정보를 넣지 않고 관리자 링크를 안내한다.
- 기존 결제 코어의 준비·확정·웹훅을 사용한다. 공개 결제 API에서 상담 준비 경로를 우회하지 못하고, 저장한 결제창 정보와 주문 ID를 재시도에서도 재사용한다. 모바일 복귀 신호는 서버 확정 요청의 계기이며 결제 완료 증명이 아니다.
- 기존 10분 크론에 별도 outbox를 연결한다. 확실한 실패만 최대 5회 자동 재시도하고 불명확한 전송은 운영자 확인 대기다. 결제 상태·취소 요청·질문별 검수 버전을 발송 시 재검사한다.
- 앱 내 Google Play 구매는 지원하지 않는다. 웹 카드 결제만 열며 이용권·월정석 정책과 기존 상품은 유지한다.
- 판매 활성화는 가격 정본과 메일·PG 설정 확인을 모두 통과해야 한다. 개발 자동 검사는 외부 요청을 차단한 mock에서 수행한다.

법령 확인: [전자상거래법 제17조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1022341977), [거래기록 보존 안내](https://easylaw.go.kr/CSP/CnpClsMain.laf?ccfNo=2&cciNo=3&cnpClsNo=2&csmSeq=2985&popMenu=ov). 고객에게 법정 권리보다 불리한 일괄 환불 불가 문구를 쓰지 않는다.

운영 검증: 회사 공식 주소로 실제 테스트 메일 1건을 보내 Resend `delivered`를 확인했다. 실결제·운영 배포 검증과 홍보 게시 완료 여부는 최종 전달 증거로 별도 기록한다. 아래는 최초 mock 구현 당시 이력이다.

## 승인 범위

질문별 독립 입력, 질문당 10,000원 합산 단건 결제, 자유 질문, 네오가 외부 AI로 작성한 답변의 수동 입력·검수, 통합 이메일. 자동 AI 호출 없음.

추가 승인: 메인 화면에 진입점, 기존 인간형 네오 이미지, 블루 문 콘셉트. 기존 neo-strategy-portrait.webp를 재사용하며 파란 표면·은빛 글자·Framer Motion의 절제한 등장 모션을 사용한다. reduced-motion에서는 이동을 제거한다. 홈 소스는 템플릿·전용 렌더러·home-funnel.css이며 sync:public으로 생성한다.

## 판매 경계

가격 정본의 neo-email-consultation은 saleEnabled:false, direct_only, per_use다. 고객·관리자 런타임 API는 서비스 어댑터를 주입하지 않아 503으로 닫힌다. URL, 헤더, 환경변수로 mock을 켤 수 없다. 실결제·메일·운영 DB 연결·운영 승격을 하지 않는다.

## 인터페이스

- 고객 /api/neo-consultations: POST 초안, GET 본인 목록, /:id GET 상세, POST /update, /quote, /prepare, /correction.
- 관리자 /api/admin/neo-consultations: 기존 관리자 인증. 목록·상세, POST /answer, /review, /correction, /send, /deliver, /resolve-delivery.
- version은 CAS 조건. 준비 중에는 질문 수정 금지. 견적 ID가 멱등키이며 수량·단가는 저장된 서버 견적에서 계산한다.
- 결제 코어의 createOrder 스냅샷에 상담 견적 신원을 기록한다. 서버 PG 검증 후 지급 경로에서 상담 접수/outbox만 기록한다. 발송 I/O를 결제에 결합하지 않는다.
- 상담 문서는 _id 기본 유니크와 version CAS를 사용한다. 기존 컬렉션 이관·운영 인덱스 생성 없음.
- 발송 중·불명확한 메일은 자동 재시도 금지. 관리자가 제공자 기록을 확인해 전달 완료 또는 미전달로 해소한다. 확실한 실패만 재시도하며 같은 idempotency key를 유지한다.
- 미발송 답변 초안은 고객 응답에서 제외하고, 완료 답변은 deliveries의 검수 스냅샷으로 재열람한다.

## 검증·출시 전 확인

필수 CI node suite가 __tests__/ui/neo-consultation.test.mjs를 자동 실행한다. UI mock 검증기는 scripts/verify-neo-consultation-ui.mjs이며 고객·관리자 실제 React 컴포넌트에 인증·API mock만 주입한다.

출시 전 답변 기한, 환불·취소, 개인정보 보존, 일일 접수 한도를 확정해야 한다. 런타임 어댑터 연결·지속 outbox 실행·실메일 제공자 상태 대조는 출시 작업이다. 이번 산출물은 판매 차단 mock 구현이며 운영 준비 완료를 의미하지 않는다.
