## 진단과 적용

기존 fortune-master와 consultation-quality에는 가상 생활 장면·강점·부담·단정 금지가 있었다. 체계별로 어떤 계산 근거를 공감 장면에 연결할지 선택하는 공통 경로는 없었다. 새 `prompts/domain/recognition.ts`는 **선택된 기존 사실**의 ID·label·값 존재 여부를 읽어 해석 후보를 구성한다. 별도 계산기·LLM 호출·새 사용자 결과 필드·추가 재시도는 없다.

## 답변 계약

첫 summary와 배정된 questionAnswers.answer부터 사용자가 무엇을 지키려 하는지, 어떤 조건 사이에서 버거울 수 있는지를 짚으며 직접 답한다. 공감만 하고 답을 뒤로 미루지 않는다. 그 뒤 근거의 쉬운 뜻 → 관련 생활 조건 → 그때 들 수 있는 감정·노력 → 작은 행동을 기존 해석·생활 장면 문단에 연결한다. 모든 사람에게 고통이 있다고 전제하지 않는다. 사용자가 밝힌 경험과 조건부 예시를 구분하며 근거 없는 과거를 “수 있어요”로 포장하지 않는다. 맞지 않는 장면은 정정할 수 있게 한다.

최초 답변은 `StructuredChapterProvider`의 `recognition`, 후속은 `questionConversation`의 동일한 계약을 신뢰된 시스템 프롬프트로 사용한다. 후속 사용자 입력과 지침을 분리한다. 후속·상세 장에서는 같은 공감 문장과 전체 성향 소개를 반복하지 않는다. 영냥이·연이·네오는 표현만 다르고 근거·판단·불확실성·행동의 의미는 같다. 모든 가격 등급에 제공한다. 영냥이의 “모든 소절을 성향·약점 판단으로 시작” 지침은 제거하고, 세 persona 모두 첫 답변에서 사용자가 지키려는 가치와 어려운 조건을 알아주도록 맞춘다. 반말/존댓말·편지형/직설형 표현은 유지한다. 확인·정정·지원에는 해석을 억지로 추가하지 않는다. 기존 출력 예산과 저장·횟수 계약을 유지한다.

## 사주 강약에 따른 현실 조언 (2026-10-07)

- 기존 엔진의 최종 strengthHeuristic.isStrong을 사용한다. 점수·오행 개수로 재판정하지 않고 생활 이력 확인에 따른 반전도 그대로 따른다.
- 현재 선택된 근거에 본인의 강약·종격·용신이 모두 있고 일반격으로 확인된 경우에만 행동 조언 후보를 붙인다. 종격 후보·확정 종격, 근거 누락, 상대 명식에는 일반 신강·신약 조언을 붙이지 않는다.
- 신약: 자기보호의 필요를 알아주고 감당 가능한 작은 도움·협력을 제안한다. 범위·시간·거절할 선을 함께 정하며 이기적이라는 낙인, 자기희생, 도움을 통한 운의 보장은 금지한다.
- 신강: 이미 들인 노력과 앞으로 낼 비용을 구분하고 시간·돈·역할·보상·상대 조건·중단 기준을 비교한다. 주변의 통상적 조건은 참고 기준이며 무조건 추종하거나 손실을 전혀 감수하지 말라는 지시는 하지 않는다.
- 최초·상세·후속 답변과 세 persona에 같은 규칙을 전달한다. 실제 질문·용신·월령·통근·조후와 맞는 조언만 사용하며 성격·과거 사건을 새 사실로 만들지 않는다.
- 행동 테스트는 강약 양쪽, 생활 이력에 따른 반전, 종격 후보/확정/기각, 누락·잘못된 값, 상대 근거, 다른 체계, 세 placement를 검사한다. 실제 LLM 문장 품질은 별도 미검증이다.
