# 사주 시간 계약 수정 — 2026-09-30

## 재현과 원인

신고 입력은 양력 1988-01-07 23:26, 서울 126.978E / Asia/Seoul이다. 성별은 회귀 데이터의 선택값일 뿐 고객 프로필 변경 대상이 아니다.
수정 전에 실행한 회귀 하네스에서 정적 셸 壬戌/辛亥, 영냥이 辛酉/戊子를 각각 재현했다.

- `js/saju-engine.js` calculate/computeProfileForModal: 원시각으로 `_cdCivilDayPillar`에서 23시 다음날을 먼저 선택하고, 보정 시각으로 시지를 계산했다. 임술일간에서 신해시가 파생됐다.
- `worker/yeongnyangi/fortune/saju/runtime.ts`: 혼합 계산한 pillars를 life-book 계산 옵션으로 전달했지만 `calculateLifeBookAiSaju`는 해당 옵션을 소비하지 않았다. 원시각 keep-day 재계산으로 신유/무자가 됐다.
- 정적 저장 프로필은 음력에서 바꾼 양력 연월일과 원래 lunar 표시를 함께 저장할 수 있었다. 새 저장은 입력 연월일/달력/원시각을 보존한다. 구형 저장값이 이미 잘못 변환됐는지는 자동으로 추측하지 않는다.

## 구현된 시간 계약

`lib/korean-calendar/natal.js`가 원국의 공통 진입점이다. 엔진 `saju-natal-v2`, 정책 `local-mean-minute-shift23-v1`.

1. 달력 변환을 한 번 수행한다. 출생지 IANA 시간대로 실제 순간과 당시 오프셋을 구한다. 중복되거나 존재하지 않는 DST 시각은 거부한다.
2. 표준 자오선=당시 비서머타임 오프셋(분)/4. 경도 차×4에서 DST 분을 빼고 Math.round로 가장 가까운 분으로 반올림한다. 균시차는 포함하지 않는다.
3. 보정은 연월일과 시분을 함께 이동한다. 보정 후 23:00~23:59는 다음 민용일 일주, 00:00~00:59는 당일 일주다. 시주는 그 일간으로 계산한다.
4. 연주/월주/절입 및 대운은 실제 순간을 절기 데이터의 고정 KST 축으로 환산해 비교한다. 보정 시계를 실제 순간으로 재해석하지 않는다.
5. 시간 미상은 시주와 실제 순간/보정 시각을 null로 보존한다. 절입의 내부 정오 가정은 별도 표시한다.
6. 출생지 미입력은 서울 기본값과 assumed=true를 기록한다. 접속 위치/언어를 사용하지 않는다.

서울 예: 경도 차 보정 -32.088분 → -32분, DST 0, 균시차 0. 원본 23:26 / 보정 22:54. 년·월·일·시=丁卯 癸丑 辛酉 己亥. 일진 기준 상수/전체 간지 인덱스는 이동하지 않았다. 특정 날짜 예외/문자열 치환은 없다.

**포스텔러에 대한 한계:** 제공된 사례와 맞지만 포스텔러의 전체 야자시 설정, 모든 지역 반올림 정책, 모든 시대별 설정을 확인한 것은 아니다. 이 문서는 서비스 자체의 명시적 정책이다. ICU의 역사적 DST 이름 판별은 한국/뉴욕/시드니 표본을 검증했으며 모든 세계 시간대의 완전성을 주장하지 않는다.

## 연결 범위

- 정적 연이/네오 calculate, 저장 프로필 모달 복원, 궁합 상대 원국, AI 입력 snapshot.
- 영냥이 saju/runtime 및 동일 결과의 십성/오행/지장간/신살/대운, 단독/복합 상담 facts와 프롬프트.
- 공통 LifeBook, 수호신 어댑터, birth snapshot, 신년, 연애비책/마스터 연애 경로.
- 영냥이 사주 구매 fingerprint 엔진/정책 버전. 무료 하루 최초 입력 고정 정책은 유지하고 다른 입력 재사용은 409로 거부한다. 구버전 무료 결과는 새 버전 조회에서 제외한다.
- 사주 AI 요청은 서버에서 메타데이터 원본으로 네 기둥을 재검산한다. 기존 완료 결제 결과는 원본 그대로 읽고 정정 필요 표식을 제공한다. 기존 접근 토큰 해시는 유지한다.
- 명시적 “당신의 일주/시주” 모순을 검사한다. 모든 자연어 주장/간접 표현을 검출하는 완전한 의미 검증기는 아니다.

## 기존 유료 결과 정정

`worker/lib/saju-correction.js`와 `worker/yeongnyangi/saju-correction.js`:
- 소유자 제한 GET `/api/yeongnyangi/requests/:id/correction`는 원본 기반 비교만 한다. POST는 동일 엔진/정책/주문 키로 정정 작업을 한 번 등록한다.
- 구매 원본 snapshot/chapters/payment는 보존하고 generationCheckpoint 아래 정정 버전을 연결한다. 변경된 기둥에 의존하는 해석은 requires-regeneration이다.
- 스냅샷 원본 입력이 없으면 구매 당시 updatedAt과 일치하는 소유 프로필만 사용한다. 원본을 확인 못 하면 needs-original-birth다.
- 생성 실행기는 주입한 provider만 사용하며 기본 작업/호출 예산 0, 최대20, 시도1회다. 저장 후 재조회하고 결제 증빙을 재확인한다. 불확실한 실패는 held로 두어 자동 중복 생성하지 않는다.
- mock 검증만 수행했다. **운영 영향 건수 미조사, 실제 정정 생성 0건.** 자동 실행 provider/운영자 처리 화면/held 검토 후 재시도 승인 경로, 정적 PaidExecutionRecord 등 영냥이 외 주문 연결, 고객 보관함 정정 표시까지는 아직 완료되지 않았다. 이 상태에서 복구 완료로 발표하거나 운영 승격하지 않는다.
