# 화면에서 콘텐츠 편집

관리자 `/admin/cms/`의 **화면 편집 모드**에서 사용한다. 기존 관리자 인증과 CMS 발행·버전 기록을 사용한다.

## 사용 순서

1. 왼쪽에서 콘텐츠 종류와 항목을 선택한다.
2. 미리보기에서 문구나 이미지를 누른다. 동일 문구가 여러 원본에 있으면 수정할 원본을 선택한다.
3. 문구를 수정하거나 이미지를 업로드하고 **초안에 적용**을 누른다.
4. **브라우저에 초안 저장**으로 보관한다. 이 초안은 다른 컴퓨터와 동기화되지 않으며 브라우저 데이터를 삭제하면 없어진다.
5. 검토 후 **발행**한다. build 채널은 **배포 검증** → GitHub Actions 성공 확인 → **운영에 반영** 순서로 반영한다.

`운영에 반영`은 발행된 모든 콘텐츠와 현재 main 코드를 배포한다. 하나의 항목만 배포하는 버튼이 아니다. 확인창에서 운영 반영을 명시적으로 선택해야 한다. 요청 접수 메시지는 배포 완료를 뜻하지 않는다.

화면 편집 모드에서는 서버 자동저장을 하지 않는다. 기존 CMS 모델은 draft와 published가 같은 행을 사용하므로 draft로 덮어쓰면 발행본이 다음 빌드에서 빠질 수 있기 때문이다. 기존 항목 편집 모드의 저장·검수 동작은 그대로다.

## 연결 범위

- 띠·별자리 성향 해설: 24종의 성향·강점·주의점·생활 조언·읽는 법·FAQ 216개 문장. 페이지 본문과 해당 FAQ 구조화 데이터가 같은 원본을 사용한다. 이름·날짜 구간·오행·지배성·궁합 관계는 편집 대상에서 제외한다.
- 날짜별 운세 공통 해설: 띠·별자리에서 날짜에 따라 선택되는 연애·재물·건강·일·조언·별자리 총운·흐름 문장 56개. 한국어 본문과 공개 결과 JSON에 함께 적용된다. 날짜·점수·선택 순서와 다른 언어는 유지한다. 특정 날짜만 고치는 것이 아니라 해당 원본을 선택하는 모든 날짜에 반영된다.
- 영냥이 모자: 6개 기숙사별 첫인상·성향·관계·일·비밀 쪽지·선물·선택 대사 66개. 배정 계산과 분기는 유지한다.
- **전체 문장 보기**: 현재 화면에서 나오지 않은 결과 문장도 검색해 클릭하고 편집한다. 날짜별 운세와 영냥이 모자는 이 보기로 시작하며 **실제 페이지 보기**로 전환할 수 있다. 기존 정적 해설 표에도 같은 보기를 제공한다.

- 서비스 상세페이지: `feature-visual-details.generated.json`의 verified 항목 전체. 소개, 목차, 해설, 질문, 이미지. 가격·이용 조건·링크·상품 키·면책 안내는 제외한다.
- 라이트 노벨: 화별 제목·부제·대사. `/stories/<화>/` 텍스트 리더로 확인한다. 발행본은 같은 정본에서 텍스트 리더와 삽화 플레이어를 함께 생성한다. 화자·분기·대사 개수와 순서는 바꾸지 않는다.
- 서비스 소개, FAQ, 찻집·전략실 문구: 기존 CMS 연결 항목.
- 정적 운세: 기존 CMS의 사주·동물·수호신·숙요·자미두수·베다 해설 표. 미리보기 주소에서 실제 결과를 연 다음 **문구 선택**으로 바꾼다. 같은 원본을 사용하는 모든 결과에 적용된다.

전체 서비스의 모든 텍스트를 자동으로 편집하는 기능은 아니다. 코드에 직접 들어 있는 미연결 문구, 계산값, 사용자 입력, 개인별 저장 결과, AI 생성 결과는 이 편집기로 바꾸지 않는다. 일치하지 않거나 분할된 문장은 아래 원본 항목 편집기를 이용한다. 현재 연결 위치 수를 화면에 표시한다.

이미지에 포함된 글자는 문자 편집 대상이 아니다. 기존 업로드 기능으로 글자 없는 이미지를 올리거나 허용된 이미지 주소로 교체한다. 업로드는 파일을 즉시 저장하지만 페이지 변경은 발행·배포 후 반영된다.

## 배포 연결과 최초 설치

공개 `/api/cms/build-bundle`은 build 채널의 현재 발행본만 반환한다. 초안과 runtime AI 프롬프트는 반환하지 않는다. 관리자 정보나 리비전도 포함하지 않는다.

릴리스 작업은 발행본을 읽어 CMS JSON, 라이트 노벨, 상세페이지를 순서대로 생성한다. 조회 실패나 잘못된 스냅샷은 릴리스를 중단한다. 로컬 개발과 일반 CI는 운영 CMS를 호출하지 않는다.

새 API가 없는 기존 운영 Worker에서 이 변경을 처음 설치할 때는 `cloudflare-pages-deploy.yml`의 `bootstrap_cms=true`를 명시적으로 선택해야 한다. 이는 최초 API 설치 전용이며 기존 발행 콘텐츠가 반영되어 있는 운영에서는 사용하지 않는다. 이후 관리자 요청은 이 옵션을 보내지 않으며 발행본 조회가 필수다. 스테이징 자동 빌드는 코드 기본값으로 검사한다. 발행 콘텐츠 검증은 관리자의 **배포 검증**으로 요청한다.

운영 배포는 개발 검증에 포함되지 않는다. 최초 설치 승인과 실제 반영 확인이 별도로 필요하다.

- `node --test __tests__/ui/cms-visual-editor.test.mjs`
- `node --test __tests__/ui/cms-static-results.test.mjs`
- `node scripts/test-cms-static-preview.mjs` — 실제 편집 컴포넌트·관리자 스타일, 로컬 대역만 사용하는 PC/모바일 검사

- mock 개발 서버에서 `node scripts/test-cms-visual-editor.mjs`
- `npm run check:fast`

브라우저 검사는 외부 요청을 차단하고 CMS 저장 요청을 대역한다. 실결제·실 LLM·운영 DB 쓰기를 수행하지 않는다.
