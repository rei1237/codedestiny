# 꿀꿀운세 브랜드 검색 운영·재측정

기준일 2026-10-05. 권장안 승인 후 구현. 운영 반영일 D는 아직 미정이며, 코드 작성일을 D로 사용하지 않는다. 목표: 정확히 `꿀꿀운세`를 검색했을 때 꿀꿀운세 홈과 영냥이 입구가 각각 첫 페이지에 노출되는지 확인한다. 검색엔진의 결과 선택을 코드로 보장할 수는 없다.

## 사용자 계정 작업

- 네이버 서치어드바이저: 루트 도메인의 등록·소유확인 유지 여부, robots 검사, 모바일 수집 결과를 확인한다. `/sitemap-index.xml`을 제출한다. 기존 aggregate `/sitemap.xml`도 유효하므로 기존 제출을 급히 삭제할 필요는 없다. RSS는 기존 피드의 실제 업데이트를 확인한 뒤 기존 제출을 유지한다.
- 아래 순서대로 웹페이지 수집 요청을 한다. 계정 화면의 당일 한도를 우선하고 초과분은 다음 날 이어간다. 중복 요청을 반복하지 않는다.
- Google Search Console: 도메인 속성 범위, 두 실제 입구의 사용자/Google 선택 canonical을 확인하고 새 sitemap index를 제출한다. 두 입구·기록·보강 글을 우선 색인 요청한다.
- Bing Webmaster Tools: 기존 등록을 확인하고 필요하면 GSC에서 가져온다. IndexNow는 이미 배포 파이프라인에 있으므로 중복 수동 자동화를 만들지 않는다.
- Cloudflare: verified bot 분류와 실제 Yeti·Googlebot·Bingbot·AI 검색 봇 방문을 조회한다. Bot Fight Mode, WAF Custom/Managed Rules, Browser Integrity Check, rate limiting, managed robots의 적용 결과를 대표 URL별로 확인한다. 단순 UA 위장 요청 200은 실제 봇 통과의 증명이 아니다. 전역 보안 해제 대신 실제 오탐 요청 ID로 범위를 좁힌다.
- 네이버 블로그 neosaju/goodbyejieun: 프로필과 소개에 `꿀꿀운세 코드데스티니`를 일관되게 쓰고 실제 홈과 공개 기록 URL을 연결한다. 공식 YouTube·Threads·Instagram·X 계정 소유 관계를 최종 확인한다. 프로필 자동 수정·글 자동 발행은 하지 않았다.

## 블로그와 공식 원문 역할

주 1회 분석·사례 글을 쓰고 관련 공식 원문 1~2개만 자연스럽게 연결한다. 1주: 꿀꿀운세 두 상담 입구의 차이 → 두 입구. 2주: 23시 입력과 보정 시각 → 계산 방법론·사주 허브. 3주: 본명숙 계산 방식 → 숙요점 허브. 4주: 대통령 사주 기록을 읽는 기준 → 공개 기록·유명인 허브. 같은 문구 반복, 이웃·댓글 품앗이, 자동 발행은 하지 않는다.

`Code Destiny`만 쓰면 게임 등 동명 검색과 혼동될 수 있다. 공식 표면의 첫 소개에 한글 브랜드와 영냥이의 관계를 명시한다. GitHub README·기술 글에는 계산 경계의 재현 가능한 예시와 출처를 사용한다. 위키 등재는 독립 출처·등재 기준을 먼저 검토할 사용자 판단 사항이며 홍보성 생성은 하지 않는다.

## D+14 / D+30

운영 Pages `/version.json`과 Worker `/api/version`에서 승인된 변경의 배포를 확인한 날을 D로 기록한다. staging 통과를 D로 쓰지 않는다. 재측정 자동화는 운영 반영 확인 후 D+14와 D+30을 계산한다. 기존 10월18일 측정은 10월4일 다른 배포의 일정이므로 보존한다.

- 동일 요일 구성의 28일 기간을 비교하고 최근 3일은 제외한다. 브랜드·6체계·의도·rolling 운세를 분리한다.
- 각 엔진에서 `꿀꿀운세`, `꿀꿀 운세`, `코드데스티니`, `영냥이`를 검색한다. 두 목표 URL 각각 첫 페이지 O/X와 결과 URL·기기·로그인 상태·날짜를 기록한다. 전체 트래픽 증가로 이 지표를 대체하지 않는다.
- GSC/Bing/Naver의 URL별 쿼리 노출·클릭·CTR·평균순위·색인 수, 실제 봇 방문 추이를 기록한다. Query와 Page의 별도 표를 임의로 결합하지 않는다.
- 아래 질문을 Naver AI 브리핑·Google AI Overviews·ChatGPT 검색·Perplexity에 같은 문장으로 묻는다. 답변의 도메인 인용 O/X와 정확한 인용 URL을 기록한다. 기능 미발동·로그인 제한은 X와 구분한다.
- 노출만 늘고 CTR이 낮으면 메타를 조정한다. 페이지 그룹별 메타 변경은 14일 간격을 지킨다. 날짜 갱신만으로 신선도를 꾸미지 않는다.

## 하지 않은 것

검색 순위 보장, 대량 랜딩 생성, 과장 적중률, 가짜 리뷰, 숨은 텍스트, 클로킹, 백링크 구매·품앗이, 임의 가격 변경, 엔진·결제·인증·DB 수정, 운영 배포, 위키 자동 등록, 블로그 자동 발행을 하지 않았다. llms-full.txt는 원문 중복 관리 비용에 비해 검증된 이익이 없어 만들지 않았다. 학습 봇 기존 허용과 CCBot 차단 정책은 유지했다.
