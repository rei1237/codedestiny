## GA4·주문 증거

속성 UI: Code:Destiny / FortuneDevelope. 전자상거래 구매 2026-08-29~09-25: 상품 조회 121, 구매 상품 1, 상품 수익 $0.74. 보고서 표시 통화이며 PG의 USD 청구 증거가 아니다. 구매는 항목 이름 `(not set)` 행에 있다. 코드상 purchase는 item_id를 보내지만 item_name은 보내지 않아 **이름 누락이 곧 주문 ID 누락이라는 뜻은 아니다**.

같은 보고서를 **항목 ID**로 전환한 결과 `yeongnyangi-saju-mackerel` 조회 43·구매 1·표시 수익 $0.74로 연결됐다. 자미 14, 베다 13, 숙요 12, 점성 11, 사주+자미 10, 타로 10 조회는 구매 0이었다. 이것은 조회 이벤트 수이며 적격 고객 세션 수가 아니다. 1/43을 고객 구매율로 발표하지 않는다. 항목 이름을 억지로 채우는 새 계측보다 기존 ID로 분석하는 것이 우선이다.
홈 90일 카드: 활성 사용자 326, 조회수 약 7.3천. 30일 페이지 카드에는 관리자 127회가 있다. 7일 세션 카드에 Google/Naver/Kakao 인증과 Inicis 복귀 referrer도 보인다. 기간 혼합 카드를 합산하지 않는다. 내부 트래픽 필터와 원 유입 귀속을 확인하기 전 고객 전환율을 산출하지 않는다.

운영 주문·환불·상품별 LLM 원가는 미확보. 읽기 전용 최소 내보내기: 날짜, 불투명 order_id, product_id, locale, 승인 시각/금액, 결과 상태/완료 시각, 환불 금액, 생성 시도·토큰·비용. 질문·출생정보·이름·이메일·상담 본문 제외. 없는 값은 0이 아니라 미확인이다.

| report_viewed | fortune_result_view / fortune_first_open | partial/complete 구분; 기기 간 최초 열람은 보장하지 않음 |
| refund | 서버 환불 원장 | GA4 refund 연결 미확인, 순매출에서 반드시 차감 |

검색 CTR=동일 범위 클릭/노출. 적격 랜딩 구매율=서버 승인 주문을 만든 적격 세션/적격 랜딩 세션. 상품→결제 진입률=checkout 진입 세션/상품 조회 세션. 승인율=서버 승인 주문/고유 결제 시도 주문. 결과 완료율=전체 저장 완료 주문/승인 주문. 열람률=완료 결과를 연 주문/완료 주문. 순매출/적격 세션=(승인금액-환불금액)/적격 세션. 모두 같은 주문 cohort와 관찰 종료 시점을 쓰며 승인 후 미완료 대기를 실패와 분리한다.
주문당 공헌이익=승인매출-환불-실제 PG 수수료-LLM(입출력+재시도)-인프라 변동비-지원비. 세금 포함/제외 기준을 고정한다. 세율·PG요율·환율·토큰 단가는 계약/원장 없이는 추정값으로 채우지 않는다.

## 약속과 실험

공개 products API의 saju_mackerel: available=true, KRW 1,000, destiny-book-v6, 5챕터. 코드의 v6 최소 5,500자, 목표 7,500~8,500자는 정책 일치 증거다. 운영 결과의 실제 분량·품질·완료율·대기시간·공헌이익 증거는 아니다. 분량·가격·권리를 줄이거나 유료 호출로 확인하지 않았다.

| 홈 | ‘영냥이에게 내 질문 남기기’ / ‘내 고민, 사주로 함께 읽기’ / ‘천원 상담은 어떤 답을 줄까?’ | 첫 후보만 적용. 행동·선택 상품 명확화 |

동시에 여러 A/B를 만들지 않는다. D0=실제 운영 승격일. 7일은 오류·예시→상품 연결 누락, 14일은 유입 의도·상품 조회 cohort, 28일은 GSC 동일 검색유형/페이지군의 순위·검색어 구성과 순매출을 비교한다. 적격 세션 200 미만 또는 승인 주문 20 미만이면 효과 방향을 확정하지 않고 건수·구간과 함께 탐색 관찰로만 보고한다. 이는 검정력 계산을 대신하는 유의성 기준이 아니다. 중복 청구·결과 손실 1건도 실험 중단/복구 우선, 환불·실패율 악화 시 원인을 조사한다. 자동 일정은 만들지 않는다.

GEO는 계산/AI 역할·가상 예시·가격 정본·공개 출처를 유지한다. 기존 FAQ/Breadcrumb/Service를 화면과 일치시키며 특별한 스키마나 llms.txt로 인용을 보장하지 않는다. 엔진·질문·언어·일시·인용 URL을 남기는 실제 AI 추천 관찰은 미실행.

공식 기준: [언어별 URL과 상호 hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions), [제목 링크](https://developers.google.com/search/docs/appearance/title-link), [AI 검색](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

## 전달·검증 기록

운영 기준은 Pages /version.json과 Worker /api/version 모두 `c54484ac0ff59e8eb06b36860bbc34e1e1aee928`였다. 이번 코드의 운영 배포 증거가 아니다. 스테이징·실기기 PG·실 LLM·운영 DB 검증은 미실행이다. CI 결과와 최종 커밋은 작업 완료 시 추가한다.
로컬 mock는 `npm run dev`(외부 API 차단, 3217/3218)로 실행했다. 360/390px 및 1440px에서 안내의 CTA·예시 가독성과 가로 넘침을 확인했고, 링크는 고등어 가격을 유지하며 ask 선택과 질문 입력을 표시했다. mock API의 상품/프로필 route 미지원 오류로 결제창 이후 검증은 수행하지 못했다. 이를 운영 오류로 보고하지 않는다.

구현 커밋: `39c9fca60` 질문 진입·예시·노출 이벤트, `84ec21fde` 모바일에서 추가 링크 겹침을 철회하고 기존 보조 내비게이션으로 이동, `de3a9b01f` 꽃돼지 다국어 홈의 상호 hreflang/사이트맵. 가격·상품 ID·Family 권리·결제·인증·API·DB 정책은 변경하지 않았다. 다른 세션의 질문 근거 엔진은 main 병합으로 포함되지만 이 작업의 성과로 집계하지 않는다.

검증: `npm run check:fast -- --plan`, `npm run check:fast` 통과(Node 1,663개, Jest 296 suites/4,207개; 첫 구현 시점). 최종 관련 Node 테스트 16/16 통과, `verify:analytics-events`, 변경 TSX ESLint, `sync:public`, `sitemap:generate`, `verify:sitemap`·`verify:sitemap-drift`(1,284 URL), `verify:public-mirror-fresh` 통과. 미러 검사는 미커밋 상태에서 판정 불가였으며 커밋 후 재실행해 통과했다. 정적 i18n 12개 파일/12,638키 정합성은 통과했으나 한국어 하드코딩 감사 49개 파일/320개 후보와 실제 구매 미번역은 별개다.

남은 구현: 한국어/영어/일본어 구매 입력→주문 locale snapshot→생성 prompt/validator→결과·보관함을 하나의 계약으로 연결하고, 그 뒤 나머지 locale을 확장한다. 현재 키 존재만으로 영냥이 번역이 끝났다고 보고하면 안 된다. 서버 주문/환불과 GA4 결합, auth/profile 사건 및 PG 단계별 시간, 실제 전체 결과 저장·재열람·공헌이익은 자료/통합 검증이 필요하다. 실 PG·LLM·운영 DB 쓰기 없이 확인 가능한 mock 회귀를 먼저 보강한다.

운영 반영은 별도 명시 승인 후 `gh workflow run "Release Cloudflare Pages and Worker" --ref main -f mode=production`이다. 실행 직전 최신 main과 포함 변경을 재검토하고, 승인된 고정 SHA의 CI·스테이징 증거를 확인한다. 이번에는 명령을 실행하지 않았다. 코드 복구는 이 작업의 구현 커밋만 역순 revert한 후 사이트맵을 재생성하며, 승인 주문·생성 작업·사용자 데이터는 삭제하지 않는다. 실제 운영 장애 복구는 기존 release rollback 절차로 이전 Pages/Worker 버전을 함께 복원한다.
