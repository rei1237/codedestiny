작성 2026-09-18. 원 요청 22개 항목(`docs/handoff/2026-09-17-seo-p1-followup.md`)
중 P7로 착수. 대상: code-destiny.com(사주·타로·자미두수·서양점성술·숙요점·
베다점).

## 방법론 — 실측 순위 데이터 없음, 수동 채움 필요

이 세션에서는 `search.naver.com`/`m.search.naver.com` 직접 접근이 환경
정책상 차단됐다. 대안으로 시도한 일반 웹 검색 도구는 네이버 자체 순위
알고리즘·파워링크 광고를 반영하지 않고 위키피디아·앱스토어 등 무관한
색인 결과만 반환해, 이를 "네이버 상위 노출 사이트"로 표기하면 실측을
가장한 추정이 된다(CLAUDE.md 코딩 원칙 8: 실측과 추정을 구분한다). 그래서
**이 문서에 실제 순위 데이터는 없다.** 아래 2절은 네이버에서 직접 확인하며
채우는 템플릿이고, 3절(검색의도 키워드 확장)만 이번 세션이 실측 없이도
작성 가능한 편집 산출물이다.

**27수 개별 키워드**: `숙(宿) 이름 + 운세` / `+ 뜻` / `+ 오늘` 패턴으로 27개
확장(예: "각수 운세", "각수 뜻", "각수 오늘"). 27수 명칭은
`worker/lib/sukuyo-relation-core.js` 정본 인용 — 각수·항수·저수·방수·심수·
미수·기수·두수·여수·허수·위수(危)·실수·벽수·규수·루수·위수(胃)·묘수·필수·
자수·삼수·정수·귀수·류수·성수·장수·익수·진수(27개). **위수가 危/胃 두 개의
동음이의 수라 표기 구분이 필수**다(구분 없이 "위수"만 쓰면 모호함).

**27수 쌍별 관계(궁합) 키워드 — 전체 C(27,2)=351개**: "이미 잘 나오는
영역이니 관계 전체를 키워드로 넣어라"는 요청에 따라 전수 생성. 오탈자·
누락 방지를 위해 스크립트로 조합을 생성했다(Node, 커밋 안 함, 산출물만

널리 알려진 사주/운세 서비스. 경쟁 구도 참고용으로만 활용하고, 실제 검색
노출 여부는 2절 템플릿으로 별도 확인이 필요하다.

- **포스텔러**: 빅데이터/AI 기반 사주·타로·별자리 통합 운세 앱
- **헬로우봇**: 사주·타로·운세·만세력·별자리·궁합을 AI 챗봇 형태로 제공
- **천명**: 실제 상담사 매칭형 타로/신점/사주 상담 플랫폼(건당 결제)

## 5. 다음 단계

1. 2절 템플릿을 네이버에서 직접 채워 실제 순위 데이터를 확보한다(⭐ 희귀
   키워드부터 우선 — 경쟁이 적어 허브 페이지 신설 효과가 가장 빠르게 나타날
   구간).
2. "숙요점 업태", "숙요점 영친" — 일반적으로 쓰이는 조합이 아니므로 네이버
   연관검색어/자동완성에서 직접 확인된 표현인지 재검증 권장.
3. **이번 라운드는 문서화까지만이다.** 3절의 확장 키워드(숙요 351쌍 포함)를
   실제 페이지 title/meta에 반영하는 작업은 남은 22개 항목 중 "허브 콘텐츠
   재작성"에서 별도로 다룬다 — 현재 네이버 노출이 양호한 상태이므로, 무분별한
   메타 변경으로 기존 순위를 흔들지 않도록 그 단계에서 우선순위·영향범위를
   먼저 판단한다.
4. 2절 템플릿을 채운 결과를 공유하면, 허브(하위 페이지) 구조 설계나 콘텐츠
   우선순위 설계로 이어서 진행한다.
