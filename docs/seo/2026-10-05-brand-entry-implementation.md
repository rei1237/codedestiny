# 꿀꿀운세 두 진입점 검색 개선

Status: active. Approved: 2026-10-05. Production deployment: pending separate approval.

목표는 정확한 브랜드 검색어 `꿀꿀운세`에서 `/ggulggul/`와 `/yeongnyangi/` 두 공식 진입점이 각각 노출되는 것이다. 브랜드 안내 페이지 노출이나 전체 사이트 트래픽을 이 목표의 달성으로 대체하지 않는다.

## Phase 1 — 기술 기반

- 기존 정본과 리다이렉트를 유지했다. 루트 이전은 하지 않았다.
- 꿀꿀운세 붙여쓰기 브랜드명, 각 입구의 제목·첫 화면·상호 링크를 정리했다. 브랜드 안내 첫 CTA 두 개를 두 공식 입구로 연결했다.
- 홈 6체계 카드의 href를 실제 허브로 바꾸고 기존 JS 행동은 유지했다.
- 날짜 운세 FAQ는 동일 배열로 화면과 JSON-LD를 렌더한다. 한국어 궁합 기준 설명의 중국어 폴백을 수정했다.
- robots는 단일 `/sitemap-index.xml`을 선언한다. 기존 `/sitemap.xml` URL 집합과 5개 언어 사이트맵은 기존 제출·도구와의 호환을 위해 유지한다. 생성·드리프트 검사에 인덱스를 포함했다.
- 검색·사용자 조회·학습 봇의 목적을 구분하고 비공개 경로 제한을 모든 그룹에 유지했다. 기존 학습 허용과 CCBot 차단을 유지했다. Cloudflare 대시보드는 변경하지 않았다.
- 초기 화면 AVIF 1024폭 221,835B (기존 WebP 361,526B), 720폭 140,729B (기존 181,460B). 작은 영냥이 이미지 26,462B (기존 113,644B). 다운로드 용량 측정이며 LCP 개선 실측은 아직 아니다.
- 참조가 발견되지 않은 public JS 3개를 `_graveyard/seo-20261005/`에 격리했다. 이 파일들은 초기 요청 목록에 없었으므로 성능 향상으로 계산하지 않는다.

### curl 증빙 — 로컬 정적 산출물, 운영 증빙 아님

`http://127.0.0.1:8931/ggulggul/`을 Yeti·Googlebot UA로 각각 curl GET: 모두 **200 / 3,245,194B**, 응답 일치. JS 없이 받은 HTML에서 새 title, 가시 H1, 영냥이 링크, 6개 허브 href 확인. 로컬 산출물 크기는 운영 압축·배포 후처리와 다르므로 Phase 0 운영 HTML 크기와 성능 비교하지 않는다.

검사: site-name-signals 8/8 PASS, sitemap local integrity 1,310 URLs PASS, SEO entity registry PASS. `check:fast` 실행 중. public-mirror-fresh는 커밋 전 dirty-tree 제한으로 판정 불가이며 커밋 후 재실행한다. 최종 CI·실제 배포 HTML 검증 전 완료로 보지 않는다.

### 유지한 경계

결제 실행 함수·가격·이용권·월정석·단건 결제·인증·콜백·DB·6개 엔진 미변경. IndexNow는 이미 발행·갱신 자동 핑이 있어 중복 구현하지 않는다. 기존 날짜·rolling 운세 유입을 보존하고 일괄 noindex하지 않는다.

### 다음 측정과 계정 작업

운영 반영일 D가 확정되면 D+14/D+30에 두 입구의 브랜드 SERP·GSC URL별 쿼리·AI 인용을 재측정한다. 최근 3일은 집계 비교에서 제외한다. 기존 10월 18일 자동화는 별도 이전 배포 측정이므로 덮어쓰지 않는다. 사용자는 신규 sitemap index 제출과 두 입구의 우선 수집 요청, Cloudflare 실제 봇 로그 확인이 필요하다.

## Phase 2 — 기존 검색의도 콘텐츠 보강

6체계 허브에 질문 직답·각 체계의 확인 기준·근거 문서 링크를 추가하고 메타를 구분했다. 기존 사주 계산법·야자시 글을 현재 어댑터의 지역 평균시 정책으로 정정하고, 같은 잘못된 설명이 있던 서비스 비교 글도 함께 정정했다. 가상 입력 4건의 실제 네 기둥과 보정 시각을 본문 표로 공개했다. 사주 vs 자미두수 페이지는 기존 검증된 동일 출생정보의 두 결과를 나란히 보여준다. 기존 2027 정미년 글은 입춘·띠·토정비결·개인 월운과 계획 예시를 구분하고 기존 신년 상담으로 연결했다. 신규 템플릿 페이지를 대량 생성하지 않았다.

검증: verify-seo-birth-examples 4/4 PASS; verify-yeongnyangi-engines 35 contracts PASS (mock 네트워크 차단, 실 LLM·PG 없음). 엔진 파일은 변경하지 않았다. source/adapter 검증이며 실제 배포 HTML과 색인 변화 증명은 아니다. Phase 1 로컬 Yeti/Googlebot curl은 두 UA 모두 200; 변경된 App Router 본문은 최종 staging curl에서 별도 확인해야 한다.

check:fast의 88개 gate 중 npm test에서 옛 action href 조건 2건이 실패했다. 승인된 허브 href 기준으로 두 테스트를 갱신한 후 관련 6 tests PASS. 전체 재검증 및 main CI는 최종 단계에 수행한다.

## Phase 3 — 대통령 사주 공개 기록

신규 정본 /insights/presidential-saju-public-records/를 기존 인사이트 발행 경로에 추가했다. 공개일·원문·사건 공공 출처·시점·방식을 분리한 표, 판정 기준, 327일 간격, 사건 전 보존본 미확보 한계를 명시했다. 세 번째 글은 연도 일치와 방식 불일치를 함께 표기했다. 정리 문서의 저자는 편집팀으로 두고 원문 분석자를 박병하로 구분했다.

홈 첫 화면 아래·영냥이 가이드·6체계 허브·About·유명인 허브·브랜드 안내에서 연결한다. 표 요약 OG 1200×630과 가시 FAQ 3개를 추가했다. 신규 URL은 생성 사이트맵 1,311개에 포함했다. 본문 단순 태그 제거 길이 2,297자(브라우저 가시 글자 수와 다른 source 측정).

원문 직접 열람은 Phase 0에서 수행했다. 현재 원문 날짜와 사건 전 수정 불변성을 혼동하지 않는다. 적중률·유일·100%·방식까지 적중 문구는 사용하지 않았다. 네이버 블로그 자동 발행·프로필 수정은 수행하지 않았으며 사용자 체크리스트로 넘긴다. 운영 반영 후 원문 링크·표·FAQ·OG의 curl/공유 미리보기와 D+14/D+30 브랜드·인용을 확인한다.

## Phase 4 — 출처와 엔티티 연결

Organization의 founder를 전역 Person ID와 연결하고, 보도는 sameAs가 아닌 subjectOf로 표현했다. 원문 분석자와 비교 문서를 정리한 편집팀을 구분한다. llms.txt에 두 실제 입구, 계산 예시의 1차 소스 범위, 공개 기록 및 수정 이력 확인 한계, 인용·갱신 기준을 추가했다. 브랜드 FAQ의 전부 무료처럼 읽히는 설명은 공개 도구와 유료 AI 상담을 구분하도록 정정했다. 결제 정책 자체는 바꾸지 않았다.

llms.txt 생성 검사와 entity registry 검사 PASS. llms.txt나 FAQ 구조화 데이터 자체가 검색 순위·AI 인용을 보장한다고 주장하지 않는다. 가짜 리뷰·평점, 숨은 텍스트, 백링크 구매, 의미 없는 수정일 갱신, 자동 블로그 발행은 하지 않았다.

### CI·staging에서 발견한 추가 수정

공개 기록의 메타 제목·OG가 기존 기본값으로 대체되는 경로를 수정했고, 실제 메타 생성 함수의 반환값을 확인했다. 두 입구의 설명은 한글 표시 폭 148/155로 줄여 160 예산 안에 맞췄다. 허브 href를 예전 모달 URL로 찾던 브라우저 검사 6개의 선택자를 유지된 data-action으로 변경했다. 홈 서비스 레지스트리에는 quickHref를 추가해 공개 허브 주소와 JS 행동을 구분하고 가격 대조는 유지했다. 사주 요약·기존 열람 상태·대운 복원 브라우저 검사는 360/390/430/1280에서 PASS.

staging preview bde365202의 실제 curl: 두 입구 모두 Yeti/Googlebot 200. 꿀꿀 본문 14,169자·영냥이 10,373자(JS 없는 파서 측정), 영냥이 FAQ 5개 모두 본문 일치. 6체계 허브·공개 기록·계산 방법론·robots·sitemap index·llms 응답을 보존했다. 없는 페이지는 404. 단 대표 staging 주소는 이전 SHA라 이 미리보기 결과를 대표 주소 반영으로 주장하지 않는다.

그 preview의 배포 smoke는 고민 이미지 8장의 `/cdn-cgi/image/` 404로 실패했다. Pages preview에는 zone 이미지 리사이즈가 없고, 기존 onerror 원본 재요청이 추가 실패를 만들었다. 동일 그림의 240/400/640px WebP를 실제 파일로 생성하고 실패 후 폴백 코드를 제거했다. 24개 파일의 포맷·폭·원본 대비 용량 감소와 7개 셸의 srcset 검사 PASS. 이는 화면/자산 수정이며 배포 검사를 무시하거나 완화하지 않았다.
