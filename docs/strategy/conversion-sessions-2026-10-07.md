# Code Destiny 전환 개선 세션별 실행 명세

작성일: 2026-10-07 KST. [분석 보고서](conversion-swot-2026-10-07.md)의 개선 후보를 독립적으로 구현·검증하기 위한 명세다. **S00은 진단·이벤트 계약·관련 mock 검증 완료, 현재 운영 기준선은 미확보다. S01~S09는 이 작업에서 수행하지 않았다.** [S00 결과와 전체 검사 제한](conversion-s00-baseline-2026-10-07.md)을 참고한다. 보고서 완성과 제품 구현 완료를 구분한다.

## 공통 실행 계약

각 세션은 지정된 ID 하나를 담당한다. 먼저 최신 `CLAUDE.md`와 해당 코드·호출부를 읽고 현재 main에서 여전히 존재하는 문제인지 재확인한다. 조사 기준 커밋은 `e8513e1f99cc45f97b42e68a4dde2634ea1097d9`이며 이후 다른 세션의 정상 변경을 되돌리지 않는다. 공감·인정 문장 개선은 이번 목록의 대상이 아니다.

가격·이용권·월정석·단건 결제 정책, 서버 권한·구매 검증, 유료 결과의 기존 보관·복구를 유지한다. 무료 결과 전체의 서버 보관·보관함 재열람을 추가하지 않는다. 기존 동의 기반 공개 한 문장 임시 공유와 만료·철회, 브라우저 다운로드는 별개로 유지한다. 상품 범위·추가 질문 횟수는 기존 정본을 사용하며 숫자를 여러 곳에 복제하지 않는다.

공통 완료 조건:

1. 문제 재현 또는 관찰 근거와 수정 범위를 기록한다. 재현되지 않으면 억지로 수정하지 않는다.
2. 지정 파일과 직접 필요한 호출부만 편집한다. 공유·라우팅·인증·결제 경계는 RED로 먼저 위험·검증·롤백을 설명한다.
3. UI 작업은 해당 서비스의 캐릭터·색·의식·본래 결과 렌더러를 보존한다. 주요 상태를 모바일/데스크톱에서 확인한다.
4. 실 LLM·실결제·운영 DB 쓰기를 사용하지 않고 기존 mock/network guard를 이용한다. mock 실패 시 실제 연동으로 폴백하지 않는다.
5. `npm run check:fast -- --plan` → `npm run check:fast`와 필요한 의미 있는 회귀 검증을 한다. 아래 명령은 시작점이며 전체를 무조건 반복 실행하는 목록이 아니다.
6. 해당 변경만 커밋·main push 후 정확한 SHA의 main CI를 확인한다. 동시에 쓰는 세션이 있으면 공식 safe-worktree 절차를 따르고 완료 시 자기 것만 배수한다. PR은 만들지 않는다. 운영 승격은 별도다.
7. “구현·mock·CI 완료”와 “운영 반영·전환 개선 확인”을 별도 보고한다. 관찰 기간 전에는 성과를 확정하지 않는다.

각 지시문은 실행을 맡기는 세션에 복사한다. 다른 세션에 메시지를 자동 전송하거나 새 채팅을 만드는 것은 이 문서의 작업이 아니다.

## S01 영냥이 선택 구성과 질문 추천의 일관성

**목표:** 상세에서 이해한 상품과 다음 단계의 상품이 설명 없이 바뀌지 않게 한다.

**근거:** F01·F02. 상세 CTA는 domain/fish를 전달하지만 기본 질문 우선 흐름은 질문에 맞춰 fish를 추천한다. 네 생선 설명은 같고 정책의 범위는 다르다. 현재 경로를 브라우저 mock으로 재현한 뒤 수정한다.

**소유 파일:** `app/yeongnyangi/_components/ProductGuide.tsx`, `app/yeongnyangi/_components/Consultation.tsx`, `app/yeongnyangi/_components/QuestionScope.tsx`, `app/yeongnyangi/_lib/reading-depth-copy.ts`, 관련 CSS/테스트.

**재사용 정본:** `worker/yeongnyangi/fortune/ask/question-policy.ts`, 기존 catalog와 `FOLLOWUP_LIMITS`, `product-curiosity`, 기존 편집 예시·후기. 정책 파일의 내용을 UI에 맞추려고 바꾸지 않는다.

**범위:** 성향 해석의 구성 선택과 질문 범위 추천을 사용자가 구별하게 한다. 구성 보존이 적절한 진입은 보존하고, 질문상 다른 범위가 필요하면 이유·가격·내용을 결제 전에 다시 확인하게 한다. 초기 폼의 중복 질문은 필요한 보충 정보만 순차적으로 보이도록 검토한다.

**완료 기준:**

- 네 생선마다 CTA 목적·도착 화면·가격·범위가 일치하거나 변경 이유가 명시된다.
- “더 비싸면 더 정확함”이라는 품질 계단을 만들지 않는다. 후속 질문 0/1/2/4 등 기존 권한을 유지한다.
- 질문 우선, 기존 성향 메뉴, 타로, 궁합, 로그인 복귀를 각각 mock 검증한다.
- 필수 근거·상황·기간을 삭제하거나 자동 추정하지 않는다. `QUESTION_PRODUCT_MISMATCH`를 우회하지 않는다.
- 결과 예시와 후기 원문·라벨, 기존 목차 snapshot을 유지한다.
- 공통 품질 설명은 보존하고 질문 범위 비교는 해당 흐름에만 적용한다. 한국어 질문 추천·한국어 기존 성향·영어 기존 성향을 각각 검증한다. 공통 helper를 바꿔 다른 언어·기존 성향 상품의 의미를 바꾸지 않는다.

**검증 출발점:** `node --test __tests__/ui/yeongnyangi-question-policy.test.mjs __tests__/ui/yeongnyangi-consultation-kinds.test.mjs __tests__/ui/feature-detail-preview.test.mjs`; 상세의 선택→다음 단계의 추천 변경 안내에 대한 브라우저 회귀를 추가한다. 파일이 이동했으면 심볼로 재탐색한다.

**지표:** 상세→범위 완료→checkout, 선택 후 되돌아감. URL·상태 계약 변경은 RED이며 가격·서버 권한 수정으로 확대하지 않는다.

## S02 홈에서 고민에 맞는 상담 찾기

**목표:** 처음 온 사람이 전문 체계를 몰라도 내 고민에 맞는 첫 상담을 찾는다.

**근거:** F03. 고민별 추천이 존재하지만 모바일 관찰에서 첫 화면보다 아래에 있다. 기존 카탈로그·검색·체계별 진입을 삭제할 이유는 없다.

**목표:** 직접 상담하려는 방문자와 이야기를 즐기려는 방문자가 모두 원하는 첫 행동을 찾는다.

## S04 네오 직접 랜딩의 구매 판단 정보

## S05 현재 상담에서 바로 후기 작성하기

**목표:** 방금 받은 상담을 사용자가 다시 찾아 고르지 않아도 된다.

**목표:** 상담을 받은 사람이 가치를 소화하고 필요할 때 다시 읽으며, 남긴 후기가 다음 구매자에게 전달되게 한다.

**검증:** 기존 결과/보관함 mock 권한·무료 제외·재열람·partial/resume 검사 중 변경 관련 항목. 운영 집계는 익명 수치만 확인하고 DB 상태를 수정하지 않는다.

**지표:** 유료 완료 코호트의 결과 재열람, 후기 승인 지연, 관련 상세→구매. D7은 7일 관찰을 마친 코호트로만 산정한다.

담당 세션은 자기 ID, 소유 파일, 시작 SHA, 구현/CI 상태, 운영 반영 여부, 관찰 기간과 결과를 짧게 남긴다. 사용자가 선택한 한 세션을 완료한 뒤 다음 ID를 제안하되 이 문서를 근거로 다른 채팅에 자동 지시하지 않는다. 실제 운영 결과가 나오면 보고서의 가설을 수정하고, 성과가 없는 변경을 계속 쌓지 않는다.
