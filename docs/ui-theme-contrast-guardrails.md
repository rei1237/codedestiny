# UI 테마 대비(가독성) 가드레일

> 연이(꽃·라이트) / 네오(달·다크) 두 모드에서 **가독성 붕괴를 영구히 막기 위한** 규칙.
> 이 문서는 2026-07 쿠키 배너 다크-온-다크 사고의 재발 방지책이다. 테마 색을 건드리는 모든 PR은 이 문서의 체크리스트를 통과해야 한다.

## 0. 한 줄 원칙

> **어두운 패널에는 밝은 글자, 밝은 패널에는 어두운 글자.**
> 배경과 그 위의 글자는 **항상 같은 규칙 블록에서 함께** 뒤집는다. 한쪽만 바꾸면 그 순간 버그다.

## 1. 두 모드의 정의 (기준색)

토큰 원본: [`styles/theme-tokens.css`](../styles/theme-tokens.css). 색을 새로 찍기 전에 여기 토큰을 먼저 쓴다.

| | 연이 (기본 · 꽃) | 네오 (달빛 · 다크) |
|---|---|---|
| 셀렉터 접두 | `html:not(.neo-mode)` / `body:not(.neo-mode)` | `html.neo-mode` / `body.neo-mode` / `html[data-cd-theme="neo"]` |
| 패널/표면 | 밝음 (크림·로즈·화이트 글래스) `#fffaf7`·`#fff3f8`·`rgba(255,255,255,.96)` | 어두움 (네이비-퍼플) `#0a0818`·`#13102a`·`rgba(19,16,42,.96)` |
| **본문 글자** | **어두움** `#3c1830` / muted `#70445c` | **밝음** `#f4eeff` / muted `rgba(200,170,255,.7)` |
| 강조(accent) | 로즈 `#b31955` | 라벤더 `#c4b5fd` |
| 골드 | `#ead089` / soft `#fff8dc` | 샴페인 `#e8d5a3` / soft `#f4e9c8` |
| 테두리 | `rgba(216,63,120,.16)` | `rgba(196,181,253,.32)` |

> ⚠ **이 레포의 base(무클래스) `<body>`는 다크다** (`background:#020617;color:#f8fafc`). 즉 **네오 = 기본값에 가깝고, 위험한 방향은 언제나 `html:not(.neo-mode)`(라이트) 오버라이드**다. 라이트 규칙은 표면을 밝히면서 글자도 반드시 어둡게 내려야 한다. 글자만 어둡게 하면 다크 base 표면 위 다크 글자 = 붕괴.

## 2. 사고 원인 — "반쪽 오버라이드"와 "유령 컨테이너"

2026-07 쿠키 배너 버그의 실제 원인 두 가지:

1. **반쪽 오버라이드**: 라이트 모드에서 제목/본문 글자만 어둡게 바꾸고(`color:#2a1420`), 배경은 그대로 다크로 둠 → 다크 위 다크.
2. **유령 컨테이너 오조준**: 배경을 바꾸긴 했는데 **실제로 색이 칠해지는 표면이 아닌 엉뚱한 요소**에 칠함.
   - `.cd-cookie-consent` = `position:fixed; pointer-events:none`인 **위치용 래퍼**(보이지 않음).
   - `.cd-cookie-consent__panel` = 실제 네이비 그라디언트가 칠해지는 **카드 표면**.
   - 래퍼에 밝은 배경을 줘봤자 그 위를 불투명 패널이 덮어 아무 효과 없음 → 패널은 다크, 글자만 다크 → 붕괴.

## 3. 절대 규칙 (배포 전 통과 조건)

1. **짝지어 바꾼다.** 한 요소의 `background`/`background-image`를 모드 스코프에서 바꾸면, **그 위에 얹히는 모든 글자(제목·본문·라벨·스위치·strong/span)의 `color`도 같은 블록에서** 반대 명도로 바꾼다. 역방향도 동일(글자만 바꾸는 것도 금지).
2. **진짜 표면을 조준한다.** 배경을 칠하기 전에 DevTools로 **실제 페인트되는 요소**를 확인한다. `__panel`/`__card`/`__inner`/`__surface` 같은 자식이 배경을 칠하면, 래퍼가 아니라 그 자식을 조준한다. 래퍼가 `pointer-events:none`·`background:none`·투명이면 십중팔구 유령이다.
3. **base가 다크임을 기억한다.** 라이트(`:not(.neo-mode)`) 규칙에서 표면을 안 밝히고 글자만 어둡게 두면 다크 base 위 다크 글자가 된다. 표면·글자 둘 다 명시한다.
4. **자식까지 내려간다.** 설정 패널·아코디언·토글·배지 등 **초기 `display:none`으로 숨어 나중에 열리는 하위 표면**도 같은 모드 스코프에서 배경+글자를 함께 처리한다(열렸을 때만 보이므로 육안 QA에서 빠지기 쉽다).
5. **6개 미러 동시 반영.** `index.html`의 홈 스타일은 `public/index.html`, `public/en|ja|zh|static/index.html`까지 **6곳이 바이트 동일**해야 한다. 한 곳만 고치면 로케일별로 깨진다. (grep으로 동일 문자열 확인 후 6곳 모두 Edit.)
6. **반투명 표면 주의.** `rgba(...,.5)` 같은 반투명 배경은 **뒤 레이어가 비쳐** 실효 명도가 달라진다. 반투명이면 뒤 레이어까지 같은 모드로 정합되는지 확인한다.

## 4. 최소 대비(명도) 기준

- 본문 텍스트: 배경 대비 **WCAG AA(4.5:1) 이상**. 큰 제목(≥1.1rem·bold)은 3:1 이상.
- 라이트 표면 위 본문은 `#3c1830`/`#70445c`, 다크 표면 위 본문은 `#f4eeff`/`rgba(200,170,255,.7)`를 기본으로 쓴다(토큰값이라 검증됨).
- **골드/로즈 위 글자**: `#ead089`(골드) CTA 위에는 어두운 글자(`#2f1329`), 다크 골드(`#e8d5a3`) 위에도 어두운 글자(`#090718`). 골드 위에 밝은 글자를 얹지 않는다.
- `text-shadow`로 대비를 "가리지" 말 것 — 그림자는 보정이지 해결이 아니다. 명도 자체를 맞춘다.

## 5. 자가 점검 (커밋 전 grep 감사)

테마 색을 만졌다면 아래로 반쪽 오버라이드 후보를 훑는다.

```bash
# 모드 스코프에서 background를 칠하는 규칙 나열 → 각각 "같은 요소의 글자색도 바꿨나?" 확인
rg -n "html:not\(\.neo-mode\)|body:not\(\.neo-mode\)|html\.neo-mode|body\.neo-mode" index.html \
  | rg "background|background-image|background-color"

# 위 목록의 각 셀렉터에 대응하는 color 규칙이 있는지 대조.
# 특히 __wrap/__container/__shell 등 '컨테이너'에 background만 있고
# __panel/__card 에 color가 없으면 유령 컨테이너 의심.
```

육안 QA는 **두 모드 × (배너 접힘/펼침) × 모바일(≤560px)** 네 조합을 모두 연다. 설정 패널처럼 접혀 있는 표면은 열어서 확인한다.

## 6. 사례: 쿠키 배너(고정 레퍼런스)

`index.html`의 `html:not(.neo-mode) .cd-cookie-consent*` 블록이 올바른 형태다:

- 배경은 **`.cd-cookie-consent__panel`**(진짜 표면)에 라이트 글래스로.
- `__panel::before`(별가루 레이어) 투명도 낮춤.
- 제목/본문/kicker/설정 패널/`__row strong`·`span`/`__switch`/버튼(`#cdCookieAcceptBtn,#cdCookieSaveBtn`, `#cdCookieEssentialBtn,#cdCookieSettingsBtn`) **글자색을 전부 어둡게 짝지음.**
- 네오 모드는 기본 다크 표면 + 밝은 글자를 그대로 유지(오버라이드 불필요).

이 블록 상단 주석에 "왜 `__panel`을 조준하는지"가 남아 있으니, 유사 오버레이(모달·시트·토스트) 작업 시 그 패턴을 복제한다.
