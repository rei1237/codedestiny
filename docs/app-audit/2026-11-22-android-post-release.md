# Android 출시 후 로그인·구매·상담 코드 검수

패키지 `com.codedestiny.app`의 Android 진입점을 기준으로 Google 로그인 복귀, Play 단건 결제, AI 상담 결과 재개와 재열람을 확인했다. 앱에서 실제로 설치된 프로덕션 버전, Play Console 상품 상태, 서비스 계정 권한과 운영 LLM 응답은 실기기 내부 테스트의 확인 범위로 남겨 둔다.

## 코드 경로와 검수 결과

| 흐름 | 확인한 동작 |
|---|---|
| 로그인 | 브라우저의 소셜 로그인 결과가 앱 딥링크로 들어온다. 앱이 토큰을 교환하고 세션을 저장한 뒤 요청 화면으로 복귀한다. 취소·교환 실패 시 진행 표시를 닫고 기존 세션을 보존하는 경로를 확인했다. |
| 결제 진입 | 적용 가능한 이용권을 먼저 확인한다. 단건 결제를 선택하면 Play 결제 시트를 열고, 월정석은 기존 서버 차감 정책을 적용한다. 앱 결제 가드나 상품 가격이 확인되지 않으면 결제 진입을 막는다. |
| 영수증 확인 | 승인된 영수증을 서버가 Play에 조회한다. 대기·취소 상태에서는 지급하지 않는다. 같은 영수증의 중복 지급을 막고, 회당 구매에만 소비를 요청한다. |
| 장시간 결제·복구 | 결제 시트를 오래 열어 액세스 토큰이 만료돼도 영수증 검증과 복구에 앱의 기존 세션 갱신 경로가 적용된다. 모의 테스트에서 구매 시트 한 번, 동일 영수증 검증, 소비 한 번을 확인했다. |
| Play 알림 | 정상 구매 상태는 유지한다. Play 조회의 인증·권한·호출 한도 및 일시 오류는 재시도 응답을 보내 권한을 보존한다. 환불 확정 알림은 기존 멱등 회수 경로를 사용한다. |
| AI 결과 | 운명의 찻집과 영냥이의 결제 증빙·요청 ID가 생성에 이어진다. 네트워크 오류, 재실행, 장별 진행 중에는 기존 요청을 다시 연결한다. 테스트에서 완성된 저장 결과 재열람에 별도 결제창을 띄우지 않는 것을 확인했다. |
| 영냥이 앱 번들 | 웹과 방·기숙사·운세 컴포넌트를 공유한다. 앱의 기숙사 초대장, 다섯 기존 기숙사와 별숲온실 WebP를 번들에서 보존한다. 목록과 결과, 저장 이미지가 동일한 기준 파일을 사용한다. |

실제 출시 앱의 상품과 기간·한도·가격 정책은 Play Console의 활성 SKU와 [앱 가격·게이팅 문서](../play-billing-app.md)를 대조한다. 기존 결제 증빙과 저장 결과의 읽기 규칙은 그대로 적용된다.

## 내부 테스트 릴리스 판정

Play의 라이선스 테스터와 내부 테스트 트랙 설치본을 사용한다. Play 구매는 테스트 수단만 쓰고, 상담 생성은 모의 제공자에 연결된 검증 환경으로 설정한다. [Android 결제 통합 테스트 안내](https://developer.android.com/google/play/billing/test)

1. 최초 설치와 기존 앱 데이터가 남은 업데이트 설치에서 Google 로그인을 검사한다. 취소 후 다시 로그인할 수 있고, 성공 시 출발한 상담 화면으로 돌아와 계정이 표시되어야 한다.
2. 판매 중인 콘텐츠 SKU 하나와 이용권 SKU 하나를 가격표 및 Play 결제 표시가와 대조한다. 취소·지연 승인·정상 승인을 각각 실행한다.
3. 결제 시트 이후 네트워크를 끊거나 앱을 닫고 다시 연다. 로그인한 계정과 기존 영수증으로 지급·결과 생성이 이어지고, 동일 회당 상품의 다음 구매가 정상적으로 열린다.
4. 상담 결과가 한 장씩 나타나는 기능에서 생성 중 재진입과 완료 후 보관함 재열람을 확인한다. 계정을 바꿨을 때 이전 계정의 결과가 남아 있지 않아야 한다.
5. 영냥이 방에서 기숙사 초대장, 배정 결과, 이미지 저장, 출석 타로, 출생 입력 단계와 하단 뒤로가기를 확인한다. 화면을 닫고 같은 동작을 한 번 더 수행한다.
6. 출시 AAB의 버전 코드와 테스트 기기의 설치 버전을 기록한다. Play 구매가 승인됐는데 결과가 복구되지 않거나 재결제가 요구되는 경우 릴리스를 보류한다.
