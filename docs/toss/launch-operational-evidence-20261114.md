# 운영 활성화 판단 근거 (2026-11-14)

실 LLM·실결제·운영 DB 쓰기 없이 코드와 콘솔을 읽고 확인했다. 모의 구매의 계정 격리 통과를 운영 최초 구매자 증명으로 간주하지 않는다. 신규 판매는 계속 닫혀 있다.

## 최초 주문의 구매자 귀속

[공식 주문 API](https://developers-apps-in-toss.toss.im/api/iap)의 현재 OpenAPI는 mTLS로 미니앱을 인증하고 요청 본문으로 `orderId`만 받는다. 사용자 헤더 파라미터는 없고 응답은 주문 ID·SKU·상태·상태 확정 시각·설명이며 구매자나 검증 가능한 서명이 없다. 현재 `worker/toss/partner.js`의 제한과 일치한다.

[공식 SDK](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iap/in-app-purchase)는 상품 지급 콜백에 `orderId`를 넘긴다. 이 클라이언트 콜백만으로 서버가 독립적으로 구매자를 증명할 수 있다는 계약은 확인되지 않았다.

[2026-10-19 담당자 답변](https://techchat-apps-in-toss.toss.im/t/webview-sdk-3-8-0-50/5026)은 구매자 검증 API 미제공과 개선 계획을 명시한다. 완료·환불 주문 페이지 인자는 이후 3.9.0에서 수정됐다고 안내하지만, 이는 구매자 검증 기능과 별개다.

[2026-10-29 담당자 답변](https://techchat-apps-in-toss.toss.im/t/iap-webview/5061)은 원래 지급 대상을 특정할 수 없는 주문의 자동 지급 보류, 미결 안내·고객센터 확인과 수동 지급 절차를 허용한다. 결제 전에 주문 ID를 받는 기능도 제공되지 않는다. 이 운영 절차를 서버의 구매자 증명 API로 해석하지 않는다.

따라서 최초 제출자에게 주문을 고정하거나 존재하지 않는 사용자 헤더를 추가하는 방식으로 판매 게이트를 열지 않는다. 독립적인 구매자 검증 계약 또는 승인된 수동 확인 운영 체계가 정해져야 신규 판매 활성화안을 확정할 수 있다. 확인 불가능한 주문은 새 결제를 유도하지 않고 미결 상태를 안내한다. 기존 소유권이 검증된 저장 원문은 별도 권리로 보존한다.

## 콘솔 관찰

- 로그인은 등록 시작 상태였다. 약관·콜백·실제 개인정보 처리 지역 등 구체 운영 정보를 임의 제출하지 않았다.
- 서버는 `/api/toss/callbacks/unlink`의 GET/POST와 Authorization 검증을 지원한다. 필요한 설정 이름은 `TOSS_CALLBACK_AUTHORIZATION`, `TOSS_MTLS`, `TOSS_MTLS_EXPIRES_AT`, `TOSS_IDENTITY_KEY`, `TOSS_DATA_KEY`다. 실제 비밀값은 조회·출력·등록하지 않았다.
- 등록 상품은 연이 사주 4,950원과 영냥이 4개 등급이었다. 연이 4,950원·영냥이 14,850원 상세는 미노출이었다. 다른 세 상품의 노출 상태는 이번 확인 범위 밖이다. 연이 SKU를 다른 상담에 재사용하지 않는다.
- 앱 정보의 반려 사유는 배경이 채워진 사각형 아이콘·썸네일이다. 현재 밝은/어두운 모드 로고를 직접 내려받아 확인한 결과 두 파일 모두 기존 교정본 SHA-256 `ae2faffe5a07829a74930b2ae9f17d69ffc6ca48ab43c678f389498c9e266bba`와 일치했다. 600×600, 투명 픽셀 0, 네 모서리 RGBA `(16,27,44,255)`이며 영냥이 전신이 잘리지 않는다. 새 아트나 재인코딩이 필요하다고 판단하지 않았다. 반려 해소 승인은 토스의 별도 판단이다.
- 기존 스크린샷 세 장은 636×1048의 이전 축소 홈이다. 최신 실제 AIT 화면으로 교체할 자료를 준비하되 모의판을 실결제 운영 화면으로 표시하지 않는다.

## 분리할 출시 범위

무료 기능의 원본 계산·콘텐츠와 검증된 기존 결과 재열람은 신규 판매와 분리해 검토할 수 있다. 그러나 현재 코드 이식·Linux AIT·실기기 검증이 모두 끝난 상태는 아니며, 이 문서는 제출이나 출시 완료 선언이 아니다. 운영 Worker 승격, 비밀값 등록, 상품 노출, 검토 요청, 출시를 각각 독립 게이트로 유지한다.
