# 간편 진입 UI와 가상 모바일 확인

실사용 제보에 따라 기능의 존재와 화면에서 찾을 수 있는 상태를 분리해 검증한다. 이전 109개 코드 집계는 사용성 완료를 뜻하지 않는다.

## 변경

- 홈은 상담실 5개를 먼저 보여준다. 나머지 분류는 개수와 설명을 보고 펼친다. 44개 운세는 사주/자미두수/숙요·베다·점성술/타로·신탁/오늘·성향·마음으로 나눴다. 전체 펼치기와 전역 검색으로 기존 73개 목적지에 접근할 수 있다.
- 운명의 찻집은 사주, 타로, 숙요점, 사주 궁합, 연이·네오 공동 상담을 먼저 선택한다. 타로의 3·5카드와 원본 배열 선택은 기존 입력에서 유지한다.
- 영냥이 출생정보는 이름·성별 → 생일·달력 → 시간·시간 모름 → 출생지의 4단계다. 입력 중 결제 요약은 숨기고 작성 중 초안은 계정·경로별로 복원한다. 기존 프로필 저장 payload, 음력 윤달, 해외 좌표·시간대, 소유권은 유지한다.
- 로그인·결제 정책, 기존 구매 권리와 서비스별 보관함은 변경하지 않는다. 원본 웹 화면은 Toss 옵션을 사용하지 않을 때 기존 동작을 유지한다.

## 사용자가 직접 확인

현재 이 PC에서 `http://127.0.0.1:4330/preview`를 연다. 360/390/430 화면 너비, 뒤로, 앱 다시 열기 버튼을 사용할 수 있다. 실제 토스·결제·LLM·운영 데이터에 접근하지 않는 모의 앱이다.

1. 홈 → 연이 → 운명의 찻집 → 원하는 상담 방식 → 입력 → 모의 로그인과 구매 → 결과.
2. 앱 다시 열기 → 연이 → 꿀꿀운세 구매 기록 → 같은 결과 다시 보기.
3. 영냥이 → 계산 방식 상담 → 질문 → 상담과 결제 확인 → 상담 프로필 → 다른 사람 출생정보 입력. 날짜와 시간 모름을 입력한 뒤 앱 다시 열기로 복원을 확인한다.
4. 앱 상단 모의 계정 A/B를 바꿔 다른 계정의 결과·초안이 보이지 않는지 확인한다. 모의 기록 초기화는 이 미리보기의 A/B 데이터만 지운다.

서버 재실행: 저장소 `apps/toss`에서 `node scripts/preview-private.mjs`. 미리보기용 빌드가 없는 새 체크아웃은 `npm run build:private-simulation`이 먼저 필요하다. 현재 모의 변형은 빌드는 생성되지만 확장 용량 100,257,263 bytes로 업로드 크기 검사를 통과하지 못한다. 이 서버는 로컬 확인에만 사용한다. 일반 AIT는 99,095,658 bytes로 100MB 한도 안이다. 테스트 중인 서버의 dist를 덮어쓰지 않는다.

## 검증 근거와 남은 확인

- 홈 전체 73개 목적지 실제 클릭 진입 PASS. 각 분류 및 검색 결과를 통한 접근을 사용하며 숨겨진 DOM 클릭이나 개발 메뉴로 대체하지 않았다.
- 찻집 6모드: 홈부터 모의 로그인/주문 1건/생성 1회/앱 재열기/저장 원문 및 후속상담/계정 B 결과 거부 PASS.
- 모바일 360/390/430 및 높이 650 입력 화면 검수. 날짜·출생지 단계에 이전/다음/저장 버튼이 보이고 결제 CTA와 경쟁하지 않는다. 실제 휴대폰 키보드와 토스 네이티브 동작은 새 QR에서 추가 확인한다.
- 디자인 검사 1회: 원본 웹의 찻집 테두리와 기존 홈 활성 표시 경고 4개 및 글자 크기 참고 경고. 원본 예화 디자인과 승인된 렌더링을 유지했고 무관한 웹 스타일은 변경하지 않았다.
- 추가 targeted73 PASS, paid77/lint/typecheck PASS. Node5099 중 당일 데이터 미준비1건은 정식 로컬 생성 후 해당 파일7/7 PASS로 해소했고 나머지 계약/Worker/encoding/Jest(479 suites·8011 tests PASS,1skip)까지 완료했다. 병합 트리 pre-push PASS. main CI/Linux AIT/새 비공개 QR은 완료 후 인수인계 문서에 기록한다. 실결제와 새 검토 제출은 보류다.
