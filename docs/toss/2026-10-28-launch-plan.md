# Code Destiny 앱인토스 출시 실행 계획

status: in-progress

## 목표와 현재 판정

사용자 요청: “앱인토스로 서비스 이식해서 론칭 준비하라고 했는데 작업 마무리해서 론칭까지 진행해줄 프롬프트나 계획을 세워서 구현해줘.” 이후 “디자인이 매우 중요하다”, “디자인과 기능 모두 최적화시키도록해줘”를 완료 기준에 반영했다.

기존 서비스의 전체 기능과 캐릭터 정체성을 유지한 토스 CSR 앱을 만든다. 소개 화면이나 상품 카드만 추가한 상태를 기능 이식 완료로 집계하지 않는다. 현재는 **출시 준비 중**이다. `SERVICE_AVAILABLE=false`, 승인 상품 목록은 비어 있다. 운영 배포·콘솔 제출·출시는 하지 않았다.

2026-11-07 재계산한 원장은 확인된 출처에서 후보 최소 90개를 식별한다. 38개는 일부 로컬 구현이 있고, 52개는 원본 계약을 추적해 이식해야 한다. 완료와 출시 제외는 각각 0개이며, 하위 흐름을 포함한 출시 범위는 아직 확정되지 않았다. 부분 구현은 로그인부터 구매·결과·재접속 복구까지 실기기 검증을 마친 수가 아니다. 최신 현황 확인: `npm run launch:status --prefix apps/toss`, 상세 차단 사항: `2026-11-04-review-readiness.md`.

## 이번 작업에서 개선한 범위

- 홈과 상담가 선택에 실제 대표 홈의 영냥이·연이·네오 이미지 사용. 상담가별 색과 문체, 서비스별 타로/꽃 이미지를 유지한다. 구체적인 기준은 `design-brief.md`를 따른다.
- 추가 요청인 하단 고급화·달빛 예화 적용: 기존 달/꽃 원화와 정본 꽃가지·인장 마스크를 사용해 크림·금빛 이중 테두리·자주색 주 버튼을 구현했다. 360/390/430/1280px 화면과 네 버튼의 이동을 직접 확인했다.
- 12개 타로 목록·질문·카드 선택·결과 화면의 시각적 위계와 모바일 읽기 간격 개선. 장수와 선택 순서가 보이고, 선택 완료 뒤 미선택 카드만 비활성화한다.
- 타로 전체 카드 집합을 새 상담마다 섞고, 입력과 선택 중에는 배열을 유지한다. 정·역방향도 상담을 시작할 때 정한다.
- 토스 구매 확인 콜백은 권한의 영구 저장까지만 수행한다. 생성 작업은 승인 확인 후 별도 요청으로 실행한다.
- 구매 복구 경로에서 서버가 상담/타로 상품을 구분한다. 입력이 없는 복구 주문은 원래 주문에 한 번만 입력을 연결한다. 판매 목록에서 빠져도 이미 소유한 주문의 복구는 새 결제를 요구하지 않는다.
- 실패한 리딩의 동일 주문 재개, 완료된 결과의 저장 원문 재열람, 생성 중단 후 5분 작업 임대 만료 시 재개를 구현했다. 이전 작업의 늦은 성공/실패가 새 작업을 덮어쓰지 못하도록 작업 토큰을 대조한다.
- 다른 계정·환경·환불된 주문의 재개를 거부한다. 화면을 떠난 뒤 늦게 도착한 요청은 화면 상태를 변경하지 않도록 정리한다.

## 2026-11-08 실행 계획

현재 원장에는 후보 90개 중 부분 구현 46개, 미이식 44개, 공식 검증 완료·출시 제외 각 0개가 있다. 승인 SKU는 0개이고 공개 설정은 꺼져 있다. 반려동물의 유료 결과와 주문 이어보기는 로컬 구현까지, 자미두수 기본 명반은 국내 출생지·양력/음력·생시 미상·12궁과 대한 표시까지다.

이식 커밋 `42628b3b7`에서 기본 사주, 유명인 사주, 연이의 운명 노벨을 추가했다. 기본 사주는 국내 출생지를 기준으로 양력·음력·윤달을 입력하고, 생시 미상이면 시주를 비운다. 유명인 사주는 공개 승인된 프로필 66편만 원본에서 발췌한다. 연이의 운명 노벨은 한국어판 73화의 대사 7,844개와 두 결말을 담은 텍스트 판이다. 연출·음향·재실행 후 책갈피는 남아 있다. 만세력은 로그인 후 결과에서 입력으로 돌아가면 그 세션의 날짜를 유지한다. 390px 오프라인 공식 devtools 브라우저에서 홈→명식→입력 복귀, 별칭 검색→원문, 소설 두 번째 쪽 이어보기를 재현했다. 기기·샌드박스 검증 완료로 세지 않는다.

이식 커밋 `b1648115e`에서 서양 점성술(열대황도·플라시두스)과 베다점(항성황도·라히리)의 출생차트는 기존 로그인 검사 뒤 로컬 Swiss 천체력을 사용한다. 음력 윤달과 대응 양력이 같은 결과인지, 출생 시각 누락과 불완전한 천체력 결과를 거부하는지 검사했다. 공개 27수 도감은 숙요점에서 다시 계산하지 않고 돌아올 수 있다. 나크샤트라 개인 리딩은 여전히 미이식이다. 음악실은 원본 정책상 전체 재생이 허용된 123곡만 노출한다. 다운로드 권리는 옮기지 않았다. 390px 오프라인 devtools에서 도감 직접 진입, 두 차트의 결과·뒤로가기, 로컬 PCM 음원의 연결 실패·재시도·재생·일시 정지를 확인했다. 실제 CDN 재생 및 공식 기기 증거와 구분한다.

이식 커밋 `5a93cb489`에서 십이운성 동물점의 공개 계산과 열두 동물 도감을 연결했다. 국내 양력·음력·윤달 명식에서 일주의 대표 동물과 네 기둥의 운성을 구하며 생시 미상이면 시주를 비운다. 빌드에는 원본 120개 운성 대응과 공개 동물 이름만 포함한다. 390px 오프라인 devtools에서 윤달 생일 → 구름 토끼 → 12동물 도감 → 같은 결과 복귀를 확인했다. 묶음 구매·상세 결과·궁합·보관과 공식 기기 동등성은 미검증이다.

원장의 `webEntitlement`는 십이운성 동물점·직업 성향·여행지·건강 리듬·스킬 트리·매력 클래스·퀀텀 명리·관계의 경계·시크릿 하우스 9개가 원본 서버에서 출생 기준의 같은 사주 묶음 권리를 읽는다는 증거다. 신규 개별 판매는 닫혀 있고 과거 개별 구매 권리는 지우지 않는다. 이는 토스 SKU·계정 연결 승인이나 이식 완료가 아니다. 승인된 구매 귀속을 확인하기 전에는 이 기능들의 유료 본문을 열지 않는다.

공식 devtools 모의 환경에서 찻집의 질문 입력 → 찻잔 선택 → 첫 화면으로 뒤로가기와 미니앱 홈 복귀를 확인했다. 연이 편지는 질문·프로필 선택 → 모의 구매 → 결과 → 같은 상담 다시 열기까지 주문 한 건을 유지했다. 자미두수는 비회원 명반 계산·잘못된 윤달 거절·다시 열었을 때 입력 초기화를 확인했고 360·390·430px에서 가로 넘침이 없었다. 이 결과는 공식 기기 주문 증거와 구분한다.

1. **기능 이식과 분류.** 토스 홈과 직접 주소에서 같은 화면을 열어 입력·결과·뒤로가기·계정 전환을 확인한다. 자미두수 기본 명반의 국내 출생 입력과 12궁 계산을 먼저 연결했다. 심화 해설·저장 프로필·기기 검증은 남는다. 기본 사주 원본의 공개 명식을 분리했고 유료 소장 해설은 열지 않았다. 기본 점성술·베다점의 로그인 후 계산도 연결했다. 비회원·저장 프로필 동등성, 찻집·연이 편지·대표 상담의 재진입과 원문 보존은 남는다. 이후 독립 서비스별로 원장의 입력·권리·결과·보관 계약을 채운다. 완료는 서비스별 통과 증거를 확인한 뒤 기록한다.
2. **가격과 판매 권리.** 이식 커밋 `e1248999e`에서 [가격 대조표](price-review.json)를 재생성했다. 가격 키 188개 중 양수 187개, 상담 70조합(영냥이 28·연이 21·네오 21)이다. 공식 공급가 단위인 10원과 부가세 10%를 적용했을 때 같은 판매가가 나오는 양수 키와 상담 조합은 각각 0개다. 각 키가 신규 판매 대상이라는 의미는 아니다. 기존 콘솔 측정에서도 5,000원 양옆은 4,994원·5,005원이었다. 비게임 앱 한도는 상품 30개다. 기존 가격·제공 권리를 보존할 수 있는 토스 측 매핑을 확인한 뒤에만 SKU를 등록한다. 반려동물 두 상품은 웹 표시와 레지스트리의 차이도 별도로 해소해야 한다. [토스 상품 등록 기준](https://developers-apps-in-toss.toss.im/guide/monetization/in-app-payment)
3. **결제 소유권과 안전 운영.** 주문번호를 모르는 중단 건은 빈 미지급 목록만으로 재구매를 허용하지 않는다. 최초 주문과 계정을 독립적으로 연결할 수 있는 방식이 확인되면 다른 계정 선점·재시작·중복 지급·환불 케이스를 검사한다. 상담 입력·출력·후속 질문의 안전 응답, 연령 제한, 민감정보 없는 오류 추적은 실제 출시 대상 경로별로 증거를 남긴다. [토스 운영진의 11월 5일 답변](https://techchat-apps-in-toss.toss.im/t/topic/5122)
4. **번들과 콘솔 자료.** 현재 앱은 `ai-saju-studio` 0.1.0이다. GitHub Actions의 기존 PR CI를 `full_ci=true`, `toss_artifact=true`로 실행해 Linux에서 공식 CLI로 만든 번들의 파일 일치·크기·경로 이식성을 검사한다. 기준 커밋의 검사는 [실행 42393987848](https://github.com/rei1237/codedestiny/actions/runs/42393987848)에서 통과했다. 최종 후보 SHA별로 다시 생성한다. 기존 콘솔 공간에서 로그인·mTLS, 반려 자산과 최신 화면, 개인정보 처리·연결 해제·삭제 범위, 연령과 심사 재현 절차를 확인한다.
5. **기기와 심사 접수.** 찻집 뒤로가기, 편지 상담, 대표 상담과 모든 유료 경로에 대해 기기·OS·앱 버전·후보 SHA를 붙여 입력→구매→결과→보관함→중단 복구 증거를 남긴다.
