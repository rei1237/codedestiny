# 원본 서비스 순차 이식

status: in-progress

사용자 요청: 샘플 미리보기에서 끝내지 않고 영냥이·운명의 찻집·네오 전략실을 출시 버전에 연결한다. 원본 UI/UX와 결과 생성·저장·재열람을 보존한다. 그 이후 초융합과 다른 운세를 하나씩 정확히 이식한다.

## 순서와 완료 기준

1. 영냥이: 원본 입력·주문서·ReadingBook·보관함, Toss 인증/승인 SKU/주문 증빙, 동일 생성·저장·복구.
2. 운명의 찻집: 원본 상담 모드·카드 선택·편지·추가 질문·보관함. 화자 변경으로 대체하지 않는다.
3. 네오 전략실: 원본 입력·브리핑·현실 점검·수정 작전·전략서·재열람. 원본 checkpoint와 재시도를 보존한다.
4. 초융합: 원본 입력과 체계별 계산·통합 리포트, 기존 결과·저장 계약을 먼저 추적한 뒤 별도 단위로 검증한다.
5. 인생의 책·연애 비책·전문가 등: 원본 화면과 API 계약 목록을 작성하고 한 서비스의 입력→결과→보관→재열람이 검증되면 다음 서비스로 진행한다.

각 단계는 소유자 격리, 중복 결제/생성 방지, 취소·환불 증빙 재검증, 저장된 원본 재열람 무과금, 모바일/데스크톱 렌더링, CI를 확인한다. 개발 검사는 실 LLM·실결제·운영 DB를 호출하지 않는다. 승인 SKU/검수/실기기 검증은 별도 증거이며 로컬 성공으로 대체하지 않는다.

## 현재 사실

- 기존 Toss 영냥이 생성/저장/주문 검증은 존재한다. yeoni/neo 상품은 영냥이의 persona 변경이므로 찻집·전략실 정본 이식이 아니다.
- 영냥이 원본 입력·주문서·결과·보관함을 `apps/toss/service` 출시 진입에 연결했다. React 타입 이중 해석을 토스 React 18로 통일하고 공유 코드의 암시적 타입을 보완했다. 원본 계산·prepare/present·추가 대화·결과 복구를 재사용한다.
- `worker/toss/canonical-yeongnyangi.js`는 토스 owner에 한정한 프로필과 원본 prepare/present 계약을 제공한다. 프로필 중복 요청은 기존 값을 보존한다.
- 토스 오프라인 전체 검사 128/128 통과. 요청 보존/외부 폴백 차단, 승인 가격, 계정별 프로필 멱등성, 저장 상품·언어 보존, 결과 재열람, 환불·타 계정 차단을 포함한다. 이후 추가한 위치·원본 재시도 연결은 별도 targeted 검사한다.
- `npm run build --prefix apps/toss` 통과: AIT 58,579,454 bytes. 화면에서 사용하는 원본 타로 std WEBP/AVIF를 유지하고 사용하지 않는 다른 해상도만 제외했다. 원본 글꼴은 내용 해시로 같은 파일에 연결하고 Latin 두 파일과 OFL을 묶음에 포함했다.
- 출시 빌드 4318에서 390px/1280px 입력·보관함·로그인·결과 대기 화면 실제 검수: 가로 넘침·깨진 이미지·React 중단 없음. 불필요한 웹 결제 Provider와 외부 글꼴 CORS 문제 수정 후 재검수 통과. 실기기 SafeArea/로그인/구매/생성 증거는 아니다.
- 공식 CI 40826722639(d5ae9f2d4), 40827772783(e63db34ea), 최신 40831088590(65a864b88) 모두 성공 확인. 과거 로컬 검사 실패와 공식 CI를 구분한다.
- `check:fast`: 90개 결제/인증 가드 중 89개 통과, `npm test` 안의 출생지 테스트 2개 실패. Jest 435 suites/7096 tests 통과, Node 3912개 중 3910개 통과. 원인은 기존 테스트가 index.js의 함수만 추출하며 새 공통 geocodePlace를 주입하지 않은 것. 테스트를 실제 공통 함수에 연결한 뒤 해당 2개 재실행 통과. 전체 공통 검사를 통과했다고 표현하지 않는다. 이후 토스 경계 targeted 23개 통과.
- `check:pre-push`에서 생성된 사이트맵 서명 원장 차이를 발견해 `npm run sitemap:generate`로 갱신했다. 재검사 통과.
- 승인 상품 목록 비어 있음, SERVICE_AVAILABLE=false 유지. 영냥이 출시 코드 연결은 로컬 커밋으로 보존했으며, 새 커밋 공식 CI/실기기 검증 전이므로 완전 이식 완료 수를 올리지 않는다. 찻집·네오는 아직 영냥이 persona 경로가 남아 있고 원본 서버 이식은 미완료다.

## 다음 구현

영냥이 출시 UI/결과 경계 검증을 마치고 작은 커밋으로 보존한다. 찻집/네오는 원본 전체 생성 handler의 접근 증빙 경계만 분리한다. 개별 LLM 함수만 호출해 checkpoint·중복 방지·저장을 생략하지 않는다. 그 다음 초융합을 별도 단위로 진행한다.

## 2026-10-29 찻집 단위 검증 및 CI 원인 확정

- 영냥이 연결은 `431d91fbd`·`07f5142bb`·`2e12db017`로 main에 push했다. 공식 CI 40836538356은 실패했다. 후속 main `d5cf9ede24d7f7cb0be145681b7faa77f3fe5c07`도 같은 실패가 남았다.
- 이번 테스트의 `module` 변수명이 Next lint에 걸린 오류는 `serviceRuntime`으로 고쳤다. 이전 `133e47ce6`의 analyticsChannel 공개 계약 검사 누락과 Node 마케팅 검사의 Jest 오수집도 확인했다. 해당 계약 키·UNKNOWN 검사, 정확한 Node/Jest 수집 목록을 보완했다. CI 수정은 `29fef91b8`로 분리 커밋했다. 관련 Jest 80개, Node 9개, 서비스 연결 5개와 파일 lint 통과. 전송 전 검사는 찻집 미커밋 변경 때문에 보류되었으며 모두 커밋한 뒤 다시 실행한다.
- 찻집 원본 화면·카드 선택·원본 결과·추가 질문·보관함을 출시 진입에 연결했다. 별도 일반 상담으로 바꾸지 않았다. 웹 원본은 기본 동작을 유지하고 Toss 서버만 Request 객체에 인증/주문 증빙을 연결한다. 고객이 보내는 헤더나 결제 설명으로 권한을 만들지 않는다.
- TossNativeConsultation은 소유자·환경·기능·원본 입력 해시·결과 ID를 고정하고 원주문을 원자적으로 연결한다. 승인 SKU 목록은 여전히 비어 있다. 결제 전 준비 입력, SDK 지급 확인, 카탈로그 제거 뒤 구매 증빙, 체크포인트 이전 중단, 원본 pending 복구와 완료 결과 재열람을 연결했다. 환불·탈퇴와 다른 계정/환경은 차단한다.
- 원본 생성 handler와 저장 코드를 실행한 오프라인 검사에서 실제 카드 선택 → 모의 AI 여러 부분 생성 → 원본 결과 저장 → 추가 생성 없는 재열람 → 회수 차단을 확인했다. 토스 전체 135/135, 원본 찻집 109/109 통과. 서버 dry-run 통과. 변경 파일 lint 0 errors / 52 warnings(기존 타입·이미지 관련 경고 포함). 이 수치는 실 AI·운영 DB·실결제 증거가 아니다.
- 타입 오류 2곳을 명시적 타입으로 보완했다. 숙요 입력 어댑터는 같은 순수 함수를 `sukuyo-coordinate`에서 가져오도록 해 브라우저 묶음에 서버용 Swiss WASM이 섞이던 빌드 오류를 해결했다.
- 앱 빌드 통과, AIT 74,055,622 bytes, deploymentId `01a186be-5d80-7d0d-b921-875ea6216ea9`. PDF 표지의 동적 경로를 414개 전체 서비스 그림으로 오인해 담던 부분은 원본 표지 목록에 지정된 파일로 제한했다. 원본 그림의 해상도/바이트를 바꾸지 않았다. 지연 조회하는 찻집 상품 설명 manifest·삽화도 묶음에 포함했다.
- 390px/1280px 실제 렌더 검수: 찻집 → 사주 입력 1/3 진입, 보관함, 저장 결과 로그인 상태에서 넘침·깨진 이미지 없음. Mulmaru CORS 오류는 원본 동일 글꼴을 포함해 수정, 재검수에서 390px/1280px 찻집·보관함의 로컬 글꼴 200과 외부 폰트 요청/CORS 없음까지 확인했다. 외부 배경·음악은 원본 경로를 유지한다.
- 다음 순서는 네오 전략실 → 초융합 → 인생의 책 → 연애 비책 → 전문가 및 나머지 서비스. 각 단계의 원본 화면·계산·저장·복구를 확인하기 전에는 신규 판매를 열지 않는다. 네오와 초융합은 아직 출시 원본 연결 완료로 표기하지 않는다.
