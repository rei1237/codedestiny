# 앱인토스 대표 기능 후속 이식 원장

status: in-progress

next: 전체 출시 범위의 원본 계약·권한·복구를 검증하고 미이식 기능을 계속 구현한다. 심사 제출은 모든 차단 해소와 사용자 최종 승인 이후에만 진행한다.

## 범위와 순서

사용자 요청: 초융합 다음에도 대표 기능을 빠뜨리지 않고 이식한다. 특히 **사주 풀이 화면 내부의 사주 기능**을 포함한다. 현재 구현은 전체 출시 범위로 확장되었으며 서비스별 검증 단위는 구분한다.

기존 순서를 유지한다: 초융합 → 인생의 책 → 연애 비책 → 전문가 상담 → 기본 명식·운세 → 독립 타로 → 기타 독립 서비스. 같은 그룹은 `full-service-inventory.json`의 원장 순서로 진행한다. 이미 연결된 서비스는 재구현 대신 누락·회귀를 먼저 확인한다.

점성술 전문가 상담은 토스 홈·직접 주소·원본 입력 및 결과 화면, 토스 상품 확인, 계정별 프로필, 주문 권한과 결과 복구 경로를 코드에 연결했다. 원본 웹 결과 로더는 보존하고 토스 전용 결과 로더를 분리했다. 원본 결과의 토스 출처를 저장하고 주문·소유자·입력 및 환불을 재확인하며, mock 검사와 로컬 빌드를 수행했다. 승인 SKU·실제 콘솔 가격, 재시작 후 미확정 결제의 내구성, 공식 샌드박스·기기, AI 및 개인정보 정책 검증이 남아 있으므로 부분 구현이다.

`npm run launch:status --prefix apps/toss`의 현재 canonical 후보는 89개이며, 이 중 34개는 부분 구현이고 나머지 55개는 추가 이식 또는 원본 계약 확인이 필요하다. 완료와 제외는 각각 0개이고 최종 출시 범위는 아직 확정되지 않았다. 이전 조사에서 사용한 후보 91개는 이 문서 작성 당시의 이력이다.

숙요점 궁합 전문가 상담은 토스 홈·직접 주소, 계정별 입력, 상품 표시, 주문에 묶인 저장 결과와 재열람을 연결하고 공식 devtools의 로컬 mock으로 구매·새로고침을 확인했다. 미연결 주문은 계정·주문·상품·기존 가격을 확인한 뒤 저장 입력을 명시적으로 선택해 연결하고, 로컬 모의 주문으로 결과 복귀를 확인했다. 거부된 권한과 늦게 도착한 응답은 결과나 저장 입력을 다시 노출하지 않는다. 저장 입력이 없을 때 새 입력을 같은 주문에 연결하고 생성 실패를 명시적으로 재시도하는 경로는 로컬 모의 테스트했다. 운영 복구 인덱스, 실제 승인 SKU, 최초 구매자 검증, 주문 ID 없는 불확실 결제, AI 정책과 공식 기기는 미완료다.

찻집의 웹 꿀방울 잔액·앨범·재화 편지 경로는 토스 권리 매핑이 없어 토스 화면에서 임시로 숨기고 웹 잔액 조회를 중지했다. 이는 출시 제외나 이식 완료가 아니다. 기존 웹 화면과 권리를 유지하며, 토스에서 기존 권리를 보존할 방법과 정책 적합성을 확인하기 전까지 찻집은 부분 구현이다. 별도 연이 편지 상담은 이 재화 편지와 다르다.

찻집 저장 결과에도 토스 화면 구분을 전달해 웹 전용 꿀방울 안내가 다시 나타나지 않도록 했고, 결과와 보관함의 이동 경로를 토스 홈·보관함에 연결했다. 기존 웹 경로는 유지하며 이 동작은 모의 화면 테스트로 확인했다. 실제 토스 기기의 뒤로가기와 전체 결제·복구 검증은 남아 있다.

연이 편지 상담은 계정 전환 순간 이전 계정 결과를 숨기고, 새 계정에서 기존 주문과 상품 표시를 다시 확인한다. 이전 계정의 늦은 상품 응답은 사용하지 않으며 로그아웃 후 재로그인도 주문을 재검증한다. 모의 회귀 테스트만 통과했고 승인 SKU·구매자 검증·공식 기기 확인은 남아 있다.

2026-11-06 최신 main 통합 커밋 `7c431ae36c0a47c7ca4d19d7e201290f73a07f8e`의 레지스트리로 다시 생성한 결과도 후보 89개·부분 29개·추가 확인 60개다. 최신 홈에서 나침반·나크샤트라 궁합/택일/VVIP·사주 궁합·사주 가디언·천체의 선율·십이지신 타로의 표시가 5,000원으로 바뀌었고, 각 feature key를 서버 `getBillingFeaturePricing`으로 확인한 금액도 5,000원이다. 이는 기존 main의 현재 설정 관측이며 토스 SKU 등록·가격 변경이나 이전 구매 재가격을 뜻하지 않는다.

운명의 업 상담은 토스 홈·직접 주소·로그인 복귀, 기존 입력·결과 화면, 토스 주문과 입력 해시를 결합한 저장·복구 경로와 승인된 결과의 추가 질문을 코드에 연결했다. 추가 질문은 저장 ID와 구매 권한을 재확인하며 서버 복구·중복 질문·환불·계정 전환을 모의 검사했다. 윤달 입력·저장과 구매 전 음력 유효성도 모의 검사했다. 로컬 목 화면의 360·390·430px 너비와 일본어 일부, 추가 질문 입력의 390px 화면을 확인했으나 다른 언어 품질, AI 안전 정책, 최초 주문 구매자 결합, 재시작 후 미확정 결제, 승인 SKU와 공식 기기는 미검증이라 부분 구현이다. 토스에서 보장되지 않는 분량·특정 기간은 표시하지 않는다.

연애 비책은 토스 기록 출처와 저장된 주문을 재확인하는 추가 질문의 화면·서버·자동 복구 경로를 연결했다. 저장되지 않은 완료 응답과 다른 상담·계정의 지연 응답은 숨기며, 환불·결제 권한 거부와 원래 답변 복구를 모의 검사했다. 390px 로컬 목 화면에서 입력과 버튼을 확인했다. 출처가 없는 과거 기록의 웹 경계, 최초 구매자 검증, AI 안전 정책, 승인 SKU 및 공식 기기는 미검증이므로 부분 구현이다.

마야 달력은 부분 이식이다. 토스 홈·직접 주소의 날짜 계산과 원본 프롬프트 생성, 구매 권한 확인, 결과 저장·재열람, 미연결 주문의 명시적 저장 입력 선택·복구를 모의 구현했다. 계정 전환·환불·지급 중단과 중복 결제 차단을 모의 검사했으나 운영 인덱스, 승인 SKU, 최초 구매자 결합, 주문 번호 없는 미확정 결제, 실제 결제창 금액과 공식 기기는 미검증이다. `src/components/maya/MayaPromptGeneratorCard.tsx`와 `src/components/maya/_lib/copy.ts`의 웹 표시는 3,000원, 서버 정본 `getBillingFeaturePricing({featureKey:'maya-prompt-generator'})`은 5,000원으로 불일치한다. 원본은 외부 AI에 붙여넣는 프롬프트를 제공하므로 [서비스 오픈 정책](https://developers-apps-in-toss.toss.im/intro/guide)상 등록 기능이 미니앱 안에서 완결되는지 확인이 필요하다. 이는 정책 위반 확정이나 출시 제외 결정이 아니다. 가격·상품은 변경하거나 등록하지 않았다.

신년운세 전문가 상담은 토스 홈·직접 주소, 원본 입력과 계산 사전 검증, 구매 계정에 묶인 결과 조회·복구를 연결했다. 목 테스트와 로컬 빌드, 360·390·430px 너비 및 모바일 프로필 배치를 확인했다. 일본어 입력은 결과가 한국어로 생성됨을 고지한다. 승인 SKU, 결제 재시작 복구, 일본어 외 언어의 화면 품질, 공식 기기 및 전체 흐름은 미검증이라 부분 구현이다.

자미두수 전문가 상담은 토스 홈과 직접 주소, 원본 입력 검증, 토스 주문과 계정에 묶인 결과 조회 및 복구를 연결했다. 로컬 모의 테스트와 360·390·430px 화면을 확인했으며 일본어 입력 화면은 결과가 한국어로 생성됨을 고지한다. 승인 SKU와 결제 상태의 재시작 복구, 다른 언어 품질, 공식 기기 및 전체 상담 흐름은 미검증이므로 부분 구현이다.

베다 전문가 상담은 토스 홈·직접 주소·계정별 프로필·원 주문에 연결된 결과 복구를 코드에 연결했다. 12개 언어 안내의 문구 존재와 일본어 로컬 화면, 360·390·430px 로컬 너비를 확인했으나 각 언어의 품질·정식 기기·SKU·결제 재시작 복구와 정책 검증이 남아 부분 구현이다.

사주 FPTI는 원본 `lib/fpti/fpti-adapter.ts`로 국내 출생정보의 기본 성향을 계산하는 토스 화면을 연결했다. 무료 결과는 현재 화면에만 남으며 토스 SDK의 공유·복사를 로컬 모의 검증했으며 출생정보 원문은 공유하지 않는다. 계정이 바뀌면 기존 입력과 결과를 지우고 진행 중인 계산·공유의 늦은 응답을 무시한다. 원본의 전체 무료 결과·프로필 연결, 영구 심층 권리와 공식 기기는 아직 이식 또는 검증 중이다.

네오 이메일 상담 `neo-consultation`은 전략실 `neo-operation-room`과 별도 후보이다. 원본 `app/neo-consultation/checkout.ts`는 이메일 주소와 웹 단건 결제를 사용하고 모바일 앱 결제를 차단한다. 토스 상품·주문 소유권·신청 후 이메일 전달·개인정보 고지와 재열람을 확인하기 전에는 전략실 이식으로 완료 처리하거나 웹 결제를 노출하지 않는다.

## 사주 풀이 화면은 만세력과 별도 검증

현재 `apps/toss/src/ManseReading.tsx`는 네 기둥·십성·오행 개수·대운 목록을 표시하는 간단 계산 화면이다. 응답은 `stored:false`이며 화면에서도 보관함 미저장을 안내한다. 이를 원본 사주 풀이 전체 완료로 처리하지 않는다.

원본 진입점은 `/?action=cdOneStepFreeSajuEntry`, 결과 정본은 `index.html`의 `resultPage`와 연결된 사주 계산·렌더링 코드다. 후속 작업에서 아래를 각각 원본과 대조한다.

| 작업 단위 | 원본 근거 | 완료 기준 |
|---|---|---|
| 기본 명식·일주·오행 해설 | `sajuCard`, 일주 상세, 오행 균형도, `js/core/saju/reading-personas.js` | 원본 계산·해석·생시 미상 처리·입력 유지·모바일 조작 동등성 |
| 십성·신살·조후·억부·절기 | `tenshinCard`, `johuCard`, `ukbuCard`, `terms24Card` | 각 체계 설명과 실제 계산 근거 보존, 비노출 조건 확인 |
| 대운·현재 시기 | `daewunCard`, `currentSeasonCard`, 생애 그래프 | 원본 시기 선택·표시·근거 및 기존 권한 조건 검증 |
| 라이트 사주 풀이 | `summaryCard`, `js/core/access-store.js`의 `saju.fullReading` | 기존 상품·가격·권리와 저장 원문 재열람의 대응 확정 |
| 궁합 | `compatCard`, `/saju/compatibility/` | 두 사람 입력·연애/사업/친구 선택·주문·저장·복구 검증 |
| 사주 화면 내 독립 콘텐츠 | 유명인·사주네컷·퀀텀·RPG·에너지 등 원본 카드 | 원장 후보와 중복을 정리한 뒤 한 서비스씩 원본 기능 확인 |

무료·유료 여부는 현재 원본 정책과 가격 등록소를 다시 확인한다. 이 표는 새 혜택·상품·저장 기능을 약속하지 않는다. 유료 대응이 확정되지 않으면 판매를 열지 않는다.

## 사주 모아보기의 대표 기능 누락 방지

`lib/saju/saju-service-catalog.mjs`의 `SAJU_SERVICE_ITEMS`를 화면 목록의 정본으로 대조한다. 대표 상담 6개뿐 아니라 무료 사주, 만세력, 오늘의 운세, FPTI, 유명인 사주, 다이어리, 궁합, 대화형 상담, 네오 이메일 상담, 시빌라, 영냥이 사주, 나침반, 인연의 장소, 최애운명, 가디언, 동물점, 뇌구조, 작명, 반려동물, 초융합과 공부 링크를 포함한다.

독립 기능·안내 문서·같은 서비스의 다른 진입점을 구분하되 목록에서 임의 삭제하지 않는다. 원장에 없는 현재 카탈로그 항목은 해당 단계에서 근거를 추가한다. 외부 접수나 지원되지 않는 기능을 단순 링크로 열어 이식 완료로 처리하지 않는다.

## 각 단계의 통과 기준

입력 → 구매(해당 시) → 생성/계산 → 저장(원본 지원 시) → 재열람 → 이탈 복구를 검증한다. 계정·환경 격리, 입력 변조, 중복 요청, 환불 접근 회수, 기존 구매 결과 보존을 포함한다. 360/390/430px와 넓은 화면을 확인하고 mock 검사 → `check:fast` → 작은 커밋 → `check:pre-push` → main CI 성공 근거를 남긴다.

상품 30개 제한과 가격·권리 대응표는 별도 출시 게이트다. 상품 통합·가격·이용권·월정석·단건 결제 정책을 이 원장으로 변경하지 않는다. `SERVICE_AVAILABLE=false`와 미승인 상품 차단을 유지한다.
