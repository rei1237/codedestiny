# 이미지형 상세 팝업 · 공개 소개 공유 개선

## 실제 변경

- 별도 상세페이지로 다시 이동하라는 팝업 링크를 제거했다. 기존 공개 소개 URL은 공유를 받은 사람이 들어오는 목적지로 유지한다.
- 공개 이미지형 상세 63개에 질문형 Hook을 제공한다. 새로 통합한 관상은 기존 질문 패널을 재사용하고, 기존 카피에 없던 9개는 홈의 `FEATURE_VISUAL_DETAILS`에서 저작하며 모두 질문 3개 이상이다.
- 기존 이미지·SVG/HTML 패널을 보존하고 미리보기를 앞에 배치한다. 같은 질문 목록의 중복은 제거한다. 해석 안내와 기존 상품 FAQ를 이미지형 렌더러 안으로 가져왔다.
- 가격·이용 방법 버튼은 기존 가격 표시와 CTA로 이동하고 포커스만 전달한다. 자동 클릭·결제·새 권한 판정은 없다.
- 정적 팝업의 본문 스크롤과 하단 CTA를 분리한다. React 팝업도 같은 렌더러·공유 도우미를 사용한다.
- 홈에서 사이트 소개 공유·링크 복사가 가능하다. 각 상세 팝업에서는 기능 소개 공유·복사와 사이트 소개 공유를 선택할 수 있다.
- 기기 공유가 없으면 링크 복사, 복사가 안 되면 읽기 전용 링크 선택으로 이어진다. 공유 취소는 복사나 성공으로 바꾸지 않는다. 중복 클릭은 한 번만 실행한다.
- 공개 소개 페이지가 `noindex`라 공유 위젯까지 차단되던 문제를 공개 기능 소개 경로에 한정해 수정했다. 검색 색인 정책과 비공개 경로 차단은 유지한다.
- 기능 소개의 OG/Twitter 제목에 해당 기능의 질문형 Hook을 사용하고 기존 대표 이미지를 유지한다.
- 기존 추천 블록은 “다른 체계에서도 같은 흐름이 보일까요?”라는 다음 탐색 이유를 제시한다. 링크 목적지와 계측은 유지한다.

## 구매 6단계

| 단계 | 적용 위치와 역할 |
| --- | --- |
| 인지 | 이미지형 팝업의 첫 제목에서 사용자 질문을 제시 |
| 호기심 | 기존 체계별 이미지·시각 미리보기를 앞에 배치 |
| 검토 | 실제 제공 항목·필요 입력·기존 상품 FAQ |
| 신뢰 | 기존 해석 과정과 참고 안내. 경력·후기를 새로 만들지 않음 |
| 전환 | 기존 가격·이용 방식·CTA로 연결. 안내 버튼이 결제를 실행하지 않음 |
| 공유 | 기능 소개 또는 사이트 소개를 자발적으로 전달. 받은 사람이 해당 소개와 기존 이용 CTA로 진입 |

## 공유 경계

`js/feature-introduction-share.mjs`는 기존 `js/share-service.mjs`를 재사용한다. 기능은 `/features/{검수된 slug}/`, 사이트는 `/`만 공유한다. 현재 URL, 생년정보, 질문, 결제 ID, 개인 결과를 읽거나 붙이지 않는다. 공유 쿼리는 기존 공개 공유 UTM 규격만 사용한다.

기존 `share_button_click`과 공유 결과 이벤트를 사용하며 수신은 `share_receive`로 집계한다. 수신 이벤트에는 소개 slug 또는 `site`만 추가한다. 복사·기기 공유 요청·취소는 구분하며 실제 수신이나 구매 성공으로 간주하지 않는다. 카카오톡은 기기 공유 또는 복사로 사용할 수 있고, 기존 공개 소개 페이지의 채널 위젯도 유지한다. 개발 검증에서 실제 메시지는 전송하지 않는다.

## 주요 원본

- `index.html`: 누락 Hook 9개와 홈 사이트 공유. 정적 카피·미러 정본.
- `js/feature-detail-panels.mjs`, `js/feature-detail-preview.mjs`: 이미지형 본문·팝업 연결.
- `app/components/FeatureVisualDetail.tsx`, `FeatureMarketingDetailModal.tsx`: React 연결.
- `js/feature-introduction-share.mjs`, `lib/share.v2.ts`, `js/core/analytics.js`: 공개 공유와 유입 계측.
- `scripts/lib/build-visual-details.mjs`: 기존 저작 데이터에서 63개 공개 소개 생성. 생성 JSON·미러는 직접 수정하지 않음.

## 검증 명령과 증거

- `node scripts/verify-feature-popup-journey.mjs`: 실제 정적 팝업 템플릿 63개 × 360/390/430/1280px, 가로 넘침·CTA 44px·본문 가림·소개 공유 URL·홈 공유·한국어 범위 검증. LLM/결제/API 호출 차단, 기존 CDN 이미지만 허용.
- `node --test __tests__/ui/feature-visual-details.test.mjs __tests__/ui/feature-introduction-share.test.mjs`: 미검수 결과 차단·escaping·로더 재시도·공개/비공개 경계·취소·수동 복사·중복 공유·계측 실패 검증.
- `npm run verify:analytics-events`: 기존 리퍼럴과 공개 소개 UTM 유입, 수신 1회 발화.
- `npm run verify:mobile-detail-nonintrusive`, `npm run verify:hero-contrast`: 공용 모바일 래퍼와 대비 규칙 보존.
- `npm run sync:public`, `npm run sitemap:generate`: 생성 원본 정합. `verify:public-mirror-fresh`는 clean 커밋 후 실행해야 한다.
- `npm run check:fast`: 최초 실행은 sitemap lastmod 드리프트에서 중단되어 생성기로 갱신했다. 최종 실행 결과는 PR과 최종 보고에 기록한다.

## 기대 영향과 A/B 테스트 후보

아래 영향은 실측 전 가설이다. 우선순위는 이번 수정 범위의 사용자 동선을 기준으로 한다.

1. 기능명보다 질문을 먼저 보여 소개 읽기 시작률을 높인다.
2. 기존 이미지 미리보기를 앞에 배치해 스크롤 지속을 돕는다.
3. 팝업 안에서 가격 안내로 이동해 검토 중 이탈을 줄인다.
4. 기존 하단 CTA를 본문과 분리해 모바일 행동 경로를 유지한다.
5. FAQ와 해석 근거를 이미지 상세에서도 보여 구매 전 의문을 줄인다.
6. 기능 소개 공유로 상대방에게도 같은 질문과 제공 내용을 전달한다.
7. 홈 사이트 공유로 특정 기능을 고르기 전에도 추천할 수 있게 한다.
8. 공개 소개의 공유 위젯 차단을 해소해 기존 채널 공유를 복원한다.
9. 공유 수신을 기능별로 구분해 어떤 소개가 방문으로 이어지는지 확인한다.
10. 관련 체계를 비교하는 추천 문구로 결과 이후 탐색 이유를 제공한다.

A/B 후보: 질문형 제목과 기존 기능명 제목, 첫 이미지 뒤와 본문 끝의 가격 안내 버튼, 기능 소개 공유 문구 두 안, 홈 공유 영역 위치. 성공 지표는 상세 방문 대비 기존 CTA 클릭률과 공유 수신률이며, 구매는 기존 구매 성공 이벤트로만 평가한다. 공유 클릭 수만으로 바이럴 또는 구매 증가를 결론 내리지 않는다.

## 보존 및 잔여 범위

가격·이용권·월정석·단건 결제, entitlement, 로그인, 결제 resume, 개인 결과의 공개 범위를 변경하지 않았다. 공유는 기능 소개를 전달하며 유료 결과 원문을 해금하지 않는다.

이 변경을 전체 사이트 구매 여정 감사 완료로 간주하지 않는다. 63개 이미지형 상세 밖의 경로, 실제 PG·실기기 카카오톡, 공유 유입의 실측 구매 전환율은 별도 확인이 필요하다. 새 보상·할인·공유 강요 팝업은 없다. 공유 효과는 배포 후 실측하며 증가율을 보장하지 않는다.
