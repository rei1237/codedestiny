## 레퍼런스 분석 요약 — 도화서원

### A. 무료 섹션 · 띠별운세
| 요소 | 도화서원 방식 | 꿀꿀운세 적용 |
|---|---|---|
| 진입 목록 | `/free` 한 화면에 카드 4개. 카드 = 포스터 이미지 + 제목 + 한 줄 설명 + "무료" 배지 | 무료 운세를 한 목록, 한 경로로 정리 (지금은 같은 기능이 5군데에서 다른 URL로 노출) |
| 페이지 상단 | 섹션 태그 → H1 → 한 줄 부제 → 대표 일러스트 → 오늘 날짜 | 모든 기능에 같은 히어로 틀 |
| 흐름 안내 | "전체 운세 → 띠 선택 → 개별 운세" 3단계를 아이콘으로 먼저 보여줌 | 모든 기능을 3~4단계 스텝 플로우로 통일 |
| CTA | 화면당 주 버튼 1개 | 단계마다 주 CTA 1개, 유료 유도는 결과 하단 1곳 |

### B. 타로 (연애·운명·재회 타로, 오늘의 운세, 탄생 타로)
| 요소 | 도화서원 방식 | 꿀꿀운세 적용 |
|---|---|---|
| 기능 랜딩 | 무음 인트로 영상(포스터 이미지) + 감성형 H1 + 한 줄 부제 + 주 CTA "○○타로 시작하기" + 보조 문구 "무료로 간단 풀이를 만나보세요" | 타로 기능마다 같은 랜딩 틀. 첫 화면에서 "무엇을 봐주는지 + 무료 범위"가 바로 보이게 |
| "이게 뭔지" 설명 | "탄생 타로란?" 블록에서 개념과 카드 종류(소울/성격 카드)를 짧게 설명 | 기능마다 "이 타로는?" 블록: 무엇을 봐주는지, 카드 몇 장, 소요 시간 |
| 신뢰 문구 | "무료, 로그인 불필요, 생년월일 전송·저장 안 함" / 공유 링크엔 카드명과 일반 해석만 | 입력·공유 범위를 CTA 바로 아래 한 줄로 |
| 주제 선택 | "이야기를 선택해 주세요" 모달에서 가장 가까운 항목 선택 | 주제 칩 단일 선택 → 자동 진행 |
| 뽑기 | 무료 3장 / 유료 심화 5장. 오늘의 운세는 "마음이 머무는 상자"를 5개 중 1개 고르는 방식, 단계는 `?step=draw` 쿼리 | 무료 n장 → 유료 심화로 장수 확장. 단계는 URL 쿼리로 |
| 무료 결과 | 요약 → 카드별 해석 → "오늘의 한 걸음"(일러스트 + 실천 한 줄) | 같은 구성 + 캐릭터 웹툰 컷으로 연출 (아래 C) |
| 유료 심화 | "더 깊은 이야기가 궁금하다면" → 리포트 구성 예시 → 챕터형 리더(목차, 표지, 이전/다음 챕터, 글자 크기 기본 "크게") | 유료 리포트도 챕터형 웹툰 리더로 |
| 결과 액션 | 다른 정보로 다시 보기 / 이미지 저장 / 공유(카카오) / 보관함(로그인) / 별점 후기 | 동일 구성, 로그인은 저장·후기에만 요구 |
| 고지 | "타로는 성찰 도구이며 미래나 상대 마음을 확정하지 않음" | 결과 하단 고정 고지 |
| 하루 1회 | 오늘의 운세는 하루 1회 무료, 같은 날 같은 브라우저에서 다시 보기 | 오늘의 타로/운세에 동일 규칙 |

### C. 캐릭터 웹툰형 결과 (도화서원에 없는, 꿀꿀운세만의 차별점)
- **꿀꿀운세 경로 → 꽃돼지 연이**가 말해주는 결과 / **영냥이 경로 → 영냥이**가 말해주는 결과
- 세로 스크롤 컷 + 말풍선. 이미 있는 영냥이 상담·달빛 연화당의 웹툰 연재형 화면을 재사용 기반으로 삼음

> ⚠️ 확인 못 한 부분: 도화서원의 카드 셔플·뒤집기 애니메이션, 자동 넘김 타이밍, 실제 결과 화면 배치는 JS로 그려져서 이번에 확인하지 못했습니다(브라우저 연결 불안정). 1단계에서 에이전트가 직접 눌러보며 기록하게 했습니다. 아래 타이밍 수치(0.45초 등)는 시작용 제안값입니다.
> 레퍼런스에서는 **구조와 동작 패턴만** 가져오고, 이미지·문구·일러스트는 복사하지 않습니다.

## 0. 공통 머리말 (모든 단계 앞에 붙이기)

```
너는 code-destiny 저장소(꿀꿀운세 code-destiny.com + 영냥이)의 시니어 프론트엔드 엔지니어다.
작업 전 루트 CLAUDE.md 와 작업별 필독 라우팅 표가 가리키는 docs/context/*.md 를 먼저 읽어라.

[작업 방식]
- 게이트 방식: 진단(읽기 전용) → 구조화된 보고 → 내 승인 → 구현 → 검증. 승인 전에는 코드 수정 금지.
- 파일 경로를 추측하지 마라. 반드시 grep/ls 로 실제 경로를 확인한 뒤 인용하라.
- 최소·외과적 변경. 브랜치 작업, Conventional Commits.
- 새 규칙·근거 문서는 docs/context/<주제>.md 에 쓰고 루트 CLAUDE.md 에는 한 줄 링크만(@import 금지).

[절대 불변 조건 — 위반 시 즉시 중단하고 보고]
1. 6개 점술 엔진(사주·타로·자미두수·점성술·숙요·베다) 코드베이스는 읽기 전용. UI는 어댑터 래퍼로만 접근.
   카드 무작위 선택·정역방향 결정·해석 원문 생성 로직을 바꾸지 마라.

3. PortOne/Inicis 결제 실행 파일은 별도 승인 게이트, 이번 범위 밖. 결제 순서 정본(이용권 우선) 변경 금지.
4. 데스크톱 960px 레이아웃 유지. 모바일만 개선하고 데스크톱 회귀 없어야 한다.

7. 결제 데이터·KV/R2 스키마·사용자 자산(저장된 타로 결과 등) 포맷은 forward-fix-only. 기존 저장 결과가 새 UI에서 계속 열려야 한다.
8. 파일 삭제가 필요하면 npm run clean:repo:dry → clean:repo:apply 를 쓴다. MOBILE_*.md, PAYMENT_POLICY.md 등 검증기가 읽는 문서는 건드리지 마라.

[성능 원칙]

## 1단계. 현황 감사 + 레퍼런스 실측 (읽기 전용)

```
[0번 공통 머리말]

3. 재사용 가능 여부와 부족한 에셋(필요한 표정 목록 대비)을 정리.

D. 레퍼런스 실측 (브라우저 도구로 390px 모바일 뷰포트에서 직접 진행)

## 2단계. 통합 UX 스펙 정의 (문서만)

```
[0번 공통 머리말]

입력: docs/context/free-tarot-ux-audit.md (1단계 승인본)

목표: 무료 운세·타로·캐릭터 웹툰 결과가 공통으로 쓸 스펙을 확정한다. 코드 수정 금지.

1. 화면 골격 (모바일 360~430px)
   - 랜딩: 섹션 태그 → 감성형 H1 → 한 줄 부제 → 대표 비주얼(고정 비율, CLS 0. 영상은 무음·자동재생·포스터 우선, 저사양/절전 모드에선 포스터만)
     → 주 CTA "○○ 시작하기" + 보조 문구 "무료로 간단 풀이를 볼 수 있어요"
     → 신뢰 한 줄(로그인 없이 가능 / 입력 정보 저장 범위 / 공유 범위)
   - "이 기능은?" 블록: 무엇을 봐주는지 1줄, 카드 장수 또는 필요한 정보, 소요 시간, 무료 범위
   - 스텝 안내 아이콘 3~4개, 하단 고정 주 CTA(safe-area 반영, 터치 영역 48px 이상)

2. 자동 진행 규칙 (1단계 실측값이 있으면 그 값을 우선)
   - 단일 선택(주제·띠·상자·카드 장수): 선택 피드백(눌림+체크) → 450ms 후 자동 다음 단계.
   - 텍스트 입력·다중 선택: 자동 진행 없음, CTA로만.
   - 연산 대기(셔플·계산): 최소 1.2초 연출, 준비되면 자동 전환. 늦어지면 캐릭터가 "조금만 기다려 줘" 류 대사로 대기 안내.
   - 전환: 다음 단계는 오른쪽에서 24px 슬라이드 + 페이드(240ms), 뒤로는 반대. transform/opacity 만.
   - prefers-reduced-motion: 슬라이드 제거, 페이드 120ms, "다음" 버튼 항상 노출.
   - 대기 중 다른 항목 선택 시 타이머 리셋. 단계는 URL ?step= 과 history state 에 반영, 새로고침 시 결과 유지.
   - 단계 전환 시 새 단계 제목으로 포커스 이동, aria-live 로 진행 안내.

3. 타로 통합 플로우
   ① 랜딩(위 골격) → ② 주제 선택(칩 단일 선택 → 자동 진행 / "직접 입력"은 CTA) →
   ③ 셔플(자동, 탭하면 스킵) → ④ 카드 펼침에서 n장 선택(탭 우선, 선택 카드는 상단 슬롯으로 이동, 다시 탭하면 취소, 마지막 장 선택 시 자동 진행) →
   ⑤ 공개(슬롯 카드 순차 자동 뒤집기 600ms 간격, 탭하면 즉시 전부 공개) →
   ⑥ 캐릭터 웹툰 결과(4번 항목) → ⑦ 결과 액션(다른 주제로 다시 보기 / 이미지 저장 / 공유 / 보관함 / 후기) →
   ⑧ 유료 심화 안내 1곳("더 깊은 이야기가 궁금하다면" + 리포트 구성 예시 + 가격)
   - 뒤집기는 rotateY + backface-visibility, will-change 는 애니메이션 중에만. 카드 이미지 고정 aspect-ratio.
   - 기능별 차이(장수, 배치, 주제 목록, 결과 섹션, 화자 캐릭터)는 설정 객체로만 표현. 화면 코드는 하나.
   - 오늘의 타로/운세: 하루 1회 무료, 같은 날 같은 브라우저(로그인 시 계정)에서 다시 보기.

4. 캐릭터 웹툰형 결과 화면
   - 화자 결정: 꿀꿀운세 경로 = 꽃돼지 연이, 영냥이 경로(/yeongnyangi/ 등 1단계에서 확인된 경로) = 영냥이. 설정의 narrator 값으로 결정.
   - 컷 구성(세로 스크롤):
     a. 오프닝 컷: 캐릭터 등장 + 인사, 사용자가 고른 주제를 짚어주는 한마디
     b. 카드 컷(카드 1장당 1컷): 카드 이미지 + 카드명·정/역방향·키워드 + 캐릭터 말풍선 해석 2~3문장
     c. 종합 컷: 카드들을 이어서 하나의 이야기로 정리
     d. "오늘의 한 걸음" 컷: 오늘 해볼 행동 한 가지
     e. 마무리 컷: 응원 한마디 + 유료 심화로 넘어가는 자연스러운 대사(가격은 말풍선 밖 UI에 명시)
   - 말풍선은 이미지에 굽지 않고 HTML 텍스트로(i18n·접근성·검색). 이미지 저장 시에만 캔버스로 합성.
   - 표정 규칙: 기본/미소/진지/걱정/응원 등 표정 세트를 정의하고, 카드 정·역방향과 해석 톤에 따라 컷별 표정을 고르는 규칙표를 만든다.
   - 연출: 컷이 화면에 들어올 때 페이드업(IntersectionObserver), 말풍선 타이핑 효과는 짧게(탭하면 즉시 전체 표시), reduced-motion 이면 즉시 표시.
   - "글로만 보기" 토글(같은 내용을 일반 텍스트 카드로)과 글자 크기 설정(기본 크게).
   - 유료 심화 리포트는 같은 컷 형식의 챕터형 리더(표지, 목차, 이전/다음 챕터).
   - 고지: "타로는 마음을 돌아보는 도구이며 미래나 상대의 마음을 확정하지 않아요"를 마무리 컷 아래 고정.

5. 캐릭터 말투 가이드 (1단계에서 찾은 기존 설정 문서를 우선, 없으면 초안을 만들고 승인받는다)
   - 꽃돼지 연이: 따뜻하고 치유하는 말투, 겁주거나 운명을 단정하지 않음, 어려운 개념은 쉽게 풀어서 설명.
   - 영냥이: 기존 영냥이 상담·브랜드 문서의 말투를 그대로 따른다(새로 지어내지 말 것).
   - 공통 금지: 단정적 예언, 공포 조장, 의료·법률·투자 판단.
   - 대사 생성 방식: 엔진/어댑터가 준 해석 원문은 바꾸지 않고, 그 위에 "화자 레이어"가 문장 분할 + 말투 변환을 한다.
     정적 해석은 i18n 대사 템플릿으로, AI 해석은 페르소나 시스템 프롬프트로 변환. 원문은 항상 보존하고 "글로만 보기"에서 확인 가능.

6. 무료/유료 경계: 무료 결과에 플레이스홀더 노출 금지, 유료 안내는 결과 하단 1곳에 가격과 함께.
   무료 기본 결과까지 로그인·꿀방울·추가 모달 없이 도달(필수 동의는 첫 진입 1회 통합).

7. 측정 이벤트: step_view, step_complete, flow_complete, flow_abandon, result_cut_view(컷 번호), text_only_toggle, paid_cta_click.
   기존 분석 체계를 확인해 이름을 맞춰라.

산출물: docs/context/guided-step-flow-spec.md, docs/context/narrator-webtoon-result-spec.md (루트 CLAUDE.md 에 한 줄 링크씩)
작성 후 멈추고 승인을 기다려라.
```

```

## 6단계. 무료 운세 섹션 재구성

```
[0번 공통 머리말]

입력: 1단계 감사, 2단계 스펙, 3단계 플로우 엔진, 4단계 웹툰 렌더러

1. 무료 운세 목록 화면
   - 1단계에서 확정한 무료 기능(명식·12신살, 타로, 자미두수 명반, 숙요 본명숙, 베다 하늘 지도, 점성술 출생 차트, 오늘의 운세 등)을 한 화면 카드 목록으로.
   - 카드 = 포스터 이미지(고정 비율) + 기능명 + 한 줄 설명 + "무료" 배지 + 소요 시간. 카드 전체가 탭 영역.
   - 무료 기간(2027-02-12까지)은 목록 상단 한 번만, 이후 무엇이 바뀌는지 한 줄로.
   - 홈 "무료 운세 정원"과 허브 무료 영역은 이 목록으로 가는 요약 카드로 축소, 중복 경로 통합.
2. 기능별 플로우: 랜딩 → 정보 확인(저장 프로필 1탭 확인 또는 입력, 출생 시간 "모름" 칩 명시 선택) → 계산 대기(자동 진행) →
   결과(웹툰 렌더러: 오프닝 → 핵심 요약 컷 → 상세는 접힘 섹션 → 오늘의 한 걸음 → 유료 심화 1곳).
   - 엔진 호출은 기존 어댑터만. 데이터 없는 블록은 숨김(플레이스홀더 금지).
   - 차트·명반처럼 표 형태가 핵심인 결과는 표를 그대로 두고, 캐릭터 컷은 앞뒤에서 안내·요약만 맡게 하라.
3. 경로 정리: 기존 URL(/ggulggul/?action=cdHome...Entry 등)은 새 플로우로 리다이렉트(정적 경로 301, action 파라미터는 클라이언트 매핑).
   sitemap·내부 링크·푸터 갱신. 네이버 블로그 등 외부에 걸린 기존 링크도 계속 동작해야 한다.
4. 진입 장벽: 무료 기본 결과까지 로그인·꿀방울·추가 모달 없음. 출석부·꿀방울·퀘스트는 결과 하단에만 작게.

먼저 변경 계획(화면별 전/후, 수정 파일 실제 경로, 리다이렉트 표)을 보고하고 승인 후 구현하라.
완료 후: 390px·960px 스크린샷, 기능별 진입→결과 탭 수 전/후 비교표.
