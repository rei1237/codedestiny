# Code Destiny 앱 UX 최적화 — Android · iOS 공통 "네이티브처럼 느껴지는 앱"

> 실행 순서: 01(Android 마무리)과 02(iOS 이식)의 Phase 0이 끝나 브리지 계약 v1이 확정된 뒤에 실행한다. 웹 레이어 개선은 두 앱에 동시에 적용된다.

## 0. 역할

너는 아래 다섯 명의 시니어 전문가로 이루어진 팀으로 일한다.

1. **모바일 프로덕트 디자이너**: Apple HIG와 Material 3를 기준으로 하고 플랫폼별 관례를 존중한다.
2. **인터랙션·모션 디자이너**: 햅틱, 전환, 대기 연출을 다룬다.
3. **접근성 전문가**: VoiceOver, TalkBack, Dynamic Type, 명도 대비를 다룬다.
4. **전환 UX 라이터·그로스 디자이너**: 페이월, 온보딩, 오류 문구를 다룬다.
5. **웹 퍼포먼스 엔지니어**: 체감 속도와 INP를 다룬다.

목표는 사용자가 **"웹사이트를 앱으로 감싼 것"이라고 느끼지 않는 것**, 그리고 **첫 실행부터 첫 결제까지 막힘 없는 흐름**이다.

## 1. 디자인 컨텍스트

- 디자인 언어: "하나의 신비로운 세계" 프리미엄 미학이다. 모바일 퍼스트 **달빛 예화(月花)** 디자인 언어를 쓰며 주 타깃은 20–30대 여성이다.
- 캐릭터
  - 연이: 따뜻하고 비숙명론적인 내레이터
  - 네오(사자): 직설적이고 다정하지 않다
  - 꽃돼지: 치유하고 설명하며 대립하지 않는다
  - 대기, 오류, 빈 상태 연출에 캐릭터를 쓰고, 성격에 맞는 어조를 지킨다.
- 알려진 이슈: 모바일 하단 내비게이션에서 "모든 운세"에 들어가면 CSS가 깨져 클릭이 안 되는 버그. 회귀했는지 확인하라.

## 2. 절대 불변 규칙

1. 6개 엔진 코드와 `calculateLocalResult()`는 수정 금지다. 결과 데이터 포맷도 바꾸지 않는다.
2. **960px 데스크톱 레이아웃은 건드리지 않는다.** 모든 변경은 `html[data-platform="ios"|"android"]` 또는 앱 컨텍스트 셀렉터와 모바일 미디어쿼리 안으로 격리한다.
3. 모든 문구는 i18n 키를 사용한다.
4. 결제 실행 로직은 수정하지 않는다. 결제 UI 표현만 다룬다. 결제 흐름을 바꿔야 하면 별도 승인 게이트를 거친다.
5. 파일 경로를 추측하지 않는다. 진단 → 보고 → 승인 → 구현 → 검증 순서를 지킨다. Conventional Commits를 쓰고 브랜치는 `feat/app-ux-polish`다.

## Phase 0 — UX 감사 (읽기 전용)

실기기(Android 중급 1종, iPhone 1종)와 에뮬레이터·시뮬레이터에서 아래 여정을 직접 따라가며 **화면 녹화와 스크린샷을 근거로** 문제를 수집하라.

**핵심 여정 5개**
1. 첫 실행 → 온보딩 → 생년월일시 입력 → 첫 결과
2. 무료 결과 → 페이월 → 구매 → 해금된 결과
3. 재방문 → 오늘의 운세 → 다른 엔진 탐색
4. 상담 기능(네오 팩폭 전략실 패턴) → 후속 질문
5. 설정 → 계정 삭제 / 로그아웃 → 재로그인

**각 문제마다 기록할 것**: 여정 단계 | 문제 | 심각도(P0~P3) | 위반한 원칙(HIG, Material, WCAG, 휴리스틱) | 근거(스크린샷, 파일:라인) | 개선안 | 측정 지표

추가로 아래 "네이티브 감각 체크리스트" 항목별로 통과/실패를 표시한다. → **멈추고 승인을 기다린다.**

## 네이티브 감각 체크리스트 (구현 기준)

### A. 첫인상과 실행
- 스플래시(런치 스크린)와 웹 첫 화면의 배경색, 로고 위치가 **픽셀 단위로 일치**해서 깜빡임이 없다.
- 흰 화면이 300ms 넘게 보이지 않는다. 웹이 준비되기 전에는 스켈레톤을 보여준다.
- 온보딩은 최대 3단계로 하고, 건너뛸 수 있다. 가치를 먼저 보여주고 입력은 나중에 받는다.

### B. 생년월일시 입력 (핵심 전환 지점)
- 플랫폼 네이티브 날짜·시간 피커를 쓴다. 브리지를 쓰거나 `input type=date/time`을 최적화한다.
- 양력/음력/윤달 토글, **"태어난 시간 모름"** 선택지, 출생지 검색(자동완성)을 제공한다.
- 입력값은 즉시 검증하고 오류를 인라인으로 안내한다. 입력한 내용은 저장해서 재사용하고, 여러 사람의 프로필을 관리할 수 있게 한다.
- 키보드가 입력 필드를 가리지 않는다(IME 인셋, `scrollIntoView`).

### C. 내비게이션
- 하단 탭은 고정이고 safe-area를 반영한다. 활성 상태가 명확하다. "모든 운세" 버그가 0건이다.
- **모달과 시트가 history와 연동**되어 Android 뒤로가기, iOS 스와이프 백으로 닫힌다. 모달 위에서 뒤로가기를 했는데 페이지가 이탈하면 안 된다.
- 화면 전환에는 플랫폼 관례에 맞는 방향성 있는 전환을 쓴다. View Transitions API를 지원하면 활용한다.
- 스크롤 위치를 복원한다. 결과에서 목록으로 돌아오면 원래 위치에 있어야 한다.

### D. 터치와 피드백
- 터치 타깃은 iOS 44pt, Android 48dp 이상이다.
- `-webkit-tap-highlight-color: transparent`를 적용하고, 대신 명확한 `:active` 상태(스케일 0.97, 밝기 변화)를 준다.
- UI 크롬에서는 `user-select: none`으로 텍스트 선택을 막는다. 결과 본문은 복사할 수 있게 둔다.
- 과도한 오버스크롤 바운스를 정리하고, 필요한 곳에서만 당겨서 새로고침을 쓴다.
- **햅틱 맵**(브리지 호출)

| 순간 | 햅틱 |
|---|---|
| 결과 공개, 결제 완료 | success |
| 카드 뒤집기, 토글 | light impact |
| 오류 | error |
| 길게 누르기 메뉴 | medium impact |

### E. 대기 연출 (LLM 결과 생성)
- 결과는 스트리밍으로 렌더링한다. 첫 토큰이 2초 안에 보여야 한다.
- 스트리밍이 불가능한 구간에서는 캐릭터 대기 연출과 단계 메시지(i18n)를 보여준다. 예: "명식을 펼치는 중", "12궁을 살피는 중". 진행감을 줘야 한다.
- 결과 공개 순간에 짧은 리빌 모션과 햅틱을 준다.
- 대기가 길어지면 이탈을 막기 위해 "완료되면 알림 받기"(푸시)를 제공한다.

### F. 페이월과 결제 UX
- 무엇을 얻는지를 먼저 보여준다(잠긴 결과 미리보기, 블러 처리된 일부). 가격은 스토어가 내려준 값만 쓴다.
- 이용권 유형별 비교는 최대 3개로 하고, 추천 배지는 하나만 단다.
- 결제 대기, 실패, 취소 각각에 맞는 문구와 다음 행동 버튼을 둔다. 막다른 화면이 없어야 한다.
- 구매 직후 **즉시 해금 + 축하 모션 + 햅틱**을 준다. 서버 확인 중에는 "해금 중" 상태를 명시한다.
- "구매 복원" 진입점을 페이월과 설정 두 곳에 둔다.

### G. 결과 화면
- 긴 결과(A4 10페이지 분량)를 위한 장치
  - 상단 요약 카드
  - 목차 점프(스티키 칩)
  - 읽기 진행률 바
  - 섹션 접기/펼치기
- 타이포그래피: 본문 16–17px 이상, 행간 1.6–1.75, 한 줄 최대 길이 제한, 다크 모드 대비를 최적화한다.
- 결과 카드 공유(이미지 생성 → 공유 시트)와 저장을 제공한다.
- AI 결과 신고 버튼을 둔다(Play 정책 대응). 눈에 띄지 않되 찾을 수 있는 위치에 둔다.

### H. 상태 화면
- 오프라인, 서버 오류, 세션 만료, 빈 상태 각각에 캐릭터 일러스트와 성격에 맞는 문구, 행동 버튼을 넣는다.
- 401만 재로그인으로 보낸다. 그 밖의 오류는 재시도로 처리한다.

### I. 시스템 통합
- 다크 모드를 자동으로 따른다. 상태바와 내비게이션바 색상이 테마와 일치한다.
- Dynamic Type과 시스템 폰트 배율 200%에서도 레이아웃이 깨지지 않는다.
- `prefers-reduced-motion`을 존중해서 모션을 줄이고 페이드로 대체한다.
- 알림 권한, 리뷰 요청은 긍정적인 순간 이후에 요청한다. 첫 실행 때 요청하는 것은 금지다.

### J. 접근성
- 모든 아이콘 버튼에 접근성 레이블(i18n)을 단다. 카드 뒤집기 같은 커스텀 인터랙션은 스크린리더에 대체 동작을 제공한다.
- 명도 대비는 WCAG AA(본문 4.5:1)를 지킨다. 달빛 테마의 저대비 텍스트를 점검하라.
- 포커스 순서가 시각적 순서와 일치한다.

## Phase 1~3 — 구현 (승인된 항목만, 우선순위 순)

- Phase 1: P0/P1(전환을 막는 문제: 입력, 페이월, 내비게이션 버그, 대기 화면)
- Phase 2: P2(네이티브 감각: 햅틱, 전환, 상태 화면, 결과 가독성)
- Phase 3: P3(즐거움을 주는 요소: 리빌 모션, 캐릭터 연출, 공유 카드 디자인)

**측정 지표** (변경 전후를 비교해서 보고)

| 지표 | 목표 |
|---|---|
| 첫 실행 → 첫 결과 완료율 | 상승 |
| 첫 결과까지 걸린 시간 | 단축 |
| 페이월 노출 → 구매 전환율 | 상승 |
| 결제 시작 → 해금 성공률 | ≥ 99% |
| 결과 화면 평균 스크롤 도달률 | 상승 |
| INP / CLS | ≤ 200ms / ≤ 0.1 |

## 완료 기준

- [ ] 핵심 여정 5개를 두 플랫폼 실기기에서 녹화했고, P0/P1 문제가 0건이다.
- [ ] 네이티브 감각 체크리스트를 전부 통과했거나, 미통과 항목에 사유를 적었다.
- [ ] 데스크톱 960px 레이아웃 회귀 0건(변경 전후 스크린샷을 비교한다).
- [ ] 접근성: VoiceOver와 TalkBack으로 핵심 여정 2(구매)를 완주할 수 있다.
