# 진입 웹툰과 구매 동선 정리 설계

승인: 2026-11-07 사용자 승인(계획 `dreamy-orbiting-quilt.md`, ExitPlanMode 승인).
참고 랜딩: 청월당 `bluemoonladysaju26`(750px 이미지 17장, 흐름만 참고).

## 의도

`/`는 지금 연이·영냥이 중 하나를 고르는 화면이다. 처음 온 사람은 "왜 여기서 봐야 하는지"를 보지 못한 채 꿀꿀로 넘어가고, 꿀꿀 안에서도 결제까지 마찰이 많다. `/`를 긴 세로 웹툰으로 바꿔 다음 내용을 보여 준다.

1. 인간 연이가 독자에게 고민을 묻는다.
2. 대통령의 2025년 흐름을 2024년에 미리 짚은 명리학자 네오(박병하)를 원문 증거와 함께 소개한다.
3. 꽃돼지 연이가 받을 수 있는 것을 안내한다.
4. 마지막에 꿀꿀 무료 만세력으로 바로 넘긴다.

꿀꿀 쪽 동선 수정(히어로, 고민 답, 단건 우선, 로그인 복귀, 환불 안내, 측정)도 함께 한다.

## 사용자가 정한 것

- `/`를 웹툰으로 교체한다. 브랜드 선택 화면은 없앤다. 영냥이는 끝에 작은 입구로만 둔다.
- 표현은 "미리 짚은" + 원문 증거로 한다. "적중"은 쓰지 않는다.
- 화자는 인간 연이다. 네오는 기록을 남긴 스승으로 나온다. 상품 안내는 꽃돼지 연이의 말풍선으로 한다.
- 대사는 HTML 말풍선으로 넣는다(SEO 노출). "바로 무료 운세 보기"는 항상 보이게 한다.
- 무료 결과 다음 순서는 고민 답 → 5,000원 단건 → 29,000원 묶음이다.
- 꿀꿀 홈 히어로는 질문 + 고민 칩 + 신뢰 한 줄로 구성한다.
- 범위는 웹툰과 동선 수정을 함께 한다. 이전 계획의 `/` → `/ggulggul/` 리다이렉트는 취소한다.

## 목표

- `/`에서 스크롤만으로 "누가 만들었고, 왜 믿을 만하고, 무엇을 받는지"를 이해하고 무료 만세력으로 들어간다.
- 무료 결과 화면에서 고른 고민의 답을 먼저 보고, 그 고민에 맞는 단건과 묶음을 차례로 본다.
- 로그인을 거쳐도 원래 상품과 고민으로 돌아온다.

## 하지 않는 것

- 결제 동결 구역 수정(`billing-client.ts`, `useCoinGate.ts`, `portone.ts`, `index.html`의 결제 함수).
- 가격 변경. 가격은 `worker/lib/paid-feature-registry.js`에서만 읽는다.
- 사주 균일가나 단품 판매. 사주는 29,000원 묶음으로만 판다.
- DEST1NOVA 출연(시트가 없음).
- 실제 LLM, 결제, DB 호출 테스트(목만).

## 절대 안 되는 것

- "적중", "1위", "최고", "100%", 누적 고객 수 같은 근거 없는 숫자, 경쟁사 비하.
- 2024-05-12 기록을 "1년 전"이라 부르기(실제 327일). 2024-05-27 글의 "혁명" 방식이 실제와 같았다고 확대하기.
- 단정 예언, 공포 조장, 결제 압박, 사용자를 돼지라 부르기.
- 사자 네오. 혼자 팔 벌리고 고개를 젖히는 과시 포즈. 귀가 2개가 아닌 영냥이.
- 그림 안의 글자나 말풍선.

## 접근

| 안 | 내용 | 장단점 |
| --- | --- | --- |
| A. 이미지 통짜 랜딩(청월당식) | 750px 이미지에 글자까지 넣음 | 제작이 단순하다. 하지만 SEO 본문이 없고, CMS로 수정할 수 없고, 무겁고, 접근성이 나쁘다. |
| **B. 그림 컷 + HTML 대사·카드(선택)** | 글자 없는 일러스트 컷과 HTML 말풍선·증거·후기·제안 카드를 섞음 | SEO, CMS 수정, 가격 자동 반영, 원문 링크가 모두 된다. 제작량이 더 많다. |
| C. 기존 웹툰 재사용 | 영냥이 프롤로그와 달빛 가이드 컷을 재조합 | 빠르다. 하지만 네오 기록 이야기와 구매 흐름에 맞는 컷이 없다. |

B를 택한다. `/`는 GSC 클릭 1위 페이지라 본문 텍스트를 지켜야 하고, 사용자가 관리자 화면에서 문구를 고치길 원한다.

## 대본 「연이의 찻집에서, 당신의 흐름을」 (약 24컷, 그림 약 14장)

말투 정본은 `docs/context/design-canon.md` §2를 따른다.

- 인간 연이: 부드러운 존댓말, 상대를 "당신"이라 부른다.
- 네오: 짧고 정돈된 존댓말.
- 꽃돼지 연이: 밝고 짧게.

1. **상상**(밤 찻집)
   - 별밤과 찻집 등불: "한 번 상상해 볼까요?"
   - 연락을 망설이는 휴대폰, 사직서와 통장, 새해 달력이 이어진다.
   - 인간 연이 클로즈업: "그 흐름을 미리 읽는 사람이 있어요."
2. **기록**(네오)
   - 2024년 5월 서재에서 원고를 쓰는 은발 네오.
   - 기록 카드 2장(HTML): 날짜, 원문 링크, 이후 사건은 `PRESIDENTIAL_RECORDS` 그대로 쓴다. "모든 과정의 일치를 뜻하지 않아요" 고지를 붙인다.
   - 다시 찾아온 독자 반응(`PRESIDENTIAL_REACTIONS`)에는 구매 후기가 아니라는 고지를 붙인다.
   - 네오: "운은 맞히려고 보는 게 아닙니다. 대비하려고 봅니다."
3. **10년**
   - 1:1 상담 테이블: 10년 경력, 1회 30만원.
   - 카카오 후기 3장: 네오 1:1 상담·강의 이용자 후기라는 고지를 붙인다.
   - 네오가 연이에게 원고를 건넨다(헌신은 연이를 향하게).
   - 꿀꿀 운세 간판, "계산은 규칙대로, 해설은 AI가", 언론 카드(스타트업데일리).
4. **당신의 질문**
   - 손님이 찻집 문을 연다.
   - 고민 칩: 연애, 재회, 돈, 이직, 올해 흐름.
5. **받는 것**(꽃돼지 연이 안내, 01~03)
   - 01 무료 만세력, 02 무료 고민 답.
   - 03 더 깊게: 고민별 5,000원, 사주 29,000원 묶음, 대표 상담 3종. 가격은 레지스트리에서 읽는다.
   - 안심 박스: 결제 전 예시, 실패하면 자동 환불, 환불 정책 링크.
6. **초대**
   - 인간 연이가 찻잔을 내민다. CTA "무료로 내 운세 보기" → `/ggulggul/?action=cdOneStepFreeSajuEntry&concern=…&from=entry_webtoon`.
   - 보조 입구: 영냥이, 꿀꿀 둘러보기.
   - 고지(`trust-stories` `fine`)와 푸터.

화면 고정 요소: 2컷이 지나면 상단에 "바로 무료 운세 보기" 바가 나타난다. 첫 화면에는 "건너뛰기 →"를 둔다.

## 구조

- **대본 데이터**: `lib/brand/entry-webtoon.mjs`. 컷 종류는 image, record, reviews, press, concern, offer, cta다. 정치 단어는 trust-stories에서 가져와 새 파일에 들어가는 횟수를 줄인다. 남는 횟수는 `no-political-trust-copy` ALLOWED에 "2026-11-07 사용자 요청: 진입 웹툰"으로 등록한다.
- **그림**
  - 제작 폴더는 `D:\CodeDestiny-Build\entry-webtoon-20261107\`이다. `webtoon-revamp-20261107` 파이프라인(`codex exec -i` → gpt-image-2)을 복사해서 쓴다.
  - 정본 시트를 첨부하고, 결과를 정본과 나란히 놓고 검수한다.
  - 내보내기는 `public/images/entry-webtoon/`에 AVIF 640/1080, WebP 720으로 한다. 출처 원장은 `docs/design/entry-webtoon-assets.json`이다.
  - 컨택트 시트로 사용자 승인을 받은 뒤 페이지에 넣는다.
- **페이지**
  - `app/page.js`는 `EntryWebtoon`을 렌더한다. `<LegacyHomeEntry />`, `IS_APP_BUILD` 분기, canonical `/`, JSON-LD는 유지한다.
  - title은 `homeSearchTitle`을 쓰고, H1은 텍스트로 둔다.
  - 컴포넌트는 `app/_entry/`에 두고 `CutReader`의 picture와 말풍선 방식을 따른다.
  - CTA는 일반 `<a>`로 `/ggulggul/`에 직접 연결해 워커 302를 피한다. 고른 concern은 sessionStorage `cd:home-concern`에 저장한다.
- **워커**: `brandHomeRedirect`는 유지한다. 웹툰 광고 캠페인 코드는 `js/core/analytics.js` 허용 목록에 추가한다.
- **꿀꿀 동선**
  - P0 CMS 테스트 복구(`VisualPreview` EMPTY 상수, 셀렉터).
  - P2 히어로 CTA 재로드 제거, 로그인 게이트 복귀 경로.
  - P3 꿀꿀 홈 재배치와 고민 칩 단일화. 칩 정본은 `lib/marketing/home-concerns.mjs`에 두고, 가격은 빌드 생성값으로 넣는다.
  - P4 무료 결과의 고민 답 → 5,000원 타로 → 29,000원 묶음.
  - P5 환불 한 줄, 연애 비책 결과의 후기 배너, 후기가 3건 미만이면 결과 예시.
  - P6 띠운세 → 고민 다리.
  - P7 CMS `home-copy`(꿀꿀 히어로, 제안, 웹툰 대사).
  - P8 이벤트와 퍼널 리포트.

## 남은 판단(빌더 몫)

- CMS 웹툰 대사 키 이름.
