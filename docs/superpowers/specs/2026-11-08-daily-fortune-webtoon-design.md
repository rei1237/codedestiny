# 오늘·내일의 운세 웹툰 (1안) — 짧은 설계

## 의도
- 사용자 요청(2026-11-08): 오늘·내일의 운세가 저퀄리티다. 캐릭터를 써서 매일 다시 올 만큼 상세하고 재미있게 만들고, 여러 운세를 한 번에 종합하는 "초융합"으로 보여 준다. UI는 달빛 예화 스타일로 고급스럽게, 매일의 운세를 웹툰처럼 이미지로 본다.
- 대상: 무료 `/fortune/{today|tomorrow}/{띠·별자리 24종}` 48쪽. 주간·월간·날짜 보관 페이지는 이번 범위가 아니다.

## 접근 (사용자가 1안 선택)
1. **기존 상담 웹툰 컷 재사용 + 실계산 대사 (선택)**: 새 그림 없이 `lib/brand/consultation-webtoons.mjs`의 컷을 슬롯 표로 골라 쓴다. 말풍선은 그날 실제로 계산한 값으로 채운다. 단점은 그림이 원래 다른 이야기용이라 내용과 정확히 맞지 않을 수 있다는 것이다. 그래서 "예화" 표기를 단다.
2. 사용자가 그린 일일 전용 컷: 그림이 맞지만 사용자 제작이 먼저 필요하다. 1안의 슬롯 표가 그대로 교체 지점이 된다.
3. 캐릭터 초상 + 카드 UI(웹툰 아님): 가볍지만 "웹툰처럼"이라는 요청에서 멀다.

## 구성 (today·tomorrow, 한국어 화면만 서버 렌더)
- 다국어 미러(en·ja·zh)는 이번에 그리지 않는다. 대사가 한국어 계산 문장이라 번역 키가 없다.
- 구현: `lib/fortune/daily-webtoon.ts`(대사), `lib/fortune/daily-webtoon-slots.ts`(그림 슬롯), `app/fortune/[period]/DailyFortuneWebtoon.tsx`(화면).
- 컷 7장. 첫 컷은 오프닝, 마지막은 연이의 종합이다. 가운데 다섯 컷이 각 체계를 맡고, 순서는 날짜에 따라 돈다.
  | 컷 | 화자 | 실제 값 |
  |---|---|---|
  | 오프닝 | 내레이션 | 날짜, 띠·별자리, 그날 키워드 |
  | 사주·일진 | 네오 | 일진, 지지 관계 배지(삼합·충·비화·없음), 천간 오행 생극 근거 |
  | 하늘 | 윤달 | 태양궁·달 자리·달의 위상(별자리는 관계 배지 포함) |
  | 타로 | 연이 | `dailyTarotReading(날짜, "fortune-sign:{id}")` 카드·방향·풀이 |
  | 숫자판 | 무성 | 네 갈래 점수, 가장 높은·낮은 갈래와 그 갈래의 그날 문장 |
  | 마음·행운 | 서한비 | 애정운 문장 첫 문장, 행운의 색·숫자 |
  | 종합 | 연이 | 총운 점수, 점수대별 한 줄, 그날 조언 |
- 그림: 슬롯마다 후보 컷 2~3장 중 (날짜, sign, 슬롯) 해시로 하나를 고른다. 슬롯 표(`lib/fortune/daily-webtoon-slots.ts`)는 웹툰 키·컷 번호 참조나 직접 이미지 정보를 받으므로, 나중에 사용자가 그린 컷으로 바꿀 수 있다.
- 무성은 자미두수 결과를 말하지 않는다. 자미두수와 숙요는 출생 정보 없이 일일 계산이 없으므로, 대사에 그 체계 결과를 지어내지 않는다.
- 스타일: 연이 딥 플럼 밤 표면(`#3a0e28`→`#24081a`)에 로즈골드 1px 선(`--cd-yehwa-line`)과 불투명 아이보리 달 디스크(`--cd-yehwa-ivory`)를 둔다. 강조색은 로즈 하나(One Accent, Hue-Stays)이고 골드는 장식선만 쓴다. CutReader에 `yehwa` 톤을 추가한다.

## 지키는 것
- SignFortuneView는 서버 컴포넌트로 둔다. 대사는 HTML figcaption이라 서버 렌더 본문으로 잡힌다.
- URL, 제목 실험, 설명, JSON-LD, FAQ, 기존 블록은 그대로 둔다. 운세 계산 로직은 고치지 않는다. 뷰모델에 그날 하늘 값(`sky`)만 더한다.
- 공용 문구 가드: 날짜에만 의존하는 문장은 같은 날 24쪽에 겹치므로 분량에서 빠질 뿐 실패하지는 않는다. 그래서 컷마다 sign별 값(관계, 키워드, 타로, 점수 문장)을 함께 넣는다.
- 확정·보장 표현과 사용자를 낮추는 표현은 쓰지 않는다.
