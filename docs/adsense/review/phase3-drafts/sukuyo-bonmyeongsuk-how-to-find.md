# 검수용 초안: 출생일만으로 충분할까? Code Destiny 본명숙 계산 기준

- 대상 slug: `sukuyo-bonmyeongsuk-how-to-find`
- 상태: 공개 소스 반영, 배포 미실시
- 사람 검수: 미확인
- 사례: 교육용 가상 예시

## 원고

Code Destiny에서 본명숙을 확인할 때는 생년월일만 적는 것보다 출생 시각과 당시 시간대까지 함께 입력하는 편이 정확합니다. 현재 서비스는 달력의 날짜 칸에 숙을 하나씩 붙이는 방식이 아니라, 입력한 순간의 달 위치를 계산한 뒤 항성 황도를 27개 구간으로 나눠 본명숙을 찾기 때문입니다. 출생 시각을 모른다고 계산이 불가능한 것은 아니지만, 달이 다음 구간으로 넘어가는 경계에 가까우면 후보가 달라질 수 있다는 한계를 남겨야 합니다.

### 전통 날짜표와 현재 서비스 계산은 같은 질문에 답하는 두 방식입니다

숙요를 접하면 음력 날짜만 보고 숙을 찾는 조견표를 먼저 만날 때가 많습니다. 이런 표는 전승된 달력 규칙으로 빠르게 자리를 찾는 데 유용합니다. 다만 표의 판본, 윤달 처리, 하루의 경계를 잡는 방식이 다르면 결과도 달라질 수 있습니다.

Code Destiny의 현재 계산은 천문 위치를 사용합니다. 입력이 음력이라면 먼저 양력 날짜로 바꾸고, 출생지의 현지 시각과 시간대 정보를 UTC로 환산합니다. 그 시각의 달에 대한 라히리 기준 항성 황경을 구한 뒤, 360도를 27개의 같은 폭으로 나눕니다. 한 구간의 폭은 약 13도 20분입니다. 마지막으로 서비스의 숙요 배열에 맞춘 고정 대응값을 적용해 묘수·필수 등 화면에 쓰는 이름으로 변환합니다.

| 단계 | 서비스가 확인하는 값 | 왜 필요한가 |
|---|---|---|
| 1 | 양력·음력과 윤달 여부 | 음력 입력을 실제 계산 날짜로 변환하기 위해 |
| 2 | 출생 현지 시각과 시간대 | 같은 시계 숫자를 정확한 UTC 순간으로 바꾸기 위해 |
| 3 | 그 순간의 달 항성 황경 | 달이 27구간 가운데 어디에 있는지 확인하기 위해 |
| 4 | 27등분 구간과 서비스 배열 | 계산값을 Code Destiny의 숙 이름으로 표시하기 위해 |

이 내부 배열 대응은 Code Destiny 제품에서 결과를 일관되게 표시하기 위한 규칙입니다. 이 숫자 하나만으로 동아시아 숙요의 모든 판본과 인도 나크샤트라가 역사적으로 완전히 같은 순서였다고 주장할 수는 없습니다.

### 출생 시각이 결과를 바꾸는 때

달은 계속 움직이므로 같은 민간 날짜 안에서도 27구간의 경계를 지날 수 있습니다. 예를 들어 가상의 두 사람이 같은 날 같은 도시에서 태어났더라도 한 사람은 새벽, 다른 사람은 밤에 태어났다면 달의 황경이 서로 다릅니다. 둘 다 같은 구간 안에 있으면 본명숙은 같지만, 그날 중간에 경계를 통과했다면 결과가 달라질 수 있습니다.

따라서 “자정 근처에서만 시간이 중요하다”라고 설명하면 충분하지 않습니다. 날짜 경계와 별개로 달의 27등분 경계가 하루 중 어느 시각에든 나타날 수 있기 때문입니다. 출생 시각을 모르는 경우에는 임의의 시각을 확정값으로 받아들이지 말고, 시간 미상으로 계산한 결과라는 안내와 함께 인접 구간 가능성을 살펴야 합니다.

### 시간대와 출생지는 어떻게 다를까

시간대는 현지 시각을 세계 공통 시각으로 바꾸는 데 직접 필요합니다. 같은 “오전 9시”라도 서울과 런던은 같은 순간이 아닙니다. 서머타임이나 과거의 지역 시간대를 잘못 적용하면 달 위치를 계산하는 순간 자체가 달라집니다.

현재 숙요 계산 코드에는 위도와 경도도 계산 결과의 맥락 정보로 남지만, 본명숙 구간을 고르는 핵심 값은 지구 중심 기준 달의 항성 황경입니다. 그러므로 위치가 몇 킬로미터 달라지면 본명숙이 바뀐다고 과장해서는 안 됩니다. 중요한 것은 입력 시각을 어떤 시간대로 해석했는지입니다.

### 가상 예시: 경계에서 멀 때와 가까울 때

가상으로 계산된 달 황경이 한 구간의 한가운데에 있다면 출생 시각을 한두 시간 다르게 입력해도 같은 숙이 나올 가능성이 큽니다. 반대로 구간 끝에 매우 가깝다면 작은 시각 차이가 다음 구간으로 넘어가는 결과를 만들 수 있습니다. 이 예시는 특정 생년월일의 실제 천문값이 아니며, 경계의 의미를 설명하기 위한 도식입니다.

이 차이를 확인할 때는 다음 순서가 안전합니다.

1. 양력·음력과 윤달 입력을 다시 확인합니다.
2. 출생증명서나 가족 기록에서 가능한 시각 범위를 찾습니다.
3. 당시 출생지의 시간대와 서머타임 적용 여부를 확인합니다.
4. 가능한 시각 범위의 시작과 끝을 각각 계산해 같은 숙인지 비교합니다.
5. 후보가 둘이라면 성격 문구로 정답을 억지로 고르지 않고 두 가능성을 남깁니다.

### 결과가 다를 때 먼저 확인할 세 가지

다른 서비스와 본명숙이 다르다고 해서 한쪽이 곧바로 오답인 것은 아닙니다. 첫째, 한쪽이 전통 날짜표를 쓰고 다른 쪽이 천문 황경을 쓰는지 확인합니다. 둘째, 음력 윤달과 날짜 경계를 어떻게 처리했는지 확인합니다. 셋째, 출생 시각 미상일 때 정오·자정처럼 어떤 기본값을 넣었는지 확인합니다. 계산 기준이 다른 두 결과를 성격 설명의 그럴듯함만으로 고르는 것은 검증이 아닙니다.

Code Destiny 결과를 다시 볼 때는 입력 화면의 값과 계산 기준을 함께 기록하는 편이 좋습니다. 생년월일, 양력·음력, 시각, 시간대, 시간 미상 여부를 남겨 두면 나중에 결과가 바뀌었을 때 입력 변경인지 계산 버전 변경인지 구분할 수 있습니다. 공개 글은 특정 숙이 “더 잘 맞는다”는 체감 후기를 계산 정확성의 증거로 사용하지 않습니다.

### 본명숙은 관계의 결말을 결정하지 않습니다

본명숙을 찾은 다음에는 두 사람의 숙 사이 거리를 이용해 명·업태·영친·우쇠·안괴·성위 같은 관계군을 읽을 수 있습니다. 이 분류는 관계를 바라볼 질문을 만드는 상징 체계이지, 누가 나를 사랑하는지 또는 결혼과 이별이 확정되는지를 측정하는 검사가 아닙니다. 실제 관계에서는 동의, 대화, 반복되는 행동과 안전이 계산 결과보다 우선합니다.

본명숙의 이름과 기본 상징은 [숙요 27수 가이드](/insights/sukuyo-27-mansions/)에서, 관계군은 [숙요 궁합 가이드](/insights/sukuyo-compatibility-guide/)에서 이어서 볼 수 있습니다. 숙요와 사주가 서로 다른 자료를 사용하는 이유는 [숙요 궁합과 사주 궁합 비교](/insights/sukuyo-vs-saju-compatibility/)에서 확인할 수 있습니다. 내 입력값으로 계산하려면 [숙요점 시작 페이지](/sukuyo/)에서 양력·음력, 시각과 시간대를 먼저 확인하세요.

### 계산 결과를 다시 확인할 수 있게 기록하세요

본명숙 이름만 캡처해 두면 나중에 다른 결과가 나왔을 때 이유를 찾기 어렵습니다. 계산한 날짜와 함께 양력·음력 구분, 윤달 여부, 입력한 현지 시각, 시간대, 출생 시각 미상 여부를 기록하세요. 서비스가 계산 기준과 버전을 표시한다면 그것도 함께 남깁니다. 개인정보가 포함된 화면을 공개 게시할 필요는 없고, 본인이 다시 확인할 수 있는 안전한 곳에 보관하면 됩니다.

결과가 바뀌었을 때는 성격 설명부터 비교하지 말고 입력값과 계산 기준부터 비교합니다. 입력이 같다면 시간대 해석, 음양력 변환, 달 황경 자료, 27구간 배열 가운데 무엇이 달라졌는지 차례로 확인합니다. 이 과정은 어느 설명이 더 그럴듯한지를 고르는 방식보다 재현 가능하며, 문의가 필요할 때도 문제를 구체적으로 전달할 수 있게 합니다.

## 출처와 검수 메모

- 저장소 `worker/lib/sukuyo-astronomy.js`: 현지 시각의 UTC 변환, 음력 입력의 양력 변환, 달 황경 요청 경로.
- 저장소 `worker/lib/sukuyo-coordinate.js`: 27등분, 라히리 항성 달 황경, 서비스 배열 고정 대응값.
- [Swiss Ephemeris 공식 문서](https://www.astro.com/swisseph/swephprg.htm): 항성 모드와 아야남샤 계산 인터페이스. 링크가 Code Destiny의 모든 계산 결과를 외부에서 인증한다는 뜻은 아니다.
- [『숙요경』 T1299 전자본](https://buddhism.lib.ntu.edu.tw/FULLTEXT/sutra/T/T21n1299.pdf): 전통 문헌의 27숙·날짜 맥락 확인용. 현행 서비스의 동일 구간 알고리즘을 원문 번역으로 표시하지 않는다.
- 네오 확인 필요: 시간 미상 입력 시 실제 UI에 표시되는 안내와 후보 처리 방식.
