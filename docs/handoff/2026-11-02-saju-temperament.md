# 사주 LLM 상담의 타고난 성향 해석 개선

영냥이와 꿀꿀운세의 사주 상담에 공통 성향 해석 근거를 연결했다. 기존 명식·신강약·용신 계산은 유지하며, 십성의 욕구 → 선택 습관 → 강점 → 과할 때의 그림자 → 조절법을 구체적이고 조건부인 문체로 전달한다.

## 구현과 수정 파일

- `worker/lib/saju-temperament.js`: 열 가지 십성, 월지 본기, 기존 강약, 정편 구성, 원국 투간, 종격 후보, 시간 미상·부분 명식의 한계를 함께 제공하는 순수 모듈.
- `worker/lib/saju-derived-signals.js`: 기존 분포를 유지하며 성향 근거를 확장. 겉 글자와 지장간을 중복 합산하지 않고, 없는 기운을 능력·도덕성 결여로 설명하지 않는다.
- `worker/yeongnyangi/fortune/{saju,shared,concise-reading-prompt}`: 일반·질문형·장별·퓨전 근거에 연결. 모델 경계에서 공통 축약 문장을 사용해 개인정보 필터와 질문 근거의 중복 제거를 유지한다.
- `worker/lib/*prompt*`, `worker/lib/love-secret-ai-facts.js`, `worker/lib/master-love-codex-evidence.js`, 관련 `worker/routes/`: 전문가 사주, 총운, 신년, 연애, 찻집, 네오, 궁합·융합, 가디언, 작명, 다중 관점 상담에 연결. 사람별 자료를 분리한다.
- 성향 단위·프롬프트 연결 검사, 질문형 입력 예산 검사, 기존 화자 버전 검사와 영냥이 전수 요청 해시를 갱신했다.
- 최신 main의 레시피·해외 홈 수정도 병합했다. 번역 사전은 최신 main의 정본을 유지하며 중복 키를 남기지 않았다. 심리검사 진입 검사는 경로 배열의 순서에 의존하지 않도록 했다.
- 정본 생성기로 정적 셸과 사이트맵을 동기화했다. 공개 URL·색인·가격 정책은 변경하지 않았다.

## 전체 검사 실패 원인과 해결

1. Jest 전체 443개 스위트·7,246개 검사 중 화자 검사 하나가 이전 v17 문자열을 기대했다. v18 기대값으로 수정했고 해당 스위트 4개 검사는 통과했다. 나머지 7,245개는 최초 전체 실행에서 통과했다.
2. Node 최초 전체 4,151개 중 3개 실패를 확인했다. 성향 자료 중복으로 퓨전 질문형 입력이 41,087 추정 토큰이 되었고, 모델 전달용 자료를 축약해 39,729로 줄였다. 사주·자미 퓨전은 29,303이며 기존 40,000 한도를 유지했다.
3. 영냥이 전수 스냅샷은 의도된 요청 해시를 반영했다. 전체 199개 상품·상담 조합에서 사주 관련 49개 요청 해시만 달라졌다. ID·준비 응답·검증된 mock 결과·목차 해시는 그대로이며, 갱신 옵션 없는 재실행도 통과했다.
4. 테스트 실행기 한 건은 Jest와 Node 전체 병렬 실행 중 25초 제한에 걸렸다. 단독 재현 검사와 실행기 전체 5개 검사, 이후 Node 전체 실행에서는 통과했다. 네트워크 차단·워커 교체·실패 전달 검증은 완화하지 않았다.
5. 최신 main 병합 후 Node 전체 4,158개에서는 위 사주 관련 실패가 해소되었고, 새 해외 홈 번역 11개와 경로 순서 의존 검사 1개가 실패했다. 번역 누락을 수정한 동시 main 커밋을 통합하고 경로 검사를 보완했다. 관련 재실행으로 확인했다.
6. main `5e62bdcb9` CI 실패 로그에서도 같은 번역·경로 순서 문제와 레시피 제목 표시 폭 초과가 확인됐다. 후속 main `7f25e1d81`의 번역·제목 수정을 보존했다. 이전 `b14cec16b`의 중복 H1 수정 CI는 `CI required`까지 통과했다.

- 최종 원격 전체 검증 결과는 이 문서를 포함한 main push의 GitHub Actions `CI required`를 기준으로 확인한다.

## 유지한 영역과 전달

계산 엔진, 공개 API 형식, DB 스키마, 결제·인증·저장·기존 구매 결과 재열람 로직을 유지했다. 이용권·월정석·단건 결제 구조 및 가격은 바꾸지 않았다. 추가 LLM 호출이나 재생성 조건이 없다.

다른 세션의 기본 체크아웃과 미커밋 파일은 보존했다. 격리된 작업 결과를 최신 main과 병합했으며 정상 fast-forward push를 사용한다. PR·force-push·실 LLM·실결제·운영 DB 쓰기·운영 배포는 포함하지 않는다. 실제 생성 문장의 품질은 mock 검증과 별도다.
