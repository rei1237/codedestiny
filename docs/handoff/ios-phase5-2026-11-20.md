## 설계(진단 결과)

- 앱 인증은 쿠키가 아니라 localStorage Bearer + `X-Code-Destiny-Runtime: mobile-app` 헤더(worker/lib/auth.js isMobileAppAuthRequest, 출처 capacitor://localhost 포함). 웹 쿠키는 SameSite=Lax 라 앱 출처에 오지 않는다.
  → 프롬프트의 "WKHTTPCookieStore 쿠키 주입"은 이 구조에 맞지 않는다. 같은 목적의 기존 장치 = social_grant(JWT, 180초) → POST /api/auth/oauth/complete JSON 교환. 편차로 보고서에 기록.
- 결함 1: social_grant 가 1회용이 아니다(verifySocialGrant 가 jti 소비 안 함) → IdempotencyKey findOneAndDelete 패턴(consumeRestoreChallenge 와 같은 저장소)으로 jti 1회 소비.
- 결함 2: 앱 handoff 페이지가 안드로이드 전용 intent:// URL 만 쓴다 → iOS(UA) 이면 `com.codedestiny.app://auth?...` 로 이동.
- 결함 3: iOS 브리지 openAuth 가 Capacitor Browser(SFSafariViewController) → 커스텀 스킴 콜백을 못 받는다 → 네이티브 플러그인(ASWebAuthenticationSession, callbackURLScheme com.codedestiny.app).
- 네이티브 SIWA: 새 엔드포인트, aud = 번들 ID(com.codedestiny.app), nonce = sha256(raw nonce) hex, 설정 없으면 503 apple_signin_not_configured(fail-closed). 기존 웹 SIWA 와 같이 계정 자동 생성 없음(가입 티켓).
- refresh token: worker/lib/pii-crypto.js(AES-256-GCM, PII_ENC_KEY)로 암호화 저장, 키 없으면 저장 생략.
- 탈퇴: 기존 handleWithdraw 에 SIWA revoke 단계 추가, 미설정이면 건너뛰고 로그.
- 브리지 오류 분류: 401 만 재로그인, 503·네트워크는 재시도 화면.
