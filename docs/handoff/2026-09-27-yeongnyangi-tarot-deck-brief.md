# 영냥이 전용 타로 — 덱 제작 · 드로우 의식 · 티어별 마스터 상담 구현 프롬프트

## 0. 너의 역할과 목표

너는 이 저장소에서 작업하는 시니어 풀스택 엔지니어이자 타로 아트 디렉터다.
**사주보는 고양이 영냥이**(러시안 블루 고양이 캐릭터, 생선 등급 요금제 고등어/연어/광어/참치)의 타로 상담을 다음과 같이 바꾼다.

1. **흐름 변경**: 질문 → 상담이 아니라, **카드를 먼저 뽑고 → 공개 → 영냥이 상담** 순서로 진행한다.
2. **드로우 의식 연출**: 셔플·선택·공개 전 과정에 신비로운 효과를 넣어 기대감을 끌어올린다.
3. **영냥이 전용 78장 덱**: 현재 사용 중인 꿀꿀 운세 연이 타로 카드 에셋을 영냥이에서만 걷어내고, 이미지 생성 스킬로 **귀엽고 신비로운 영냥이 오리지널 덱 78장 + 카드 뒷면**을 직접 제작한다.
4. **최고의 타로 마스터 상담**: 고등어부터 참치까지 티어별로 깊이가 분명히 다른, 상세하고 전문적인 상담을 제공한다.

## 1. 절대 규칙 (모든 Phase 공통)

- **게이트 방식**: 각 Phase는 `진단/작업 → 구조화된 보고서 → 명시적 승인 대기`로 끝난다. 승인 없이 다음 Phase로 넘어가지 않는다.
- **경로 추측 금지**: 파일 경로, 스킬 이름, 버킷 이름, 컬렉션 이름은 반드시 실제로 확인한 뒤 사용한다. 확인하지 못했으면 보고서에 "미확인"으로 적고 멈춘다.
- **엔진 코드 읽기 전용**: 6개 점술 엔진(타로 포함) 코드베이스는 수정하지 않는다. 카드 의미 데이터 등이 필요하면 **어댑터 래퍼로만** 접근한다.
- **결제 파일 별도 게이트**: PortOne/Inicis 결제 실행 파일, 이용권·영구 해금(entitlement) 로직을 건드려야 하면 즉시 멈추고 별도 승인을 요청한다. 가격은 변경하지 않는다.
- **연이 덱 보존**: 연이 타로 에셋과 그것을 쓰는 코드(꿀꿀 운세 / Code Destiny 쪽)는 삭제·이동·수정하지 않는다. 영냥이만 새 덱을 바라보게 한다. 폐기 코드는 `_graveyard/` 격리 패턴을 따른다.
- **브랜드 혼합 금지**: 영냥이 화면에 연이 카드 아트가 섞여 나오는 일은 어떤 fallback 상황에서도 없어야 한다.
- **Forward-fix only**: 사용자 에셋 포맷, KV/R2 스키마, 결제 데이터 포맷은 기존 것을 바꾸지 말고 새 버전 네임스페이스로 추가한다.
- **i18n**: 사용자에게 보이는 모든 문자열(카드 이름, 포지션 이름, 연출 문구, alt 텍스트 포함)은 i18n 키를 사용한다.
- **레이아웃**: 960px 데스크톱 레이아웃을 유지한다. 모바일 우선, Android WebView에서 동작해야 한다.
- **커밋**: 전용 브랜치(예: `feat/youngnyangee-tarot-deck`)에서 작업, Conventional Commits, 최소·외과적 변경.

## Phase 0 — 진단 (읽기 전용)

코드를 한 줄도 수정하지 말고 아래를 조사해 보고서로 제출한다.

1. **영냥이 타로 현재 흐름**: 진입점, 화면 구성, 질문 입력 → 드로우 → 상담 순서가 현재 어떻게 되어 있는지. 관련 파일 경로 목록.
2. **현재 카드 에셋 참조 방식**: 연이 타로 에셋을 어디서 어떻게 불러오는지(하드코딩 경로 / manifest / R2 / public 폴더 등). 영냥이와 연이가 공유하는 지점과 분리 가능 지점.
3. **드로우 로직**: 카드 결정이 클라이언트인지 서버인지, 난수 방식, 정/역방향 처리, 새로고침 시 재뽑기 가능 여부.
4. **상담 파이프라인**: 사용 중인 LLM 호출 경로, 프롬프트 위치, 스트리밍 여부, 비동기 큐 사용 여부, 영냥이 캐릭터 말투 정의 위치.
5. **티어 설정**: 고등어/연어/광어/참치 각각의 현재 정의(가격, 스프레드, 분량, 후속 질문 수 등)가 있는 파일. 기존 콘텐츠 분량 정책이 있으면 그 기준.
6. **결제·이용권 연동 지점**: 타로 이용권/영구 해금 모델이 드로우·상담 어느 시점에 체크되는지.
7. **이미지 생성 스킬**: 이 환경에서 사용 가능한 이미지 생성 스킬/도구를 실제로 목록에서 찾고, 그 SKILL.md(또는 도구 설명)를 읽어 지원 비율·해상도·참조 이미지 입력 가능 여부·시드 고정 가능 여부·비용/속도 제약을 정리한다. **찾지 못하면 여기서 멈추고 보고한다.**
8. **영냥이 기존 캐릭터 자료**: 저장소 안의 영냥이 일러스트·캐릭터 시트·컬러 정의 위치. 이것이 새 덱 캐릭터 디자인의 기준이 된다.
9. **에셋 저장소**: 영냥이 에셋이 올라가는 R2 버킷/경로 규칙(스테이징 포함), 이미지 최적화 파이프라인 유무.

**보고서에 반드시 포함할 결정 요청 사항**
- **결제 시점 vs 드로우 시점**: "카드를 먼저 뽑는다"는 흐름에서, 결제/이용권 확인을 드로우 전에 할지, 무료로 카드를 보여주고 상세 상담에서 결제를 받을지(미리보기 → 페이월). 각 안의 전환율·어뷰징(무료로 뽑고 이탈) 리스크를 정리해 선택지로 제시한다. 결정은 내가 한다.
- 티어별 기존 정의와 아래 Phase 6 기본안의 차이.

→ **승인 대기**

## Phase 1 — 아트 디렉션 확정 (스타일 바이블 · 캐릭터 시트 · 카드 뒷면 · 프레임)

이미지를 대량 생성하기 전에 일관성의 기준부터 만든다. 산출물은 `docs/` 또는 Phase 0에서 확인한 문서 위치에 둔다(경로 추측 금지).

### 1-1. 스타일 바이블
- **톤**: 귀엽지만 유치하지 않은, 동화책 같은 신비로움. "밤하늘 아래 작은 마법사 고양이".
- **팔레트(기본안, 기존 영냥이 컬러가 있으면 그쪽 우선)**: 미드나잇 네이비 배경, 달빛 실버, 라벤더, 포인트는 금박 골드. 슈트별 보조색(아래 1-4).
- **렌더링**: 부드러운 수채+디지털 페인팅 질감, 은은한 발광(글로우), 별가루 입자. 선명한 실루엣으로 썸네일 크기에서도 읽혀야 한다.
- **구도 규칙**: 세로 2:3, 상단 10%와 하단 14%는 프레임·카드명 오버레이 영역이므로 중요한 요소를 두지 않는다.
- **금지**: 이미지 안의 글자·숫자·서명·워터마크, 실존 상업 타로 덱의 구도 복제, 연이 캐릭터와 닮은 요소, 공포·유혈 표현.

### 1-2. 영냥이 캐릭터 시트
- 기존 영냥이 자료를 기준으로 턴어라운드(정면·3/4·측면·뒷모습), 표정 6종(평온·미소·놀람·진지·졸림·장난), 체형 비율, 털색(블루그레이), 눈 색, 고유 소품(있다면)을 고정한다.
- 이 시트를 이후 모든 생성의 **참조 이미지**로 사용한다(스킬이 참조 입력을 지원하는 경우).

### 1-3. 조연 캐스트 시트
- 마이너 아르카나 코트 카드와 다인원 장면에 필요한 **오리지널 조연 고양이** 4~6마리(서로 다른 품종·털색·실루엣)를 정의한다. 영냥이와 한눈에 구분되어야 한다.

### 1-4. 슈트 모티프 매핑 (기본안)

| 슈트 | 원소·주제 | 영냥이 모티프 | 보조색 |
|---|---|---|---|
| 완드 | 불 · 열정/행동 | 별빛 깃털 낚싯대 장난감(고양이 wand) | 호박색·주황 |
| 컵 | 물 · 감정/관계 | 달빛이 고인 찻잔·물그릇 | 청록·아쿠아 |
| 소드 | 공기 · 사고/갈등 | 고양이 수염 모양의 은빛 검 | 연보라·실버 |
| 펜타클 | 흙 · 물질/현실 | 황금 생선 동전(생선 등급 세계관 연결) | 골드·올리브 |

### 1-5. 카드 뒷면
- 초승달 + 영냥이 실루엣 + 고양이 눈 문양 + 별자리 링.
- **180° 회전 대칭 필수**: 뒷면만 보고 정/역방향을 알 수 없어야 한다.

### 1-6. 프레임
- 금박 테두리 + 코너 장식. 카드 번호·이름은 **이미지에 굽지 않고** 런타임 오버레이(i18n)로 표시한다. 프레임은 SVG 또는 별도 PNG 레이어.

**산출물**: 스타일 바이블 문서, 캐릭터 시트 이미지, 조연 캐스트 시트, 카드 뒷면 후보 3종, 프레임 시안.
→ **승인 대기**

## Phase 2 — 파일럿 카드 (5장)

아래 5장을 먼저 제작해 스타일·일관성·기술 파이프라인을 검증한다.
**0 광대 · 18 달 · 16 탑 · 컵 에이스 · 펜타클 5**
(밝은 카드 / 어두운 카드 / 역동적 카드 / 사물 중심 카드 / 개수 정확도가 중요한 카드를 한 번씩 시험)

### 생성 프로토콜
- 모든 생성 요청은 **프롬프트 원장**(예: `prompts/tarot/youngnyangee/<cardId>.json`, 위치는 Phase 0 확인 후 결정)에 기록한다: 프롬프트 전문, 네거티브 프롬프트, 참조 이미지, 시드, 모델/스킬 버전, 생성 일시, 채택 여부.
- 카드별로 후보 2~4장을 생성해 최선을 채택한다.

### 카드별 QA 체크리스트 (모든 카드에 적용)
- [ ] 영냥이 캐릭터 시트와 일치(털색·눈·비율·얼굴형)
- [ ] 전통 타로 상징이 카드 의미를 전달함(아래 상징표 기준)
- [ ] **마이너 2~10: 슈트 심볼 개수가 정확함** (예: 펜타클 5 = 동전 정확히 5개). 이미지 모델이 개수를 틀리면 재생성하고, 3회 실패 시 심볼 레이어를 별도 합성하는 방식으로 전환한다.
- [ ] 글자·숫자·워터마크·서명 없음
- [ ] 손발·꼬리 개수 이상 없음, 해부학적 왜곡 없음
- [ ] 오버레이 영역(상단 10%, 하단 14%)이 비어 있음
- [ ] 240px 썸네일에서도 무슨 카드인지 식별 가능
- [ ] 캐릭터의 **시선 방향**(좌/우/정면/위)을 manifest에 기록 — 상담에서 카드 간 흐름 해석에 사용

**산출물**: 5장 원본 + 채택 사유, QA 결과표, 컨택트 시트(5장 + 뒷면 나란히).
→ **승인 대기** (여기서 스타일이 확정되면 이후 변경하지 않는다)

## Phase 3 — 전체 덱 제작 (78장)

배치 순서: **메이저 22장 → 완드 14 → 컵 14 → 소드 14 → 펜타클 14**. 배치마다 컨택트 시트와 QA 결과표를 제출하고 승인 후 다음 배치로 간다.

### 등장 규칙
- **메이저 22장**: 전부 영냥이 주연.
- **마이너 에이스**: 사물(슈트 심볼) 중심, 영냥이의 앞발이나 실루엣이 함께 등장.
- **마이너 2~10**: 영냥이 주연 기본. 장면상 여러 인물이 필요하면 조연 캐스트 사용.
- **코트 카드 16장**: 슈트별 조연 캐스트. 시종=아기 고양이 견습생, 기사=모험하는 청년 고양이, 여왕·왕=성숙한 고양이. 영냥이는 배경의 작은 카메오로만.

### 메이저 아르카나 콘셉트 (기본안 — 전통 상징을 지키되 영냥이식으로 재해석)

| # | 카드 | 콘셉트 |
|---|---|---|
| 0 | 광대 | 작은 보따리를 멘 영냥이가 구름 절벽 끝에서 나비를 쫓아 한 발을 내딛는다. 흰 장미, 떠오르는 해 |
| 1 | 마법사 | 한 발은 하늘, 한 발은 땅. 탁자 위 4슈트 도구, 머리 위로 꼬리가 ∞ 모양 |
| 2 | 여고위사제 | 달빛 두 기둥(흑·백) 사이, 석류 무늬 베일, 두루마리, 발치의 초승달 |
| 3 | 여황제 | 밀밭과 꽃 쿠션 정원, 별 12개 왕관, 풍요로운 햇살 |
| 4 | 황제 | 숫양 문양 돌 왕좌, 붉은 망토, 험준한 산맥 — 단단하지만 귀여운 위엄 |
| 5 | 교황 | 열쇠 두 개, 경청하는 아기 고양이 제자 둘, 삼중관 |
| 6 | 연인 | 두 고양이 위로 날개 달린 빛의 존재, 선택의 나무 두 그루 |
| 7 | 전차 | 흑·백 고양이 석상이 끄는 별빛 전차, 별 캐노피 |
| 8 | 힘 | 영냥이가 사자의 갈기를 부드럽게 쓰다듬는다, 머리 위 ∞ |
| 9 | 은둔자 | 눈 덮인 봉우리에서 별이 든 등불을 든 영냥이 |
| 10 | 운명의 수레바퀴 | 구름 속 거대한 바퀴, 네 모서리의 날개 달린 수호 동물 |

| 13 | 죽음 | 검은 망토의 영냥이가 흰 장미 깃발을 들고 저무는 해 너머로 — 공포 없이 "끝과 새 시작" |
| 14 | 절제 | 두 잔 사이로 흐르는 빛의 물, 한 발은 물 한 발은 땅, 날개 |
| 15 | 악마 | 뿔 달린 그림자 아래 느슨한 사슬의 두 고양이 — 스스로 벗어날 수 있음이 보이게, 귀엽지만 어둡게 |
| 16 | 탑 | 번개 맞아 무너지는 **캣타워**, 떨어지는 왕관, 튀어나오는 불꽃 |
| 17 | 별 | 별빛 호수에 물을 붓는 영냥이, 큰 별 1 + 작은 별 7, 새 한 마리 |
| 18 | 달 | 두 탑 사이 길, 물가의 가재, 달을 향해 우는 집고양이와 살쾡이 |
| 19 | 태양 | 해바라기 담장 앞, 흰 조랑말을 탄 아기 영냥이, 거대한 미소 짓는 해 |
| 20 | 심판 | 나팔 부는 천사, 상자에서 깨어나 두 팔(앞발)을 드는 고양이들 |
| 21 | 세계 | 월계관 고리 안에서 춤추는 영냥이, 네 모서리 수호 동물 |

마이너 56장 콘셉트는 전통 상징(예: 컵 5 = 쏟아진 잔 3 + 서 있는 잔 2, 소드 10 = 새벽이 오는 수평선)을 유지하며 같은 방식으로 표를 작성해 **배치 시작 전 콘셉트표를 먼저 제출**한다.

**산출물**: 배치별 컨택트 시트, QA 결과표, 프롬프트 원장 갱신.

## Phase 4 — 에셋 파이프라인 & 덱 레지스트리

1. **최적화**: 원본 보관 + 배포용 WebP(가능하면 AVIF 병행) 3사이즈 — 썸네일 240w / 표준 600w / 고해상도 1200w. 뒷면·프레임 포함.
2. **역방향은 CSS 회전**으로 처리하고 별도 이미지를 만들지 않는다.
3. **버전 네임스페이스**: 기존 경로를 덮어쓰지 말고 새 경로(예: `.../youngnyangee/tarot/v1/`)로 추가. 실제 버킷·경로는 Phase 0 확인값을 사용하고 **스테이징 먼저** 업로드한다.
4. **manifest.json**: 카드별 `id, arcana, suit, rank, files{thumb,std,hi}, altKey(i18n), nameKey(i18n), gaze, dominantColor, contentHash, deckVersion`.
5. **덱 레지스트리**: 브랜드별로 덱을 선택하는 얇은 계층(`brand → deckId → manifest`). 영냥이는 영냥이 덱, 연이 쪽은 기존 동작 그대로. 타로 엔진은 수정하지 않고 어댑터에서 카드 ID ↔ 에셋을 매핑한다.
6. **Fallback**: 이미지 로드 실패 시 영냥이 카드 뒷면 + 카드명 텍스트로 대체. 연이 아트로 절대 대체하지 않는다.
7. **검증 스크립트**: 78장 + 뒷면 전부 존재, 사이즈별 파일 존재, manifest 스키마 유효, i18n 키 누락 없음을 확인하는 스크립트를 추가하고 CI에서 돌릴 수 있게 한다.

→ **승인 대기**

## Phase 5 — 드로우 의식 UX (카드 먼저, 상담은 나중)

### 5-1. 흐름
1. **질문 정리**: 영냥이가 질문을 다듬도록 돕는다(선택 입력, 주제 칩: 연애·재회·일·돈·선택·오늘의 운세). 티어에 맞는 스프레드가 자동 선택되거나 고를 수 있다.
2. **집중 의식**: 화면이 어두워지고 달빛이 차오르며 영냥이가 "눈을 감고 질문을 떠올려 보라냥" (i18n). 3초 호흡 가이드 링.
3. **셔플**: 덱이 달빛 소용돌이 속에서 섞이고 영냥이의 앞발이 카드를 톡톡 친다. 사용자가 원하는 순간 탭해서 셔플을 멈춘다.
4. **펼침 & 선택**: 카드가 부채꼴로 펼쳐진다. 손가락을 올리면 카드가 살짝 떠오르며 발광. 사용자가 스프레드 장수만큼 직접 고른다. 선택된 카드는 빛 꼬리를 남기며 스프레드 자리로 날아간다.
5. **공개**: 사용자가 한 장씩 탭해 뒤집는다. 3D 플립 + 빛 번짐 + 별가루 + 카드명 페이드인. 메이저 아르카나는 한 단계 더 화려한 효과(금빛 룬 링). 역방향은 뒤집힌 채로 공개.
6. **전환**: 모두 공개되면 카드들이 은은하게 맥동하고 "영냥이가 카드를 읽고 있다냥…" 로딩과 함께 상담이 스트리밍된다.

### 5-2. 드로우 무결성 (서버 결정)
- 카드 결과는 **사용자가 선택을 확정하는 순간 서버에서** 암호학적 난수로 결정해 **드로우 세션**에 저장한다(`drawSessionId, userId, tier, spreadId, question, cards[{position, cardId, reversed}], createdAt, status, consultationId`). 저장소·컬렉션은 기존 패턴을 확인 후 따른다.
- 새로고침·재진입 시 같은 세션을 복원한다. **다시 뽑기로 결과를 바꿀 수 없다.** 요청은 멱등(idempotent)이어야 한다.
- 결제/이용권 체크 시점은 Phase 0에서 내가 결정한 안을 따른다. 결제 관련 파일 수정이 필요하면 멈추고 별도 승인을 받는다.

### 5-3. 체감 속도 최적화
- 카드 ID가 확정되면 공개 애니메이션이 도는 동안 **해당 카드 이미지만 미리 로드**한다(78장 전체 선로딩 금지).
- 선택 확정 시점에 **상담 생성을 즉시 시작**해, 사용자가 카드를 뒤집는 시간으로 LLM 대기 시간을 가린다. 기존 비동기 큐가 있으면 재사용한다.

### 5-4. 연출 기술 기준
- `transform`/`opacity` 중심 애니메이션, 레이아웃 스래싱 금지, 60fps 목표.
- 파티클은 가벼운 캔버스 1개 또는 CSS로. 저사양(`deviceMemory`, `hardwareConcurrency`)에서는 파티클 수를 자동 축소.
- `prefers-reduced-motion`이면 페이드 위주의 간소화 연출.
- 효과음은 기본 **꺼짐**, 토글 제공. Android는 기존 네이티브 브리지에 햅틱이 있으면 공개 순간 가벼운 진동(없으면 추가하지 말고 보고).
- 스크린리더: 각 카드 공개 시 카드명·정/역방향을 aria-live로 안내.

→ **승인 대기**

## Phase 6 — 최고의 타로 마스터 상담 엔진

### 6-1. 영냥이 페르소나
- 수백 년 달빛 도서관에서 타로를 연구해 온 **최고의 타로 마스터 고양이**. 다정하고 통찰력 있으며, 귀여움은 말끝에서만 살짝("~냥"은 문단당 최대 1회), 해석의 깊이는 진지한 전문가 수준.
- 기존에 정의된 영냥이 말투가 있으면 그것을 우선한다.
- 비숙명론: 카드는 흐름과 가능성을 보여줄 뿐, 선택은 사용자에게 있다.

### 6-2. 티어별 상담 스펙 (기본안 — Phase 0에서 기존 정의와 대조, 가격 변경 금지)

| 티어 | 스프레드 | 상담 구성 |
|---|---|---|
| 🐟 고등어 | 원카드 또는 3장(상황·조언·결과) | 핵심 답 한 줄 → 카드별 해석 → 오늘 바로 할 수 있는 행동 1가지 |
| 🍣 연어 | 3~5장 (주제별 스프레드) | 카드별 심층 해석 → 카드 간 관계 → 행동 조언 3가지 → 주의할 점 |
| 🐠 광어 | 7장 호스슈 또는 주제 전용(관계·A/B 선택·재회) | 위 내용 + 시간 흐름(과거·현재·가까운 미래) + 상대/환경 분석 + 시기 힌트 |
| 🐟👑 참치 | 켈틱 크로스 10장 + 조언 카드 1~2장 추가 드로우 | 위 내용 + 원소·수비학·메이저 비중 종합 분석 + 시나리오별(유지/변화) 전망 + 한 달 실행 가이드 + 후속 질문 |

분량은 기존 콘텐츠 분량 정책이 있으면 그 기준을 따르고, 없으면 티어별 분량안을 Phase 0 보고서에 제안한다. **상위 티어는 분량뿐 아니라 해석 기법 자체가 더 깊어야 한다.**

### 6-3. 해석 방법론 (시스템 프롬프트에 반드시 반영)
1. **포지션 × 카드 × 방향 × 질문 맥락**의 4요소를 교차해 해석한다. 카드 사전 뜻을 나열하지 않는다.
2. **역방향**: 단순 반대 의미 금지. 에너지의 막힘·내면화·지연·과잉 중 무엇인지 맥락으로 판단한다.
3. **원소 균형**: 슈트 분포로 부족하거나 넘치는 에너지를 읽는다.
4. **메이저 비중**: 메이저가 많으면 개인 의지를 넘어선 큰 흐름, 적으면 일상적 선택의 영역.
5. **숫자 반복**: 같은 숫자가 여러 장이면 그 수비학적 주제(예: 5 = 변화와 갈등)를 강조.
6. **코트 카드**: 실제 인물인지 사용자의 태도인지 질문 맥락으로 판단하고 근거를 밝힌다.
7. **시선 흐름**: manifest의 `gaze` 값으로 카드 속 영냥이가 어느 카드를 바라보는지 읽어 카드 간 연결 서사를 만든다(영냥이 덱만의 고유 해석 포인트).
8. **질문 유형별 규칙**: 예/아니오, 시기, A/B 선택, 관계, 재회 질문마다 결론을 내리는 방식을 정의한다. 예/아니오도 "조건부 답"으로 구체화.
9. **구체적 행동**: 모든 조언은 사용자가 실제로 할 수 있는 행동으로 끝난다.

### 6-4. 출력 구조와 검증
- LLM 출력은 구조화된 JSON(섹션별)으로 받아 UI에서 렌더링한다. 섹션은 티어 스펙을 따른다.
- **검증기** (실패 시 1회 재생성, 그래도 실패하면 안전한 축약 응답 + 로그):
  - 뽑힌 모든 카드가 해석에 등장하는가
  - **뽑히지 않은 카드 이름이 등장하지 않는가** (LLM에는 드로우 세션의 카드 JSON만 전달)
  - 정/역방향 표기가 세션과 일치하는가
  - 티어별 최소 섹션·분량 충족
  - 금지 표현: 죽음·질병·사고의 단정적 예언, 의료·법률·투자에 대한 확정적 지시, 공포 조장
- **위기 신호**(자해·극단적 선택 암시 등)가 질문에 있으면 타로 해석보다 안전 안내를 우선하는 기존 정책을 따르고, 없으면 추가를 제안한다.
- 카드 의미 기초 데이터는 타로 엔진을 **어댑터로만** 읽어 사용한다.

### 6-5. 품질 평가
- 대표 질문 10개 × 4티어로 샘플 상담을 생성해 제출한다. 각 샘플에 대해 위 방법론 9항목 충족 여부를 자체 채점하고, 티어 간 차이가 분명한지 비교표를 만든다.

→ **승인 대기**

## Phase 7 — 통합 검증 & 최종 보고

- E2E: 4티어 전체 플로우(질문 → 의식 → 선택 → 공개 → 상담), 새로고침 복원, 중복 요청 멱등성, 결제/이용권 경로.
- 기기: 모바일 웹, Android WebView 앱, 960px 데스크톱. 저사양 기기 연출 축소 확인.
- 성능: 드로우 화면 LCP·애니메이션 프레임 드롭, 이미지 전송량(선택된 카드만 로드되는지).
- 접근성: reduced-motion, 스크린리더 안내, 대비.
- **회귀**: 연이 타로(꿀꿀 운세/Code Destiny)가 이전과 동일하게 동작하는지, 연이 에셋이 영냥이에 한 장도 노출되지 않는지.
- 최종 보고서: 변경 파일 목록, 추가된 에셋·manifest 위치, 프롬프트 원장 위치, 남은 리스크, 프로덕션 배포 체크리스트.
