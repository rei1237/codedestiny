## 3. 도구 — 지금 무엇을 어떻게 재나

```bash
npm run build:cf
npm run perf:tap-cost   -- --runs=3 --label=<라벨>              # 🔴 1차 판정 기준
npm run perf:interaction -- --runs=3 --label=<라벨>             # 무프로필
npm run perf:interaction -- --runs=3 --label=<라벨>p --profile=1 # 프로필 카드 시드
```

### 🔴 판정 규칙

1. **1차 기준은 ms 가 아니라 호출 횟수**(`perf:tap-cost`). 이 레포의 ms 밴드는 결론이 한 번 뒤집힐 만큼
   넓다(`mobile-home-perf.md` §3-1). 호출 횟수는 편차 0 이다.
2. ms 는 **min~max 밴드 비겹침**으로만 판정한다. 겹치면 "개선"이 아니라 **"미증명"**이라고 쓴다.
3. 🔴 `perf:tap-cost` 의 **`컬렉션 헤더(대조군)` 는 줄면 안 된다.** 헤더만 줄고 대조군이 그대로여야
   성공이고, 대조군까지 줄었으면 좌표 폴백의 구제 경로를 죽인 것이다.
4. 회귀 감시: `스크롤 50ms 초과 프레임 수` · `부팅 이후 레이아웃 시프트` 가 오르면 실패.
5. 🔴 `--profile=1` 은 **다른 모든 대상의 값도 바꾼다**. 베이스라인을 2벌 잡고 라벨을 섞지 않는다.

### 🔴 이 표에서 반드시 읽어야 하는 것

**모든 대상에서 `처리` ≈ 0 이고 `렌더`가 지배한다.**
Event Timing 의 `처리`는 **핸들러 본문**만 센다. 핸들러가 끝난 뒤 rAF·`setTimeout`·이벤트 팬아웃으로
도는 일은 전부 `렌더`로 계상된다. 즉 남은 비용은 **"핸들러가 끝난 뒤 다음 페인트까지"**에 있다.

⚠ = 이동을 막고 잰 대상 — **입력 대기·처리만 신뢰하고 렌더 성분은 신뢰하지 않는다**(취소가 확정되기
전까지 크로미움이 페인트를 미룰 수 있다).

## 6. 작업 규칙 (앞 문서 §7 에 더해)

1. 성능 변경은 `index.html` 의 인라인 블록 **내용**만 고친다. **구조**(`data-marker`·id·태그 배치)를
   바꾸면 `scripts/verify-*.mjs` **74개**가 문자열로 단언하고 있어 깨진다.
2. 8KB 인라인 블록 경계: 위험 블록은 `cd-service-index-search-v20260723`(**7,958B**, 여유 234B)
   **하나뿐**이다. `mobile-bottom-navigation-v20260701` 은 27.5KB 로 이미 외부화 대상이라 무관하다.
   블록 크기 재는 법:
   ```bash
   node -e "const fs=require('fs');const s=fs.readFileSync('index.html','utf8');
   const i=s.indexOf('data-marker=\"cd-service-index-search-v20260723\"');
   const st=s.lastIndexOf('<script',i),en=s.indexOf('</script>',i);
   console.log(Buffer.byteLength(s.slice(st,en+9),'utf8'))"
   ```
3. 🔴 `js/mobile-interaction-patch.js` 를 고치면 `scripts/sync-legacy-static-to-public.mjs` 의
   `MOBILE_INTERACTION_PATCH_CACHE_KEY` 를 **실제 SHA-256 prefix 로** 갱신한다:
   ```bash
   node -e "const c=require('crypto'),fs=require('fs');
   console.log('build-'+c.createHash('sha256').update(fs.readFileSync('js/mobile-interaction-patch.js')).digest('hex').slice(0,12))"
   ```
   안 올리면 파일만 바뀌고 URL 이 그대로라 재방문 사용자는 옛 캐시를 계속 쓴다.
4. `index.html` 을 고쳤으면 `npm run sync:public`(미러 6벌). `js/core/*` 의 `?v=build-…` 변경은
   셸 캐시 키라 **정당한 산출물이니 함께 커밋**한다. 🔴 `rss.xml`·`insights/rss.xml`·`sitemap.xml` 과

## 7. 🔴 끝나지 않은 진단 (추측으로 메우지 말 것)

1. **`#cdTodayPanelSaju` 1,032ms 가 입력 대기인지 렌더인지 모른다.** 그 요소는 위임 리스너의 모든
   분기가 return 이라 처리 ≈ 0 이다. `header.logo-area` 와 같은 부류일 가능성이 크지만 **확인 못 했다.**
   PR-5 를 내기 전에 `perf:interaction` 3단 분해로 먼저 가를 것.
2. **`.dp-fsel-btn--saju` 416ms 의 정체를 모른다.** 클릭 동기 비용은 `classList.remove` +
   `setTimeout(…,350)` 뿐이라, 입력 대기일 가능성이 크다. PR-6 이 고치는 것은 INP 가 아니라
   "눌렀는데 몇 초 동안 아무 일도 안 일어난다"는 체감이다 — **둘을 섞어 보고하지 말 것.**
3. **앞 문서 §6-5 의 CLS 0.3185 는 그대로 미해결이다.** 이번 라운드에서 `0.3562` 로 관측됐고
   `#685` 로도 변하지 않았다(0.3562 → 0.3562). 귀속은 여전히 **서비스 검색 입력**이다.
   앞 문서 §6-5 의 미해결 질문(뷰포트가 움직인 것인지 문서가 재배치된 것인지)이 그대로 남아 있다.
4. **필드 재측정을 못 했다.** `#685` 의 INP 개선은 **필드에서만 확인된다.** 머지 후 사용자에게 같은
   형식의 데이터를 다시 받아야 판정할 수 있다. 그 전에는 "고정 비용 68% 감소(실측)"까지만 말할 것이고
