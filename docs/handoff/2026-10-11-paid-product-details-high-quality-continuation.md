## 고품질 제작의 합격선

1. **사실 먼저:** 실제 진입→입력→가격 정본→생성 계약→결과 렌더러→조건부 항목을 연결해서 읽는다. 정적 해석, AI 답변, AI에 복사할 질문문, PDF를 구분한다. 프롬프트 요구사항만 보고 제공을 약속하지 않는다.
2. **상품만의 이야기:** 그 상품을 찾는 구체적인 질문, 해석 근거, 실제 목차, 확대 예시, 활용 행동을 새로 편집한다. 다른 상품의 글에 이름만 치환하지 않는다. 목차도 실제 결과의 순서와 범위로 쓴다.
3. **장면과 읽기 리듬:** 큰 대표 장면, 여백 있는 인용, 확대 해석, 도해를 글과 교차한다. 같은 둥근 카드 목록을 매 장 반복하지 않는다. 서양 차트를 베다/자미두수 장식에 혼용하지 않는다.
4. **조판:** 기본 8~10장, 작은 해금은 약 6장. 각 1080×1440px. 본문 48~54px, 제목 78~108px, 좌우 여백 80px 이상을 출발점으로 삼는다. 360px 실제 상세 영역에서는 이미지 폭이 더 작아질 수 있으므로 실제 화면을 확인한다. 넘침을 글씨 축소로 감추지 말고 문장·패널을 재편집한다.
5. **예시의 정직성:** 합성/편집 예시는 화면 안에도 표시한다. ‘편집 예시’, ‘가상 예시’, ‘가상 활용 예시’ 등 출처를 분명히 한다. 실제 고객 결과나 과금 LLM 결과라고 부르지 않는다. 본문 notice만으로 모든 예시 표시를 대신하지 않는다.
6. **후기와 제작자:** 실제 원문과 공개 범위를 확인한다. 과거 직접 1:1 상담 후기를 디지털 상품 구매 후기로 바꾸지 않는다. 근거가 없으면 후기 대신 방법론·해석 예시를 쓴다. 숫자·별점·성공 보장을 만들지 않는다.
7. **정책:** 이용권·월정석·단건 결제 유지. 무료·무제한·평생·PDF·저장·이어 묻기는 구현 근거가 있을 때만 쓴다. 연이/네오의 말투 차이로 기능 계약을 바꾸지 않는다.
8. **접근성과 기능:** 이미지와 같은 내용의 접근 가능한 본문을 유지하고 긴 alt 중복 낭독을 피한다. 이미지 실패 대체 본문, 크기 예약, 첫 이미지 로딩, 후속 지연 로딩, 실제 CTA 접근성을 확인한다. 이미지 속 가짜 버튼을 만들지 않는다.

## 재사용할 구현과 검증 도구

공통 출력 도구는 재사용해도 된다. 상품 원고·목차·장면은 재사용 템플릿으로 찍어내지 않는다.

```powershell
# cwd는 현재 작업 중인 안전한 체크아웃이어야 한다.
node scripts/render-crafted-detail.cjs <실제로-작성한-id>
node --test __tests__/ui/feature-visual-details.test.mjs
npm run check:fast -- --plan
npm run check:fast
# 관련 authored 소스를 수정한 경우 생성물을 동기화한다.
npm run sync:public
node scripts/sync-legacy-static-to-public.mjs
# 필요한 경우 sitemap 생성 후 최종 커밋에서 검사한다.
git diff --check
# 검증한 파일만 지정해 커밋한 다음:
npm run check:pre-push
```

위 명령은 후속 작업용이다. 이 인수인계 작성만으로 모두 다시 실행했다는 뜻이 아니다. 변경 범위와 최신 저장소 규칙을 적용하고 전체 lint/typecheck/build를 습관적으로 반복하지 않는다. 생성기 실행이 끝나기 전에 소스를 수정하거나 다른 동기화를 겹쳐 돌리지 않는다. 캐시 의존 경로 때문에 public 미러 동기화가 여러 번 필요했던 이력이 있다. 커밋 후 `check:pre-push`의 무변경 검사를 근거로 완료한다.

실제 화면 검수 예제: `scripts/verify-crafted-ifa.cjs`, `scripts/verify-crafted-vedic-prashna-prompt.cjs`, `scripts/verify-crafted-chat-engine.cjs`, `scripts/verify-crafted-olympus.cjs`. 먼저 스크립트를 읽고 해당 상품의 실제 선택자·입력·mock·CTA로 조정한다. 프라슈나 스크립트의 로컬 origin은 `http://127.0.0.1:14330`이다. 기존 서버가 존재하거나 올바른 소스를 제공한다고 가정하지 않는다. 공통 강제 mount만 성공한 화면을 실제 연결 검증으로 대신하지 않는다.

- IFA와 프라슈나의 표시/서버 가격 차이는 이전에 발견되었고 사용자 가격 수정 중이다. 상세 이미지에 가격을 고정하지 않았으며 기존 결제 진입을 유지했다. 최신 가격 정본과 다른 세션 수정 상태를 확인한다.

CI/배포를 sleep+조회 루프로 기다리지 않는다. 다음 push 직전 또는 최종 보고 직전에 한 번 결과를 확인한다. 다른 세션의 커밋 때문에 main이 실패 중이면 그 위에 push하지 말고 원인 SHA를 보고한다. 내 변경의 실패면 원인을 해결하고 관련 검사를 한다.

## 정리와 보고

이 작업본의 임시파일 일괄 삭제는 자동 승인 검토가 구체적인 사유 없이 “정책에 의해 차단됨”으로 거절하여 수행하지 않았다. 다른 언어/셸로 같은 삭제를 우회하지 않는다. 다른 세션 파일·워크트리를 지우지 않는다. 남은 정리는 허용된 범위에서 소유와 경로를 확인한 뒤 처리하고 실제 남은 것을 보고한다.

최종 보고에는 수정 파일, 개별 편집 의도, 유지한 정책, 실행한 명령과 결과, 미확인/보류 항목, 실제 미리보기 링크를 포함한다. 새 판매 근거가 없는 10개를 제작하지 못했다고 해서 기존 페이지를 재포장하거나 존재하지 않는 상품을 만들지 않는다. 반대로 새 판매 근거가 확인되었으면 이 문서의 과거 보류를 이유로 작업을 중단하지 않는다.

후속 제작을 모두 종료했을 때 이 인수인계의 status를 done으로 닫는다. 인수인계 문서 전달 완료와 상세페이지 후속 제작 완료는 구분한다.
