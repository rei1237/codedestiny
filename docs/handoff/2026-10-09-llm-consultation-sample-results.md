## 수정할 결함 (심각도 순)

모든 결함에 공통으로 적용하는 금지 사항이 있다.
- 기대값·테스트를 고쳐 실패를 덮지 않는다.
- 프롬프트 문구만 늘려 모델에게 맡기지 않는다. 근거 데이터 결함은 데이터에서 고친다.
- 생년월일 원값을 테스트 fixture나 로그에 새로 넣지 않는다.

### D8. 결제 후 전달 보장과 등급별 타임아웃

#### D8-1. 현재 동작

- **길이 보정.** 길이가 부족하면 한 번만 보정한다. 보정된 초안은 길이로 다시 거부하지 않는다(`worker/yeongnyangi/fortune/reading-quality.ts:19-26`).
- **남은 차단 경로 ①: 전달 하한.** `chapterDeliveryFloor`는 minimumChars의 50%다(`worker/yeongnyangi/chapter-delivery-contract.js:12-13`). 이보다 짧으면 `CHAPTER_TOO_SHORT`로 실패한다.
- **남은 차단 경로 ②: 시도 소진.** 장당 시도는 자동 3회, 시스템 2회, 수동 3회다(`chapter-retry-policy.js:2-4`). 이를 다 쓰면 주문이 `FORTUNE_FAILED / GENERATION_REVIEW_REQUIRED`로 보류되고 남은 장은 전달되지 않는다(`repository.js:403-423`).
- **위험.** 장 수가 24~36장으로 늘면 주문 1건의 보류 확률이 장 수에 비례해 커진다.

#### D8-2. 지시

1. **전달 하한 조정.** 새 계약의 minimumChars는 장당 목표 하한의 약 55%로 둔다. 그러면 전달 하한은 목표의 약 27%가 되어, 잘림·빈 응답만 거른다.
2. **최선 초안 보존.** 보정 시도가 실패하거나 더 짧으면, 앞서 형식·근거 검사를 통과한 초안을 전달한다.
   - 기존 `saveChapterDraft` / `storedChapterDraft`(`service.ts:448`, `repository.js:822`)를 쓴다.
   - 참고 패턴: 하네스 `r9.mjs` L57의 keepPrior 판정. 이 판정은 `worker/routes/life-book-ai.js` handleStart에서 옮긴 것이다.
3. **길이만 부족하면 보류하지 않는다.** 길이만 부족한 장은 마지막 시도에서도 전달한다. 운영 진단 로그 `CHAPTER_SHORT_DELIVERED`(본문 제외, 장 번호·글자 수·목표만)를 남긴다.
4. **합계로 막지 않는다.** 주문 전체 합계가 목표보다 적다는 이유로 완료를 막는 게이트는 만들지 않는다. 꿀꿀 R9의 `total_content_too_short` 같은 규칙을 영냥이에 들여오지 않는다.
5. **그대로 유지할 것:**
   - 잘림·빈 응답 차단
   - 이어쓰기 표식 차단
   - 블록 구조 검사
   - 차트 사실 모순 차단(`SAJU_PILLAR_CONTRADICTION`, D1 수정 후의 사화 검사)

- **답변 장이 목표 하한보다 짧다.** M 2장 1,252자(하한 1,623), Y1 2장 1,463자(하한 2,221). 하한 미달 장 수는 M 2·Y1 4·Y2 8·Y3 4·MA 10. 전체 분량은 목표를 넘지만 질문에 직접 답하는 장이 얇다. 답변 장 길이 수리를 따로 볼지 결정이 필요하다.
- **장 요약 반복.** 장 수가 늘어 요약이 주제상 비슷해졌다. D4 기준(문장 유사도)은 통과한다(MA 25장 모두 서로 다름).
- **예방 장 입력 초과(위 MA).** 사주가 들어간 모듬·오마카세·참치는 운영에서도 예방 장에서 멈출 가능성이 높다. 별건으로 고쳐야 한다.
- **D9 는 화면 표시만 바꿨다.** 계약·검사는 계속 글자 수로 센다. A4 1장 = 1,800자 가정(10pt 본문, 기본 여백)이다.
