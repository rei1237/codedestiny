# GSC 색인 커버리지 — 미크롤 173건의 실체

## 왜

"GSC 색인 데이터로 SEO 최적화를 꼼꼼하고 정확하게 진행해줘". 사용자가 "페이지 색인 생성" CSV 4종에 이어 **"발견됨 - 현재 색인이 생성되지 않음" 173건 per-URL 목록**까지 내보내 주면서 추정이 실측으로 바뀌었다.

## 지금 상태

- PR #1338 (`worktree-seo-crawl-depth`) — 도달 거리 단축 3건 + `verify:internal-link-depth` 신설. CI 전부 통과, **사용자 머지 대기**.

## 확정된 판정 (다시 재지 말 것)

- **173건 전부 최종 크롤링이 `1970-01-01`** — 즉 구글이 URL 은 알지만 **한 번도 가져간 적이 없다**. 이전 세션의 "≥145" 산술 하한은 이제 **정확히 166**(사이트맵 URL)으로 확정됐다.
- **사이트맵 밖 7건은 둘 다 정상이다** — `/high-value/*` 6건은 `public/_redirects:57` 의 `/guides/*` 301 리네임 이전 레거시 URL 이고, `/reviews` 는 `noindex, follow` 라 사이트맵에 없는 게 맞다. **손댈 것 없음.**
- 🔴 **도달 거리는 절반만 설명한다.** 미크롤 166건 중 3~4홉이던 것은 `stories` 45 + `fortune/{기간}/{sign}` 32 = **77건뿐**이고, **나머지 89건은 이미 1~2홉이었다.** 특히 **홈이 직접 `<a>` 로 링크하는 21개**(`/kkul-kkul-unse` · `/psychotest` · `/vedic-ai` · 가이드 7개 등)도 한 번도 크롤되지 않았다. PR #1338 은 옳지만 **이 166건을 혼자 풀지 못한다.**
- **크롤 속도 제한이 아니다** — 미크롤 라우트 10건 라이브 프로브(2026-08-30): 전부 200, 228~949ms. 기술적 색인성도 439 전수 스윕에서 이상 0.
- ⇒ 남은 원인은 **크롤 수요(사이트 권위)** 다. 코드 레버는 여기서 한계효용이 급격히 떨어진다. `gsc-performance-2026-08-30.md` §2 의 "모수가 없다"·`site-has-no-crux-field-data` 와 같은 결론이다.
- 🔴 **GSC 추이가 증설을 경고한다** — 발견됨-미색인은 152(7/25) → 176(8/11) → 240(8/15) → 173(8/21). **페이지를 늘리면 미크롤 백로그가 같이 늘었다.** `seo-content-expansion-roadmap.md` 의 대량 증설 계획과 정면으로 부딪히므로 재개 전 사용자 판단이 필요하다.

## 남은 작업

- [ ] **관측이 먼저다.** #1338 머지·배포 후 2~4주 뒤 같은 CSV 를 다시 받아 판정한다. 됐다의 기준: 173이 줄고, `stories`·`fortune/{기간}` 77건의 최종 크롤링이 `1970-01-01` 이 아니게 되는 것.
- [ ] **사이트맵 `lastmod` 정직화** (효과는 **추정·미검증**) — 라이브 439개 중 318개가 배포일이다. 원인은 `scripts/lib/sitemap-lastmod.mjs` 가 서명에 전이 import 클로저를 넣는 설계라 공유 크롬 한 줄이 수백 라우트를 "오늘 바뀜"으로 만드는 것. 고칠 때 서명 스킴 버전을 올리되 기존 날짜를 보존해야 하고(안 그러면 315개가 한 번에 튄다) `verify:sitemap-drift` 와 맞물린다.
- [ ] **`/saju-fpti` 정책 드리프트** — `lib/seo/siteSeo.ts:401` 의 `noindexPathPrefixes` 에 있는데 `scripts/generate-sitemap.mjs:222` 가 사이트맵에 싣는다. 어느 쪽으로 맞출지는 **사용자 판단**.
- [ ] **`/destiny-poker` 링크 형태** — 내부 링크는 `.html`, canonical·사이트맵은 확장자 없음.

## 정본 예시

`scripts/verify-internal-link-depth.mjs` 헤더 — 무엇을 간선으로 세는지(①~④)와 상한 2홉의 근거. `DECLARED_EXCEPTIONS` 가 유일한 예외 통로다.

## 함정

- **hreflang 을 간선에서 빼면 로케일 라우트 21개가 헛실패한다.** 구글이 실제로 쓰는 발견 경로라 그래프 정정이지 임계 완화가 아니다.
- 홈 셸 링크를 만지면 `public/i18n/*.json` **12개 전부**에 키가 필요하다(저작 5개, 나머지는 영어 사본).
- 푸터 링크는 `SiteFooterHub.jsx` 와 `lib/i18n/siteFooterHubCopy.ts` **양쪽**에 넣어야 한다.
- 새 가드의 세계는 **사이트맵**이다 — 사이트맵 밖 라우트의 고아 여부는 못 본다(이번 7건이 그 사각지대였고, 확인 결과 둘 다 정상이었다).
