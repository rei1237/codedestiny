## 3. 🔴 도구와 판정에 대해 이번에 배운 것

### 3-1. `verify-home-visual-parity` 는 **계산된 스타일**로 판정한다 — 픽셀이 아니다

그래서 **CSS 속성을 바꾸는 항목은 이 도구로 "픽셀 차이 0" 을 증명할 수 없다.** 그 속성이 그대로
차이로 잡히기 때문이다. 실제로 PR-2 의 `.moon-hero__lead` `backdrop-filter` 제거는 4셀 전부에서
`backdrop-filter: "blur(4px)" → "none"` **단 한 건**으로 FAIL 했다 — 렌더가 바뀌었는지는 알 수 없다.
👉 **앞 문서가 "픽셀 차이 0 이 아니면 넣지 말 것"이라 못박은 항목은 이 도구로는 판정 불가다.**
전용 픽셀 비교(히어로 영역 크롭 diff)를 따로 만들거나, 그 항목을 빼야 한다. **PR-2 에서는 뺐다**(§4-0).

### 3-2. 🔴 노이즈 기준선은 **판정하려는 빌드에서** 뽑아야 한다

`--noise=<이전빌드쌍>` 으로 판정했을 때 `desktop-yeon` 이 `<span class="notranslate">` 의 폭
262→274px 로 FAIL 했다. **같은 빌드에서 노이즈 쌍을 다시 뽑아**(`--noise=r2p2b,r2p2c`) 판정하니
그 항목이 제외되고 **4셀 전부 통과**했다. 회전하는 카피 위젯이라 실행마다 폭이 달라진다.
👉 절차: `--snapshot --label=X` 2벌을 **after 빌드에서** 뽑아 노이즈 쌍으로 쓰고,
`--compare=<before>,<after>` 로 판정한다. dist 가 소스보다 낡았다고 죽으면 `--allow-stale`
(before 스냅샷을 이전 빌드에서 떠야 할 때 정당하게 필요하다).

### 3-3. 🔴 PR-2 의 판정 지표는 **baseline 이 이미 0** 이었다

`perf:interaction` baseline(PR-1 tip, 3회): 스크롤 **50ms 초과 프레임 0 [0–1] · 최장 프레임 0 [0–134] ·
블로킹 합계 0 [0–67]**. 앞 문서가 PR-2 의 판정 기준으로 지정한 세 값이 전부 바닥이라
**개선을 보일 여지가 없다.** 착수 전에 baseline 을 먼저 보면 판정 불가를 미리 알 수 있다.
👉 **PR-3~7 도 착수 전에 그 PR 의 판정 지표 baseline 을 먼저 확인할 것.**

### 3-4. `animation: … !important` 단축속성 함정

`animation-play-state` 를 따로 걸 때 **`!important` 가 없으면 조용히 무시된다.** 단축속성이
`animation-play-state:running` 까지 !important 로 세팅하기 때문이다. 이 레포 히어로 셀렉터
다수가 그렇다(`cosmic-main.css:266` `logo-star`, `index.html` 네오 moon 오버라이드 등).
PR-2 는 `!important` 를 붙였고 **computed style 로 10/10 정지를 실행 확인**했다(추측 금지).

   만든 회귀가 아니라 **기존 상태**다. 유력한 원인은 고스트 클릭 억제 / `invokeMobileCardLink`

   `stopPropagation` 하는 지점을 찾을 것). 발화하지 않는다면 이건 성능이 아니라 **기능 버그**이고,
   고친 뒤에야 지연이 의미를 갖는다.

   **4라운드 정적 추적 결과 — 후보 2개를 특정했다(🔴 런타임 미검증).** 경로가 서로 다르다:
   1. **실제 터치(모바일)** — `js/mobile-interaction-patch.js:2214` 의 touchend capture 핸들러
      (`{ passive:false, capture:true }`)가 `invokeMobileCardLink(state.linkEl)`(`:1746`,

      `stopImmediatePropagation() + preventDefault()` 를 건다(`NAV_OWNED_SELECTOR` 밖이면 무조건).
      선행 `pointerdown`/`touchstart` 가 오면 `clear()` 로 풀리므로 **합성 클릭만** 죽는다 —
      round-3 하네스가 본 것과 정확히 맞는다.

   CDP 실제 터치 1회 + 합성 클릭 1회를 쏴 **어느 단계에서 끊기는지** 기록한다.
