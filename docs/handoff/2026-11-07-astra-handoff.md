## 브라우저와 UI 작업

브라우저 작업에는 설치된 `ego-browser` 지침을 따른다. 기존 작업에서 사용한 TaskSpace가 사용자 인증 handoff 뒤 사라져 현재 접근할 수 없었다. 해당 지침은 전체 사용자 목표에 TaskSpace 하나만 사용하고, 막혔을 때 새 TaskSpace로 복구하지 말며 기존 공간을 계속할 수 없으면 사용자에게 요청하도록 한다. 같은 작업을 위해 새 공간이나 다른 브라우저 자동화로 우회하지 않는다. 코드·오프라인 검증 등 독립 작업을 먼저 진행하고 브라우저 작업이 실제로 막힐 때만 기존 공간 복원을 요청한다. 토스 비즈니스 로그인이 필요해지는 시점에는 사용자가 열린 Chrome에서 직접 로그인하도록 안내한다.

모바일 UI 변경에는 이미 읽은 `impeccable`과 Code Destiny 적용 지침을 따른다. 기존 반려동물 화면·자산과 사용자 정책을 유지하고, 편집 직전에 `reference/craft-floor.md`를 읽는다. 네트워크 차단 목 데이터로만 시험한다. 시각 검사는 실제 가능한 범위를 명시하며 공식 기기 시험으로 대체하지 않는다.

## 인계받는 에이전트가 첫 실행할 일

재개 위치는 위 전용 워크트리다. 마지막 검증된 코드 커밋은 `2717700abbfe65cfe153fcad60ff57ef4563eade`이며, 그 뒤의 인계 문서 커밋은 `git log -1`로 확인한다. 인계 시점의 실제 마지막 SHA는 전달 메시지의 재개 프롬프트를 따른다. 이 작업은 아직 main에 반영하거나 push하지 않았다.

```powershell
Set-Location 'D:\Development\code-destiny\.codex-worktrees\toss-release-20261103-231835'
Get-Content -Raw 'D:\Development\code-destiny\.codex-worktrees\toss-release-20261103-231835\docs\handoff\2026-11-07-astra-handoff.md'
git status --short
git log -1 --oneline
git show --no-patch 2717700abbfe65cfe153fcad60ff57ef4563eade
```

1. `AGENTS.md`, `CLAUDE.md`, 이 문서와 심사 준비 기록을 읽고 사용자 지시를 우선한다. 전용 워크트리의 상태·HEAD와 다른 세션 main의 현재 상태를 읽기 전용으로 확인한다.
2. 인계 직전의 마지막 커밋과 `check:fast`, 앱 전체 테스트 결과를 확인한다. 검사가 실패했거나 결과가 없으면 통과라고 적지 말고 해당 원인을 해결한다.
3. 반려동물의 결과 화면·두 상품의 결제 및 복구 연결을 이어서 완성한다. 그 다음 전체 인벤토리의 남은 범위를 처리한다. 기존 문서와 코드가 충돌하면 코드를 검증해 문서를 갱신한다.
4. 최종 조건이 모두 충족되고 콘솔 제출 직전 화면이 준비되었을 때만 사용자에게 최종 심사 제출 승인을 요청한다. 승인 전에는 제출하지 않는다.
