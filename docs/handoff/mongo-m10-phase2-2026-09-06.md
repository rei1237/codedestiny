- [ ] **D — 8초 hang: 스테이징에서 재현됨(2026-09-06, #1622 빌드 072630a)**. 동시 3건 × 5회(5분 간격): 15요청 중 `[db-op-timeout]` 4건(3회차 2·5회차 2), wall p95 `/api/reviews` 11.7s · `/api/reviews/summary` 9.7s · `/api/insights` 6.5s. 재현 스크립트는 세션 scratchpad `burst.mjs`(fetch 3개 `Promise.all` + 5분 sleep, 20줄) — 커밋하지 않았다. 캡처 파일은 IP 가 있어 폐기.
  - **메커니즘(실측)**: 3회차 `summary` 의 payload 가 `connectMs=300`(ping 실패)인데 `[db-connect] starting connection … warmPingMs=300` 이 **없다** → `worker/lib/db.js` 웜 분기 catch 의 "이웃 op 이 있으면 끊지 않고 그대로 돌려준다" 가드(`countActiveMongoOps() > activeOpsOwned`, 현재 `:745`)가 **죽었다고 판정한 커넥션을 돌려줬고**, 그 뒤 들어온 `reviews` 2 op 은 #1622 로 ping 을 건너뛰어 같은 죽은 커넥션을 받았다. 세 op 전부 8000ms 예산을 태웠다. 카운터: `checkOutFailed 2~3 · lastCheckOutFailReason:"timeout" · maxCheckoutWaitMs 2849~3944 · commandStarted−Succeeded−Failed = 5`(응답 없는 명령이 풀을 붙든다). 다음 회차(4회차)는 세 요청 모두 ping 실패→detach→재수립으로 4.1~4.8s 에 정상 복구 — 즉 hang 은 "죽은 웜 커넥션 + 동시 op ≥2" 조합에서만 나고, 단독 요청은 ping 이 걸러 낸다.
  - **후보 수정(전부 `connectDb` 안, 새 계층 없음)**: ① `추천` ping 실패 시 이웃이 있어도 `detachDeadWarmConnection()` 을 실행한다 — 지금의 detach 는 떼고 배경에서 닫으므로 2026-08-08 의 전역 disconnect 와 다르고, 이웃은 어차피 죽은 소켓 위에 있다(이웃의 op 는 transient 로 실패 → `withMongoRetry` 재시도가 새 커넥션을 탄다). 위험: ping 이 **거짓 실패**면 살아 있는 이웃까지 끊는다 — 스테이징 웜 ping 실측 rtt 186~261ms 로 예산 300 과 40ms 차이라 거짓 실패가 실재할 수 있다(프로덕션 rtt 는 미측정). 그래서 ①은 `[db-ping]` rtt 를 프로덕션 tail 로 먼저 재고 예산을 그 p95 위로 두는 것과 한 세트. ② 돌려주기 전에 `pendingPoolReset=true` 만 걸어 마지막 op 이 빠질 때 리셋 — 이번 버스트는 못 살리고 다음 요청만 빨라진다(지금도 4회차가 스스로 복구했으므로 이득 작음). ③ 이웃 op 을 기다렸다가(짧게) 이웃이 빠지면 detach — 대기 계층이 하나 늘어 원칙 6 위반 소지.
  - **① 구현함(2026-09-06, 이 브랜치)**: `connectDb` catch 의 이웃 가드 삭제(ping 실패면 항상 `detachDeadWarmConnection()`). 먼저 돌던 op(크론 포함)은 #1622 의 ping 건너뛰기 분기가 계속 지키므로 catch 에 이웃이 보이는 경우는 "내 ping 300ms 사이에 들어온 이웃"뿐이다. 🔴 인수인계의 "이웃 op 는 transient 로 실패한다"는 틀렸었다 — 떼어 낸 클라이언트 위의 op 은 `MongoExpiredSessionError`·`MongoNotConnectedError`(2026-09-03 크론 사고 로그의 두 메시지)로 실패하고 둘 다 분류기에 없었다. 그래서 `isTransientMongoError` 에 두 이름을 추가했다(없으면 이웃이 8초 hang 대신 즉시 500). 이 분류기는 라우트 57파일이 503 매핑에 쓰므로 그 두 에러의 응답이 500→503+`Retry-After` 로 바뀐다(의도한 변화). 테스트: `db.warm-connection-revalidation.test.js` 의 "must not disconnect" 를 뒤집고 분류 테스트 1건 추가, 옛 가드 되살리는 변이로 빨간불 확인. 스테이징 실측은 **미검증** — 머지 뒤 재버스트가 다음 단계다.
  - **① 머지 후 재버스트(2026-09-06 00:20~00:46Z, #1633 = caf66a7 배포 뒤) — 기준 미달**. 버스트 자체의 `[db-op-timeout]` 은 0 이었지만 **3·4·5회차 `/api/insights` 가 전부 500**(`[worker-unhandled] MongoExpiredSessionError`), `reviews`·`summary` 는 200 이나 wall 5.3~7.9s. 2회차는 `summary`·`insights` 가 워커에 도달하지 못하고 클라이언트에서 303s 뒤 `fetch failed`(tail 에 이벤트 없음, 미해명). 측정 창이 오염됐다: 00:29·00:38 에 다른 PR 머지로 스테이징이 재배포됐고(회차마다 콜드), 00:24~00:31 브라우저 로그인 트래픽이 섞였다.
  - **①이 틀린 이유(tail 실측)**: 콜드 회차의 `reviews` 가 연결을 세운 뒤 `withMongoRetry` 의 두 번째 `connectDb` 가 **방금 세운 커넥션**에 ping 을 던지는데, 이웃 2 op 이 소켓을 쓰는 중이라 ping 은 풀에서 새 소켓을 열어야 하고(`socketReadyMs≈940`) 300ms 예산에 못 든다 → **거짓 실패** → ①이 detach → 그 위의 `insights` 는 `MongoExpiredSessionError`(insights 는 `withMongoRetry` 가 없어 재시도 없이 500), 나머지는 attempt 2 로 재수립. 즉 옛 이웃 가드가 지키던 "살아 있는 커넥션의 거짓 ping 실패" 경로가 #1633 로 열렸다. 브라우저 창(페이지당 DB 라우트 5~8건 동시)에서는 `[db-op-timeout]` 8000ms 6건 중 4건이 `lastCheckOutFailReason:"poolClosed"` 로 `db.js` 상단 주석의 2026-08-08 사고 사유와 같다(추정: 같은 메커니즘, 브라우저 창은 재현 조건이 통제되지 않아 미검증).

## 후속 과제(이번 범위 밖, 고치지 않았다)

- `worker/routes/insights.js:385` 공개 목록 로드가 `connectDb` 뒤 `Insight.find` 를 **`withMongoRetry` 없이** 부른다(파일 내 `withMongoRetry` 0건, 검색 범위 그 파일) — 1회차에서 `MongoWaitQueueTimeoutError` 가 `[worker-unhandled]` 500 으로 나갔다(다른 라우트는 503+`Retry-After`).
- 라우트가 `connectDb(env)` 를 부른 뒤 `withMongoRetry` 가 다시 `connectDb` 를 부르므로 **콜드 요청이 방금 세운 커넥션에 300ms ping 을 던진다**(5회차 `summary`: 연결 +2968ms → +3268ms ping 실패 → detach → 재수립 2353ms, 요청 5.3s). 새 풀은 첫 소켓 생성(socketReadyMs≈1300)이 필요해 예산 안에 못 돌아온다. `lastHealthyAt` 은 수립 직후 찍히지만 `MONGO_PING_MIN_INTERVAL_MS=0` 이라 무효.
- 스테이징 tail 에 `Possible EventEmitter memory leak detected` 43건 — `observeConnectPhases` 리스너 누적 추정(미검증).
- 동시 3요청 중 한 요청이 별도 아이솔레이트에 떨어져 자기 커넥션을 새로 세운 회차가 있다(1·3·5회차 `insights`) — 추정, tail 에 아이솔레이트 식별자가 없다.

## 함정

- `db.js` 는 `autoIndex:false` — 스키마 선언은 아무것도 만들지 않는다. 새 인덱스는 선언과 마이그레이션 둘 다 넣는다(`verify:mongo-query-index-shapes` 는 선언+리터럴을 원장으로 쓴다).
- `verify:reconcile-index-drift` 의 `unused` 는 "리터럴 쿼리가 없다"이지 "쿼리가 없다"가 아니다 — 변수 조립 필터는 `DYNAMIC_READERS` 에 근거를 올린다.
- 워크트리엔 `.env.local`·`node_modules` 가 없다. `MONGO_URI` 는 루트 `.env.local` 에서 셸 환경변수로 주입(값 비출력, `.env*` 수정 금지). `wrangler`·`mongodb` 는 루트 `node_modules` 절대 경로로 부른다.
- 로컬 `check:quick` 의 `build:worker` 는 `workers-og` 미설치로 실패한다(회귀 아님, PR CI 로 확인).
- `wrangler tail --format json` 은 NDJSON 이 아니다 — `scripts/report-worker-tail-latency.mjs` 의 괄호 깊이 파서를 쓴다.
