# MongoDB Atlas M10 × Workers 최적화 — Phase 2 잔여

## 왜

M10(3노드, 노드당 신규 커넥션 15/s) 한계 안에서 결제(PortOne/Inicis·Google Play)·로그인/세션/권한 경로를 최적화한다. 게이트형 4단계: 진단 → 보고·승인 → 구현(1변경 1커밋, 결제 실행 파일은 별도 브랜치·별도 승인) → 전후 비교·회귀 체크리스트. 결제 정합성(멱등·majority)은 성능을 이유로 완화하지 않고, M20 상향으로 결론내지 않는다.

## 함정

- `payment-service.js:141` `DEFAULT_TRANSACTION_OPTIONS` 는 `{timeoutMS: 8000}` 그대로 — `db.transaction-budget` 의 정규식이 그 모양을 요구한다. 유일한 호출부 `billing.js:1948` 가 `mongoTransactionOptions()` 를 넘기므로 실효 경로는 majority 다.
- `[vars]` 노브를 올리면 `__tests__/worker/db.vars-code-default-parity.test.js` 의 `PAIRED_KNOBS` 에 넣고 `wrangler.staging.toml` 에도 같은 값을 둔다(스테이징 전용 키 금지).
- 로컬 `check:quick` 은 마지막 `build:worker` 가 `workers-og` 미설치로 실패한다(코드 회귀 아님, CI 로 확인).
