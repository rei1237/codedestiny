# 관리자 코인 결제 플로우 수동 검증 체크리스트 (2026-04-14)

## 목적
- 관리자 계정에서 코인 표시가 항상 9999로 유지되는지 확인한다.
- 관리자 계정도 일반 사용자와 동일하게 실제 차감 API를 타는지 확인한다.
- 관리자 우회(즉시 통과/무차감)가 동작하지 않는지 확인한다.

## 사전 조건
- 대상 환경: 운영 또는 스테이징(실제 인증/결제 API 연결 상태)
- 브라우저: 크롬 일반 모드 1개, 시크릿 모드 1개
- 관리자 계정 로그인 가능
- DevTools Network 탭 사용 가능

## 준비 단계
1. 일반 모드에서 사이트 접속 후 관리자 로그인.
2. 로컬 저장소 초기화:
   - localStorage의 fortune_auth_user, fortune_auth_token, fortune_auth_role 확인
   - sessionStorage의 flower_admin_token 존재 여부 확인
3. 페이지 강력 새로고침(Ctrl+F5).
4. 메인 화면 상단 잔액 배지 값이 9999인지 확인.

## 시나리오 A: 잔액 표시 고정 검증
1. 로그인 직후 잔액 표시가 9999인지 확인.
2. 페이지 새로고침 3회 반복 후 매번 9999 유지되는지 확인.
3. /api/payments/me 응답 이후에도 배지가 9999로 유지되는지 확인.
4. 다른 섹션 이동 후 메인 복귀 시 9999 유지되는지 확인.

### 합격 기준
- 어떤 재렌더/동기화 이후에도 관리자 배지가 9999에서 0 또는 다른 값으로 내려가지 않는다.

## 시나리오 B: 유료 기능 1회 결제(회당 차감) 검증
1. 코인 필요 타일(예: 프리미엄 카드) 클릭.
2. 결제 확인 모달에서 진행 선택.
3. Network에서 다음 요청 확인:
   - POST /api/fortune/pig-coin/consume 발생
   - 요청 body에 cost, reason 포함
   - 응답 status 200 확인
4. 응답 직후 기능이 실제로 열리는지 확인.
5. 직후 잔액 표시가 9999로 복구되는지 확인.

### 합격 기준
- consume 호출이 반드시 발생한다.
- 호출 없이 기능이 열리는 우회 경로가 없다.
- 동작 완료 후 관리자 표시값은 다시 9999다.

## 시나리오 C: 영구 해금형 결제 검증
1. 잠금 섹션 해금 버튼 클릭.
2. 결제 확인 후 Network에서 POST /api/fortune/pig-coin/consume 확인.
3. 해금 완료 상태 표시 확인.
4. 새로고침 후 해금 상태 유지 확인.
5. 잔액 배지가 9999로 유지/복구되는지 확인.

### 합격 기준
- 영구 해금도 consume API를 정상 호출한다.
- 해금 상태는 유지되고, 관리자 표시값은 9999다.

## 시나리오 D: 부족 코인/예외 처리 검증
1. 테스트용으로 consume 402를 유도 가능한 환경이면 유도.
2. 부족 코인 안내/충전 유도 UI가 정상 노출되는지 확인.
3. consume 실패 시 기능이 열리지 않는지 확인.

### 합격 기준
- 실패 시 유료 기능이 열리지 않는다.
- 우회 없이 정책대로 차단된다.

## 시나리오 E: 우회 회귀 검증
1. 관리자 토큰 존재 여부와 관계없이 결제 요청이 항상 나가는지 확인.
2. 프리미엄 플랜 상태가 있어도 무차감 즉시 통과가 없는지 확인.
3. 클릭/터치 양쪽 입력에서 동일하게 consume 호출이 발생하는지 확인.

### 합격 기준
- 클릭/터치/플랜/토큰 조건과 무관하게 우회 없이 동일 결제 경로를 탄다.

## 기록 템플릿
- 일시:
- 환경(도메인/브라우저):
- 시나리오 A 결과: PASS/FAIL
- 시나리오 B 결과: PASS/FAIL
- 시나리오 C 결과: PASS/FAIL
- 시나리오 D 결과: PASS/FAIL
- 시나리오 E 결과: PASS/FAIL
- 실패 시 증거:
  - Network 캡처(요청 URL, status, body)
  - 콘솔 로그
  - 재현 단계

## 최종 판정 규칙
- 모든 시나리오 PASS면 배포 가능.
- B 또는 C에서 consume 미호출 1건이라도 발견되면 즉시 FAIL.
- A에서 관리자 표시값 9999 이탈이 1회라도 발생하면 FAIL.
