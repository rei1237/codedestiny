# 원본 상담 화면 개발 테스트

범위는 **영냥이 사주 질문 상담 · 운명의 찻집 · 네오 팩폭 작전실**이다. 원본 React 컴포넌트, CSS, 캐릭터 자산과 입력·결과 렌더러를 직접 사용한다. 새로운 공통 상담 결과를 만들지 않는다.

`npm run dev --prefix apps/toss -- --strictPort` 실행 후 `http://127.0.0.1:4317/test/playground.html`에서 시작한다. 미니앱 홈의 상담 진입도 개발 모드에서는 원본 화면으로 연결된다.

| 서비스 | 직접 테스트할 흐름 | 원본 구현 |
|---|---|---|
| 영냥이 | 질문·깊이·프로필 → 샘플 결과 → 목차·본문 → 영냥이 보관함 → 재열람 | Consultation, Result, ReadingBook, QuestionConversation, Library |
| 운명의 찻집 | 이야기·찻잔·질문 → 카드 선택·확정 → 결과·편지 → 추가 질문 1회 → 보관함·재열람 | FortuneTeaHouseClient/Page, TeaHouseResultSheet, SavedTeaReading |
| 네오 | 고민·주제·방식·출생정보·강도 → 1차 브리핑 → 현실 점검 → 수정 작전 → 전용 결과 재열람 | NeoOperationRoomPage/ResultPage, RecordsClient |

## 개발용 대역의 경계

- 가상 계정과 샘플 본문이다. 실제 개인의 사주 계산·유료 AI 해석·계정 결과 품질을 증명하지 않는다. 결과 화면 상단에도 이를 표시한다.
- 영냥이는 사주 질문만 준비되어 있다. 다른 체계는 준비 요청에서 거부한다. 원본 가격·상품·목차·추가 질문 구성은 정본에서 읽는다.
- 찻집은 기존 `mock-tea-house.mjs`를 재사용한다. 타로 선택은 기존 카드 선택 코어를 사용한다. 사주·숙요점·공동 상담 전체의 화면/내용 동등성을 이번 검증으로 주장하지 않는다.
- 네오는 원본에 이미 있던 로컬 브리핑·수정 명령서 표본을 쓴다. 입력에 따라 AI 내용이 달라지지 않는다. 최신 샘플 하나만 탭 세션에 보관한다. 전략서 목록은 빈 대역이며 전략서 발행은 제공하지 않는다.
- 영냥이·찻집 표본은 개발 서버 메모리에만 있다. **서버 재시작 시 사라진다.** 실제 구매 기록과 연결되지 않는다. 영냥이와 꿀꿀운세 보관함은 분리한다.
- 요청 본문과 메서드는 보존하되 인증 헤더·쿠키는 전달하지 않는다. 미구현 API는 실패하며 실제 서버로 폴백하지 않는다. CSP도 외부 연결·폼 전송·결제 프레임을 차단한다.
- `vite-preview.mjs`는 `apply: serve` 전용이다. `entry.jsx`도 DEV에서만 실행된다. Next 대체 모듈·가상 계정·결제 대역·표본 API는 출시 번들에 들어가지 않는다.

## 출시 이식에 남은 일

1. 이 원본 화면 진입을 출시 빌드에서도 사용할 수 있도록 Next 의존 부분을 공용 CSR 경계로 분리한다. 현재 출시 빌드의 기존 공통 상담 경로는 그대로다.
2. 토스 사용자·상품·주문을 서비스별 원본 입력/결과 API와 연결하고 소유권·중복 차감·결제 복귀·생성 중단/재시도·저장 원문 재열람을 각각 검증한다. 웹 계정을 임의로 연결하거나 개발 대역을 운영용으로 켜지 않는다.
3. 토스 검수 상품 및 실제 기기에서 로그인·구매·복구·긴 결과 읽기·뒤로가기·성능을 확인한다. 별도 승인 없이 실결제나 유료 AI 검증을 실행하지 않는다.

이 테스트 구현만으로 “완전 이식”, “현재 서비스와 결과 품질 동등”, “출시 준비 완료”로 집계하지 않는다.

검사: `node --test apps/toss/test/canonical-preview.test.mjs`, `npm test --prefix apps/toss`, `npm run build --prefix apps/toss`. 실제 UI 검증과 공식 main CI는 별도로 기록한다.
