# 측정 기준선과 운영표

기준 기간: 2026-09-23 00:00부터 2026-10-21 00:00 직전까지, Asia/Seoul, 완료된 28일.

| 항목 | 값 | 확보 상태 |
|---|---|---|
| GA4 동의 방문 세션, 소스/매체별 | 미확보 | 현재 작업에서 해당 기간의 GA4 export를 받지 않음 |
| 상품별 상세 진입 세션 | 미확보 | 기존 page_view·product_detail_view의 보고서 추출 필요 |
| 결과 예시 열람 세션 | 미확보 | 이번 sample_view 보완 이후부터 관측, 과거 소급 추정 안 함 |
| 상품별 상담 시작 세션 | 미확보 | 기존 product_start_click 등 상품별 의미를 맞춰 추출 |
| GA4 purchase가 기록된 동의 세션 | 미확보 | 결제 검증 후 기록 이벤트, 취소·중복 구분 필요 |
| 서버 전체 확인 구매·전달 건수 | 미확보 | 운영 기록 read-only export 필요, 이 작업에서 DB 접근 없음 |
| 기존 YouTube 시청 유지·링크 유입 | 미확보 | 채널 보고서 export 필요 |

분모는 섞지 않는다. GA4 구매 세션 / GA4 동의 상세 진입 세션은 같은 기간·동일 상품·동일 동의 집단에서만 계산한다. 서버 전체 주문은 별도 운영 건수로 적는다. 이용권·월정석 해금은 신규 단건 구매와 따로 본다. 구매와 전달은 주문 키 기준으로 중복 제거하되 원문 개인정보는 마케팅 보고서에 넣지 않는다.

이벤트 사전:

| 단계 | 기존 신호 / 보완 | 해석 |
|---|---|---|
| 상세 | page_view + 공개 상품 경로, 인연의 서 product_detail_view | shell checkout_opened를 상세 열람으로 대체하지 않음 |
| 예시 | sample_view | 실제 예시 제목 50% 노출, 닫힌 details는 제외. item_id·sample_type·공개 content_id만 보냄 |
| 펼치기 | 인연의 서 product_sample_open | 클릭 의도, sample_view와 합산하지 않음 |
| 시작 | 상품 기존 start 이벤트 / 인연의 서 product_start_click | 결과 생성·결제 완료와 다름 |
| 구매 | 기존 서버 확인 purchase | entitlement_granted와 구분 |
| 전달 | 기존 fortune_delivery 계열·이메일 발송 기록 | 결제만으로 전달 완료를 가정하지 않음 |

한 화면 내 여러 예시·재진입이 있을 수 있으므로 이벤트 횟수 대신 상품별 고유 세션으로 퍼널을 만든다. 무동의·차단 환경·서버 대비 누락을 0건으로 해석하지 않는다. 기존 GA4 동의·비운영 환경 차단을 유지한다.

UTM: utm_campaign=growth_20261021, utm_medium=social, utm_source=naver_blog 또는 youtube. 공개 content ID만 사용한다. 기존 growth-20261012-v2는 스키마 버전으로 재사용하며 새 캠페인 허용 목록만 확장한다. 과거 Threads 기록은 보존하지만 신규 캠페인에서는 허용하지 않는다. 생년월일·이름·질문·이메일·결과 ID를 링크에 넣지 않는다.
