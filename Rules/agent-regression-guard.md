AI 또는 자동화 에이전트가 이 저장소에서 수행하는 모든 수정 작업에 적용한다.

## 1) 요청 범위 고정 원칙

- 사용자가 특정 화면이나 기능을 지정하면, 해당 범위 밖의 파일은 수정하지 않는다.
- 범위 밖 수정이 필요하다고 판단되면, 수정 전에 사용자에게 명시적으로 확인받는다.

## 2) 대규모 롤백 금지

- 요청한 일부를 고치기 위해 관련 없는 파일 묶음을 커밋 단위로 되돌리지 않는다.
- 특히 `index.html`, `public/**/index.html`, 전역 CSS, 폰트, 인증, 결제, 이용권 관련 파일은 사용자 승인 없이 복원하거나 되돌리지 않는다.

## 3) 이미지 이슈 수정 원칙

- 이미지 불일치나 미노출 문제는 먼저 경로 존재 여부와 매핑 데이터를 확인해 해결한다.
- 사용자가 특정 이미지를 지정한 경우가 아니면 전역 스타일 변경으로 우회하지 않는다.

## 4) 관리자/결제 회귀 방지 원칙

- 이미지나 콘텐츠 수정 중 관리자 권한, 결제 계산, 이용권 판정, 결제 게이트 로직을 변경하지 않는다.
- 관련 문자열이 diff에 포함되면 커밋을 중단하고 작업 범위를 다시 확인한다.

## 5) 커밋 전 강제 점검

- 커밋 전에는 반드시 변경 파일과 요청 범위가 일치하는지 확인한다.
- `git diff --name-only`로 변경 파일을 확인한다.
- `git diff --numstat`로 비정상적인 대량 변경 여부를 확인한다.
- 범위 밖 파일이 포함되면 staging을 해제하고 다시 검증한다.

## 6) 커밋 메시지 제한

- 커밋 메시지는 실제 변경 범위만 반영해야 한다.
- 메시지 범위와 실제 변경 파일이 다르면 커밋하지 않는다.

## 7) 복구 우선순위

- 회귀가 발생하면 아래 순서로 대응한다.
- 1순위: 서비스 전체 동작, 권한, 결제, 이용권 로직 정상화
- 2순위: 요청받은 기능의 최소 수정
- 3순위: 시각 보정과 세부 문구 정리

## 8) 내부 검색 비노출 원칙

- 코드 작성이나 수정 전에 관련 파일 탐색, 영향 범위 분석, 회귀 가능성 판단을 수행한다.
- 탐색 과정과 중간 추론을 사용자 응답에 장황하게 노출하지 않는다.
- 사용자에게는 실제 수행한 작업 요약과 필요한 검증 결과만 전달한다.

## 9) 프리미엄/기본 운세 가격 분리 원칙

- 프리미엄 운세 진입(`gotoZiweiPremium`, `gotoAstrologyPremium`, `gotoSukuyoPremium`, `gotoVedicPremium`)의 가격 정책은 기본 운세 궁합 정책과 분리해 관리한다.
- 기본 운세 궁합 가격 정책을 프리미엄 카드, 프리뷰, 결제 안내에 일괄 치환하지 않는다.
- 가격 수정 작업 전에는 아래 세 범주를 분리 확인한다.
- 1) 기본 운세 궁합: `runCompat`, `*_CompatCoinGate`, 기본 명반/궁합 안내 영역
- 2) 프리미엄 운세: `goto*Premium` 카드와 모달 진입 가격
- 3) 프리뷰 결제 안내: `D` 객체의 `cost`/`feats`, `_premDesc`, 카드 배지와 `aria-label`
- 세 범주가 동시에 변경되면 커밋 전 차단하고, 사용자 요청 범위에 맞게 분리한다.

## 10) 결제 방식 우선순위(잠금 콘텐츠 포함) — 🔴 폐기됨 (2026-08-15 사용자 결정: 이용권 우선 확정. 아래는 이력 보존용, 적용 금지)

- 모든 결제 해제/차감 판정은 아래 순서로 통일한다.
- 1순위: 단건 결제(직접 결제 / single_purchase)
- 2순위: 월정석 결제(월간 잔액/월정석 크레딧)
- 3순위: 이용권(멤버십/패스)
- 잠금 콘텐츠 해제도 동일 순서로 적용한다.
- 단건 결제가 가능한 경우 월정석/이용권은 보조 확인으로만 처리한다.
