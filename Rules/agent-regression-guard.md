# Agent Regression Guard Rules

적용 대상: 이 저장소에서 AI/자동화 에이전트가 수행하는 모든 수정 작업.

## 1) 요청 범위 고정 원칙
- 사용자 요청이 특정 화면/기능(예: "사주 분석 화면의 재밌는 사주 콘텐츠 이미지")으로 한정되면, 해당 범위 밖 파일 수정은 금지한다.
- 범위 밖 파일 수정이 필요하다고 판단되면, 수정 전에 사용자에게 명시 확인을 받는다.

## 2) 대규모 롤백 금지
- 요청이 부분 수정인 경우, 다음 파일군에 대한 커밋 단위 대량 롤백/복원(git restore --source <commit>)을 금지한다.
- 금지 파일군: index.html, public/index.html, public/*/index.html, 전역 CSS/런타임/인증/코인 게이트 관련 파일.

## 3) 이미지 이슈 수정 원칙
- 이미지 불일치/미노출 이슈는 먼저 "경로 존재 여부"와 "매핑 데이터"를 점검해 해결한다.
- 전역 스타일 변경은 마지막 수단이며, 사용자 요청이 이미지에 한정되면 전역 CSS 변경을 금지한다.

## 4) 관리자/코인 회귀 방지 원칙
- 이미지/콘텐츠 수정 작업 중 관리자 권한, 코인 계산, 게이트 로직(isAdminUser, __cdAdminBypass, fortune_auth_user) 변경 금지.
- 해당 문자열이 diff에 포함되면 커밋 중단 후 작업 범위를 재검토한다.

## 5) 커밋 전 강제 점검
- 커밋 전 반드시 아래를 확인한다.
- git diff --name-only 로 변경 파일이 요청 범위와 일치하는지 검증
- git diff --numstat 으로 비정상 대량 변경(특히 index 계열) 여부 검증
- 범위 밖 파일이 포함되면 staging 해제 후 재검증

## 6) 커밋 메시지 제한
- 커밋 메시지는 실제 변경 범위를 반영해야 한다.
- 메시지 범위와 실제 변경 파일이 불일치하면 커밋을 금지한다.

## 7) 복구 우선순위
- 회귀 발생 시 우선순위는 다음과 같다.
- 1. 서비스 전체 동작/권한/코인 로직 정상화
- 2. 요청된 기능(이미지/매핑) 최소 수정
- 3. 시각 보정(필요시)

## 8) 내부 검토 비노출 원칙
- 코드 작성·수정 전 내부 검토(파일 탐색, 영향 범위 분석, 회귀 가능성 판단 등)는 반드시 수행하되, 그 검토 과정과 결과를 응답 텍스트에 출력하지 않는다.
- 사용자에게 전달하는 텍스트는 실제 수행한 작업 요약과 필요한 결과물만으로 제한한다.
- 검토 내용은 도구 호출(파일 읽기, 검색 등)로만 처리하고, "검토 결과" "분석하면" "확인해보니" 등의 중간 서술을 생략한다.

## 9) 프리미엄/기본 운세 가격 분리 원칙
- 프리미엄 운세(`gotoZiweiPremium`, `gotoAstrologyPremium`, `gotoSukuyoPremium`, `gotoVedicPremium`)의 가격 정책은 기본 운세 궁합 정책과 분리해 관리한다.
- 기본 운세 궁합 50코인 정책을 반영할 때 프리미엄 카드/프리뷰(`data-coin-cost`, `D` 프리뷰 객체, `_premDesc`)를 일괄 치환하지 않는다.
- 가격 수정 작업 전 아래 3개 범주를 반드시 분리 확인한다.
- 1) 기본 운세 궁합: `runCompat`, `*_CompatCoinGate(50)` 및 "기본 명반 무료 · 궁합 50코인" 영역
- 2) 프리미엄 운세: `goto*Premium` 카드/모달 진입 가격
- 3) 프리뷰/결제 안내: `D` 객체의 `cost`/`feats`, `_premDesc`, 카드 배지/aria-label
- 위 3개 범주가 동시에 변경되면 커밋 전 차단하고, 사용자 요청 범위에 맞게 재분리한다.
